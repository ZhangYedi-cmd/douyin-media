# 治理执行记录报告（模板）

> 治理线**所有任务**的统一产物格式。铁律：本报告**只提议、不落地**——改 `brain/`/线上资产
> 由人审勾选后才应用（见 `README.md`）。报告存 `harness/logs/<date>-<task>.md`，
> 摘要 append 进 `logs/index.jsonl`（dispatcher 落地后自动；现在手动）。

```markdown
# 治理执行记录 · <任务名> · <YYYY-MM-DD>

## 任务 / 触发 / 目标
- 任务：<如 benchmark-refresher>
- 触发：<定时 / 手动 / dispatcher 选中>
- 目标对象：<查的是哪些资产，如 brain/benchmarks.md 的对标账号+打法>

## 现状（查了什么、用什么查）
- 数据来源：<agent-reach 搜了哪些平台/关键词、拉了哪些数据，带日期>

## 发现（逐条，每条带证据）
| 条目 | 判定 | 证据（链接+日期） |
|---|---|---|
| <如 打法"蹭旗舰模型实测"> | ✅成立 / ⚠存疑 / ❌失效 / ➕建议新增 | <来源> |

## 变更提议（给人审勾选；不自动改）
- [ ] <改什么：增/删/改哪条> —— 依据：<对应上面哪条发现> —— 可逆性：<可回滚?>
- [ ] ...

## 盲区 / 未决（机器查不了，需人工）
- <如：对标账号的抖音活跃度无读取通道，需人工核 或 靠 douyin-retro 自有数据>

## 落地记录（人审后回填）
- 批准：<勾选了哪些提议> · 审核人：<> · 时间：<> · 已应用到：<文件>
```
