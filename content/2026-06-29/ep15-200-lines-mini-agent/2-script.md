## 第一章 · 冷开钩子（coldopen，2 段）

**[1]** 两百行代码，能读你的文件、能跑命令、还能自己决定下一步干嘛——一个真正能用的 AI agent，核心就这么大。今天我手写一个迷你版 Claude Code，当场跑通给你看。

**[2]** 你可能以为 agent 多神秘。其实剥掉所有工程外壳，骨架就四样东西：一个循环、几个工具、一道权限闸、流式输出。咱们一行一行搭。

## 第二章 · 四步搭骨架 + 跑给你看（build，11 段）

**[3]** 第一步，agent 的心脏：一个 while 循环。逻辑特别朴素——把你的话发给大模型，看它回什么。它要是只说话，那就是答案，循环结束；它要是说「我想调个工具」，那就去执行，把结果塞回对话历史，再循环一次。

**[4]** 就这么转圈，直到模型不再要工具为止。Claude Code 那个满血版的 query 函数，扒到底，核心也是这么一个 while true。我这版二十行写完。一个 agent 的本质，就是这个 while 循环。

**[5]** 第二步，工具。我给它两个：一个读文件，一个跑命令。对照 Claude Code 的 Tool 接口，一个工具最小必要的就三样：叫什么名字、参数长什么样、还有真正干活的那段代码。

**[6]** 把工具的名字和参数描述一起打包告诉模型，模型就知道「我有这些手脚可以用」。需要时它会主动说要调哪个、传什么参数。我这两个工具，各十几行。

**[7]** 第三步，权限闸。读文件无所谓，但「跑命令」会真改你的机器，落地之前必须问一句。所以执行前我加了一道拦截：把要跑的命令打印出来，等你点头说行，才放行。

**[8]** 五行代码而已。一个 agent 敢在你电脑上跑命令的底气，不是它多聪明，是这道「先问你一句」的闸。

**[9]** 第四步，流式输出。模型一边想、我一边打印，不等它整段写完。逐块读、吐一个字就打一个字到屏幕上——你平时看到的那个打字机效果，就是这么来的。

**[10]** 四步合起来，不到两百行，零框架依赖，只用了 Node 自带的东西。下面跑给你看。

**[11]** 我给它一个任务：先读一个文件、告诉我它导出了啥，再统计这个目录里有几个 ts 文件、把数量写进 report 文件。一句话，扔给它。

**[12]** 你看它的动作：先调读文件，回我「这文件导出了一个常量」；接着它要跑命令，停下来问我一句要不要放行；我放行，它执行，report 文件落地，数字三个，对得上。读文件、问权限、跑命令、流式回话——一个不少。
