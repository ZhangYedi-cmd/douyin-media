## 一句话选题
腾讯 Hunyuan 把 295B 的 Hy3 用 Apache 2.0 全开源了，官方口径「一半大小对标 2–5 倍参数的旗舰」。扒完 model card + benchmark 附录发现：它不是靠堆料，是靠一套 MoE + MTP 的取舍——用 21B 激活跑出 295B 的智商、小模型的成本；代价是把仓库级编码让给了体量翻倍的 GLM-5.2。这一集讲清「一半体量做近前沿」到底是怎么算出来的。

## 核心信息（全部锚主源，2026-07-14 读）
> 主源：HF model card `huggingface.co/tencent/Hy3`（curl raw README 拿到全表）+ GitHub `Tencent-Hunyuan/Hy3` README + VentureBeat 07-06 报道（详引 model card）。

### 架构参数（HF model card 原表，一手）
- MoE：总参 **295B**，激活 **21B**，另有 **3.8B MTP 层**（多 token 预测，做投机解码）。
- 专家：**192 个专家，top-8 激活**（每次前向只点亮 8 个）。
- 层数：主干 **80 层**（不含 MTP），MTP 层 1 层。
- 注意力：64 头 GQA（8 个 KV 头，head dim 128），hidden 4096，intermediate 13312。
- 上下文 **256K**，词表 120832，精度 BF16。
- 有思考档位：`reasoning_effort` = no_think(默认) / low / high。

### 「一半体量」怎么算（机制，讲给工程师）
- MoE 稀疏激活：295B 是「知识总量」，但每个 token 只走 21B 的路 → **算力/成本按 21B 收，智商按 295B 存**。这是「一半体量做近前沿」的第一层。
- MTP 投机解码：3.8B 的多 token 预测层，一次多猜几个 token（vLLM 配 `num_speculative_tokens 2`）→ 提吞吐、降延迟。这是第二层省。
- 部署账（VentureBeat）：Hy3 FP8 footprint **<300GB**，GLM-5.2（~744B/40B激活）FP8 **~744GB**；同样 8 卡，Hy3 一个高配节点搞定、还留 KV cache 余量。官方推荐 8× **H20-3e**（对华合规卡）——刻意按「能合法买到的卡」设计体量。

### 真相对比：别被「打赢 GLM-5.2」带跑（★诚实核心）
- 官方盲测（270 位专家、312 组有效对比）：Hy3 **2.67/4** vs **GLM-5.1 2.51/4**——赢的是**旧版 GLM-5.1**。
- 而 benchmark 附录里，**GLM-5.2（新版）编码全面领先** Hy3：SWE-bench Verified **84.2 vs 78.0**、SWE-bench Multilingual 83.0 vs 75.8、Terminal-Bench 2.1 81 vs 71.7、DeepSWE 46.2 vs 28.0。**GLM-5.2 仍守着编码王冠**。
- Hy3 真赢的地方：**agentic 搜索/工具编排/长上下文** —— BrowseComp 84.2、DeepSearchQA 91.0、MCP 工具编排、AA-LCR 长文检索 73.4（表内领先开源、逼近 Opus 4.8/GPT-5.5）。
- 一句话定性：**Hy3 = 搜索/工具/可靠性优先 + 割舍仓库级编码，换来一半体量的性价比**；GLM-5.2 = 编码封顶但要双倍机器。

### 可靠性（model card 主打，比跑分更像「生产报告」）
- 幻觉率 12.5% → **5.4%**；常识错误 25.4% → **12.7%**；多轮问题率 17.4% → **7.9%**（均对比 4 月预览版、内部真实场景自评）。
- 训练准则明写：**有据才答、没据就说没据、不混淆来源、不编数据**（这条正好跟本账号红线同频，可点一句）。
- 跨脚手架稳定：SWE-Bench Verified 在 CodeBuddy/Cline/KiloCode 等不同 agent 脚手架上方差 **<4%**（呼应账号 harness 心智）。

## 钩子（冷开自成立，L11）
「一个模型只有别人一半大，却敢说自己对标两倍参数的旗舰」——腾讯刚开源的 Hy3 就这么标。我把它的架构表扒开算了一遍，发现这『一半』不是吹的，是三笔账算出来的；但它标题里那个『打赢 GLM-5.2』，得打个折。

## takeaway / 互动
- takeaway：看开源模型别只盯总参数和「打赢谁」。真正决定你部署账单的是**激活参数 + 稀疏架构 + 投机解码**这套「一半体量」的组合拳；Hy3 教科书级地演示了「用取舍换性价比」。
- 互动：你自己部署会选「一半机器的 Hy3」还是「编码封顶的 GLM-5.2」？评论区聊聊你的场景。
