## 钩子（冷开）

**[1]** narration：一个模型，参数只有对手的一半，却敢在自己主页上写：对标两倍参数的旗舰。这不是我说的，是腾讯刚开源的混元 Hy3，官方自己标的。
画面：中央一行大字「295B 对标 2–5 倍参数旗舰」，左边一个小方块标 Hy3 21B 激活，右边一个两倍大的方块标对手；氛围：小个子叫板大块头。

**[2]** narration：我把它的架构表整个扒开算了一遍。结论是：这个一半，不是吹的，是三笔账实打实算出来的。但它标题里那句打赢 GLM-5.2，得给你打个折。这一集就把这两件事讲清楚。
画面：两条线索卡淡入——线索一「一半是怎么算出来的（3 笔账）」、线索二「打赢 GLM-5.2 的水分」；底部标注「架构表来自 Hugging Face 官方 model card」。

## 点一 · 「一半」的第一笔账：MoE 稀疏激活

**[3]** narration：先看最关键的一笔。Hy3 总参数是 295B，听着不小。但它是个 MoE 模型，里面切了 192 个专家，每次真正干活，只点亮其中 8 个，算下来激活参数只有 21B。
画面：192 个小方格网格，8 个被点亮成橙色，其余暗；两个数字对照「总参 295B / 激活 21B」；标签「192 专家，top-8 激活」。

**[4]** narration：这就是稀疏激活的精髓：知识按 295B 的量存着，但每个字的算力和账单，只按 21B 收。你花的是小模型的钱，调的是大模型的脑子。一半体量的第一层，就从这来。
画面：一个天平，左盘「存：295B 知识」，右盘「算：21B 成本」；金句「按大模型存，按小模型算」。

## 点二 · 第二、三笔账：投机解码 + 部署账

**[5]** narration：第二笔账，藏在架构表一个容易被跳过的地方：它专门挂了一个 3.8B 的 MTP 层，多 token 预测。说人话，就是让模型一次别只猜下一个字，顺手多猜几个，猜对了就省一轮计算。这是给推理提速的投机解码。
画面：一条生成流，普通模式一次吐 1 个 token，MTP 模式一次吐 3 个（2 个是投机猜的），命中打勾；标签「3.8B MTP 层 · 投机解码提吞吐」。

**[6]** narration：第三笔账最实在，是部署账。同样跑起来，Hy3 用 FP8 压完不到 300GB；对手 GLM-5.2 是七百多 B 的模型，压完要 744GB。同样八张卡，Hy3 一个高配节点就装下，还留得出显存做缓存。腾讯甚至是照着国内能合规买到的 H20 这类卡，去卡它的体量的。
画面：两条显存条对比「Hy3 <300GB」对「GLM-5.2 ~744GB」；下方「8× H20-3e 一个节点搞定」；小字标注来源 VentureBeat / 官方部署指南。

## 点三 · 「打赢 GLM-5.2」，得打个折

**[7]** narration：好，现在说那个要打折的部分。腾讯主打一个盲测：270 位各行专家，拿真实工作任务盲评，Hy3 拿 2.67 分，对手 2.51 分，赢了。但你仔细看，这里被比下去的，是上一代的 GLM-5.1。
画面：盲测卡「270 专家盲评：Hy3 2.67 vs 2.51」，对手名字放大高亮「= GLM-5.1（旧版）」；一个问号盖在「那 5.2 呢？」。

**[8]** narration：翻到它自己的 benchmark 附录，跟当打的 GLM-5.2 一比，编码这条线，Hy3 是全面落后的。就说最常被引用的 SWE-bench Verified，GLM-5.2 是 84.2，Hy3 是 78.0。终端任务、多语言编码，也都是 5.2 领先。仓库级写代码这顶王冠，还在 GLM-5.2 头上。
画面：编码对比表，四行数字全是 GLM-5.2 领先（SWE-bench 84.2 vs 78.0 高亮）；顶部标题「编码：GLM-5.2 仍领先」。

**[9]** narration：那 Hy3 赢在哪？赢在另一条赛道：给 agent 用的搜索、工具编排、长上下文。找信息、连工具、翻长文档这些活，它在开源里是领先的，甚至逼近 Opus 4.8 和 GPT-5.5。所以真相不是打赢，是取舍：它拿仓库级编码，换来了一半体量的性价比和更强的 agent 能力。
画面：两条赛道分栏——左「编码：让给 GLM-5.2」、右「搜索/工具/长上下文：Hy3 领先」；中间大字「不是打赢，是取舍」。

## 点四 · 它真正想卖的，是可靠性

**[10]** narration：还有个细节我觉得最有意思。它的 model card 读起来不像跑分榜，更像一份生产可靠性报告。比预览版，幻觉率从 12.5 降到 5.4，常识错误从 25.4 降到 12.7，多轮对话出问题的比例从 17.4 降到 7.9。都快砍一半。
画面：三组降幅条动画「幻觉 12.5→5.4」「常识错误 25.4→12.7」「多轮问题 17.4→7.9」；标签「像生产报告，不像跑分榜」。

**[11]** narration：更妙的是它写的训练准则：有据才答，没据就说没据，不混淆来源，不编数据。这话，做过内容的人听着都眼熟。而且它强调一件工程上很值钱的事：换不同的 agent 脚手架去跑，成绩波动能压在 4% 以内。模型稳不稳，比多两分跑分实在多了。
画面：四条准则卡「有据才答 / 没据说没据 / 不混淆来源 / 不编数据」；下方「跨脚手架方差 <4%」徽章。

## takeaway + 互动

**[12]** narration：所以扒完这一圈，我的建议是：看开源模型，别只盯总参数和打赢了谁。真正决定你账单的，是激活参数、稀疏架构、投机解码这套一半体量的组合拳。最后提醒一句，这些数字全是腾讯自己测的，第三方独立评测还没跟上，别当铁板结论。你要自己部署，会选一半机器的 Hy3，还是编码封顶但要双倍机器的 GLM-5.2？评论区聊聊你的场景。想细看的去 Hugging Face 搜 tencent 斜杠 Hy3。
画面：结尾卡，三个关键词定格「激活参数 / 稀疏架构 / 投机解码」+ 诚实标注「数据均为官方自测，第三方验证待定」+ 互动问题大字「你选谁？」+ 底部「HF 搜 tencent/Hy3」（不念外链）。

## 信息来源（可溯源，全部一手/官方）

1. 架构参数 = Hugging Face 官方 model card `huggingface.co/tencent/Hy3` 原始 README 表（2026-07-14 curl raw 拿到）：MoE 总参 295B / 激活 21B / MTP 层 3.8B；主干 80 层；192 专家 top-8 激活；64 头 GQA(8 KV 头, head dim 128)；hidden 4096；上下文 256K；BF16。
2. 盲测 = model card「Stronger Agent Capabilities」段：270 专家、Hy3 2.67/4 vs GLM-5.1 2.51/4。
3. 编码落后 GLM-5.2 = VentureBeat 07-06 报道引腾讯 benchmark 附录：SWE-bench Verified 84.2 vs 78.0、SWE-bench Multilingual 83.0 vs 75.8、Terminal-Bench 2.1 81 vs 71.7、DeepSWE 46.2 vs 28.0（GLM-5.2 全领先）。
4. Hy3 真赢项 = 同源附录：BrowseComp 84.2、DeepSearchQA 91.0、MCP 工具编排 79.1、长上下文 AA-LCR 73.4，逼近 Opus 4.8 / GPT-5.5。
5. 部署账 = VentureBeat + 官方部署指南：Hy3 FP8 <300GB vs GLM-5.2(~744B/40B激活) FP8 ~744GB；推荐 8× H20-3e（对华合规卡）；vLLM/SGLang + MTP 投机解码。
6. 可靠性 = model card「More Reliable Product Experiences」段：幻觉 12.5%→5.4%、常识错误 25.4%→12.7%、多轮问题 17.4%→7.9%（对比 4 月预览版，内部真实场景自评）；训练准则「有据才答/没据就说/不混淆/不编数据」；SWE-Bench Verified 跨 CodeBuddy/Cline/KiloCode 脚手架方差 <4%。
7. 关键诚实标注 = VentureBeat 明写「competitor numbers 多为腾讯自测，独立验证（Artificial Analysis）待定」；盲测对手是旧版 GLM-5.1，GLM-5.2 编码仍领先。
