# 口播稿 · 同一个模型塞进 5 个 CLI coding agent，跑分差出 2 倍

> 唯一真相源。build/ 内 script.md / narrations.ts 是本文派生件，改文案先改这里。
> 数据口径：全部数字来自 CLIArena 仓库 README（作者自报实测），详见 1-brief.md。
> `---` = step 节拍边界，与 build 内各章 narrations.ts 一一对应。

## 第 1 章 · coldopen — 钩子（反差冷开，3 步）

同一个模型，装进五个不同的编程 agent，跑分能差出两倍多。

---

大名鼎鼎的 Claude Code 没能登顶，OpenAI 的亲儿子 Codex，直接垫底。

---

有人真做了这个实验，我把他的仓库扒完了。文末还有个彩蛋：AI 顺手赢了作者手调八年的算法代码。

## 第 2 章 · experiment — 实验怎么做的（模型锁死，5 步）

大家吵「哪家 agent 强」，其实一直在吵模型。这位作者干了件狠事：把模型这个变量，直接锁死。

---

他 fork 了 Codex、Gemini CLI、Mistral Vibe 三个 agent 的源码，全部改造成走同一家 API。

---

再加上本来就有官方接入的 Claude Code 和 OpenCode。

---

五个 agent，跑同一个模型 GLM 4.7，上同一套 Terminal-Bench 测试。

---

这时候再比，比的就只剩「壳」，也就是脚手架本身。

## 第 3 章 · results — 结果（2 倍差距 + 排名不动，5 步）

结果很反直觉。Mistral Vibe 零点三五分领跑，Claude Code 零点二九，Gemini CLI 零点二三，OpenCode 零点二一，Codex 只有零点一五。

---

头和尾，差了两倍还多。记住，模型是同一个。

---

更狠的在后面：作者换上新一代的 GLM 5 重跑，每家都涨了百分之四五十。

---

但排名，一个位置都没动。

---

模型升级抬高了所有人的水位，可船还是那几条船。差距不在模型，在脚手架。

## 第 4 章 · gaps — 差距差在哪（五个维度，4 步）

作者把这几份源码都读了一遍，总结出五个真正拉开差距的地方。

---

文件编辑的容错度、上下文管理、报错之后怎么恢复、命令沙箱，还有跨会话的记忆。

---

他的结论就一句话：宽容的编辑工具加干净的适配层，赢；私有协议加跟厂商绑死的设计，输。

---

还有个旁证：他改造哪个 agent 时改动越大、耦合越深，那个 agent 的跑分就越差。

## 第 5 章 · ending — 彩蛋 + takeaway（5 步）

说好的彩蛋：作者顺手加了一道压箱底的 NP-hard 光纤布线题。

---

他自己那套 C++ 方案，手调了八年。

---

Claude Code 用一个小时写的 Python，比他这八年的方案还好了千分之二。

---

所以下次选编程 agent，别只盯模型跑分。模型决定能力上限，脚手架决定你每天真实用到的下限。

---

想自己跑一遍这个实验的，评论区扣「脚手架」，我把这个开源仓库的名字发给你。

---
