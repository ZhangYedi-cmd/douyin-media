# 第 16 课材料盘点（analyzed.md）

## 1. 核心定位与痛点
- 教学目标：带领开发者构建零外部依赖、单端口、文件驱动的本地可视化监控控制台。
- 痛点分析：
  - 传统后台开发需要数据库、前端构建服务、后端框架、WebSocket 以及反向代理，对个人自媒体流水线来说过重且难以随处运行。
  - 全流水线在终端静默运行，人工无法直观感知当前处于哪一阶段、选题池状态、待审物料与治理日志。
  - 传统轮询浪费请求，WebSocket 双向通道存在繁琐的心跳与鉴权状态机。
- 解决路径：
  - 单端口托管：Hono 或原生 Node.js HTTP 静态托管前端页面与提供只读 API。
  - 被动刷新机制：chokidar 监听本地 YAML 与 Markdown 变更，递增版本号，经由 SSE 广播给浏览器，前端比对版本后拉取快照。
  - 快写收敛：前端写操作只发指令，后端通过子进程调用 media 命令行工具修改真相源，保持单一真实源架构。

## 2. 核心架构与技术细节
- 单一真实源与派生视图：
  - 本地文件（meta.yaml、backlog.yaml、harness/tasks.md）为真相源。
  - 前端控制台是只读派生视图，不保留自己的独立数据库。
- 服务端事件流（SSE）：
  - 标准 HTTP 长连接，头部设置 text/event-stream、Cache-Control: no-cache、Connection: keep-alive。
  - 心跳维持（ping 事件）与连接注销清理。
- 文件变动感知与防抖：
  - chokidar 监听白名单文件，设置 awaitWriteFinish 避免文件写入中途读到半截内容。
  - 50ms 到 500ms 时间窗口防抖，合并突发多文件变更。
- 提示词工程落地：
  - 提示词 1：构建 Node.js 原生 HTTP + SSE 事件广播服务。
  - 提示词 2：构建 Vanilla JS 响应式单页只读看板。
  - 提示词 3：处理高频文件抖动与断线指数退避重连的自愈提示词。

## 3. 陷阱与卡点拦截
- 卡点 1：SSE 客户端断开连接后未释放监听器导致内存泄漏与 EPIPE 错误。
- 卡点 2：编辑器或脚本原子保存时触发多次 add/unlink/change 事件，导致快照重复计算。
- 卡点 3：前端 EventSource 重连风暴与缓存导致数据不刷新。
- 卡点 4：后端动作路由直接拼接 shell 字符串导致命令注入风险。
