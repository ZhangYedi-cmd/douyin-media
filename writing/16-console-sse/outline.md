# 第 16 课大纲规划（outline.md）

## 方案选定：以极简文件驱动架构为主线，以提示词工程为落地手段

### 引言：告别后台黑盒
- 终端静默运行流水线的盲区。
- 单一真实源（SSOT）在可视化层的映射。
- 架构目标：单端口、零外部数据库、基于 SSE 的被动实时刷新。

### 一、技术选型：为什么是原生 Node.js 与 SSE？
- 1.1 传统全栈管理后台的沉重包袱
  - 多进程编排痛点：前端 Vite + 后端框架 + 数据库容器。
  - 为什么个人工程不需要传统数据库。
- 1.2 极简单端口架构方案
  - 原生 Node.js / Hono 单端口承载 API 与静态前端。
  - 克隆即跑，开箱即用。

### 二、数据流架构：只读快照与 SSE 被动刷新
- 2.1 读路由设计与文件快照生成
  - 内存快照机制与 API 聚合（overview、contents、backlog、harness）。
- 2.2 为什么放弃定时轮询与 WebSocket
  - 资源开销、连接状态管理与复杂度对比。
- 2.3 chokidar 监听与 SSE 被动广播机制
  - 监听本地文件树 -> 版本号递增 -> SSE 广播刷新事件 -> 前端拉取新快照。

### 三、快写路由设计：一切写操作收敛到 CLI
- 3.1 前端操作按钮与动作路由
  - 审核通过、打回重做、应用提议、选题提权。
- 3.2 严禁后端直接写文件
  - 使用 execFile 安全调用 media 命令行工具。
  - 规避命令注入与格式破坏。
- 3.3 状态流转闭环
  - 动作触发 -> CLI 原子落盘 -> watcher 感知 -> SSE 广播 -> 视图自动刷新。

### 四、提示词引导实战：驱动 AI 零依赖构建看板
- 4.1 提示词 1：构建 Node.js 原生 HTTP 与 SSE 广播服务
  - 给出系统提示词、输入要求与输出核心实现代码。
- 4.2 提示词 2：构建 Vanilla JS 响应式单页只读看板
  - 零外部 npm 依赖的前端单页应用设计，DOM 更新策略。
- 4.3 提示词 3：自愈提示词处理高频抖动与断线重连
  - 50ms 到 300ms 防抖消除中间态，指数退避算法应对网络中断。

### 五、核心看板视图设计与工程呈现
- 5.1 总览看板：流水线阶段卡片与今日待办
- 5.2 内容列表与详情看板：流转追踪与 Markdown 渲染
- 5.3 选题池看板：分数排序与赛道分布
- 5.4 治理看板：任务注册表与待审变更提议

### 六、验收标准与排查清单
- 启动验证与端到端联动测试。
- 常见报错诊断与解决方案。
