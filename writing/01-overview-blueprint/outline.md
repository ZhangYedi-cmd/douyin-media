# 1. 写作背景与目标：从聊天对话到自动化流水线
核心判断: 单步对话让人沦为 AI 工具的外挂，真正的提效来自把各个工具串联成由确定性规则驱动的自动化闭环。
支撑材料:
- [数据] METR 2024 开发者对照试验：单次无闭环交互使资深开发者耗时增加 19%
- [出处] Norbert Wiener 控制论（Cybernetics）的监督控制理论（Supervisory Control）
- [对比表] 人工搬运与闭环流水线的核心耗时与稳定性对比表
二级标题:
- 1.1 系统目标：从文章输入到飞书审批
- 1.2 为什么做流水线：闭环与确定性
- 1.3 核心资产与人机分工矩阵

# 2. 基础搭建：单点突破与质量自愈（阶段 1 与阶段 2）
核心判断: 先用开源工具完成文案到声画的最简成片，再用机器检测与裁判子代理封死质量漏洞。
二级标题:
- 2.1 阶段 1：开源借力与声画组装（输入到初步成片）
  - 阶段目标与交付：口播文案提炼、16:9 Vite+React 演示网页、TTS 分段合成、竖屏封面
  - 核心痛点与难点：痛点 1（文案书面化与前 3 秒划走）、痛点 2（TTS 长停顿死气与多音字冲突）
  - 架构解法与配置：冷开规则（第一句自成立）、ffmpeg silencedetect 扫描与去停顿、tts.config.json 分段注音 overrides
  - 配图：阶段 1 声画资产生成流 Mermaid 图
- 2.2 阶段 2：质量体检与无头录屏（机器质检与确定性录制）
  - 阶段目标与交付：自动体检脚本、dubbing-reviewer 子代理、确定性渲染 final.mp4
  - 核心痛点与难点：痛点 3（单 Agent 自检的上下文偏置与虚假合格、质检死循环）、痛点 4（无头录屏因系统负载导致时间膨胀与音画脱节）
  - 架构解法与配置：亮点 1（裁判与选手严格分离，只读权限 + 3 轮硬熔断）、Playwright 虚拟时钟逐帧推进 + ffmpeg 混流 mux
  - 配图：阶段 2 质检自愈回路与无头录屏流 Mermaid 图

# 3. 系统成型：交付安全与双线治理（阶段 3 与阶段 4）
核心判断: 流程稳定运行的关键在于状态写入收敛到单点，以及日常生产与长期资产维护在物理上彻底解耦。
二级标题:
- 3.1 阶段 3：交付安全与状态收敛（人审闸口与 CLI 收敛）
  - 阶段目标与交付：media CLI 状态机、feishu-notify 卡片审批通知、douyin-publish 模块
  - 核心痛点与难点：痛点 5（自动化失控误发布风险）、痛点 6（多端并发修改导致的文件状态漂移）
  - 架构解法与配置：亮点 2（CLI 唯一写入收敛，以 meta.yaml 为单一真实源）、人审闸口与 dry-run 预览机制
  - 配图：阶段 3 状态机单点流转与飞书审批流 Mermaid 图
- 3.2 阶段 4：双线治理与数据反哺（资产维护与进化）
  - 阶段目标与交付：账号大脑 brain/、douyin-retro 复盘工具、douyin-ideate 选题引擎、harness-dispatcher 调度器
  - 核心痛点与难点：痛点 7（缺乏外部反馈导致选题自嗨与枯竭、资产老化失效）
  - 架构解法与配置：亮点 3（生产线 pipeline/ 与治理线 harness/ 彻底解耦）、治理线铁律（只产报告与提议，人工核准后回写 brain/）、agent-reach 外网扫描与完播率漏斗归因
  - 配图：阶段 4 生产线与治理线双线闭环 Mermaid 图
