# 第 07 课大纲：自愈机制与 3 轮熔断：告别死循环，打造高可用的自动化修复环

## 篇章设计定位
- 篇幅目标：6500 到 7500 字，结构扎实，直奔工程实操。
- 风格目标：严格遵守工程教程体硬禁令，无加粗、无破折号、无花哨标点，讲清为什么与怎么做。
- 核心交付：完整数据流状态机、三大自愈套路与避坑实战、三轮熔断数学与工程逻辑、录屏抽帧小循环、三套开箱即用的核心提示词。

## 详细目录结构

### 引言
- 痛点切入：自动化流程遇到单点报错中断与模型死循环打转。
- 核心思路：通过客观度量形成确定性反馈回路，配合硬上限熔断实现工程自愈。

### 1. 自愈闭环的完整数据流与时序逻辑
- 1.1 从第一批合成到复验放行的时序流转：生成音频、审查判决、路由动作、重抽合成、二次复验。
- 1.2 状态机的三大出口路径：首轮直通放行、多轮修复收敛放行、满 3 轮硬熔断挂起。

### 2. 三大经典缺陷的自动化自愈套路
- 2.1 音频死气自愈：silencedetect 捕获停顿，depause.mjs 临时文件安全切除，复扫清零验证。
- 2.2 多音字漏注自愈：解析 YAML 建议，注入 build/tts.config.json 的 overrides，重排键名防错位。
- 2.3 同段两读冲突自愈：同一句多音字冲突无法通过配置解决，文案重构并同步 2-script.md、narrations.ts 与组件。

### 3. 安全熔断与状态挂起设计
- 3.1 为什么熔断阈值定为 3 轮：收敛概率衰减模型、Token 成本控制与死锁判定。
- 3.2 达到 3 轮上限后的优雅降级：现场现场现场锁定、meta.yaml 状态翻转 drafting_blocked、生成飞书工单通知人工。

### 4. 录屏后的补充质检闸与抽帧对齐
- 4.1 为什么无头录屏需要独立质检小循环：headless 渲染时间膨胀与 ?subs=1 参数丢失风险。
- 4.2 自动化抽帧验证与音画同步率检测：按调度时间戳抽帧核对字幕与画面。

### 5. 自愈实战：三套核心提示词模板与落地演练
- 5.1 第一步：自愈闭环启动提示词（将客观测试失败日志打包为修复任务信封喂给修补 Agent）。
- 5.2 第二步：多轮修复的迭代提示词（携带前一轮修复记录与残余报错，避免重复踩坑）。
- 5.3 第三步：触发 3 轮熔断后的兜底提示词（自动挂起任务、标记状态、生成人工接管工单）。

### 6. 总结与课后作业
- 总结核心原则：客观度量为锚、确定性路由、严格 3 轮硬熔断。
- 课后实战作业：跑通一次多音字注入自愈闭环，以及注入同段两读冲突验证 3 轮熔断挂起。
