# 第 05 课：ffmpeg 音频体检脚本：如何用纯脚本建立客观音画质检门禁？

## 1. 为什么大语言模型必须依赖底层物理度量工具？
### 1.1 语言模型的物理盲区：听不见波形、分贝与毫秒
- 文本概率模型与物理声学事实的割裂
- 为什么直接让大模型评价音频质量必然产生主观幻觉
- 确定性工具（ffmpeg）与概率模型（LLM）的职责分界
- 测量归测量，推理归推理的工程原则
### 1.2 什么是音频死气？为什么 0.45 秒是短视频完播率的生死线？
- 短视频受众心理与注意力窗口机制
- 超过 0.45 秒异常静音导致跳出率陡增的机理
- TTS 引擎在遇到标点、括号、代码片段时机械插入长停顿的根因
- 物理死气与自然气口的毫秒级界限（0.2 秒舒适区与 0.45 秒警戒线）

## 2. 实战拆解：用 silencedetect 与 ffprobe 捕获声学异常
### 2.1 ffmpeg 与 ffprobe 核心参数深度剖析
- silencedetect 滤镜参数全解析：noise=-30dB 与 d=0.45 的设定依据
- ffprobe 提取精准音频时长、采样率与声道数的无开销参数组合
- volumedetect 滤镜检测音频峰值（max_volume）与均方根音量，规避爆音与蚊子音
- 底层命令行与 Node.js / Python 进程调用的标准写法
### 2.2 批量扫描与多切片时间线对齐
- 遍历音频切片目录与多章节组织规范
- 解析 stderr 中的 silence_start 与 silence_end 并转为时间戳
- 计算音频时长与字幕文案预期时长的偏差毫秒数
- 卡点拦截：跨平台 ffmpeg 路径缺失与 stderr 流数据截断问题处理

## 3. 架构设计：结构化体检信封与去停顿工具
### 3.1 为什么严禁让体检脚本输出散文日志？
- 散文式终端日志在自动化流程中的解析崩溃风险
- 统一结构化体检信封（YAML / JSON）的设计规范
- 信封字段定义：run_id、summary、segments 详情、error_type 与 metrics
- 契约先行的接口设计如何保证下游质检 Agent 稳定消费
### 3.2 静音自动切除工具（depause.mjs）的原理与防坑实战
- 压平机制：将超标死气压缩至 0.20 到 0.25 秒，保留自然呼吸感
- 避免直接切除导致字头被吞的渐变保护窗口设计
- 原地写入静默失败踩坑实录：ffmpeg 输入输出同名导致文件变 0 字节且退出码返回 0
- 临时文件写入、原子重命名（rename）与二轮复扫验收流程

## 4. 零代码与提示词引导：如何用三步法指挥 AI 搭建质检闭环
### 4.1 第一步：用提示词引导 AI 封装底层度量工具
- 编写清晰的需求契约提示词，引导 AI 编写 ffmpeg / ffprobe 包装函数
- 强制要求 AI 产出结构化对象而非文本控制台输出
- 包含超时控制、异常捕获与退出码检查的健壮性提示词模版
### 4.2 第二步：将客观测试数据封装为结构化信封喂给 AI
- 组装包含段落 ID、问题类型、起止时间戳、偏差毫秒的上下文信封
- 提示词中隔离主观推断，只喂入经过脚本验证的纯物理事实
- 示例信封数据展示与下游接收标准
### 4.3 第三步：用质检提示词引导 AI 自动生成修复参数
- 质检裁判的角色定义与无文件写入权限的硬性约束
- 引导 AI 针对静音、音量、时差分别输出精准修复指令（如 ffmpeg filter 参数、tts.config.json 注音补丁）
- 三轮修复熔断机制与人工兜底通道设计
