# 材料盘点：包装 social-auto-upload 发布 Skill

## 1. 核心论点与技术事实
- 事实 1：短视频平台上传脚本极其脆弱。网页前端频繁变动 DOM 选择器、大文件切片上传协议复杂、封面裁剪弹窗与各类活动弹窗不定时弹出、滑动验证码与风控机制严格，手写浏览器自动化（Playwright/Selenium）维护成本过高。
- 事实 2：专业开源项目 `social-auto-upload`（`sau` CLI）通过统一环境（uv + Python 3.12）封装了抖音、小红书、视频号、B站等多平台上传逻辑与 Cookie 管理，具有社区维护红利。
- 事实 3：薄封装原则。不对开源库核心代码进行破坏性侵入，仅通过 Skill 层完成物料契约解析、参数映射与 CLI 调用，隔离外部变更。
- 事实 4：发布物料契约（`4-publish.md`）。在进入发布前必须形成包含标题、正文简介、话题标签、封面路径、媒体文件绝对路径的标准结构，严禁在发布阶段临时让模型生成文案。
- 事实 5：Dry-run 绝对铁律。发布属于不可逆外部副作用。在真发前必须通过 `--dry-run` 模式组装出完整的底层命令和物料清单，推送给人类二次确认。只有收到明确授权信号（如 `--publish` 参数）才执行真正发布。
- 事实 6：环境与登录态实战排错。
  - `NODE_OPTIONS` 污染排查：cmux/Claude 会话注入的预加载脚本导致 Playwright 驱动崩溃，必须使用 `env -u NODE_OPTIONS uv run sau ...` 清空环境变量。
  - Cookie 弱探针假死与误报：`sau check` 探针与上传页面的校验强度不一致可能误报 valid 并静默跳过扫码。排查方案为移走旧 Cookie 文件强制拉起扫码，并核查 sessionid 过期时间（60-90天）与文件修改时间。
  - `--schedule` 定时格式约束：严格要求 `YYYY-MM-DD HH:MM` 格式且在平台有效时间窗口内（2小时至14天），严禁传递自然语言时间描述。
- 事实 7：发布收尾原子记账。发布成功后由 `media publish-done` 统一收口，同步翻转 `meta.yaml`、`backlog.yaml` 和 `dashboard.md`，杜绝状态不一致。

## 2. 核心 Prompt 交付资产
- 资产 1：发布 Dry-run 检查提示词。校验前置状态（approved）、文件存在性、封面比例、标题与话题格式，生成完整 `sau` CLI 命令与物料摘要。
- 资产 2：人类授权执行提示词。解析 `--publish` 授权信号，执行真实上传命令，捕获终端输出并识别成功标识，杜绝二次重复确认卡死。
- 资产 3：异常重试与挂起排错提示词。针对网络超时、Cookie 假死、页面改版等错误进行分类拦截，安全重试一次，仍失败则保持状态不动、记录日志并触发告警，严禁重复提交导致多发。
