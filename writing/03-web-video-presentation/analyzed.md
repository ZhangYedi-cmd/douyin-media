# 第 03 课材料盘点：web-video-presentation 实战

## 1. 核心定位与痛点
- 目标受众：有技术背景、想制作高表现力短视频但缺乏视频剪辑动效经验的工程师；使用传统录屏或 PPT 录制呆板、手写动效耗时费力的创作者。
- 核心痛点：
  1. 传统视频剪辑软件（PR、剪映、AE）缺乏纯文本数据接口，无法被大模型与自动化流水线编排。
  2. 从零手写前端动效耗时长，文案与组件代码深度耦合，修改台词导致布局全乱。
  3. 移动端横屏压窄条导致字号太小、单屏文字堆砌、动画千篇一律卡片化（AI 模板味重）。

## 2. 核心技术事实与参数储备
- 架构机制：Web-as-Video。把视频时间线映射为离散的 Step 计数器，每一页独占 16:9 画幅（1920x1080 基础分辨率，外层 transform scale 居中缩放），进度条平时隐藏仅悬浮可见。
- 脚手架选型：Vite + React + TypeScript + Tailwind CSS + Lucide 图标库。
- 契约规范：
  - 目录隔离：工程落位于 `build/` 目录，源码隔离在 `src/chapters/<NN>-<id>/`。
  - 单一真实源：`narrations.ts` 是口播文本与步数的唯一真相源。`narrations.length` 严格等于 TSX 渲染里 `step === N` 的最大 N + 1。
  - 冷开规则：`2-script.md` 首句必须单句自成立，前 3 秒直击技术痛点或反差，禁止承接词。
- 视觉与动效标准：
  - 字体层级：钩子大字 120-160px，主标题 66-88px，正文核心 40-46px（抖音移动端窄条防模糊底线）。
  - 去 AI 味规则：禁用紫粉渐变、彩色药丸边框、emoji 代替图标、全场统一淡入、伪造数据。
  - 逐步揭示（Staggered Reveal）：列表清单一项一个 step，当前项高亮，历史项灰化保留上下文，严禁单步弹出全量列表。
  - 动画时长与音频约束：单步 CSS 动效时长必须小于等于该步口播时长（估算：字数 ÷ 4 秒）。

## 3. HOW 环节提示词工程支撑
- 阶段一提示词：文案解析与分镜架构。输入 `2-script.md`，抽取 Chapter/Step 节奏，生成 `outline.md`、`chapters.ts` 与 `narrations.ts` 脚手架。
- 阶段二提示词：电影感动效与排版渲染。基于设计 Token、深色主题、大字号排版、SVG 架构图连线点亮与逐步揭示，生成 TSX 与 CSS。
- 阶段三提示词：结构化报错与排障调优。针对动画卡顿（GPU 硬件加速）、字号过小（移动端自适应与基准 rem/px）、步骤音画错位（步数一致性校验与时间线补齐）的精确修正提示词。

## 4. 卡点拦截与报错储备
- 卡点 1：`npx tsc --noEmit` 类型报错，Lucide 图标导入名称错误或未导出的图标组件。
- 卡点 2：`narrations.ts` 数组长度与 TSX 中 step 判断分支数量不一致，导致录屏时自动切步提前或挂死。
- 卡点 3：CSS 动画使用 `top/left/width` 触发大量重排（Reflow），导致录屏掉帧；改为 `transform` 与 `opacity`。
- 卡点 4：页面内自定义按钮触发事件冒泡导致步数误推进，需补充 `data-no-advance` 属性。
