# 第 03 课大纲：web-video-presentation 实战：如何用网页做有电影感的技术解说视频？

## 1. 架构选型：为什么用前端代码替代传统剪辑软件？
- 1.1 传统图形剪辑工具与纯文本代码渲染的工程断层：比较 PR/剪映等 GUI 软件与前端代码在自动化、可复用和大模型协作维度的差异。
- 1.2 Web-as-Video 核心机制：离散步进状态机、16:9 画布自适应与无干扰录屏控制。
- 1.3 开源脚手架架构解耦：Vite + React + Tailwind + Lucide 与主题 Token 系统的职责边界。

## 2. 输入契约：口播脚本 2-script.md 的设计法则
- 2.1 黄金前 3 秒冷开规则：短视频注意力衰减规律、单句自成立契约与禁承接词标准。
- 2.2 台词与分镜步进的解耦契约：章节、步骤与单句口播的 1:1 映射机制。
- 2.3 单一真相源：从 script.md 到 narrations.ts 的映射与自动抽取保障。

## 3. 提示词工程实战：指挥 AI 构建电影感演示页面
- 3.1 第一步：用结构化提示词解析口播脚本并生成分镜骨架（分章、分步、抽取信息池）。
- 3.2 第二步：用设计约束提示词驱动 AI 构建电影感动效与排版（深色主题、大字号排版、SVG 架构图逐步揭示、反 AI 模板味）。
- 3.3 预览与调试：启动本地 Vite 环境验证交互与状态机推进。

## 4. 结构化报错调优：消除卡顿、字小与音画错位
- 4.1 动画卡顿排障提示词：从 DOM 重排（top/left）切换至 GPU 硬件加速（transform/opacity）。
- 4.2 移动端字号修正提示词：建立大字号梯度防压缩模糊（钩子 120-160px、标题 66-88px、正文 40-46px）。
- 4.3 音画脱节排障提示词：校验步数一致性（narrations.length 与 TSX step）与动效时长约束。

## 5. 验收标准与工程自检清单
- 5.1 自动化类型检查与契约自检：TypeScript 编译门禁与断点拦截。
- 5.2 移动端实际观感验证与交付标准：无干扰录屏、大字可读性与无声步清零。
