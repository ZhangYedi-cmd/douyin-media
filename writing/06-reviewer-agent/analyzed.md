# 第 06 课材料盘点与概念梳理

## 1. 核心主题与痛点
- 主题：质检 Agent 设计与裁判解耦（为什么运动员不能同时当裁判）。
- 痛点：在同一个对话上下文（Context）中让同一个 AI 既生成内容又做审查，AI 存在严重的自洽幻觉与注意力偏置；若质检工具具备写权限，AI 会倾向于自行修改掩盖错误，导致全局音画与代码状态脱节。
- 目标：构建只读、只判不改的独立审判 Agent（dubbing-reviewer），定义结构化 YAML 判决书协议，掌握生产 Agent 的外科手术式修补与仲裁防循环提示词。

## 2. 关键技术实体与资产
- 代理配置：`.claude/agents/dubbing-reviewer.md`（权限裁剪：仅只读 Bash、Read、Grep，彻底移除 Edit、Write）。
- 工具度量信封：第 05 课生成的 `check-result.yaml`（客观声学与物理数据）。
- 判决书协议：包含 verdict（PASS/FAIL）、round、issues 列表（segment_id、issue_type、root_cause、suggested_patch、patch_params）。
- 配置文件与源文件：`tts.config.json`（注音词典与语速覆盖）、`narrations.ts`（前端文案）、`audio-segments.json`（分段音频映射）。
- 提示词三件套：
  1. 裁判 Agent 提示词（只判不改、结构化判决、附带具体参数）；
  2. 生产 Agent 修复提示词（外科手术式精准修补、只改目标字段、禁止推翻重写）；
  3. 仲裁与熔断提示词（终止争论、3轮硬熔断、降维裁决）。

## 3. 结构规划
- 导语：从一个真实的翻车案例切入（同一会话让 AI 检查自己刚生成的配音与文案，AI 信誓旦旦说完美无缺，实际视频里出现读错多音字和音画不同步）。
- 1. 为什么同一个 AI 永远当不好自己的裁判？
  - 1.1 大语言模型的上下文偏置与自洽幻觉（注意力矩阵惯性、自圆其说本能、为什么必须清空上下文）。
  - 1.2 工业级系统中的职责隔离（SoD）：选手与裁判角色分离，独立进程与子代理（Subagent/Fork）隔离。
- 2. 配置只判不改的审判者：dubbing-reviewer
  - 2.1 权限沙盒：彻底剥夺写权限的工具裁剪（为何给写权限会让裁判沦为掩盖错误的帮凶）。
  - 2.2 四大质检闸门：客观审查标准（音频完整性、语速离群率、多音字注音覆盖、音画文案一致性）。
- 3. 判决书协议设计：结构化回传与带改法判决
  - 3.1 YAML 判决书标准契约（verdict、round、issues、patch_params 强规范）。
  - 3.2 拒绝模糊报错：为什么优秀裁判必须直接输出确定性修补参数（精确到字符级注音与毫秒级时间戳）。
- 4. 零代码与提示词引导：如何用三步法编排裁判与生产 Agent
  - 4.1 第一步：编写只读裁判 Agent 的系统提示词与配置文件。
  - 4.2 第二步：编写生产 Agent 接收裁判反馈并执行外科手术式修补的提示词。
  - 4.3 第三步：编写仲裁与引导提示词终结争论与防止死循环。
- 5. 验收标准、卡点拦截与实战作业
  - 5.1 验收清单与卡点拦截汇总（权限探针、上下文漂移拦截、3轮熔断排查）。
  - 5.2 课后实战作业（3道渐进式练习）。
