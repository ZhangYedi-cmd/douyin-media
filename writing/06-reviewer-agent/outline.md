# 第 06 课详细大纲：质检Agent设计与裁判解耦：为什么运动员不能同时当裁判？

## 篇幅规划（目标 6500 - 7500 字）

### 导语（约 400 字）
- 场景还原：在同一个会话中让 AI 写完文案并生成音频后，接着让它自查，AI 给出毫无瑕疵的评价，成片上线后却发现多音字读错、音画文案脱节。
- 核心洞察：大语言模型在生成内容后其注意力矩阵存在强烈的自洽惯性。
- 解决路径：实施职责隔离（SoD），打造只读、独立进程、只判不改的质检 Agent，以确定性协议驱动生产 Agent 修补。

### 1. 为什么同一个 AI 永远当不好自己的裁判？（约 1400 字）
- 1.1 大语言模型的上下文偏置与自洽幻觉（约 700 字）
  - 核心机理：Transformer 注意力机制在同一会话中对先前生成 Token 的自洽强化。
  - 心理机制映射：AI 的自圆其说倾向，倾向于证明自己给出的结论是合理的。
  - 上下文污染与注意力漂移：长会话下，写代码的思维路径会干扰审判逻辑，对缺失的字符、多音字读音视而不见。
  - 图解：同一会话自审 vs 干净上下文独立审判对比。
- 1.2 工业级系统中的职责隔离（SoD）（约 700 字）
  - 传统金融与安全系统的 SoD 原则在 AI Agent 架构中的映射。
  - 选手（Generator）与裁判（Auditor）的职责划分。
  - 为什么必须使用独立进程与干净上下文（Subagent / Fork）。
  - 图解：选手与裁判双 Agent 协作与交互流图。

### 2. 配置只判不改的审判者：dubbing-reviewer（约 1600 字）
- 2.1 权限沙盒：彻底剥夺写权限的工具裁剪（约 800 字）
  - 权限决定立场：为什么质检 Agent 必须被剥夺 Edit 和 Write 权限。
  - 案例分析：当裁判拥有写权限时，它会偷偷直接改动音频或文案，导致前端文案（narrations.ts）与音频索引（audio-segments.json）状态断裂，小隐患演变成全局雪崩。
  - 配置文件实战：`.claude/agents/dubbing-reviewer.md` 的 Tools 裁剪规范（只开放 Bash 只读探测、Read、Grep）。
  - 卡点拦截：如何通过探针验证 Agent 无法调用文件修改工具。
- 2.2 四大质检闸门：裁判的客观审查标准（约 800 字）
  - 闸门 1：音频物理完整性（文件存在性、体积大于 1KB、非空校验）。
  - 闸门 2：语速离群率与时长异常（字数与时长比例越界检测、停顿死气超标检测）。
  - 闸门 3：多音字与专有名词注音覆盖（命中文档中的多音字黑名单，检查是否在 tts.config.json 中显式注音）。
  - 闸门 4：音画文案一致性（逐字比对 narrations.ts 与 audio-segments.json 中的文本哈希）。
  - 图解：四大质检闸门串联流水线。

### 3. 判决书协议设计：结构化回传与带改法判决（约 1400 字）
- 3.1 YAML 判决书标准契约（约 700 字）
  - 为什么散文式报错（“第三段有点问题”）在自动化流水线中毫无价值。
  - 结构化判决书的 Schema 设计（verdict, round, issues, root_cause, suggested_action, patch_params）。
  - 规范完整的判决书 YAML 样本。
- 3.2 拒绝模糊报错：为什么优秀裁判必须直接输出确定性修补参数（约 700 字）
  - 差裁判与好裁判的对比：报怨 vs 出方案。
  - 直接输出具体参数的工程价值：多音字注音 overrides（{"行": "háng"}）、语速调节 ratio（1.08）、去停顿毫秒区间。
  - 生产 Agent 拿来即用，单轮修复命中率从 35% 提升到 90% 以上。

### 4. 零代码与提示词引导：如何用三步法编排裁判与生产 Agent（约 1800 字）
- 4.1 第一步：编写只读裁判 Agent 的系统提示词与配置文件（约 600 字）
  - 剥夺写权限的 Agent Markdown 定义与系统提示词模版。
  - 严格约束只基于客观扫描结果输出 YAML 判决书。
- 4.2 第二步：编写生产 Agent 接收裁判反馈并执行外科手术式修补的提示词（约 600 字）
  - 生产 Agent 提示词设计：外科手术式精准修补。
  - 限制修改范围：只碰有问题的行，不动前后上下文，不动正常音频。
  - 补丁写入与单切片重新合成逻辑。
- 4.3 第三步：编写仲裁与引导提示词终结争论与防止死循环（约 600 字）
  - 当生产 Agent 修复后裁判依然报 FAIL、或者双方针对某个多音字陷入死循环时该怎么办。
  - 3 轮硬熔断设计。
  - 仲裁提示词设计：强制降维（如文案换词规避多音字）、终结争论、输出确定性最终补丁。
  - 图解：三轮闭环与仲裁熔断流程图。

### 5. 验收标准、卡点拦截与实战作业（约 800 字）
- 5.1 验收清单与卡点拦截汇总（约 400 字）
