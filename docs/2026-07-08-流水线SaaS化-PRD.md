## 1. 背景与问题

### 1.1 我们手上有什么
一套已跑通、日更验证过的**抖音 AI 技术账号内容工厂**（Claude Code 原生驱动）：
- 15 集「Claude Code 源码解读」系列全自动产出到「出审」，人审后发布，账号级完播 1.65%、单条互动/涨粉在同类高分位（`dashboard.md` 数据）。
- 核心资产不是底层能力，而是**方法论编排**：账号大脑（定位/人设/风格/对标）+ 五阶段 SOP + 配音质检闸口 + 出审前 A–G 终检闸 + 人审闭环 + 复盘回流。

### 1.2 想解决的问题
把这套东西 SaaS 化、上云，**供其他人使用**。核心不确定性在外部——谁会付费、竞品占了哪些坑、上云的技术与合规红线在哪。本 PRD 就是回答这三个问题，并给出可执行的产品方案。

### 1.3 这份文档要回答的三件事
1. 当前系统到底是什么架构，哪些是资产、哪些是上云的硬骨头。（§3）
2. 市场真实需求、竞品空位、能不能收上钱、合规能不能活。（§2、§5、§9、§10）
3. 该做成什么产品——给 3 个方案、讲清优缺点、给推荐路径。（§6~§8）

## 2. 市场与用户洞察（调研结论，带数字）

### 2.1 目标用户分层与真实付费意愿

| 用户层 | 画像 | 核心痛点 | 付费意愿锚点 | 判断 |
|---|---|---|---|---|
| **个人创作者** | 单打独斗，一条 3min 视频全流程约 7 小时 | 重复劳动时间黑洞、多平台差异化分发要重做 | 对纯产量工具价值低（日更 2 年 120 万粉月入仅 3000）；头部愿付（海螺万元年费有人买） | **流量入口，非收入主力**；ARPU 低、易流失 |
| **独立矩阵玩家** | 1 人撑 100 个号 | 真死穴是「产能」和「判重封号」，不是效率 | 第一驱动力是降封号风险 | **付费意愿强但撞合规红线**（见 §5），战略上主动回避 |
| **MCN 小工作室** | 1–5 人超级个体（大 MCN 在萎缩，小微逆势增 14%） | 优秀编导/剪辑稀缺难复制；接 AI 后单条 3–5 天压到 1–2 小时 | **B 端付费意愿是 C 端 10–50 倍**（蝉妈妈企业版 ¥1299/月） | **最真实的付费群体** |
| **企业蓝V** | 企业/政府蓝V | 买的是「结果对赌」不是软件（中传招标全年代运营 43–46 万，带 KPI 对赌） | 折算单条 540–575 元，但买团队+KPI 不买自助工具 | 纯 SaaS 切不进，**只能 B2B2B** 卖给代运营公司做内部提效 |
| **开发者/技术服务商** | 独立开发者 | C 端订阅费不是大头，给企业做「AI 融入内容工作流」定制才是 | 定制咨询 + 私有化 > 标准订阅 | 承接定制/私有化需求 |

**一句话结论**：能真正收上钱的是 **MCN 小工作室**，以及通过**代运营公司间接触达的企业蓝V**。个人创作者当引流入口，别指望它的 ARPU。

### 2.2 一条反直觉的关键事实
**产量 ≠ 变现。** 日更 2 年涨粉 120 万、月入仅 3000。所以「产量放大器」这个叙事对技术向创作者价值有限、还容易被质疑割韭菜。产品叙事必须是**「把机械环节自动化，把精力还给核心判断」**，不是「一天给你产 100 条」。

## 3. 当前系统架构分析

### 3.1 本质
不是传统 web 应用——**没有自己的后端服务、没有中心数据库、没有 API 层**。系统 = Claude Code（agent 运行时）+ markdown SOP（当 prompt）+ skills（当函数）+ 定时/人工触发，状态全记在本地文件。等价于「把资深内容运营的工作流写成 AI 能执行的 markdown，让 Claude Code 在 Mac 上照着跑」。

### 3.2 六层结构

| 层 | 是什么 | 在哪 |
|---|---|---|
| ① 账号大脑 | 定位/人设/风格/对标/信息源，硬约束配置 | `brain/*.md` |
| ② 流水线 SOP | 五阶段「怎么跑」，一阶段一文件 | `pipeline/1-ideate.md`→`4-publish.md` |
| ③ 执行 skills | 每阶段实际执行能力 | `douyin-ideate`、创作四件套、`douyin-publish` |
| ④ 工具底座 | skills 底下真正带代码的部分 | `tools/social-auto-upload`、`tools/feishu-bot` |
| ⑤ 状态/数据 | 内容条目 + 双层状态机 + 选题池 | `content/<日期>/<slug>/meta.yaml`、`_backlog/backlog.yaml` |
| ⑥ 编排/触发 | 定时全自动 + 治理线 | `automation/daily-run.md`、`automation/harness/` |

### 3.3 数据模型（双层状态机，互不镜像）
- **选题池**（`backlog.yaml`，粗粒度）：`idea → picked → published`
- **生产线**（每条内容 `meta.yaml`，细粒度）：`ideated → drafting → review → approved → scheduled → published`
- 双向指针互勾（`backlog.content_path` ↔ `meta.source`），`retro_done` 由治理线单独置位。

### 3.4 真正的「代码」只有两处（上云要重写/替换）
1. **发布引擎** `tools/social-auto-upload/sau_cli.py:1` —— Flask + SQLite + **Playwright 无头 Chrome** 登录抖音等平台发布，靠 **cookie 登录态**。技术最重、合规最危险。
2. **人审 server** `tools/feishu-bot/server.py:1` —— 飞书官方 SDK 长连接，收卡片按钮回调，**就地改本地文件驱动状态机**。

其余重活是**外部 API + 本地算力**：创作靠本地 Node+Vite+**无头 Chrome 录屏 + ffmpeg**，配音靠 **MiniMax TTS**（`tts.config.json` 挂账号克隆音色），封面靠 **Gemini 图像**。

### 3.5 资产 vs 硬骨头（通向方案的桥）

**真护城河（值钱、难复制）不是底层能力，是上面那层方法论编排**：
- 「把内容运营写成可执行 SOP」的抽象（账号大脑 + 五阶段）；
- **质检闸口**（`dubbing-reviewer` 配音质检 3 轮循环、出审前 A–G 终检闸）——**保证 AI 产物能过审，多数竞品没有**；
- 人审闭环 + 「发布必人确认」铁律；
- 复盘数据回流账号大脑的治理线。

**上云四块硬骨头**：
1. **编排没服务化**——现在是 Claude Code CLI 在 Mac 上跑，多租户要重做成工作流引擎。
2. **浏览器自动化发布 + cookie 托管**——合规雷区 + 技术最难规模化。
3. **成本**——每条视频烧 LLM+TTS+图像+渲染，单位经济必须算清。
4. **单租户假设遍布全身**——文件系统状态、单一账号大脑、本地密钥，全要多租户化。

## 4. 核心判断（产品定位，我的观点）

调研把我最初的预判修正了。三条硬判断：

### 判断一：只做「技术深度垂类的可信选题 + 口播稿生产」这个空位，别做全链路通用工具
- **依据**：生成层红海且被字节收编（Coze 已上线「一键生成抖音 AI 分身」）；分发层已开源商品化无壁垒（`social-auto-upload` 至少 4 个活跃 fork）；**唯一没人占好的是「代码库/论文 → 准确可溯源 → 短视频」的翻译层**——DeepWiki 只解决「读懂代码」没下沉到短视频，MoneyPrinterTurbo 类通用工具不懂代码语境、保证不了技术准确。这正好是本项目 brain 定位。
- **护城河建在**：选题判断 / 内容准确性 / 人设一致性 / 审核工作流——这些非生成能力上。纯生成能力很快被开源追平。

### 判断二：把「事实可追溯 + 人审卡点 + AI 标识合规」从内部纪律升级为核心卖点
- **依据**：全行业默认卖点是「快」和「降本 90%」，**没有一家强调内容准确性/可信**——对技术圈这个对准确性敏感的受众，这是差异化空白。而合规大势（抖音健康分打「AI 批量同质化」、AI 标识办法 2025/9/1 生效、清朗专项）恰好让「半自动 + 人审 + 个性化改写 + 主动标识」从合规负担变成**产品正当性和信任卖点**。

### 判断三：商业化别押 C 端个人自助订阅，走「C 端轻订阅引流 + 小工作室/MCN 定制及私有化 + 代运营公司 B2B2B」的分层
- **依据**：C 端 ARPU 天花板低 + 月流失 3–7%；B 端付费意愿 10–50 倍且月流失仅 0.5–1%；企业蓝V 买「团队 + KPI 对赌」不买软件，纯 SaaS 切不进只能 B2B2B；独立开发者真实收入大头是定制咨询不是订阅。早期靠**定制咨询 + 标杆案例反哺产品**，再逐步标准化。

> **一句话核心思路**：不要做「又一个 AI 视频/矩阵工具」（红海 + 被字节收编 + 踩合规雷）。做**技术深度垂类的、可信的、带人审工作流的内容生产平台**，靠 B 端收钱。**「自动发布」明确从核心卖点降级为谨慎的半自动增值模块**——它不是护城河、还是最大风险源。

## 5. 合规红线与风险（做任何方案前必须先认清）

调研结论：这是决定产品形态的**硬约束**，不是可选项。

### 5.1 红线清单（从平台规则到刑事，递进）
1. **官方代发布接口已堵死**：抖音「代替用户发布」OAuth API 于 2023 底停新申请、**2024/7/20 存量全部收回**，仅「企业内部/签约号」窄口子且必须用户在客户端手动触发。「全自动无人值守批量发布」在官方层面被明文封死。
2. **抖音健康分（2025）直接打「AI 批量生成」本身**：明确扣分「固定框架工业化生产、套路化模板批量炮制高度相似内容」。哪怕人工一条条发，被识别为 AI 批量流水线一样限流。**纯模板套壳是红线不是灰线。**
3. **矩阵号「一荣俱损」连坐**：抖音 2025/4 新规对矩阵不当获利「大小号统一严格处置」含封号 + 清退 MCN；小红书 2025 年封 1200 万假号。「一人多账号矩阵」几乎必撞红线。
4. **AI 标识办法（2025/9/1 生效）**：要求显式 + 隐式双重标识。不写隐式元数据 → 被动挂「疑似 AI」影响推荐；**帮用户抹除/隐匿标识 → 从违反平台规则升级为违反部门规章。**
5. **托管账号 cookie/密码**：违反几乎所有平台「账号不得出租/托管」条款，**法律风险主承担者是 SaaS 公司不是终端用户**。判例：腾讯诉群控案判赔 260 万；微信外挂案主犯刑事定罪；抖音诉抓取案判赔 500 万。
6. **个保法**：cookie/密码属个人信息，泄露是独立追责线，非法获取 5000 条以上追刑责。托管越多账号，单点泄露赔偿基数越大。
7. **生成式 AI 服务备案**：封装第三方大模型对外提供服务 = 被认定为服务提供者，敏感垂类（财经/时政/健康）基本跑不掉备案 + 安全评估；纯 AI 技术/科普风险相对低。

### 5.2 规避策略（内化进产品设计）
- 发布走「官方 OAuth 授权 / 用户主动登录 + 短期 token」，**绝不后台存明文密码或逆向模拟登录**。
- **默认写入 AI 隐式标识，绝不做抹除/隐匿标识功能。**
- 定位「一人一账号、辅助/半自动」，**不做矩阵批量运营**；确要覆盖则强制内容去同质化 + 限单客户账号数。
- 文案层强制「个性化改写 + 真人观点注入」，不做纯模板套壳。
- **保留人审卡点**，产品落在「模板生成 + 人工审核确认再手动发布」这个监管和平台都认可的灰度内，而非全自动无人值守。
- 凭据能不存就不存，最小化留存 + 信封加密（见 §8.4）。

## 6. 三个方案（对比 + 推荐）

三个方案在三条轴上取不同点：**做多深（产品边界）／担多大合规风险／卖给谁**。

### 方案 A —「可信内容副驾」（Copilot）· 轻、聚焦空位、最合规
- **范围**：选题判断 + 可信口播稿/脚本生产 +（可选）成品视频生成。**不碰自动发布**——成品导出，用户自己发。
- **卖点**：技术深度垂类「代码库/论文 → 可信可溯源口播稿 → 短视频」翻译层 + 事实可追溯 + 出审终检闸 + AI 标识合规。
- **卖给谁 & 收钱**：C 端技术创作者 freemium 引流（¥19–99/月）+ 小工作室团队档。
- **优点**：合规安全（不托管账号、不自动发）；正中真实空位；启动快；成本可控（本地/轻云渲染，边际近零）；护城河在选题+可信+审核。
- **缺点**：砍掉「全自动」性感卖点；C 端 ARPU 低要教育付费；成品视频生成能力部分会被开源追平。

### 方案 B —「托管式内容运营工作台」（Managed Studio）· 全流程含半自动发布、to B
- **范围**：端到端 = 选题→创作→人审→**半自动发布**→复盘。发布走「用户主动授权登录 + 短期 token + 人确认 + 错峰」的合规半自动，**不做矩阵批量、不存明文密码**。
- **卖给谁 & 收钱**：小工作室/MCN/代运营公司，按坐席/账号数 + 白标私有化 + 定制搭建费。
- **优点**：完整交付「省人力」价值；B 端付费意愿高、留存好、客单价高；私有化把凭据/合规风险转移给客户。
- **缺点**：**合规风险最高**（浏览器托管 + 多租户账号关联风控）；技术最重（浏览器农场 + 编排 + 成本治理）；启动慢；发布层无护城河；法律主承担者是你。

### 方案 C —「内容 Agent 编排平台」（Platform/PaaS）· 把 SOP+skill+人审编排产品化
- **范围**：把「账号大脑 + 阶段 SOP + skill 编排 + 质检闸口 + 人审」抽象成面向自媒体内容的**可视化 Agent 工作流引擎**（vertical Coze-for-content）。用户自搭流水线、自接模型/TTS/发布通道——**发布责任落到用户自己接的通道，平台不直接代发**。
- **卖给谁 & 收钱**：有技术能力的团队/服务商/开发者，PaaS 用量计费 + 模板市场分成 + 企业私有化。
- **优点**：天花板最高；把真正护城河（编排能力）产品化；规避「替用户发布」直接责任；可承接多垂类。
- **缺点**：最难做；教育成本最高；离普通创作者远；短期变现慢；要跟 Coze/Dify 通用平台正面差异化。

### 6.1 对比表

| 维度 | 方案 A 副驾 | 方案 B 托管工作台 | 方案 C 编排平台 |
|---|---|---|---|
| 产品边界 | 选题+创作，不发布 | 端到端含半自动发布 | 可编排引擎，用户自搭 |
| 合规风险 | **低** | 高 | 中（发布责任转移给用户） |
| 技术复杂度 | 低 | **高** | 最高 |
| 启动速度 | **快（1–2 月出 MVP）** | 慢（4–6 月） | 最慢（6–12 月） |
| 主要客户 | C 端引流 + 小工作室 | MCN/代运营（B/B2B2B） | 团队/服务商/开发者 |
| 客单价 | 低–中 | **高** | 中–高 |
| 护城河 | 选题+可信+审核 | 交付完整度（发布层无壁垒） | **编排能力** |
| 天花板 | 中 | 中–高 | **最高** |
| 被字节收编风险 | 低（垂类深） | 中 | 中 |

### 6.2 我的推荐：不是三选一，是**分阶段的 A→B→C**

**核心思路：以 A 为内核站稳，用 B 的合规半自动发布 + 团队/私有化向 B 端要收入，长期把内核沉淀成 C 的编排能力拉高天花板。**

- **第一阶段（0–3 月）做 A 的内核**：验证「技术深度垂类可信内容生产」这个空位有没有真付费。最快、最安全、最聚焦。North Star = 付费小工作室数。
- **第二阶段（3–6 月）加 B 的增值层**：给已验证的小工作室/MCN 客户，加「半自动发布（合规版）+ 团队协作 + 私有化」。发布严守 §5 边界——**半自动而非无人值守**。这是向 B 端要高客单价的关键，但风险受控。
- **第三阶段（6 月+）演进到 C**：把打磨成熟的 SOP + skill + 人审编排，抽象成可配置的引擎，开放模板市场。这时候你卖的是「编排能力」这个真护城河。

**如果只能押一个**：押 **A 的内核 + B 端商业化**——即「可信内容副驾，to 小工作室，先咨询定制反哺产品」。因为调研最硬的两条结论是：**空位在可信选题+口播稿生产，钱在 B 端**。方案 B 的「自动发布」始终是谨慎的半自动增值模块，不是核心。

## 7. 功能需求（按推荐路径展开，P0/P1/P2）

> P0 = 第一阶段 A 内核 MVP 必须有；P1 = 第二阶段 B 增值；P2 = 第三阶段 C 平台化。

### 7.1 账号大脑管理（P0）
把 `brain/*.md` 从「单账号硬编码文件」变成「每租户可配置的结构化配置」。
- **用户故事**：作为创作者，我能填写/编辑我的账号定位、人设语气、内容支柱、对标账号、信息源，让 AI 按我的调性产出。
- **功能点**：定位/人设/风格/对标/信息源五张表单；支持从已有账号「一键分析生成初版大脑」（喂几条历史作品，AI 反推人设）；版本管理。
- **验收**：换一个账号大脑，同一选题产出的口播稿语气/侧重明显不同。

### 7.2 可信选题引擎（P0，核心差异化）
产品化现有 `douyin-ideate`。
- **用户故事**：作为技术创作者，我能让系统从 AI 一手信息源（X/Reddit/HN/GitHub/arxiv）抓料，按传播力模型打分，给我排序好的选题 + 推荐理由 + 素材链接。
- **功能点**：多源抓取（复用 `agent-reach`）；双赛道 6 维打分（practical/social/emotion/hook/timeliness/trigger）；选题池管理（idea→picked）；30 天去重；**每条选题附「事实溯源链接」**。
- **验收**：给定信息源，产出 ≥10 条带评分和溯源的选题，人工判断相关度 ≥70%。

### 7.3 可信口播稿/脚本生产（P0，核心差异化）
产品化「代码库/论文 → 可信可溯源口播稿」这个翻译层。
- **用户故事**：作为技术创作者，我丢一个 GitHub 仓库/论文/源码路径，系统产出一份**事实可追溯**的口播稿——每个技术结论都能点回源码行号/论文出处。
- **功能点**：源码/论文导入与理解（借鉴 `ljg-paper`/`ljg-think` 骨架）；口播稿生成（冷开钩子 + 分点主体 + takeaway）；**fact_check 溯源块**（每个结论挂 `file:line` 或出处，这是 `meta.yaml` 里已验证的做法）；人设语气对齐账号大脑；**AI 标识就地标注**。
- **验收**：产出稿件的技术结论 100% 可点回源，人审「无臆造数据」通过率 ≥95%。

### 7.4 成品视频生成（P0 可选 / P1 完整）
产品化创作四件套。
- **功能点**：口播稿 → 网页演示（`web-video-presentation`）→ TTS 配音（`tts-dub`，账号级音色）→ **配音质检闸口**（`dubbing-check` 3 轮循环）→ 无头录屏出 mp4 → 竖屏封面（`baoyu-image-gen`）。
- **P0 折中**：先只交付「口播稿 + 网页演示 + 音频」，视频渲染放 P1（渲染上云成本高，见 §8.5）。
- **验收**：出审前 A–G 终检闸全过（声画一致/音频自然度/钩子冷启/事实合规/封面/音画同步/发布物料）。

### 7.5 人审工作流（P0，核心差异化）
把 `feishu-bot` 的人审闸口产品化成「内容审核工作台」。
- **用户故事**：作为团队负责人，成品产出后我能在一个界面里看到待审内容（稿子+封面+视频+溯源），一键通过/打回，打回可选自动重做或挂待办。
- **功能点**：Web 审核台（+ 飞书/微信/企微通知通道）；人审清单（事实/时效/定位/语气/合规/观感）；打回意见回流；审核留痕。
- **验收**：一条内容从「出审」到「人审决策」全程在产品内闭环，不落本地文件。

### 7.6 复盘与数据回流（P1）
产品化治理线 `douyin-retro`。
- **功能点**：接入创作者中心数据（半自动，用户授权登录导出 CSV）；漏斗归因；产出「账号大脑变更提议」交人审后应用（守治理线「只提议不自动改」铁律）。

### 7.7 合规半自动发布（P1，谨慎）
- **功能点**：用户主动授权登录 + 短期 token；发布前人确认（守发布铁律）；**错峰调度**；强制 AI 标识；单账号限流。**不做**矩阵批量、不存明文密码、不做无人值守。
- **验收**：全流程无明文凭据留存；每次发布有人确认记录；发布节奏可配置错峰。

### 7.8 团队协作与私有化（P1）
- **功能点**：多成员坐席、角色权限（创作/审核/管理）；工作空间隔离；私有化部署包（把凭据/合规风险转移给客户）。

### 7.9 可视化编排引擎 + 模板市场（P2）
- **功能点**：把阶段 SOP + skill 做成可拖拽节点；用户自搭流水线、自接模型/TTS/发布通道；官方模板（技术号内容工厂）+ 社区模板市场分成。

## 8. 技术架构与实现思路（上云）

> 结论：**别照抄「本地脚本 + 无头浏览器」的形态硬上云**。编排、发布、成本、凭据四块要重新选型。

### 8.1 总体分层（目标态）
```
┌─────────────────────────────────────────────┐
│  前端 Web 控制台（大脑配置 / 选题 / 审核台 / 复盘）  │
├─────────────────────────────────────────────┤
│  API 网关 + 多租户身份 + 计量计费                  │
├─────────────────────────────────────────────┤
│  编排层：Temporal（每条内容 = 一个 workflow，       │
│         人审 = 等 signal，可持久数月不丢状态）        │
├──────────┬──────────┬──────────┬─────────────┤
│ 选题 Agent │ 创作 Agent │ 渲染 worker│ 发布 worker  │
│ (LLM+抓料) │ (LLM+TTS) │ (Fargate) │ (托管浏览器)  │
├──────────┴──────────┴──────────┴─────────────┤
│  成本治理：Redis 配额 + LiteLLM 网关 + Langfuse 审计 │
├─────────────────────────────────────────────┤
│  数据：PostgreSQL(pooled+RLS 起步) + 对象存储(媒体) │
│  凭据：Vault + KMS 信封加密（每租户独立 DEK，隔离）    │
└─────────────────────────────────────────────┘
```

### 8.2 编排层——最值得投入的选型：Temporal
- **为什么**：内容生产是长任务 + 有人审断点。Temporal 是目前**唯一有生产验证**的成熟参考——用 signal 把人审决策注入正在等待的 workflow，可持久运行数月不丢状态。每条视频 = 一个 workflow 实例，人审 = 等 signal。
- **为什么不是 n8n/Dify/Coze**：n8n（Redis at-most-once）不适配长任务人审；**Dify OSS License 和 Coze 开源版都明确禁止直接拿开源版做多租户 SaaS**（要买企业版），多租户隔离+计费得自研。
- **现有资产怎么迁**：markdown SOP 的「阶段」天然对应 workflow 的 activity；`meta.yaml` 双层状态机对应 workflow state；`dubbing-reviewer` 3 轮循环对应带重试上限的子 workflow。

### 8.3 发布层——最大架构分叉，必须当决策点点破
- **官方 API 这条路基本堵死**（§5.1）：2024/7/20 收回，只剩「企业自有/签约号 + 手动触发」窄口子。**不能把商业模式押在官方 API 长期稳定上。**
- **退路**：Browserbase/browserless 托管浏览器（每 session 隔离 userDataDir + 加密快照 cookie/localStorage，可持久 90 天），不必自建 K8s+Puppeteer 农场（自建痛点是内存先于 CPU 爆、session 隔离运维复杂）。
- **但**：多租户聚合本身制造新的「账号关联/风控聚簇」风险——同批 IP、同套渲染流水线发出，平台可能判定为工具化矩阵号。架构需预留**出口 IP 隔离 + 发布节奏错峰**余量。
- **产品决策**：所以推荐路径把发布做成 **P1 的谨慎半自动**，不是 P0 核心。

### 8.4 凭据安全——最高风险资产，单独隔离
- 抖音 cookie + 用户 API key 用 **HashiCorp Vault + KMS 信封加密**（每租户一个 DEK 被主密钥包裹），标准是「单租户密钥泄露不牵连其他租户」，**不要跟业务库共用加密**。
- 业务数据可用较轻的 **PostgreSQL pooled + RLS** 起步，按合规需求再升级混合模式。

### 8.5 成本治理——四维度分别配额 + 熔断
本项目成本结构有**四个独立维度**（这是相对同行的天然优势——本地录屏时边际 GPU 近零）：

| 成本维度 | 计量单位 | 参考成本 | 治理 |
|---|---|---|---|
| LLM（选题/写稿） | token | 随模型 | 网关虚拟 key（LiteLLM）按 token 限流 |
| TTS（配音） | 字符 | MiniMax ≈ ¥0.35/千字符（比 ElevenLabs 便宜 3–8 倍） | 字符配额 |
| 渲染（录屏+ffmpeg） | 容器分钟 | Fargate/Batch，**不需要 GPU** | 分钟配额 |
| 浏览器（发布） | session 分钟 | 托管浏览器 | session 配额 |

- **关键**：不能用一个笼统「积分桶」——否则大概率是渲染或 session 先被个别重度租户吃穿而无感知（5% 租户吃 60% 资源是普遍现象）。**请求数限流对 LLM 无效，必须按 token/资源分钟限流。**
- 最小可行：Redis 配额 + LiteLLM 网关 + Langfuse 审计。单 H100 可撑 50–100 客户（若引入自有模型）。

### 8.6 渲染上云——不需要 GPU，但别照抄 Remotion Lambda
- headless Chromium 默认关 GPU，编码也不用 GPU，省这笔预算。
- **但**本项目是「录网页真实交互 + 同步配音」，比 Remotion「代码定义帧」更难分片、更耗时，**Lambda 15 分钟硬限大概率不够**，用 **Fargate/Batch 容器化长任务**。

### 8.7 BYOK vs 平台统一 key
- 默认**平台统一 key + 分层套餐计费**（覆盖四类资源）；给企业/代理商级客户开放 **BYOK**（转移账单风险）。不是二选一，是主流折中。

### 8.8 单位经济估算（每条 3–5min 口播视频，粗算，需实测校准）
- LLM（选题+写稿）：≈ ¥1–5
- TTS（800–1200 字）：≈ ¥0.3–0.5
- 封面图：≈ ¥0.3–0.8
- 渲染（云端 Fargate，若做视频）：≈ ¥1–3；**本地/边缘渲染 ≈ 0**
- 发布 session（若做）：≈ ¥0.2–0.5
- **合计边际成本 ≈ ¥3–10/条（做视频）或 ¥2–6/条（只到脚本+音频）**
- AI 生成类目标毛利 60–70%（低于传统 SaaS 的 80–90%，业内把「低于 40% 毛利」当警戒线）。定价须按此倒推，别先定价再看成本。

## 9. 竞品格局与市场空位

### 9.1 格局地图（按流水线分层）
1. **生成层**（数字人/口播）：**红海 + 价格战**，卷到近免费。剪映 AI 成片免费、即梦免费 60 积分/天、可灵 Plus 199/月不限次、蝉镜 298/月。海外 HeyGen/Opus Clip/Pika 口碑分裂（Trustpilot 2.4/4.0/1.6），共性痛点是积分制不透明。→ **护城河不能建在生成能力本身。**
2. **分发层**：蚁小二（60+ 平台，个人 198/年）、易媒助手（70+ 平台）。技术底层已开源商品化。→ **直接复用开源，别做同类。**
3. **Agent/工作流平台**：Coze/Dify/n8n/Make 通用基础设施，无内容账号垂类现成模板。→ 当被集成的底层。
4. **最大潜在竞争者字节系**：Coze 已上线「一键生成抖音 AI 分身」。→ **通用型「AI 生成人设账号」窗口期基本关闭，必须避开通用自动化。**

### 9.2 没被占好的坑（市场空位）
1. **技术深度垂类空位（最大机会）**：「代码库/论文 → 可信技术口播稿 → 短视频」这个翻译层**没有任何一体化产品**。DeepWiki 只解决「读懂代码」，MoneyPrinterTurbo 类不懂代码语境。
2. **「事实可追溯/不编造」作为核心卖点**：全行业没一家强调，对技术圈是差异化空白。
3. **「人审卡点」作为产品第一公民**：所有矩阵工具都吹「一键全自动」，没人把「先经人审再发布」当能力展示。
4. **选题判断层**：没有工具做「一手信息源抓料 → 传播力打分 → 选题」，productize 有独占空间。
5. **简单透明定价**：海外头部普遍积分制不透明被差评，透明定价本身就是差异化。

## 10. 商业化与定价

### 10.1 方法论要点
- **毛利结构性回落**：AI 生成类 50–70%（非传统 SaaS 80–90%），COGS 常占 30–60%，先算清每次调用真实成本再倒推售价。
- **几乎没有纯订阅**：主流是「分层订阅 + 积分 + 超额计费」混合，靠「无限/慢速兜底档」消解 credit 焦虑。
- **免费转付费基准**：organic freemium 2.6%，加分层门槛 5.1%，顶尖 6–8%；「先体验后注册」约 8% 更高。别指望自然转化，主动设功能墙。
- **B 端付费意愿是 C 端 10–50 倍，留存显著更好**（企业月流失 0.5–1% vs SMB 自助 3–7%）。

### 10.2 定价档位建议
| 档位 | 对象 | 定价锚点 | 设计 |
|---|---|---|---|
| **免费引流** | 试用者 | ¥0 | 每日领额度 + 邀请解锁；导出加水印/降清晰度做转化钩子；先体验后注册 |
| **个人创作者** | C 端技术博主 | ¥19–99/月 | 基础订阅含额度 + 超额收费。叙事=「把机械环节自动化，把精力还给核心判断」，**不是产量放大器** |
| **团队/MCN** | 小工作室 | 锚蝉妈妈企业 ¥1299/月 | 按坐席/账号数，可到个人档 10 倍+；官方价 + 代理渠道价两套 |
| **白标/私有化** | 代运营公司/企业蓝V | 3–5 倍成本缓冲 + 搭建费 | B2B2B，明确超额规则；行业白标 markup 3–10 倍 |

- **关键成本分岔**：是否引入**云端视频生成**。引入会把成本拉近 Runway/HeyGen 重成本线（原始 $6–7.2/分钟）。**建议先守本地/轻云渲染的轻成本路线。**
- 国内 TTS/视频成本半年可能整体下移 30–50%，**超额费率做成「成本联动」而非写死一口价**。

## 11. 未决问题（需你拍板，非调研能定）

这三个决定产品形态，我给了推荐但最终你定：

1. **目标客户到底是 C 端自助还是 B2B2B？**（两条路的商业模式/定价/渠道完全不同）
   - 我的推荐：**C 端轻订阅引流 + B 端小工作室/MCN 收钱**（§4 判断三）。
2. **是否引入云端视频生成？**（决定「轻成本工具」还是「重成本平台」）

3. **是否覆盖「矩阵/批量起号」这层需求？**（会砍掉相当一部分真实付费需求，但撞合规红线）
   - 我的推荐：**主动划红线不做**（§5）。合规风险 + 法律主责在你，不值得。
