### 2.2 状态机（唯一定义，实现在 `tools/media.mjs`，文档一律引用不复述）

- `meta.yaml` 细粒度状态：`ideated → drafting → review → approved → published → retro_done`；打回：`review → drafting`；合法迁移仅相邻（含打回），跳跃非法。
- `backlog.yaml` 粗粒度三态：`idea → picked → published`，异常态 `expired`。只在两个时点翻动：`promote`（→picked）、`publish-done`（→published）。
- 双向指针：backlog 条目 `content_path` → 内容目录；`meta.yaml` 的 `source` → backlog `id`。

### 2.3 文件 schema

**`content/_backlog/backlog.yaml`**：
```yaml
next_up: null            # 人钦点指针：填 id 则 next 最优先取它
items:
  - id: 2026-08-21-001   # YYYY-MM-DD-NNN
    title: ""            # 建议标题
    track: depth         # depth(深度实测) | traffic(热点速评)
    status: idea         # idea | picked | published | expired
    score: 17            # 六维总分
    scores: {practical: 3, social: 3, emotion: 2, hook: 3, timeliness: 3, trigger: 3}  # 各 0-5
    reason: ""           # 一句话推荐理由
    tags: [screenshot, macos]   # 归一化标签（去重用）
    created: 2026-08-21
    content_path: null   # promote 后回填 content/<date>/<slug>/
```

**`content/<date>/<slug>/meta.yaml`**：
```yaml
slug: ""
title: ""
type: kouban             # 本教学仓只做口播
track: depth             # depth | traffic
status: ideated
source: 2026-08-21-001   # backlog id
publish_url: null        # publish-done 写入模拟链接 mock://douyin/<slug>
timestamps: {ideated: null, drafting: null, review: null, approved: null, published: null, retro_done: null}
```

**内容目录五件套**（`content/_template/`）：`1-brief.md`、`2-script.md`、`3-review.md`、`4-publish.md`、`5-retro.md`、`meta.yaml`、`assets/`（空目录 + `.gitkeep`）、`build/`（创作时由 skill 从 `tools/presentation-template/` 复制而来，**整目录 gitignore**）。

**`2-script.md` 结构标准**（doctor 验）：一级标题 = 内容标题；`## 钩子`（第一句必须自成立，冷开铁律）；`## 主体`（2–4 个 `### 分点`）；`## 结尾`（含行动号召）。每个小节正文即口播文案，口语化第一人称。

**`4-publish.md` 可解析 bullet**（doctor 验，格式 `- **键**：值`）：`标题`（≤30 字含钩子）、`正文`（简介）、`话题标签`（`#a #b` 3–5 个）、`封面`（`assets/cover.png`）、`媒体文件`（`assets/<slug>.mp4`）。

**`build/audio-segments.json`**（演示页派生，配音真相源）：
```json
{"segments": [{"id": "01", "text": "第一段口播文案"}, {"id": "02", "text": "..."}]}
```

**`brain/tts.config.json`**（账号级模板，创作时复制进 build/）：
```json
{"voice": "zh-CN-YunxiNeural", "rate": "+8%",
 "overrides": [{"segment": "03", "match": "行不行", "replace": "型不型",
                "why": "教学示例：多音字 háng/xíng 读错时，用同音字替换法纠正"}]}
```
overrides 语义 = **合成前文本替换**（edge-tts 不支持注音，教「同音字替换」这一招）；`segment` 省略则全局生效。

**`content/<date>/<slug>/metrics.json`**（mock-metrics 产出，模拟创作者中心）：
```json
{"generated_at": "", "windows": {
  "h24": {"plays": 0, "two_sec_bounce": 0.0, "five_sec_finish": 0.0, "completion_rate": 0.0,
           "avg_watch_seconds": 0.0, "likes": 0, "comments": 0, "favorites": 0, "follows": 0},
  "h72": {"同上": "…"}, "d7": {"同上": "…"}}}
```

**`dashboard.md`**：整个文件由 `media` 派生重写（教学简化：不设人写区）。三节：`## 在制`（表：slug/status/停留天数）、`## 选题池`（idea/picked/published/expired 计数 + next_up）、`## 已发布`（表：slug/发布日/是否 retro_done）。文件头注释注明「派生视图，真相源 = meta.yaml + backlog.yaml，手改无效」。

### 2.4 `tools/media.mjs` 命令契约（单文件，node:test 出测试）

| 命令 | 行为 | 退出码 |
|---|---|---|
| `media next [--json]` | next_up 非空→返回该条；否则 status:idea 中 score 最高（同分 depth 优先，再同取 id 小者）。池空→`decision:"empty"` | 空池 0（decision 表达） |
| `media promote <id> --slug <slug> [--date YYYY-MM-DD]` | 五处一次改齐：backlog→picked、回填 content_path、清 next_up、从 `_template` 建目录、写 meta（status:ideated, source:id, timestamps.ideated）。date 默认今天 | id 不存在/非 idea/slug 已存在→1 |
| `media flip <slug> <status>` | 验合法迁移→写 meta.status + timestamps→重写 dashboard | 非法迁移→1 并打印合法迁移表 |
| `media publish-done <slug> [--url <url>]` | 三处记账：meta→published+publish_url（默认 `mock://douyin/<slug>`）、backlog→published、dashboard 重写 | 前置状态非 approved→1 |
| `media check` | 状态账本一致性：双向指针闭合、backlog/meta 状态对应（picked↔ideated..approved；published↔published/retro_done）、published 必有 publish_url、dashboard 与快照一致。输出 errors/warns 分级 | 有 error→1 |
| `media doctor <slug>\|--all` | 产物格式 lint，按当前 status 决定验哪些（规则见 2.5） | 有 FAIL→1 |
| `media --help` 及各子命令 `--help` | 用法 + 状态机全图（活文档） | 0 |

实现约束：零 npm 依赖（自写 ~60 行够用的 yaml 子集读写器，格式按 2.3 固定缩进；文件头注释声明「教学用极简解析，勿写花式 yaml」）；总量目标 ≤600 行 + 充分注释；测试 `tools/media.test.mjs` 用 `node --test`，覆盖每命令主路径 + 非法迁移 + 空池。

### 2.6 mock-metrics 埋规律（教学彩蛋，复盘时可被归因挖出）

`node tools/mock-metrics.mjs <slug>`：读该内容 `2-script.md` + meta，生成 `metrics.json`。随机种子 = slug 哈希（**可复现**）。基线随机 ±20%，之上叠加规律：

1. 结尾含强行动号召（正则 `评论区(扣|回复|打)`）→ comments ×4、follows ×2；软号召（`聊聊|说说|讨论`）→ 无加成。
2. `### 分点` 数 >4 → completion_rate ×0.55（知识点堆砌拉低完播）。
3. 钩子首句含数字对比或反差词（`居然|竟然|明明|反而|倍|其实`）→ two_sec_bounce ×0.7。
4. track=traffic → plays ×2.2 但 favorites ×0.5（流量题曝光高沉淀低）。
5. 三窗口时间演化：h24≈d7 的 35%、h72≈75%，follows 在 h24 恒为 0（教「早窗转粉数据不可信」）。

规律**写在源码注释里**（学员复盘归因后可对答案），README 不剧透。

### WP3 · 创作链技术件（可并行）

**产出文件**（住 `tools/presentation-template/`，创作时整目录复制为内容的 `build/`）：
- `index.html`：单文件演示页（内嵌 CSS/JS，无构建步）——`slides` 数组驱动的分步演示（每步 = 标题+要点+可选配图占位），底部字幕条显示当前段口播文案，`?step=N` 定位，`window.__advance()` 翻页钩子供录屏驱动
- `slides.js`：内容数据文件（skill 按 2-script.md 填写）：`[{id:"01", title:"", bullets:[], narration:"口播文案"}]`——**narration 是 audio-segments 的上游真相源**

- `record.mjs`：playwright chromium headless——逐段：翻页→ffprobe 取该段 mp3 时长→停留等长；用 playwright video 录 webm→ffmpeg 拼接全部 mp3 为总音轨→mux 出 `assets/<slug>.mp4`（1080×1920 竖屏？**定横屏 1920×1080**，与原仓「先横屏跑通」一致）；末尾自检：mp4 时长 vs 音轨总长偏差 >2s 则报错
- `cover.mjs`：读 slides.js 首屏标题 → 生成竖版 9:16 封面：SVG 模板（统一底色+大字两行标题+账号名角标）→ 有 `rsvg-convert`/`ffmpeg` 则转 PNG，否则留 SVG 并提示（doctor 认 cover.png 或 cover.svg 均可——**此处放宽 2.5 的封面规则，contracts.md 同步注明**）
- `tools/presentation-template/README.md`：本模板文件间的数据流图（slides.js → extract → segments.json → synth → mp3 → record → mp4），及与原仓四件套 skill 的对应关系（教学注记）

**验收**：用 3 段假数据 slides.js 走通 extract→synth→record 全链，产出能播放的 mp4（音画时长齐）；synth 断网/无 edge-tts 时报错信息可读（指导 pip install）。
