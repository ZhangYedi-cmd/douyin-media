# 第 11 课大纲：状态真相源：用 media CLI 彻底告别数据漂移

## 1. 课程定位与痛点
- **目标受众**：流水线跑起来后，发现前端页面显示已发布，但实际文件还是待审；或者 markdown 已经手动修改，但元数据没有更新，系统频频报错崩溃的开发者。
- **核心痛点**：多处散落修改文件、缺乏唯一状态机定义，导致严重的数据不一致和状态漂移（State Drift）；把派生视图当成了真相源。
- **课时建议**：状态机工程化与单一真实源架构课，篇幅随内容讲透自然展开，重点把单一真实源原则、状态机严格转移矩阵与 CLI 唯一写入收敛讲透。

## 2. 课程目标
- 深刻理解单一真实源（Single Source of Truth, SSOT）原则在文件系统级架构中的应用。
- 掌握真相源（`meta.yaml` 与 `backlog.yaml`）与派生视图（`dashboard.md`、前端看板）的严格界定。
- 掌握领域状态机（`state.ts`）设计：唯一定义状态枚举与合法转移路径。
- 构建全系统唯一的写路径收敛工具：`media` CLI。

## 3. 核心思路与私教心法
- **绝不允许多处各自写文件**：全系统只能有一个 writer 包。前端动作、后端路由、自动化脚本想改状态，必须统一调用 `media` 命令行。
- **派生视图不可写**：看板 markdown 只是根据真相源渲染出来的只读报表，绝不能通过编辑 markdown 反向修改状态。

## 4. 详细内容大纲（标注篇幅与重点分配）

### 一级标题 1：[★ 核心重点 · WHAT & WHY · 大篇幅讲透] 为什么多处写文件是分布式系统的噩梦？
- 二级标题 1.1：[★ 核心重点 · WHY · 真实踩坑案例] 自媒体生产中的典型状态漂移惨剧
  - **WHY 漂移根因**：定时任务直接改了 markdown 表格但漏翻了 YAML 元数据；发布脚本成功后未回填线上 URL；前端页面强行修改状态覆盖了后台录屏进度。
- 二级标题 1.2：[★ 核心重点 · WHAT & WHY · 架构原则] 单一真实源（SSOT）架构定义
  - **WHAT 真相源**：每条内容的真相永远且只落在自身的 `meta.yaml` 与总选题池 `backlog.yaml`。
  - **WHAT 派生视图**：`dashboard.md` 和 Web 前端界面属于派生只读快照（Derived View），任何直接修改派生视图的行为都属于非法操作。

### 一级标题 2：[★ 核心重点 · WHAT & WHY · 领域建模] 领域状态机建模：state.ts
- 二级标题 2.1：[★ 核心重点 · WHAT · 状态枚举定义] 自媒体全生命周期状态枚举
  - 核心状态：`idea`（入池） -> `drafting`（制作中） -> `review`（待审核） -> `approved`（已过审） -> `published`（已发布） -> `retro_done`（已复盘）
  - 异常分支：`failed` / `drafting_blocked`（已挂起）
- 二级标题 2.2：[★ 核心重点 · WHAT & WHY · 转移矩阵] 合法状态转移矩阵与非法越级拦截
  - **WHY 为什么必须防越级**：严禁从 `idea` 直接跳到 `published`；严禁在未生成 `4-publish.md` 时直接翻转到 `review`。
  - **WHAT 纯函数设计**：状态机核心逻辑不依赖任何外部 I/O，入参是当前状态和触发事件，出参是新状态或报错，保证 100% 可测性。

### 一级标题 3：[★ 核心重点 · WHAT · 核心命令族] 全系统唯一写手：打造 media CLI
- 二级标题 3.1：`media` 命令族全景设计
  - `media st`：只读检查当前工作区与所有内容状态；
  - `media promote <id> --slug <slug>`：从选题池原子取题并初始化工作目录；
  - `media flip <slug> <target_state>`：严格按照状态机规则翻转状态；
  - `media publish-done <slug> --url <url>`：发布收尾唯一原子记账入口。
- 二级标题 3.2：发布收尾原子性：一条 `media publish-done` 命令同时完成：
  1. `meta.yaml` 翻至终态并回填链接；
  2. `backlog.yaml` 对应条目同步翻转；
  3. `dashboard.md` 在制表自动移出。
- 二级标题 3.3：`media doctor`：系统健康自检与异常漂移自动修复工具。

## 5. 验收标准与作业
- 本地能够正常运行 `media st` 与 `media doctor`，无任何语法或路径错误。
- 尝试执行一次非法的状态跳转（如直接将 `idea` 翻转为 `published`），验证 CLI 是否能够准确报错并拒绝写入。
