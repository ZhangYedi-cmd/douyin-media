# 第 16 课大纲：告别纯黑盒：打造基于 SSE 的本地实时控制看板

## 1. 课程定位与痛点
- **目标受众**：整套流水线在终端后台跑，完全不知道当前卡在哪一步、选题池还剩多少题、哪些内容待审，感到处于纯黑盒中的开发者。
- **核心痛点**：缺乏直观的可视化界面；传统前端开发需要起前后端多个服务、配复杂的数据库、跨域和 WebSocket，维护负担极重。
- **课时建议**：全栈架构与轻量级可视化控制台课，篇幅随内容讲透自然展开，重点把单端口极简架构、SSE 被动刷新机制与快写收敛路由讲透。

## 2. 课程目标
- 掌握极简单端口架构：Hono 后端 + React 19 / antd 6 前端 + 静态托管（Clone 即跑，零部署，零外部数据库依赖）。
- 掌握服务端事件流（Server-Sent Events, SSE）驱动的前端被动刷新机制。
- 掌握只读看板与快写路由的分工（前端只读展示，写操作一律转发后端调用 `media` CLI）。
- 学会指导 AI 快速构建包含总览、内容列表、详情、选题池、治理与数据 6 大看板的控制台。

## 3. 核心思路与私教心法
- **零配置、单端口、文件驱动**：不要引入 MySQL/Redis，后端直接读本地 Markdown/YAML 生成快照；前端静态产物进 Git，后端一个端口直接把静态页面兜出去。
- **被动刷新优于主动轮询**：后端用 chokidar 监听文件变动，一旦文件改了就通过 SSE 推一个 revision 版本号，前端比对后自动刷新数据。

## 4. 详细内容大纲（标注篇幅与重点分配）

### 一级标题 1：[★ 核心重点 · WHAT & WHY · 大篇幅讲透] 技术选型：为什么是 Hono + React + SSE？
- 二级标题 1.1：[★ 核心重点 · WHY · 传统方案痛点] 传统全栈管理后台的沉重包袱
  - **WHY 为什么不走传统前后端**：传统方案需要启动 SpringBoot/NestJS 后端、Vite 前端开发服务器，配置 MySQL 数据库迁移、Redis 缓存与 Nginx 反向代理，环境极其脆弱，难以在不同机器上开箱即跑。
- 二级标题 1.2：[★ 核心重点 · WHAT · 极简方案] 现代单端口方案：Hono 4 原生 Node.js 托管
  - **WHAT 架构设计**：前端 `dist/` 产物直接静态打包进仓库，由 Hono 单端口统一代理 API 与页面托管，输入 `node server.js` 一个命令即可在 `http://localhost:5170` 启动整套控制台。

### 一级标题 2：[★ 核心重点 · WHAT & WHY · 数据流架构] 数据流架构：纯只读快照与 SSE 被动刷新
- 二级标题 2.1：[★ 核心重点 · WHAT · 读路由设计] 读路由设计与文件快照生成
  - **WHAT 路由**：`GET /api/overview`、`/api/contents`、`/api/backlog`、`/api/harness` 直接解析本地 YAML/Markdown 拼装 JSON 返回。
- 二级标题 2.2：[★ 核心重点 · WHAT & WHY · 核心机制] SSE 事件通道与文件感知
  - **WHY 为什么放弃定时轮询与 WebSocket**：短轮询浪费请求，长连接 WebSocket 状态复杂且心跳繁琐；SSE（Server-Sent Events）单向推流极其轻量，天然支持断线重连。
  - **WHAT 被动刷新流**：chokidar 监听本地文件变动 -> 触发 revision 递增 -> SSE 向前端广播 `refresh(revision)` 信号 -> 前端 hook 重新拉取快照。

### 一级标题 3：[★ 核心重点 · WHAT & 路由安全] 快写路由设计：一切写操作收敛到 CLI
- 二级标题 3.1：前端操作按钮（通过审核、打回重做、应用提议、选题提权）
- 二级标题 3.2：后端动作路由处理：严禁后端直接写文件，一律通过 `execFile("media", ...)` 触发 CLI 执行
- 二级标题 3.3：写操作 -> fs 变动 -> watcher 感知 -> SSE 广播 -> 前端视图自动刷新的闭环流转

### 一级标题 4：前端看板核心页面设计与呈现
- 二级标题 4.1：P1 总览看板：流水线阶段卡片、今日待办与去抖警报（Alerts）
- 二级标题 4.2：P2 内容管理：列表流转、阶段筛选与详情页 Markdown 渲染
- 二级标题 4.3：P4 选题池看板：分数排序、赛道分布与一键提权
- 二级标题 4.4：P5 治理看板：任务注册表状态、历史账本与待审变更提议

## 5. 验收标准与作业
- 本地成功启动控制台服务（单端口 5170），浏览器能够正常访问全部 6 大看板页面。
- 手动在终端修改一个 `meta.yaml` 文件，观察前端页面是否能在 1 秒内通过 SSE 自动刷新视图。
