# 流水线看板（Pipeline Console）· PRD

> 版本：v0.1｜日期：2026-07-11｜状态：待评审
> 一句话：给这套抖音内容流水线做一个**本地 Web 看板**，把散在 `meta.yaml` / `backlog.yaml` / 日志里的状态一屏看清——**只做派生视图，绝不当真相源**。
> 关系：这是「自用工具」，不是 SaaS（那是 `2026-07-08-流水线SaaS化-PRD.md`）。但它就是 SaaS 方案 A 里「人审工作台」的种子，先自用验证。

---

## 1. 背景与问题

现状看流水线状态只有三条路，都难受：
1. **`dashboard.md`**：手工/agent 维护的 markdown，单元格塞满长文本（EP15 那行 500+ 字），不可扫读、易漂移、常漏翻（EP04 状态存疑挂了 20 天没人发现）。
2. **翻文件**：状态真相源散在 16 个 `content/<日期>/<slug>/meta.yaml` + `backlog.yaml`，想知道「现在有几条卡在待审」得逐个打开。
3. **翻日志**：治理线跑没跑、报告有没有人看，得读 `harness/logs/index.jsonl` 和一堆 md。

核心痛点：**状态是文件里的真相，但没有一个「一眼看全局」的视图**；阻塞（TTS 余额、状态漏翻、待审积压）靠人偶然发现。

## 2. 定位与三条铁律（继承仓库约定，不可违反）

- **定位**：单用户、本地运行的 Web 看板。`npm run console` 起在 `localhost:5170`，读仓库文件渲染。
- **铁律 1 · 派生视图**：看板**只读解析**真相源文件，自身不存业务状态（无数据库）。文件变，看板变；看板永远不是权威。
- **铁律 2 · 不代翻状态**：状态记账唯一位置 = `douyin-publish` Step 5（meta/backlog/dashboard 一次翻齐）。看板 V1 **没有任何写状态按钮**；V2 起的「动作」也只是触发既有 skill/命令，由 skill 按既有规则记账。
- **铁律 3 · 治理线只产报告**：看板对治理报告只做「展示 + 标记已读」，不提供「一键应用提议」——应用必须走人审后手动改 `brain/`。

## 3. 用户场景（决定页面优先级）

| 场景 | 频率 | 问的问题 | 对应页面 |
|---|---|---|---|
| 晨检 | 每天 | 昨晚 daily-run 跑了吗？有没有阻塞？今天几条在制？ | P1 总览 |
| 审前 | 每次出审 | 待审的是哪条？稿子/封面/终检结果在哪？ | P2 看板 → P3 详情 |
| 发布后 | 每次发布 | 状态翻齐了吗？backlog 同步了吗？ | P2 看板 + P1 警报 |
| 治理审 | 每周 | 攒了几份报告没看？提议要不要采纳？ | P5 治理线 |
| 选题 | 每 2 天 | 池子里几条 idea？分数排序？撞题吗？ | P4 选题池 |
| 复盘 | 每周 | 数据趋势？哪条漏斗漏在哪？ | P6 数据 |

## 4. 信息架构

```
侧边导航（6 页）
├── P1 总览 Overview        今日健康度 + 警报 + 待办
├── P2 生产看板 Kanban       内容条目按状态列拖览（只读）
├── P3 内容详情 Detail       单条内容全链路（从 P2/P4 点入，非导航项）
├── P4 选题池 Backlog        idea 池排序/筛选/撞题标记
├── P5 治理线 Harness        任务注册表 + 运行账本 + 报告阅读器
└── P6 数据复盘 Metrics      发布数据与漏斗（数据源受限，V1 降级为快照展示）
全局：顶栏 = 系统健康灯 ×4 + 全局搜索 + 手动刷新
```

## 5. 页面详设

### P1 总览 Overview（默认首页）

**目标**：10 秒回答「流水线今天正不正常、有什么需要我」。

| # | 功能 | 说明 | 数据来源 | 边界/验收 |
|---|---|---|---|---|
| 1.1 | 今日运行卡 | 最近一次 daily-run 的日期、结果摘要（产出/空跑/报错），点开看全文 | `pipeline/logs/<date>.md`（取最新） | 当天无日志 → 显示「今日未跑」+ 上次运行时间 |
| 1.2 | 在制统计条 | 各状态内容计数：ideated/drafting/review/approved/scheduled 各几条 | 扫全部 `content/*/*/meta.yaml` 的 `status` | published 不计入「在制」；计数与 P2 列数一致 |
| 1.3 | 警报区 ★核心 | 自动检出异常并置顶：见下方「警报规则表」 | 多源交叉校验 | 每条警报给「原因 + 指向文件 + 建议动作文案」 |
| 1.4 | 待人处理清单 | 待审内容（status=review）、待确认发布（approved）、未读治理报告（applied=false 且未标已读） | meta.yaml + `harness/logs/index.jsonl` | 点击跳 P3 / P5 对应项 |
| 1.5 | 治理线心跳 | 4 个 enabled 任务距上次运行天数 vs 周期，逾期标黄 | `harness/tasks.md`(trigger) + `index.jsonl`(ts) | retro 是事件触发，只显示「最近一次」不判逾期 |
| 1.6 | 选题池水位 | idea 数量 + 最高分 + 距上次 ideate 天数 | `backlog.yaml` + index.jsonl | idea < 3 条时标黄提示「池子见底」 |

**警报规则表（V1 内置 5 条，硬编码即可）**：
| 规则 | 判定 | 例子 |
|---|---|---|
| 状态失联 | meta=`scheduled` 且 schedule 时间已过 >24h 未翻 published | EP04 那类漏翻 |
| 双层不同步 | meta=`published` 但 backlog 对应条目仍是 `picked` | 发布收尾漏账 |
| 待审积压 | status=`review` 停留 >48h | 人审卡住 |
| 治理逾期 | periodic 任务距上次成功 > 周期 ×1.5 | ideate 5 天没跑 |
| 日志报错 | 最新 daily-run 日志含「阻塞/失败/1008」关键词 | TTS 余额阻塞 |

### P2 生产看板 Kanban

**目标**：内容条目按生产线状态机排成列，一眼看到每条卡在哪。

| # | 功能 | 说明 | 数据来源 | 边界 |
|---|---|---|---|---|
| 2.1 | 状态列 | 7 列：ideated → drafting → review → approved → scheduled → published → rejected；列头带计数 | meta.yaml `status` | **不可拖拽换列**（铁律 2）；published 列默认折叠只显示最近 5 条 |
| 2.2 | 内容卡片 | 标题、slug、类型(口播/图文)、pillar(深度/流量)、在当前状态停留天数、封面缩略图（有则显） | meta.yaml + `assets/cover.png` | 停留 >48h 卡片描边变琥珀色（和警报联动） |
| 2.3 | 卡片点击 | 进 P3 内容详情 | - | - |
| 2.4 | 筛选器 | 按类型 / pillar / 日期范围 / 系列 | meta.yaml 字段 | 默认显示近 30 天 + 全部未完成 |
| 2.5 | 状态机图例 | 底部小字显示两层状态机规则（谁在何时翻状态），防遗忘 | 静态文案（引 CLAUDE.md） | - |

### P3 内容详情 Detail（从卡片点入）

**目标**：一条内容的全链路一页看完，审前不用翻目录。

| # | 功能 | 说明 | 数据来源 | 边界 |
|---|---|---|---|---|
| 3.1 | 元信息头 | 标题/slug/状态/类型/pillar/schedule/publish_url/时间戳轴（ideated→…→published 各节点时间） | meta.yaml `timestamps` | 缺失节点显示为空，不推断 |
| 3.2 | 阶段产物导航 | 1-brief / 2-script / 3-review / 4-publish 四个文件的存在性 + 内容渲染（md 渲染成页） | `content/<日期>/<slug>/*.md` | 文件缺失显式标红（如出审前没产 4-publish = 踩过的坑） |
| 3.3 | 口播稿阅读器 | `2-script.md` 渲染，钩子段高亮 | 同上 | 只读 |
| 3.4 | 封面预览 | `assets/cover.png` 大图 + cover-prompt.md | assets/ | 无封面时显示「缺封面」警示（终检闸 E） |
| 3.5 | 成片信息 | mp4 文件名/大小/时长（ffprobe 可选） | `assets/*.mp4` | V1 只列文件，不内嵌播放器（V2 加） |
| 3.6 | 终检/质检摘要 | 从 meta.yaml 注释区提取 A–G 终检、dubbing-reviewer 轮次结论 | meta.yaml 注释 | 解析失败就原样展示注释文本，不硬结构化 |
| 3.7 | 溯源链 | backlog 来源条目（meta.source ↔ backlog id 双向指针校验）+ fact_check 块展示 | meta.yaml + backlog.yaml | 指针断裂标红（双层不同步警报的详情版） |
| 3.8 | 安全动作 | 「在编辑器打开目录」「复制 sau dry-run 命令」（从 4-publish.md 拼，仅复制不执行） | 4-publish.md 字段 | **绝不提供执行按钮**（V1） |

### P4 选题池 Backlog

**目标**：替代手翻 `backlog.yaml`，选题决策一屏做。

| # | 功能 | 说明 | 数据来源 | 边界 |
|---|---|---|---|---|
| 4.1 | 池子表格 | id/标题/track/format/score/tier/urgency/created/tags/status，默认按 score 降序 | `backlog.yaml` topics | status=idea 为主视图；picked/published 折叠分区 |
| 4.2 | 六维分数展开 | 行展开显示 scores 六维（practical/social/…）+ reason + links | 同上 | - |
| 4.3 | 新鲜度标记 | created 距今 >30 天标灰（douyin-ideate 的过期清扫口径） | created 字段 | 只标记不删除（清扫归 ideate Step 2.0） |
| 4.4 | 撞题标记 | 展示 backlog-gardener 最近报告里点名的撞题对 | `harness/logs/<date>-backlog-gardener.md` | 只读展示报告结论，不合并条目 |
| 4.5 | 调研报告入口 | 最近一次 `content/_research/research-<date>.md` 渲染 | _research/ | - |
| 4.6 | promote 指引 | 选中一条 idea → 显示「promote 该走的命令/流程」文案（不执行） | 静态（引 1-ideate.md 契约） | V2 才考虑触发执行 |

### P5 治理线 Harness

**目标**：治理任务「跑没跑、产了什么、人看了没」三问一页答。

| # | 功能 | 说明 | 数据来源 | 边界 |
|---|---|---|---|---|
| 5.1 | 任务注册表 | 解析 tasks.md yaml：task/skill/enabled/trigger/windows，enabled 高亮 | `harness/tasks.md` | yaml 解析失败降级为原文展示 |
| 5.2 | 运行账本 | index.jsonl 逆序表格：ts/task/target/window/result/findings/applied | `harness/logs/index.jsonl` | 每行链接到 report 文件 |
| 5.3 | 报告阅读器 | 点开任意 `logs/*.md` 报告渲染阅读；提取「变更提议」小节置顶 | `harness/logs/*.md` | 无「应用」按钮（铁律 3）；只有「标记已读」（存看板本地 localStorage，不写仓库） |
| 5.4 | 待审提议聚合 | 所有 applied=false 的报告的提议条目汇总成清单 | index.jsonl + 报告文件 | 采纳动作 = 人去改 brain/，看板只给文件路径 |
| 5.5 | 复盘窗口追踪 | 已发布内容 × 24h/72h/7d 三窗口的完成矩阵（哪条哪个窗口没跑 retro） | meta.yaml(published+时间) × index.jsonl(retro 记录) | 这是 retro 事件触发的可视化，dispatcher 逻辑的镜像 |

### P6 数据复盘 Metrics（V1 降级版）

**目标**：展示已有复盘数据。**诚实边界**：平台数据只能靠 douyin-retro 拉取后落盘，看板不直连抖音。

| # | 功能 | 说明 | 数据来源 | 边界 |
|---|---|---|---|---|
| 6.1 | 数据快照表 | 各内容的 metrics（plays/完播/likes…），有啥显啥 | backlog.yaml `metrics` + retro 报告 | 大量字段缺失是常态，空值不装有 |
| 6.2 | 趋势小图 | 按发布日期排的完播率/互动折线 | 同上 | 数据点 <5 时只显示表格不画线 |
| 6.3 | 漏斗归因摘要 | 最近 retro 报告的漏斗结论原文块 | `harness/logs/*-retro.md` | 展示不重算 |

### 全局功能

| # | 功能 | 说明 | 边界 |
|---|---|---|---|
| G1 | 系统健康灯 ×4 | 顶栏四个灯：① 飞书 server 进程在不在（`ps` 查 server.py）② 抖音 cookie 状态（读 sau 最近 check 结果缓存，不主动跑）③ TTS 余额哨兵（读最近日志有无 1008）④ git 工作区干净度 | 全部是「读缓存/日志」级检查，不发起外呼 |

| G3 | 数据刷新 | chokidar 监听 content/ harness/ pipeline/ backlog 变更 → SSE 推送前端自动刷新；顶栏也留手动刷新钮 | 监听失败降级为 30s 轮询 |
| G4 | 解析容错 | 任何 yaml/md 解析失败：该条目降级显示原文 + 标记「解析失败」，绝不吞掉或崩页 | 真相源是手写文件，容错是生存前提 |

## 6. 动作权限分级（路线图的另一条轴）

| 级别 | 能做什么 | 版本 |
|---|---|---|
| L0 只读 | 全部页面的展示、搜索、警报 | **V1（本 PRD 主体）** |
| L1 安全动作 | 打开文件/目录、复制命令、标记已读（不写仓库） | **V1** |
| L2 触发 | 按钮触发既有 skill（跑 ideate、跑 dispatcher、sau dry-run），输出回显到看板；记账仍由 skill 做 | V2 |
| L3 记账 | 看板内完成人审点击（对接/替代飞书卡片），驱动状态翻转 | V3（需先解决与 feishu-notify 的关系，见未决问题） |

## 7. 技术实现思路

- **形态**：单仓单进程本地应用，代码住 `tools/console/`（与 sau、feishu-bot 并列）。
- **后端**：Node + Hono（或 Express）。三层：
  1. **解析层**：`js-yaml` 读 meta/backlog/tasks，`gray-matter`+自写解析器处理 md/jsonl；每个源一个 parser，独立容错。
  2. **聚合层**：内存态 store，交叉校验产出警报（§5 警报规则表）；无数据库。
  3. **接口层**：REST（`/api/overview` `/api/contents` `/api/content/:slug` `/api/backlog` `/api/harness` `/api/metrics` `/api/health`）+ `/api/events`（SSE 推文件变更）。
- **前端**：Vite + React + TS（你的主场）；状态用 SWR/TanStack Query 吃 REST + SSE 失效重取；UI 可用 shadcn 或裸 Tailwind，暗色为主。
- **文件监听**：chokidar 监听四个目录，debounce 500ms 触发重解析对应 parser。
- **启动**：根 `package.json` 加 `"console": "node tools/console/server.mjs"`；前端构建产物由后端静态托管，单端口 5170。
- **不做**：数据库、鉴权（本机单用户）、外呼平台 API、写真相源文件。
