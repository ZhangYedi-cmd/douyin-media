## 一、背景与动机

douyin-media 已经是一套跑了两个多月的真实系统：生产线（选题→创作→出审→人审发布）+ 治理线（复盘/养池/对标复核/自审元层），两条线由定时 agent 驱动、以 markdown SOP 和 skill 编排、用 `media` CLI 记账，大环（发布→复盘→变更提议→人审→改 brain→下轮打分）已闭合。

现在要把这个仓库改造成一个**教学项目**：不是写一篇系统介绍，而是产出一门课，带学员从零搭出一套属于自己的自闭环 AI 自媒体工作流。

## 二、课程定位（一句话）

**名为口播视频制作课，实为「自闭环 Loop 系统设计课」**——以开源 skill `web-video-presentation` 为入口抓手，沿着本系统真实的生长史（单条视频→内容工厂→无人值守→治理线→Loop 成环），带学员边操作边理解：一个能自己跑、自己复盘、自己调整战略的 AI 工作流，应该怎么设计。

### 课程目标（承接需求原文）
1. 通过 douyin-media 案例，理解从 harness 到 Loop——自闭环的 Loop 如何搭建，Loop 思想是什么。
2. 深入理解系统设计：长任务的 skill 应该如何分层，AI 时代为什么 CLI 是最合适的接口，以及本系统的其它关键设计亮点（见第五节清单）。
3. **全程不手写一行代码**：所有写代码的环节用 AI 工具完成，课程只讲系统设计；过程中穿插 AI Coding 基础知识（SDD、Subagent、Agent Team 等）、AI 写作技巧，以及**与 AI 协作的心法**（关键结论落文档、如何拆分 agent 等，清单见第五节附）——学员跟做的过程本身就是协作训练，心法是课程介绍中明说的第三条收获线。
4. 从开源的 `web-video-presentation` skill 出发，把各种开源 skill 拼装成一套自驱工作流：AI 定时发任务、人审核，到点自动复盘、自动调整账号战略、自动抓竞对数据、自动抓实时热点。**能不造轮子就不造轮子。**

## 三、已拍板的决策

### D1 受众：会用 AI 的泛技术人
用过 ChatGPT / Cursor / Claude 之类工具，但没系统搭过 AI 工作流。含义：
- 不假设工程背景；CLI、skill、subagent、状态机等概念**首次出现时给一句话解释**，再进正文。
- 不铺零基础的电脑操作；也不设「深水区」分层——一条主线讲到位。

### D2 动线：跟做式，组件按「三类三教法」处理
学员每课亲手用 AI 工具搭出对应环节，结课时拥有自己的一套 Loop。组件不搞一刀切：

| 类别 | 例子 | 教法 |
|---|---|---|
| **开源直用** | `web-video-presentation`、`agent-reach`、`baoyu-image-gen`、TTS 类 | 讲清原理 + 执行流程，学员 copy 过来直接用，不重造 |
| **二次包装** | `social-auto-upload` → `douyin-publish` 薄封装 | 重点讲**为什么要包**（状态校验 / dry-run 铁律 / 授权信号 / 留痕），包装本身让 AI 写 |
| **自建件** | `media` CLI、`harness-dispatcher`、`feishu-notify`、全部 markdown SOP | 讲设计与规格（SDD），代码全部由 AI 生成，学员只写「规格」不写码 |

### D3 载体：图文讲义为主
Markdown 图文课，配架构图与操作截图，本仓直接承载。视频化不在本期范围（若做，是流水线自产的独立迭代）。

### D4 本轮交付：ADR + 课程大纲，人审后再写正文
本文件 + `01-课程大纲.md`。正文批量生产是下一轮，且建议先出第一课样稿校准风格再铺开。

### D5 课程代码：一课一分支（`NN-<slug>`）
每课配一个 git 分支，分支 = 该课「跟做」完成后的**学员参考仓状态**。学员卡壳时 checkout 对照；`git diff` 相邻两个分支 = 该课的全部增量。

- **双轨分离**：`main` 保持生产仓真身（= 课程终态的完整参考）；教学轨从 **orphan 分支**起步（第 1 课只有最小骨架），逐课累积，不带生产仓的历史与私有数据。教学轨放本仓（学员一个 clone 全拿到），不另开 starter 仓。
- **渐进累积**：`NN` 分支基于 `NN-1` 分支生长，链式继承。讲义每课头部固定标注「起点分支（上一课完成态）/ 完成分支（本课目标态）」。
- **分支命名表**（与 01 大纲课号一一对应）：

  | 课 | 分支 | 课 | 分支 |
  |---|---|---|---|
  | 1 | `01-setup` | 9 | `09-daily-run` |
  | 2 | `02-web-video` | 10 | `10-alerting` |
  | 3 | `03-tts-dubbing` | 11 | `11-harness` |
  | 4 | `04-review-gate` | 12 | `12-dispatcher` |
  | 5 | `05-content-factory` | 13 | `13-the-loop` |
  | 6 | `06-media-cli` | 14 | `14-meta-audit` |
  | 7 | `07-publish-wrapper` | 15 | `15-lessons` |
  | 8 | `08-human-review` | 16 | —（无新代码，终态 = `15-lessons`，对照 `main`） |

  第 0 课（开篇导览）为纯阅读课，无分支；学员从第 1 课起接触 `01-setup`。

- **维护纪律**（分支制的最大成本，必须钉死）：修改早课内容，必须沿链**顺序向后 merge 到所有后续分支**，一处改动全链同步——正文生产轮为此配一个合并顺序清单/脚本，禁止只改单个分支。
- **安全红线**：教学分支同受本仓 GitHub 推送红线约束——不含 cookie、API key、`.env`、corp 关键词；付费依赖在分支里只留配置模板（如 `tts.config.json` 模板化）。

## 四、课程设计原则

1. **由浅至深、边操作边讲原理**：每课先「跟做出一个能跑的东西」，再回头拆它背后的设计决策。原理永远挂在刚做完的操作上，不空讲。
2. **沿真实生长史编排**：课程模块顺序 = 本系统真实的演化顺序（先有一条视频，才有状态机；先空跑了 6 天，才有阻塞即上报；先池子烂了 24 天，才有治理线）。学员遇到的每个「为什么要加这层」，都先让他撞一下没有这层的墙——用真实事故（`pipeline/lessons.md` L1–L18）当墙。
3. **不造玩具示例**：全部素材取自本仓一手文件（SOP 原文、任务卡原文、事故记录、真实运行日志）。教学仓即生产仓。
4. **能不造轮子就不造轮子**：每次要新能力，先问「有没有开源 skill」；只有当开源件与系统契约冲突时才包装或自建，且要能说清冲突在哪。
5. **每课固定骨架**：本课地图（在整个 Loop 里的位置）→ 跟做（操作步骤+产出物）→ 原理深挖（本课的设计决策）→ AI Coding 加油站（穿插知识点）→ 检查清单（学员自验产出）。AI 写作技巧按需嵌入创作相关课。

## 五、关键设计亮点清单（课程要讲透的「为什么」）

> 这是需求里「…等课程关键设计亮点」的展开，也是大纲各课「原理深挖」的选题池。

1. **AI 时代为什么用 CLI**：LLM 干判断活，确定性活给代码；状态记账靠 CLI 唯一入口（`media`）而不是靠 LLM 自觉，一条命令五处改齐，杜绝漏翻账。
2. **skill 分层**：阶段契约（`pipeline/*.md`，输入/输出/状态翻转/闸口）与操作细节（SKILL.md）分离，同一规则只写一处；长任务 skill 内部再分 checkpoint 硬节点（人机对齐点）。
3. **真相源与派生件**：`2-script.md` 是口播稿唯一真相源，`audio-segments.json`/`narrations.ts` 是派生件；dashboard 是派生视图，meta.yaml+backlog 才是状态真相。音画不符（L2）就是真相源纪律被破坏的代价。
4. **阶段是状态字段，不是目录位置**：内容全生命周期住一个目录，靠 meta.yaml 翻状态。
5. **不可逆操作的自动化边界**：发布必经人审；dry-run 铁律（`--publish` 单一授权信号）；治理线「只产报告不自动改」，可自动的只有可逆、限幅、留痕的记账类动作。
6. **人在环上的位置设计**：全自动停在「出审」，飞书两张卡（审核卡+确认发布卡）是人的两次进场；闸口放在不可逆点之前，而不是撒在全流程。
7. **调度与执行解耦**：dispatcher 只读 `tasks.md` 注册表评估 trigger（事件窗口/周期/加权池三型），加任务只改注册表不改调度器。
8. **Loop 大环**：发布→复盘拉数据→漏斗归因→变更提议→人审→回写 brain→下轮选题打分。受众信号只有复盘一条来路（选题端不爬抖音）——信息流单向可控。
9. **Loop 的 Loop（元层）**：account-audit 对着运行账本调治理线自身参数，带自调限幅表与熄火线（样本 <5 只出报告不调参）——系统自我调参也要有边界。
10. **无人系统的可观测性**：阻塞即上报铁律，只写本地日志不算上报（L14 六天空跑事故）。
11. **Subagent 职责分离**：dubbing-reviewer 只判不改（无写权限），修复归主回话，≤3 轮上限后升级人审——质检者与执行者分权。
12. **教训驱动进化**：坑的「故事」只登记 lessons.md，「规则」回写对应 SOP 标 Lx 回指——系统长记性的机制。
13. **熵增治理观**：「没人催、但放着会烂的」才进治理线；养资产（池子/大脑/已发布物）与造内容（生产线）严格分界。

### 附：AI 协作心法线（课程介绍明说的第三条收获）

> 亮点清单讲「系统为什么这样设计」，心法线讲「人怎么和 AI 一起干活」。心法不单开课，全部嵌在跟做章节里现场示范（分配见 01 附表、02 章节表），课程介绍（第 1 课开篇）需点明：结课带走的除了系统和设计思想，还有这套工作方式。

1. **关键结论落文档，不留在对话里**——对话会结束，文档才是人和 AI 的共享记忆；CLAUDE.md、brain/、SOP、lessons.md 全是这一条的产物。
2. **如何拆分 agent**——按判断独立性、权限隔离、可并行度拆，不按工作量拆（dubbing-reviewer 只判不改是范本）。
3. **在返工成本突变处停下对齐**——Checkpoint 硬节点的摆放逻辑：稿子定了才开发、第 1 章过了才批量。
4. **给 AI 的任务带机器可验判据**——「命令没报错」≠「干成了」，验产物不验 exit code。
5. **说明书思维**——方法论沉淀成 skill 一次，AI 每次加载执行；能不造轮子就不造的前提是会「读别人的说明书」。
6. **铁律前置**——红线写在文档最前面（skill 铁律段、CLAUDE.md 内容红线），AI 先看到约束再看到步骤。

## 八、非目标

- 不教手写代码，不逐行讲解任何实现（包括 AI 生成的）。
- 不教抖音运营/涨粉技巧本身——账号方法论只讲到「它如何被系统消费与反哺」为止。
- 不做视频课载体（本期）。
- 不承诺学员复刻出与本仓一模一样的系统——目标是学员拥有**自己领域**的最小 Loop。
