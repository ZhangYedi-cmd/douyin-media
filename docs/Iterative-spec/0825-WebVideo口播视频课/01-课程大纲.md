## 模块一 · 单点跑通：第一条口播视频（4 课）

**模块目标**：不讲任何系统设计大词，先让学员用三个开源 skill 拼出一条带配音、带字幕、无人录屏的口播视频。原理只讲「手上刚发生的事」。

### 第 1 课 · 装备上手：让 AI 替你干活的最小配置
- **跟做**：装 Claude Code；认识 skill / CLAUDE.md / 会话的最小概念；克隆课程仓库，跑一遍 `media check --json` 感受「系统在自我体检」（一天实录与全景导览已前移至第 0 课）。
- **原理深挖**：AI 时代为什么用 CLI（亮点 1 初讲，后续反复回扣）——文本进文本出、可组合、可定时、可留痕，天生是 LLM 的手脚。
- **AI Coding 加油站**：什么是 skill——把方法论和流程封装成 AI 可加载的说明书；`/` 调用与自动触发。
- **素材**：`README.md`、`pipeline/daily-run.md`、`pipeline/logs/` 任一日实录。
- **依赖**：Claude Code（必需）。

### 第 2 课 · 开源件直用：web-video-presentation，从一篇文章到「伪装成视频的网页」
- **跟做**：copy 开源 skill `web-video-presentation`，拿一篇自己的文章走完 Phase 1→2：产口播稿 + outline，过 Checkpoint Plan 五件事对齐，验收第 1 章，生成完整网页演示。
- **原理深挖**：
  - 「网页伪装视频」的核心洞察：点击驱动 = 确定性时间线，为无人录屏铺路；
  - **长任务 skill 的分层设计**（亮点 2）：Phase 切分、Checkpoint 硬节点是「人机对齐点」而不是流程装饰——AI 一次跑到黑 vs 在关键分叉停下对齐；
  - 开源件为什么直接用不改造（ADR D2 三类三教法之「开源直用」）。
- **AI 写作技巧**：口播稿写作——3 秒钩子、冷开铁律（第一句自成立，L11 事故引入）、口语化不写论文腔。
- **AI Coding 加油站**：开发模式 A/B/C（逐章/顺序/并行）背后的并行 agent 思想，为模块二的 Subagent 课打伏笔。
- **素材**：`.claude/skills/web-video-presentation/SKILL.md`、`pipeline/2-create.md` 步骤 1–2、`lessons.md` L11。
- **依赖**：Claude Code。

### 第 3 课 · 配音链：tts-dub 与「真相源」的第一堂课
- **跟做**：`npm run extract-narrations` 抽分段文案 → 用 tts-dub 合成每段 mp3（MiniMax 或免费 TTS 替代）→ 处理一个多音字、扫一次死气。
- **原理深挖**：
  - **真相源与派生件**（亮点 3）：`2-script.md`（真相）→ `narrations.ts` → `audio-segments.json`（派生），改上游必重抽下游——用 L2 音画不符事故讲「破坏真相源纪律的代价」；
  - 为什么绕开 skill 自带的坏 CLI 直调 HTTP（能不造轮子就不造，但轮子坏了要会换胎）；
  - 静默失败：L16 depause 原地写事故——「命令没报错」不等于「干成了」，验收要验产物不验 exit code。
- **AI Coding 加油站**：给 AI 的任务要有机器可验的完成判据（silencedetect 复扫数为 0，而不是「看起来没问题」）。
- **素材**：`pipeline/2-create.md` 步骤 3、`lessons.md` L2/L3/L16/L17/L18、`brain/tts.config.json`。
- **依赖**：TTS（推荐 MiniMax，可免费替代）。

### 第 4 课 · 质检闸口与成片：第一次派 Subagent
- **跟做**：照抄 dubbing-reviewer agent 定义派一个质检 subagent 审自己的配音批次；PASS 后 `npm run record` 无人录屏出 final.mp4；抽帧验音画与字幕；用图像 skill 出一张竖版封面。
- **原理深挖**：
  - **Subagent 职责分离**（亮点 11）：reviewer 只判不改（无写权限）、修复归主回话、≤3 轮上限后升级人审——为什么「质检者不能自己动手改」；
  - **终检闸设计**：L4 分轮反应式修的代价 → 所有检查一次性前置；检查对象是最终 mp4 不是组件截图（验成品不验半成品）；
  - L15 漏字幕事故：默认参数的坑要在契约里钉死。
- **AI Coding 加油站**：Subagent 与 Agent Team 正式登场——什么时候派子代理（独立判断/并行/权限隔离），什么时候主会话自己干。
- **素材**：`pipeline/2-create.md` 步骤 4–6 + 终检闸 A–G、`.claude/agents/` dubbing-reviewer、`lessons.md` L1/L4/L15。
- **依赖**：图像生成 API（可选，可手动出图）。
- **模块一里程碑**：学员手里有一条完整成片。下一个问题自然浮出：**第二条呢？十条呢？状态谁记？**

## 模块二 · 从作品到工厂：状态机与记账（4 课）

**模块目标**：把「一次成功」变成「可重复的流水线」。核心是状态机、真相源账本、CLI 记账，以及第一次把人放进环里。

### 第 5 课 · 内容工厂的骨架：目录、状态机、账号大脑
- **跟做**：搭出自己的仓库骨架——`content/`（一条内容一目录 + meta.yaml）、`content/_backlog/`（选题池，一题一文件）、`brain/`（定位/人设/风格/对标/信息源五件）、`dashboard.md`。用 AI 按模板生成自己账号的 brain 五件套初稿。
- **原理深挖**：
  - **阶段是状态字段，不是目录位置**（亮点 4）：内容全生命周期住一个目录，靠 meta.yaml 翻状态——对比「按阶段挪文件夹」方案的坏处；
  - **真相源 vs 派生视图**（亮点 3 再扣）：dashboard 只是投影，meta.yaml + backlog.yaml 才是账本；
  - brain 为什么是「大脑」：所有创作/选题决策的唯一依据，也是日后 Loop 反哺的唯一落点。
- **AI 写作技巧**：账号定位与 persona 人设怎么写——写给 AI 消费的人设文档和写给人看的有何不同。
- **素材**：`content/_template/`、`brain/` 五件、`CLAUDE.md` 文档架构约定。

### 第 6 课 · 记账为什么要 CLI：用 SDD 让 AI 造出 media 命令
- **跟做**：**第一次完整的 SDD 实战**——学员写一份 spec（状态合法值、翻转规则、`next`/`promote`/`flip`/`check` 四个子命令的契约），让 AI 从 spec 生成自己的记账 CLI，全程不看一行实现。
- **原理深挖**：
  - **亮点 1 正面讲透**：LLM 干判断活（slug 怎么起、题好不好），确定性活给代码（五处账一次改齐、状态合法性校验）——「让 LLM 自觉记账」等于让它每次都重新发明规则，必漏；
  - `media promote` 一条命令五处改齐的设计：把「容易漏的多处一致性」压进一个原子操作；
  - `media check` 是机器判据：一致性规则唯一定义在代码里，AI 和人都信同一个裁判。
- **AI Coding 加油站**：**SDD（Spec-Driven Development）**正式登场——spec 是唯一需要人写的「代码」；验收 = 跑契约用例，不 review 实现。
- **素材**：`tools/console/`（`state.ts`/`alerts.ts` 作为「规则唯一定义处」的例证）、`pipeline/daily-run.md` 取题步骤。

### 第 7 课 · 发布与二次包装：为什么不直接用 social-auto-upload
- **跟做**：装开源 `social-auto-upload`，先裸用 sau CLI 手动发一条（或 dry-run）；再让 AI 按 spec 包出自己的 publish skill：状态校验（只发 approved）→ 字段映射 → dry-run 输出完整命令+物料 → `--publish` 单一授权信号 → 结果留痕。
- **原理深挖**：
  - **二次包装的判断标准**（ADR D2）:裸 sau 什么都能发——它不认识你的状态机、不做授权确认、不留痕。包装补的是「工具与系统契约之间的缝」，不是重写工具；
  - **不可逆操作的自动化边界**（亮点 5）：dry-run 铁律；`--publish` 在 = 授权已发生在上游，skill 不设第二道确认——授权信号要「单一且语义明确」；
  - L7/L8 事故：发布失败先原样重试一次再排查——真实世界的浏览器自动化就是会抖。
- **AI Coding 加油站**：给 AI 用的工具说明书怎么写（skill 的铁律段为什么放最前面）。
- **素材**：`.claude/skills/douyin-publish/SKILL.md`、`tools/social-auto-upload`、`lessons.md` L5/L6/L7/L8。
- **依赖**：抖音账号（可选，无账号停在 dry-run）。

### 第 8 课 · 人在环上：飞书双卡与闸口位置设计
- **跟做**：搭 feishu-notify 通道（或降级为本地确认模式），跑通「出审推审核卡 → 人点过审 → 确认发布卡 → 点确认才真发」全链。
- **原理深挖**：
  - **闸口位置设计**（亮点 6）：全自动为什么停在「出审」而不是更早或更晚——闸口只放在不可逆点（发布）之前，而不是撒在全流程让人疲劳；
  - 两次确认的分工：审核卡审内容质量，确认发布卡审「此刻要不要发」——两个不同的决策不合并成一次点击；
  - 审批数据流：按钮点击如何变成 `--publish` 信号（上一课授权语义的闭合）。
- **AI Coding 加油站**：Human-in-the-loop 的通用模式——把人的进场做成「结构化事件」而不是「口头同意」。
- **素材**：`pipeline/3-review.md`、`pipeline/4-publish.md`、`.claude/skills/feishu-notify/`、`tools/feishu-bot/`。
- **依赖**：飞书自建应用（推荐，可降级）。
- **模块二里程碑**：一条人审把关的完整流水线。下一个问题：**还是要人每天来点火。**

## 模块三 · 无人值守：编排与定时（2 课）

**模块目标**：把点火权交给时间。学员第一次体验「早上醒来，AI 已经把活干到了人审这一步」。

### 第 9 课 · 文档即程序：daily-run 编排与定时 agent
- **跟做**：为自己的流水线写 `daily-run.md` 入口 prompt（取题→创作→出审→停在人审），配置定时任务喂给它；跑一次完整的无人日更。
- **原理深挖**：
  - **markdown SOP 就是编排代码**：daily-run 是给定时 agent 读的「入口 prompt」，版本管理、可 diff、可回滚——SDD 思想从「造工具」扩展到「编排流程」；
  - **契约与操作分层**（亮点 2 完整版）：`pipeline/*.md` 定输入/输出/状态翻转/闸口，SKILL.md 住操作细节，同一规则只写一处——两处漂移是文档系统的头号死因；
  - 取题优先级设计：`next_up` 人工钦点指针 > score 排序——给人留插手位，但默认不需要人。
- **AI Coding 加油站**：定时 agent 的工程要点——幂等（重复触发不出重复内容）、断点（跑一半挂了怎么办）。
- **素材**：`pipeline/daily-run.md`、`pipeline/1-ideate.md`、`CLAUDE.md` 文档架构约定。

### 第 10 课 · 阻塞即上报：无人系统的可观测性
- **跟做**：给自己的 daily-run 加上报通道：取题空、TTS 余额尽（1008）、录制失败超重试——任何导致停产的事件推通知给人，写清事件/根因/需要人做什么。
- **原理深挖**：
  - **L14 事故完整复盘**：2026-06-30~07-05 取题空跑 6 天，日志喊了 6 天人没看见——「只写本地日志不算上报」这条铁律的由来；
  - 上报的分级：生产线「阻塞即上报」（有时效）vs 治理线「连续 2 轮失效才推」（可延迟）——不是所有异常都值得打扰人；
  - L9 余额事故：外部依赖耗尽要「停在明确状态 + 报充值」，不硬跑也不静默。
- **AI Coding 加油站**：无人系统的三问——它挂了你多久知道？你知道时能定位根因吗？它自己知道该停还是该重试吗？
- **素材**：`pipeline/daily-run.md` 阻塞即上报节、`lessons.md` L9/L14。
- **模块三里程碑**：无人日更跑通。新问题浮现：**跑了几周后——池子过期了、打法过时了、发布的数据没人看。系统在熵增。**

## 模块四 · 治理线：Loop 成环（4 课）

**模块目标**：课程题眼所在。生产线只会消耗资产，治理线负责养资产；复盘反哺闭合大环，元层让 Loop 自己调自己。

### 第 11 课 · 熵增与治理线：没人催、但放着会烂的
- **跟做**：盘点自己流水线跑几周后的「烂账」：过期选题、过时对标、没人看的发布数据。为自己的系统立治理线宪法（只养资产不造内容 / 只产报告不自动改）。
- **原理深挖**：
  - **治理线的准入判据**（亮点 13）：「没人催、但放着会烂的」——有人催有时效的归生产线，两条线为什么必须分开（本仓实证：池子保鲜耦合在 daily-run 上时，生产一换模式保鲜就停摆）；
  - **只产报告不自动改**（亮点 5 治理版）：改 brain、改已发布资产一律人审后应用；可自动的只有可逆、规则已钉死的记账类动作——自动化边界由「可逆性」划定，不由「技术上能不能」划定；
  - 选题池是库存资产：入池是补库存，promote 起才是造内容——资产视角 vs 内容视角。
- **素材**：`harness/README.md`、真实实证（24 天没补水 9 条全过期）。

### 第 12 课 · 调度与执行解耦：dispatcher 与任务注册表
- **跟做**：用 SDD 让 AI 生成自己的 dispatcher skill + `tasks.md` 注册表；注册前两个任务（ideate 养池 periodic:2d、check 日巡 periodic:1d）；写第一张任务卡。
- **原理深挖**：
  - **调度/执行解耦**（亮点 7）：dispatcher 只评估 trigger 派活，加任务只改注册表——对比「每个定时任务各配一个 cron」的失控；
  - **trigger 三型**：事件窗口（post-publish-window）/ 周期（periodic:Nd）/ 加权池（weighted-pool，海量同质维护债）——按任务性质选型，不是无脑加权随机；
  - **任务卡五件事**：为什么存在/目标怎么选/干什么/产物与记账/人审关注点——有 skill 的卡只写契约级判据，没 skill 的卡就是未来 skill 的规格种子（SDD 又一次）；
  - 运行账本 `logs/index.jsonl`：treat 调度历史为数据——为元层课埋伏笔。
- **素材**：`harness/tasks.md`（yaml + 任务卡全文）、`.claude/skills/harness-dispatcher/`。

### 第 13 课 · 大环闭合：复盘反哺、热点入池、竞对复核
- **跟做**：三件套接入自己的治理线——
  1. **复盘**（douyin-retro 思路）：拉发布数据（或用课程样例数据集）→ 漏斗归因 → 产出「大脑变更提议」→ 人审 → 回写 brain；
  2. **抓实时热点**（douyin-ideate + agent-reach）：定时扫信源 → 双赛道打分 → 入池；
  3. **抓竞对/对标复核**（benchmark-refresher）：定期验证对标账号与打法是否还成立。
- **原理深挖**：
  - **这就是 Loop**（亮点 8）：发布→数据→归因→提议→人审→brain→下轮打分——画出完整大环，指认每一段在前面哪课已经搭好；
  - **信号单向来路**：受众平台信号只走复盘这一条路，选题端不爬抖音——信息流可控才能归因（否则打分被污染，你不知道是选题好还是恰好蹭到推荐）；
  - 窗口触发（24h/72h/7d）与欠账问题：错过窗口的债怎么办（retro-debt-collector 任务卡 = 用规格占位未来的能力）。
- **AI 写作技巧**：从评论区挖真实反馈与新选题——数据不只是数字。
- **素材**：`harness/tasks.md` retro/ideate/benchmark-refresher 三张卡、`harness/retro.md`、`.claude/skills/douyin-retro/`、`brain/benchmarks.md`。
- **依赖**：抖音数据通道（可选，课程提供样例数据集）。

### 第 14 课 · Loop 的 Loop：元层自审与自调边界
- **跟做**：接入 account-audit 元层：读自己的 `logs/index.jsonl` 统计每任务执行数/成功率/人采纳率，为自己的治理线定一张「自调限幅表」（哪些参数可自动调、范围步长多少、哪些锁定）。
- **原理深挖**：
  - **系统自我调参的边界设计**（亮点 9）：自动档 = 可逆数值、限幅、必留痕；启停与大跳变一律提议人审——「AI 自己改自己的配置」不是玄学，是一张明确的权限表；
  - **熄火线**：单任务记录 <5 条只出「样本不足」报告不调参——没数据时最优动作是承认没数据；
  - 采纳率口径设计：只统计落盘 ≥7 天的报告——别把「人还没来得及审」算成「不采纳」；提议多但采纳低 = 该修任务卡，不是加大力度。
- **AI Coding 加油站**：Agent Team 全景回顾——主回话/子代理/定时 agent/dispatcher 派活，一张图看清本系统里所有「AI 角色」的分工与权限。
- **素材**：`harness/tasks.md` account-audit 卡（含限幅表原文）、`harness/logs/index.jsonl`。
- **模块四里程碑**：学员的系统大环闭合，且有元层看着治理线自己。

## 模块五 · 方法论提炼与结课（4 课）

**模块目标**：把 Loop 的方法论提炼出来带走。本模块先讲系统怎么长记性，再补上一直被绕开的完整后端——第 8 课把无头 claude 当黑盒主链已经够用，本课拆开黑盒，把无头 AI 当一台进程管理，讲清消息解析与接口设计（主链必经）；接着把派生视图从文件升成屏（前端面板，可选增强）；最后整课程回望——逐段回望每个阶段掌握了什么，用 Loop 七要素把整门课收成一张总纲，并提炼系统设计心法与 AI 协作心法两层，带学员把这张图迁移到自己的领域。

### 第 15 课 · 系统怎么长记性：教训驱动进化
- **跟做**：建立自己的 `lessons.md` 机制：踩坑先登记「故事」，规则回写对应 SOP 标 Lx 回指；把自己跟做过程中真实踩的坑登记进去（每个学员一定踩过）。
- **原理深挖**：
  - **故事与规则分离**（亮点 12）：故事只写一处（防 SOP 变成事故陈列馆），规则住它该在的位置（防教训变成没人读的博物馆）——L1–L18 全表导读，指认每条坑如何变成了前面课程里讲过的某条铁律；
  - 打法与坑分流：复盘沉淀的「打法」进 brain/benchmarks.md，「坑」进 lessons.md——正反馈和负反馈落点不同；
  - 文档架构防漂移约定全景：真相源唯一、派生视图标注、同一规则只写一处、历史存档只读。
- **素材**：`pipeline/lessons.md` 全文、`CLAUDE.md` 文档架构约定。

### 第 16 课 · 后端架构：无头 AI 是一台进程，不是一张嘴
- **跟做**：**SDD 第四次实战（后端）**——用 SDD 让 AI 从 spec 造出自己的最小后端闭环：一个读接口（`GET /api/contents` 出 `{revision, now, data}` 信封）、一条动作层快写（`POST /api/actions/promote` 用 `execFile("media", [...])` 翻账）、一个慢作业（`POST /api/actions/publish` 用 `spawn claude -p` 起发布 skill，回 202 + jobId，进度走 SSE）、一个 job runner 最小版（job 状态机 queued → running → verifying → succeeded/failed）。全程不看一行实现。
- **原理深挖**：
  - **CC 进程管理**（亮点 5 后端版）：spawn 无头 claude 的四个防坑点——env 剔除 `ANTHROPIC_API_KEY`（本机是 OAuth token，误当 API key 发布必失败）、`--allowedTools` 白名单、授权语义写死进 prompt、成败判定读状态不读文字（第 8 课黑盒模型的深化：进度展示看工具事件，成败裁决只看 meta.status，两级信任分层）；幂等锁防双发（同 slug 同时只许一个任务，双击/回调重投都进不来）；单并发不引队列中间件（本地单人工具背不动，崩溃安全靠文件真相——进程死了账本还在，重建即恢复）；
  - **消息结构解析**：claude 无头输出是机器可读的 stream-json 事件流（text 片段 / tool_use 记录 / tool_result 混排）；信任分级三层（text 只展示、tool_use 驱动步骤条、meta.status 唯一裁决）；三层解析（传输层 readline + JSON.parse → 事件归一层 6 种 NormEvent → 里程碑引擎正则×tool_use 匹配）；cc-stream 为什么独立成零依赖叶子包（引擎进包、知识留外，五包边界硬切）；
  - **HTTP 接口设计**：动作层白名单 1:1（`POST /api/actions/*` 逐个映射 media 命令，execFile 参数数组不经 shell，注入面为零）；快写与慢作业两条通道的分界（秒回 vs 202 异步）；读响应信封统一 `{revision, now, data}`（前端拿 revision 当版本号）；token 按威胁模型定档（单机单用户不上认证系统，只挡误触不挡入侵）。
- **AI Coding 加油站**：写路径纪律——server 永不直接写文件，写路径唯一入口 media（唯一 import writer.ts 的包，server 禁 import writer.ts）；**文件系统即总线**（写者读者经文件解耦，谁都能崩，状态可重建）——本课把第 5 课「真相源在文件里」从概念落成工程实现。
- **素材**：`docs/Iterative-spec/0818-看板工作台/2026-08-18-看板后端与CC进程调度技术方案.md`（spawn 四防坑点/幂等锁/单并发/3 秒窗口）、`02-后端执行方案.md`（三层解析/信任分级/信封）、`01-CLI执行方案.md`（动作层白名单）、`00-执行版总览.md`（五包一仓/写路径纪律）、`tools/console/packages/server`+`cc-stream`（成品）、`03-前端执行方案.md`（读信封消费方视角）。
- **依赖**：可选（Node 后端工具链；可读课程仓 console server 成品理解设计，主链只要求理解设计）。

### 第 17 课 · 前端面板：把派生视图从文件升成屏
- **跟做**：用 SDD 让 AI 从 `docs/design/` 六页设计稿造出自己的看板面板（复用课程仓 `tools/console/packages/ui` 思路）——定三样 spec 输入：页面清单（P1 总览晨检/警报、P4 选题池、P5 治理线、P6 数据复盘等，每页核心组件）、数据契约（账本 → server API + SSE，revision 变了就重拉）、视觉 token（设计系统映射进 antd theme）。先建一页跑通「账本 → API → 渲染 → SSE 刷新」整环，再逐页补。
- **原理深挖**：
  - **派生视图升级的判断**（亮点 5 再扣）：dashboard.md 够用 vs Web UI 面板——什么时候值得升；面板不记任何状态，真相源仍在文件里，SSE revision 只是「账本变了」的信号（F6 不上状态库的理由）；
  - **前端选型四连，全带推翻记录**（F1-F5）：React vs vanilla（只读看板升级成裁决台，前提变结论变）；Vite vs Umi（本地单人工具背不动 Umi 的约定链）；antd vs 手写组件（Table/Drawer/Steps 是真实用武之地，token 映射承接设计系统）；不上图表库（metrics 折线自绘 SVG）；
  - **给 AI 写前端契约的判据形态**（ui 包四条约定）：一页一目录、数据只走两个 hook 不裸 fetch、视觉只引 token、新增依赖先登记——每条都可 grep 判真伪。
- **AI Coding 加油站**：给 AI 造前端的三样 spec 输入——页面清单、数据契约、视觉 token，三样钉死，AI 就能从设计稿造出真前端（SDD 实战延续：CLI、dispatcher、后端之后，这次是前端；server 读接口与两条写通道就是上一课造的后端）。
- **素材**：`docs/Iterative-spec/0818-看板工作台/2026-08-18-看板前端技术方案.md`（F1-F6+§7 约定）、`docs/design/` 六页设计稿、`tools/console/packages/ui/`（成品+CLAUDE.md）、`docs/Iterative-spec/0818-看板工作台/00-执行版总览.md`（五包一仓/API 契约/写路径纪律）、`tools/console/packages/core`+`server`（buildSnapshot / execFile media）。
- **依赖**：可选（Node 前端工具链；不强求自建，可读课程仓成品理解设计）。

### 第 18 课 · 结课：把整门课收成一张总纲
- **判断锚点**：结课不教新命令，它把前面十七课攒下的判断收成一张能带走的图——系统只是案例，可迁移的是你搭它时立起的每条判断。
- **模块回望**（整课程回望）：按五段生长史逐段回望，每段三列——这段搭了什么实物 / 掌握了哪条判断 / 对应课号。五段：①单点跑通（0–4）②状态机+记账（5–8）③定时编排（9–10）④治理线成环（11–14）⑤教训+后端+面板（15–17）。每段收一句「这段立的判断，是后面哪段的支点」。
- **Loop 七要素总纲**：七要素收成一张总纲表——要素 × 指回课号 × 对应实物 × 一句话判断：
  1. **真相源与状态机**（账本唯一，派生视图只读）——模块二；**文件系统即总线**（写者读者经文件解耦，谁都能崩，状态可重建）——第 16 课
  2. **确定性接口**（CLI 记账，判断归 LLM、确定性归代码）——第 6 课
  3. **闸口**（人审钉在不可逆点前，授权信号单一明确）——第 7/8 课
  4. **调度**（时间/事件触发，调度与执行解耦）——第 9/12 课
  5. **反哺回路**（数据单向来路 → 提议 → 人审 → 改大脑）——第 13 课
  6. **自审与记性**（元层限幅自调 + 教训账本）——第 14/15 课
  7. **进程管理**（无头 AI 是一台进程不是一张嘴：最小权限、判成败看它改的文件、容忍它死因为状态可重建）——第 16 课
  每个要素后讲「为什么是这根梁，少了它环会断在哪」。
- **搭建心法（系统设计层）**：7–8 条判断，每条「判断 + 为什么 + 代价」——真相源永远在文件里；写路径唯一入口；人审只钉在不可逆点；信息流单向可控；判断归 LLM、确定性归代码；先撞墙再立规则；能造最小就最小；无头 AI 是进程不是嘴。第 16 课后端是「文件系统即总线 + 进程管理」的现场，第 17 课面板是「派生视图升成屏」的现场。
- **AI 协作心法收拢**（00-ADR 心法线六条，逐条指回示范课）：落文档不落对话（1/5/9/15）、按判断独立性拆 agent（4/14）、返工成本突变处对齐（2）、机器可验判据（3/6/10）、说明书思维（2/9）、铁律前置（4/7）。补一句「它们嵌在各课，本课收拢」。
- **迁移指南**：口播视频只是本课的「货」。带学员把七要素映射到其它领域各举一例（如个人知识库运营、开源项目维护、求职投递流水线），完成一份自己领域的「最小 Loop 设计一页纸」（七格：领域名 + 七要素各填一行）。
- **结课检查清单**：学员应拥有——①至少一条自产口播成片 ②一条带人审闸口的流水线 ③一份 daily-run + 定时触发 ④一条至少注册了 ideate+check+retro 的治理线 ⑤自己的 lessons.md ⑥一份最小后端闭环（读接口 + 快写 + 慢作业 + job runner）⑦一页纸最小 Loop 迁移设计。
- **mermaid**：2 张——①七根梁收成 Loop 大环（flowchart）；②最小 Loop 设计一页纸七格结构。
