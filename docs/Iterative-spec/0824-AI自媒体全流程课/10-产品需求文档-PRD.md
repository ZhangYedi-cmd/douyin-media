# AI 自媒体全流程课与参考工作台 PRD

> 产品形态：实操训练营 + 可运行参考仓 + 本地控制台  
> 上游决策：`00-ADR.md`、`03-已拍板补充.md`  
> 当前状态：课程架构已拍板，参考实现已存在；训练营物料切分尚未完成。

## 1. 产品背景

目标用户通常已经使用过 Claude Code 或 Codex，能让 Agent 写一段代码或生成一篇内容，但还没有建立稳定的工程方法。他们常见的问题不是“不会调用模型”，而是：

- 把 Agent 当成更强的聊天机器人，没有任务契约、状态和验收证据。
- 把 Prompt、规则、SOP、Skill 和代码混在一起，系统一迭代就漂移。
- 相信 Agent 的“完成了”，没有复读真实文件、运行测试或核对外部结果。
- 能跑通一次选题或创作，无法处理并发、失败、重试、人工授权和恢复。
- 做完内容不复盘，经验无法回流，系统没有形成闭环。
- 知道需要 Web 看板，却容易让看板成为第二真相源，最终和文件账本打架。

本产品用一个真实 AI 自媒体项目作为贯穿案例，让学员亲手造出从选题到复盘的可信流水线，并能把同样的方法迁移到研发、研究、知识生产、销售运营等流程。

## 2. 产品定位

### 2.1 一句话定位

让已经会用 Agent 的人，掌握如何把一项真实工作建模成可运行、可观察、可人审、可恢复、可持续进化的 Loop Engineering 系统。

### 2.2 产品组成

| 组成 | 作用 | 交付形态 |
|---|---|---|
| 课程正文 | 讲清原理、方法和决策 | 9 章 27 篇，结构由内容动态生成 |
| `starter/` | 学员起步骨架 | 只有最小目录、样例数据和任务说明 |
| `checkpoint/m01...m09/` | 每章参考状态 | 能对照 Diff 和运行结果验收 |
| `reference/` | 完整参考实现 | 当前完整项目的脱敏、可公开版本 |
| `labs/` | 故障注入与迁移练习 | 错误 fixture、排障任务、跨域案例 |
| 本地控制台 | 观察和授权 | 总览、看板、选题池、治理线、数据复盘、任务日志 |

### 2.3 目标用户

- 已经用过 Claude Code、Codex 或同类 Agent 的开发者与技术创作者。
- 想搭建个人内容工厂、研究流水线或自动化运营系统的独立创作者。
- 需要设计 Agent 工作流、Human-in-the-loop 和可审计控制面的工程负责人。
- 希望从“会写 Prompt”升级为“会做 Agent 工程”的产品、运营和技术人员。

### 2.4 非目标用户

- 完全没有命令行、Git 和文件系统基础，且不愿补齐基础能力的用户。
- 只想获得一键生成爆款、无需审核、自动涨粉承诺的用户。
- 只学习抖音运营技巧，不关心工程架构和系统可信度的用户。

## 3. 产品目标与成功标准

### 3.1 学习目标

学员完成训练营后应能独立完成：

1. 把模糊工作拆成输入、输出、状态、闸口和验收证据。
2. 区分 Prompt、项目规则、阶段 SOP、Skill、CLI 和传统代码的职责。
3. 设计文件真相源、派生视图和双层状态机。
4. 用 CLI 收回状态写入权，并实现原子写、锁、审计和故障恢复。
5. 建立 React + Server + SSE 控制面，但不让控制面变成业务真相源。
6. 让长任务可观察、可取消、可回放，并以文件事实做终局裁决。
7. 在不可逆动作和判断性变更前设置人工授权。
8. 建立独立治理线，用数据、报告、提议和人审形成闭环。
9. 把上述方法迁移到另一个真实业务流程。

### 3.2 交付成功标准

每位学员需交付九个里程碑，每个里程碑至少包含四类证据：

- 设计说明：为什么这么拆、真相源在哪里、边界是什么。
- Agent 任务记录：给 Agent 的任务契约、过程和关键决策。
- Git Diff：实际修改了哪些文件，没有越过哪些红线。
- 测试或运行结果：命令输出、页面截图、状态迁移或故障恢复证据。

仅有文章、代码压缩包或 Agent 自述均不算完成。

### 3.3 业务指标

首期试运行建议关注：

| 指标 | 口径 | 目标 |
|---|---|---|
| 开营到 M1 完成率 | 提交 M1 四类证据的人数 / 开营人数 | `{待填写}` |
| 九里程碑完成率 | 提交 M9 的人数 / 开营人数 | `{待填写}` |
| 独立恢复率 | 在不看标准答案时完成指定故障恢复的人数占比 | `{待填写}` |
| 迁移成功率 | 毕业项目能在新领域复用同一架构原则的人数占比 | `{待填写}` |
| 助教介入强度 | 每人每里程碑平均需要的人工答疑次数 | 趋势下降 |
| 证据合格率 | 四类证据齐全且可复核的提交占比 | `{待填写}` |

这些是课程指标，不等同于抖音账号播放量、涨粉量或收入指标。

## 4. 核心用户旅程

### 4.1 旅程 A：从零建立第一条生产线

1. 学员从 `starter/` 启动，读账号定位和样例选题池。
2. 用任务契约让 Agent 选择一个题并生成内容目录。
3. 写入口播稿、配音、录屏、封面和发布物料。
4. 通过质量检查后进入 `review`，流程必须停下。
5. 学员检查状态文件、产物和日志，提交里程碑证据。

### 4.2 旅程 B：建立可信记账

1. 学员观察手工改 YAML 导致的多文件不一致。
2. 实现或补齐 `media` CLI，把状态迁移、时间戳、backlog 和 dashboard 收口到事务。
3. 注入非法迁移、并发写、进程中断等故障。
4. 用 Check、审计日志和原子写证明系统可恢复。

### 4.3 旅程 C：建立人工授权控制面

1. 学员打开本地 Web 看板查看当前内容、警报和选题水位。
2. 在详情页做通过、打回或拒绝决策。
3. 对真实发布先看 dry-run，再进行独立确认。
4. 观察慢作业的进度、工具调用、日志、取消和终局裁决。

### 4.4 旅程 D：形成治理闭环

1. 发布后在 24h、72h、7d 拉取数据。
2. 找出漏斗主漏点并生成账号大脑变更提议。
3. 人工审核提议后才更新 `brain/`。
4. 新策略影响下一轮选题评分和创作约束。
5. 学员证明系统完成“生产 → 数据 → 提议 → 人审 → 策略 → 再生产”的大环。

### 4.5 旅程 E：跨域迁移

学员选择研究、代码交付、知识库、销售运营等新领域，重新定义工作单元、状态机、闸口、真相源、控制面和治理线。毕业标准不是复制目录名，而是保持架构原则成立。

## 6. 控制台页面需求

### 6.1 总览

- 显示今日生产阶段、在制品数量、警报、待办、选题池水位、治理心跳。
- 所有数字来自 Server 投影，不现场扫描文件。
- 点击证据路径可打开 FileDrawer。
- 页面只提供跳转和查看，不做高风险写动作。

### 6.2 生产看板

- 按状态分组展示内容条目。
- 展示标题、类型、支柱、状态、关键产物和停留时间。
- 对 `ideated` 内容可启动创作。
- 点击条目进入详情页。

### 6.3 内容详情

- 展示 meta、阶段时间轴、脚本、审核、发布物料、复盘和执行记录。
- 根据当前状态只显示合法动作。
- 审核动作支持通过、打回、拒绝；打回和拒绝必须填写原因。
- 发布必须从 `approved` 发起，并展示独立确认。
- 可查看历史 Job、当前 Job、工具调用和终局裁决。

### 6.4 选题池

- 展示水位、idea 列表、模拟下一题、`next_up` 指针、机械过期预览和撞题提议。
- promote 必须显式输入 kebab-case slug，不由前端静默猜测。
- 合并或归档提议先 dry-run，再应用。

### 6.5 治理线

- 展示任务注册表、是否启用、触发类型、上次运行、是否逾期。
- 展示运行账本、复盘矩阵、待审提议和报告正文。
- 只有注册表中启用且配置了 Skill 的任务可手动启动 Agent 作业。
- 应用账号大脑提议前必须再次确认。

### 6.6 数据复盘

- 展示各窗口快照、趋势和漏斗引用。
- 无数据时给出明确的补数据指引。
- 不允许页面现场计算出另一套与账本不同的业务指标口径。

## 7. 人工授权与权限边界

| 动作 | 默认自动化 | 人工授权 | 原因 |
|---|---|---|---|
| 选题入池 | 可自动 | 不要求 | 可逆、属于库存记账 |
| 机械过期清扫 | 可自动 | 规则已预先拍板 | 客观规则、可审计 |
| promote | 生产线可自动或人工指定 | 由 `next_up`/模式决定 | 创建在制品但不对外发布 |
| 创作到出审 | 可自动 | 开始创作可由定时或看板授权 | 最终停在人审 |
| 审核通过/打回/拒绝 | 不自动 | 必须 | 内容判断 |
| 真实发布 | 不自动 | 必须独立确认 | 不可逆外部动作 |
| 复盘报告 | 可自动 | 不要求 | 只产报告与提议 |
| 应用 `brain/` 提议 | 不自动 | 必须 | 会改变后续策略 |
| 调整治理线有限数值 | 边界内可自动 | Git Diff 复核 | 可逆、有限幅、留痕 |
| 公开仓库/真实外发 | 不自动 | 必须 | 不可逆或高影响 |

## 8. 关键业务规则

1. 工作日生产线自动化只到 `review`。
2. 发布审核和确认发布是两个不同授权。
3. 状态写入必须经 `media`，Server 和 UI 不直接改 YAML。
4. `dashboard.md` 是派生视图，不能反推业务状态。
5. 复盘和治理任务只产报告与变更提议，除明确的记账例外外不直接改 `brain/`。
6. Agent 自述、工具里程碑和子进程退出码都不是唯一成功依据；最终复读文件或 Git Diff。
7. 阻塞生产的错误必须上报给人，只写本地日志不算完成上报。
8. 课程示例不能包含企业内部信息、个人凭证、本机绝对路径或不可公开数据。

## 9. 非功能需求

### 9.1 可靠性

- 任一写命令在校验失败时零写入。
- 多文件修改须在同一事务、同一锁内完成。
- 长任务必须有超时、取消、原始日志和终态落盘。
- 单个内容文件损坏不能拖垮整个看板，需降级显示 parse error。

### 9.2 可观察性

- 页面通过 revision + SSE 感知仓库变化。
- 慢作业展示 queued、running、verifying、succeeded、failed、cancelled。
- 工具调用和输出摘要可回放，展示与判定分离。
- Check、Doctor、审计日志和治理账本可交叉验证。

### 9.3 安全

- Server 仅监听 `127.0.0.1`。
- `/api/*` 使用随机 token 鉴权。
- Server 执行 `media` 使用 `execFile` 参数数组和固定白名单，不经过 shell。
- 文件读取必须限制在仓库允许路径内，媒体访问同样鉴权。
- 真实发布不得自动登录或绕过 cookie 失效提示。

### 9.4 可移植性

- 课程参考仓不得包含 `/Users/...` 绝对路径。
- 外部工具、模型和凭证通过配置或环境变量注入。
- 课程核心方法不依赖单一 Agent 厂商。

## 10. 验收场景

### 10.1 主链路

给定一个 `status: idea` 的选题，系统能完成：

`next/promote → ideated → create → drafting → review → 人审 approved → 人工确认发布 → published → retro → retro_done`

验收必须同时核对：

- `meta.yaml` 状态与时间戳。
- `backlog.yaml` 对应条目状态和 `content_path`。
- `dashboard.md` 机器区。
- 内容产物文件。
- CLI 审计日志。
- Job 终局与原始 JSONL。
- 飞书或看板的人审记录。

### 10.2 异常链路

- 选题池为空：停产并上报，不硬造题。
- TTS 余额不足：停在 drafting，不推审核。
- 音频连续三轮质检失败：升级人审。
- `approved` 但 mp4 缺失：Doctor 阻断发布。
- cookie 失效：发布失败且不改 published。
- 同一 slug 重复启动任务：JobRunner 返回 `JOB_DUPLICATE`。
- Server 重启：可从文件真相和磁盘结果日志恢复可见性。
- 人工取消任务：子进程最终进入 cancelled，队列按单取消/全部取消语义处理。

## 11. 依赖与约束

- 本地 Node.js、npm、Git、Claude Code CLI。
- TTS、图像生成、浏览器录制、抖音上传和数据采集所需的外部工具与凭证。
- 飞书 Bot 的应用凭证和长连接权限。
- macOS launchd 配置仅是当前运行形态，公开课程需提供跨平台说明。
- 外部平台、模型 API、cookie 和第三方 Skill 都可能变化，课程必须标注验证日期。

## 12. 待拍板项

1. 训练营是否要求学员执行真实外部发布，还是以 dry-run 和模拟平台为主。
2. Web 看板是每位学员完整实现，还是部分章节只补齐指定模块。
3. 毕业项目采用个人项目还是分组项目。
4. 课程正文仓名称、可见性和许可证。
5. 工具教学中 Claude Code、Codex 和通用 Agent 原理的占比。
6. 首期班级规模、助教配置和上述成功指标的具体目标值。
