### 1.6 CLI 命令数

测法：`ls packages/cli/src/commands/*.ts` 数命令模块文件；再读 `packages/cli/src/index.ts` 的 `createProgram()` 数实际注册的 `.command(...)` 调用与其挂载的子命令。

命令**模块文件**共 **14 个**：`backlogAdd.ts backlogApply.ts backlogLs.ts backlogSweep.ts check.ts dashboardRebuild.ts doctor.ts flip.ts metricsRecord.ts next.ts nextUp.ts promote.ts publishDone.ts st.ts`。`index.ts` 里对应有 14 条 `register*()` 调用（`registerSt`…`registerMetricsRecord`，含 `registerNextUp`），这大概率是 ADR「14 个 CLI 命令」的口径来源。

但**实际可在终端敲出来的叶子命令**（即 `media <这里>`）有 **15 个**，因为 `nextUp.ts` 这一个模块内部注册了 `next-up set` 和 `next-up clear` 两个子命令（1 个模块 → 2 个叶子命令），其余模块都是 1 模块对 1 叶子命令：

`st`、`next`、`check`、`doctor`、`promote`、`publish-done`、`flip`、`backlog add`、`backlog apply`、`backlog ls`、`backlog sweep`、`dashboard rebuild`、`metrics record`、`next-up set`、`next-up clear`。

**歧义需要人定口径**：「一个 CLI 命令」算「一个命令模块文件」（14）还是算「一个可执行的叶子命令」（15）？本表两个数字都给出，不替 ADR 悄悄选一个。

### 口径已定（2026-08-24，主回话裁决）

**两个数都能用，但每次出现必须写明用的是哪一种**，不许只写「14 个命令」或「15 个命令」。

- 讲代码结构、讲这一层由哪些模块组成时，写「**14 个命令模块**」
- 讲 Agent 或人能敲出什么、讲协议表面有多大时，写「**15 个可敲的叶子命令**」

理由：这门课讲的是 CLI 作为人与 Agent 共用的协议，协议的表面积按叶子命令算才有意义（`next-up set` 和 `next-up clear` 对调用方是两件事）；但讲分层架构时读者看的是目录里有多少文件，模块数才对得上。两个视角都真实，含糊其辞才是错的。

第 0 章用的是 15（叶子命令），4.1 用的是 14（模块），**两处都要按上面的写法补上限定词**。这个歧义本身也是个小教学点：同一个系统的「大小」取决于你从哪一侧看它。

## 七、有歧义、需要人定口径的项汇总

1. **packages/logs 是否存在**：题面前提说"已知 `packages/logs` 是这种伪 package"，但本次三种方式（当前目录树、`git ls-files`、`git log --all --diff-filter=A`）均未在磁盘或 git 历史中找到 `tools/console/packages/logs` 的任何痕迹。需要人确认这个前提的依据（是否指别的仓、别的历史提交，或该目录确实已被清理但题面信息未同步）。
2. **CLI 命令怎么算一个**：按命令模块文件数算是 14 个；按实际可敲的叶子命令算是 15 个（`next-up` 一个模块产出 `set`/`clear` 两个叶子）。ADR 写的"14 个"字面上和模块数吻合，但没写清楚口径，建议改 ADR 时补一句"按命令模块文件数"或改成更准确的"15 个可执行命令"。
3. **`packages/core/src/` "总行数"是否含测试**：字面上"总行数"应含 `__test__/`（4151 行），但课程语境大概率想要纯源码口径（2148 行，与另一条"源码行数不含测试文件"的要求一致）。本表两个都给了。
4. **`pipeline/` 下"阶段契约"是否含 `daily-run.md`**：CLAUDE.md 原文把 `daily-run.md` 称为"编排入口"、与"阶段契约"并列区分，严格算不算阶段契约存在歧义。窄口径（仅 1/2/3/4）合计 161 行，宽口径（含 daily-run.md）合计 205 行。
5. **"测试文件"是否含 e2e 的 `.spec.ts`**：`*.test.ts`/`*.test.tsx` 口径下是 77 个；若把 `e2e/` 下 6 个 `.spec.ts` 也算作广义"测试文件"，总数是 83 个。
