# 扩写规范

27 篇正文已交付。这一轮给每篇补深度。

## 一、先说清楚这一轮不是什么

派工口径是「每篇扩充 30% 到 50%」。**这个百分比不是目标，是自然结果。**

直接照百分比写，拿回来的一定是注水。这不是猜测，`04-单篇写作规范.md` §9 明写不许用重复解释灌字数，§11 明写篇幅由内容定；今晚 5.2 那篇正是因为怕注水主动缩到 2842 汉字，缩对了。现在反过来给一个字数下限，等于把之前立的纪律推翻。

所以这一轮的口径是：**下面列的缺口，凡是本篇该补的都补上。补完自然会长 30% 到 50%。长不到就说明这篇本来就够厚，不许硬凑。**

判据不变，还是 §6.1 陌生人判据：新加的每一段，都要是「只有做过的人才知道」的东西。写出「谁都能写」的段落，扩写就是负收益，宁可不加。

## 二、要补的三类缺口

### 2.1 开源 skill 的实现（最大的缺口）

全课把 `web-video-presentation`、`tts-dub`、`dubbing-check`、`douyin-ideate` 这些 skill 当既有工具在用，从没教过**一个 skill 内部长什么样、为什么这么长**。

学员学完能设计流水线，但不会写一个 skill，等于少了一只手。

具体讲什么由 `08-开源skill实现盘点.md` 定（另有 agent 在产出），大致方向：

- SKILL.md 怎么组织，渐进披露怎么做，什么时候该拆 `references/`
- 判断标准怎么写成可回读的检查项，而不是一句「注意质量」
- 可执行脚本什么时候该有，脚本和文字判断的分界在哪（这条要承接 2.2 §2 已经立住的「答案有没有商量余地」判据，不要另起一套）
- 失败与重试怎么设计
- 第三方来源的部分要标清楚哪些是自己写的

### 2.2 被跳过的概念

面向的读者是工程师，但不保证熟悉 Agent 这套东西。通读时留意有没有「用了但没解释」的概念，尤其是第 1、2 章之后突然出现的。

补的时候按 §5.2：先摆问题，再上证据。不要写成术语表。

### 2.3 已有论证的下一层

有些地方结论给了，但只推了一层。往下再推一层通常比新加一节有价值。

**第一轮扩写暴露出一件事**：有专属 skill 材料的篇能自然长 30% 以上，没有的只长 10% 到 17%。差别不在这些篇不够深，在于「往下推一层」当时只写了一句话，没给方法，agent 找不到抓手。

下面五个问题逐节问一遍，问出来的都是真材料，不是水。

**一、读者读完这节会接着问什么。** 把那个问题写出来。文章答不上来的，就是该补的地方。

**二、这条判断做错了会长什么样。** 大部分小节只讲了对的做法，没给错的样子。错的样子往往比对的做法更能让人记住，而且这个仓里真摔过的跟头都登记在 `pipeline/lessons.md`，18 条，不用编。

**三、这条规则到哪儿就不适用了。** 规则被写成绝对的，读者换个场景照抄就会撞墙。ADR 第 7 节要求每个设计点都讲「代价」和「演进条件」，但各篇通常只对本篇的主结论做了，子结论没做。

**四、这个数字是怎么量出来的。** 正文引了很多体量数字和阈值，读者没法复现。测法写出来（哪条命令、数的是什么），一句话的事，但把「你信我」变成了「你自己去数」。`02-体量数字实测表.md` 里每条都有测法可抄。

**五、这里有没有一个「只有做过的人才知道」的细节被省掉了。** §6.1 陌生人判据反过来用：不是删空话，是找那些当时觉得太琐碎没写、其实正是读者会栽的地方。

**这五个问题问不出东西的节，就是真的够厚了，跳过。** 不许为了凑百分比硬答。

## 三、不许干的事

- **不许动已有的判断和结论。** 这一轮是加厚，不是重写。原有论证链不许改方向。
- **不许把后面篇目的内容提前讲。** 边界仍以 `05-跨篇概念首出索引.md` 为准，§10.1 §10.2 照旧生效。
- **不许重复解释已登记的概念。** 加厚不是重讲的借口，这是最容易破功的地方。
- **不许为了凑百分比新增并列罗列。** §6.3 两项为限照旧。
- **不许动 `<!-- ILLUST: ... -->` 占位和 `![图注](imgs/xxx.png)` 引用行。**
- **不许改已核实过的体量数字。** 数值以 `02-体量数字实测表.md` 为准。
