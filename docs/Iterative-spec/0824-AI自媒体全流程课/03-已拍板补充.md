ADR §14 待定项 1 现已拍板。课程是**训练营**，不是读物。学员跟着造，九个里程碑各自交四类证据（设计说明、Agent 任务记录、Git Diff、测试或运行结果）。

### 1.3 不用统一模板，章节动态生成

ADR §9 的八段模板**不再作为章节结构使用**，改判为素材类型清单。

原因是模板会挤压内容。27 篇套同一套小标题，读起来必然一个样，而且「1.1 Agent 是什么」这类篇目根本长不出故障注入与架构决策卡，硬套就是注水。上一版课程失败的病根之一正是模板挤掉教学内容。

新规则是**定性质不定形式**：每篇必须满足金字塔原理的四条性质与由浅至深的认知曲线，章节数量、层级与标题由本篇内容自己长出来。完整判据与生成方法见 `04-单篇写作规范.md`。

ADR §9 八段降级为写完之后的自查清单，用来检查有没有漏掉某类内容，不规定顺序，不要求全有。

## 二、对 ADR 的三处修订

以下三条按金字塔原理对 ADR 正文做修订，ADR 与本文冲突时以本文为准。

### 2.1 章内结构改为结论先行，且不套固定模板

ADR §9 的八段顺序是「事故 → 原理 → 仓库证据 → AI 实现 → 证据验收 → 故障注入 → 跨域迁移 → 决策卡」，这是从现象推到结论的归纳顺序。读者要读到第二段才知道这篇在讲什么。

修订两点。其一，每篇开篇给出**本篇结论**，一句话说清这篇要立什么，全部后续内容作为它的论据存在。其二，八段不再充当章节结构，改为素材类型自查清单。

章节由内容动态生成，判据与方法见 `04-单篇写作规范.md`。

### 2.2 第 1 章重新定位

ADR §2.1 写明目标学员**已经用过** Claude Code / Codex，§6 的 1.1 却从「Agent 是什么」讲起，两者打架。且这块内容公开资料极多，是全课差异化最低的部分，放在最前面会造成开篇流失。

修订：第 1 章从科普改为**照镜子**。开场直接摆 ADR §1.1 那八条学员现状（把 Agent 当更强的聊天机器人、看到说完成就默认完成、不知道规则该放 Prompt 还是 SOP 还是代码），让读者对号入座，再讲原理。

章名与子章节编号不变，改的是每篇的立论方式与开场。

### 2.3 篇幅不做硬性卡控

ADR 未规定字数，此处显式钉死：**不设下限也不设上限**，长度由内容定。

这一条是对更早一版课程的直接纠正。那一版把「单章不低于 3000 字」写进规格，结果是注水、待填模板与凑数引用。materials 不足时的正确动作是缩短本篇或与相邻篇合并，不是灌字数。

## 三、从旧设计线继承的三条判断

旧目录整体作废，但下列三条经过人审、在新结构下继续成立。

### 3.1 不要每章都从翻车讲起

旧实施计划把 `pipeline/lessons.md` 的 L1 到 L18 指定为各章开场的问题现场，产出的两章分别从连续六天空跑、17 条规格冲突开场，人审判定方向错了。

读者要的是这条流水线怎么跑、每一层起什么作用、要掌握什么心法、怎么用 AI 快速造出来，不是这套系统哪里出过问题。事故用来引出设计约束，不是用来当每篇的主叙事。

ADR §9 的第①段「事故或问题」按此理解执行，且已按 §2.1 降级为引子。

### 3.2 配图分两类，写作阶段只留图位

- **机制图**用 mermaid，写作 agent 直接画进正文。判据是这东西本身就是图，用文字描述要绕好几段的才画。每篇至多两张。
- **叙事插图**在写作阶段只留占位 `<!-- ILLUST: 描述 -->`，正文定稿后统一出图。占位描述要具体到能照着画。

顺序不能反。先出图再写文字，文字会被图牵着走;写完再硬塞图,图与文字互相打架。

出图链路（`technical-article-illustrator` 依赖本地 codex 配置的 gpt-image-2）**尚未验证跑通**，正文定稿前需单独验证。

### 3.3 写作红线

走 `human-writing` skill。禁破折号，冒号只允许引出人物直接原话，禁翻案腔，禁洞察路标，禁动词名词化。mermaid 围栏块内不受限。机器生成的文案（如 `dashboard.ts` 渲染出的 `（空——check 无警报）`）不受限，改了会与生成器输出对不上。
