## 六、Prompt 输入真实性（本课特别检查项，优先看这一节）

按严重程度排序。

1. 【最严重】3.1节的 Prompt 块（第90到99行）要求"逐条实现判定逻辑，接到已有的规则计算模块里"。按第14课学员产物清单，`check` 命令本身明确写着"留到第 15 课"，也就是到14课结束，读者手上并不确定存在一个独立于 `check` 命令、已经跑通的"规则计算模块"。这条 Prompt 把这个模块当成既定事实塞给 AI，读者没有任何依据核实自己手上真有这个东西；如果 AI 照着 Prompt 去找一个不存在的模块，读者不知道该怎么应对。

2. 3.2节末尾（第119行）临时引入"陈旧锁"细节：锁文件记录持锁者和时间戳、30秒判定阈值、抢占前先打印提醒。这段内容从未出现在第2节任何一条 Prompt 里（第2节的 Prompt 只列了"拿锁、算写计划、支持 --dry-run、原子落盘、写审计记录"五项，没提陈旧锁判定），也没有注明这是第14课已经做好的还是这一课顺带补的。读者读到这里既不知道自己手上有没有这个功能，也没有一条 Prompt 教他实现或验证它。这个精确到"30秒"的细节，读起来像是从参考实现里直接搬过来的，不像是读者自己执行方案里写出来的东西。

3. 第2.1节反复断言"核心的引擎实现只有一份，第14课已经把它做出来了"（第29行），2.1节的 Prompt 块（第35到47行）也要求"接进已有的事务引擎（拿锁、算写计划、支持 --dry-run、原子落盘、写审计记录）"。第14课学员产物清单里，写命令只完成了 `promote` 和 `publish-done` 两条，并没有独立列出一个已经从这两条命令里抽出来、可以被其它命令直接"接入"的公共事务引擎模块。草稿把"这个公共引擎已经存在且可复用"当成不需要证明的既定事实，读者没法从自己手上的东西反向确认这句话是否成立。

4. 2.1节的 Prompt 块开头写"读 docs/spec/media/02-执行方案.md 第2节里…"。读者在第13课确实已经写出这份执行方案（清单已确认，属于合法引用），但"第2节"是一个具体的章节编号断言。执行方案模板本身只被描述到"四节"的粒度，没有规定每节具体讲什么、编号怎么对应，每个学员自己写的执行方案章节顺序未必一致。读者复制这条 Prompt 时，如果自己文件里第2节不是这七条命令的四件套，第一步就会卡住。

## 三、逻辑断裂

1. 【最严重】命令总数算术对不上。第5节总结"五条读命令加九条写命令，十四条全部能用"（第192行）。但第2节的表格和正文明确把 `next-up` 算作"剩余写命令"七条之一（第15、23行："flip、next-up、backlog add/sweep/apply、metrics record、dashboard rebuild，共七条"），写命令合计 2（`promote`/`publish-done`）加 7 等于 9，跟"九条"吻合；可读命令这边，第14课已经跑通的 `st`/`next`/`backlog ls` 三条，加上这一课新补的 `check`，只有四条，凑不出"五条"。草稿没有交代第五条读命令是谁，前后数字自相矛盾。

3. 陈旧锁30秒判定的细节（第119行）突然出现在3.2节退出码讨论的末尾，前面在讲退出码 3 和退出码 4 的含义，后面直接跳到锁文件怎么记时间戳、30秒阈值怎么判定，中间没有过渡，读起来像是话题被岔开了，跟上下文承接不上。

## 五、装（对照禁令清单逐类扫）

1. 【最严重】排比三连加轻度金句收尾。第9行："命令没写完，这行记录压根不会产生；规则没写完，产生了也没人核对；手改没收敛，产生的干脆是另一条谁都不知道的路。"三个"X没Y，Z"分句用分号并列，第三句还刻意压出"谁都不知道的路"这种带一点文学腔的收尾，命中禁令里的排比三连。而且这句话出现在全文第一节第一段，读者一开篇就会撞见。

2."不是……是……"转折拿腔句式变形，至少三处：
   - 第33行："事务这层麻烦不是为了应付某一条命令，是为了保证审计记录不会漏掉任何一条。"
   - 第73行："八条规则不是随手拍出来的，每一条对应一种真实会发生的漂移。"

3."看似/看起来……其实"变形，第9行："这三件事看起来不搭界，其实是同一件事的三个侧面。"

4. 轻度导游腔候选，第5行"先把话说在前头"，跟禁令里"先说明一下"的话术很接近，是在向读者预告即将要讲的重点，而不是直接给内容。

5. 结尾反问句（第196行"可你怎么证明写路径真的唯一，而不是自己以为唯一？"）带一点悬念钓鱼式收尾的意味，把还没验证完的事留成一句问句吊住读者，跟"预告下一课"的导游腔性质相近。
