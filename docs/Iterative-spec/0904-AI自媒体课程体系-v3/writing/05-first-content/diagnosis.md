# 读者诊断（Step 5，sonnet subagent）

读者画像：会用 Claude Code、没做过自动化流水线、手上没有参考仓库、只有前几课自己做出来的东西。附带 inventory.md 第 04 课那一节作为「本课输入是否齐备」的判据。

## 1. 读不懂
- 第 149-158 行附近："旧版讲义里这条命令只写了两级 `..`"，读者从未见过"旧版讲义"，这是编辑遗留痕迹，对读者无意义。

## 2. 太啰唆
- 小结表格与结尾段落重复：正文已交代"稿子你审过、网页你验收过、配音你听过、封面你核过"，小结表格又用"谁产/你验什么"复述一遍。

## 3. 逻辑断裂
- "它走的是一个坏掉的命令行工具，多音字注音参数传的格式和接口要的对不上"，这个结论没有点出处，同类断言（L15、L1）都点了仓库依据，这一条没有，标准不一致。

## 4. AI 味儿
- 每节结尾套同一种"播报式"过渡：第 1 节"网页做完了……下一步把它录成一条真正的视频"、第 2 节"无声成片有了……接下来把声音接上"、第 3 节"配音合上了……最后补一张封面"，三处结构一致，读起来像进度条。

## 5. 哪里在装
- "走完你手上会多出四样东西"，与禁令清单里点名的反例"读完你会拿到两样东西"字面撞车，是交付预告式导游腔。
- "是下一课要接着问的事"，给下一课卖关子式预告。
- "稿子第一句你审过，第一章网页你验收过，配音你听过，封面比例你核过"，四项并列对称句式，排比连缀。
- "第一次跑流水线的人十有八九会在这里卡一下"，读者还没报错就替他预判会出错，猜心句变形。
- 多处用直角引号给普通词语加强调（"上一集""前面说过""淡入""从左滑入""章/步"），违反标点规则。

## 6. 【本课额外维度】输入是否齐备
- 第 3 节两条 Prompt 都要求 AI 读 `build/audio-segments.json`，但这个文件从未在第 1、2 节的产出清单里出现过。第 1 节交代的产出是 `script.md`、`outline.md`、`build/` 工程和分章代码，Checkpoint Plan 五件事表里也没提过分段音频清单。读者读到第 3 节时不知道这个文件从哪来、是谁生成的，是全文最严重的一处输入缺口。

## 处理方式（对应写进 polish-report.md）
六条全部采纳修改，第 6 条（输入缺口）是最高优先级：在第 1 节 Prompt 后补一句交代 `npm run extract-narrations` 产出 `audio-segments.json`，让第 3 节引用的文件先在正文里"出场"。
