# 润色报告 · 第 04 课「账号大脑：五份文件怎么写」

对象：`draft.md` → `final.md`。诊断来源：`diagnosis.md`（sonnet subagent 读者诊断，读者画像=会用 Claude Code、没做过自动化流水线、手上没有参考仓库，只有前几课自己做出的东西；额外查了本课特有的第六维度：每条 Prompt 块的输入是不是读者手上真有的东西）。

## 一、按诊断逐条处理

### 1. 读不懂

1. 第 3 节 benchmarks，“空置二十多天”那句叙述主语不明（读者当下没发过内容，却读到一段已经发生、带具体日期的往事，分不清是谁的账号）。已改：明确点出这是“这条流水线本来跑着的参考账号”的真实记录，并在段末补一句“你的账号现在一条内容都还没发，这笔代价此刻还没轮到你”，把参考账号的历史和读者当下的处境分开说清楚。
2. 第 2 节 Layer B 的判据句里，“它们同时给选题归类当标签”这个功能没有铺垫就冒出来，且和“宽词也留着”两头话没给出边界。已改：拆成“检索之外，还给选题结果打标签分类，所以宽词不必删光；但一层全是宽词，检索这个用途就落空了”，先给功能再给边界。
3. 第 2 节，`douyin-ideate` 首次出现没有解释这是什么、读者现在有没有它。已改：加一句“现在还没有它”，明确这是第 23 课才会造的技能，本课只是先把词表骨架留好。
4. 第 1 节 persona 反例行，“前面几十条已经这么念完了”指代不明。已改成“前面几十条口播稿已经这么念完了”。

### 2. 太啰唆

1. “技术深度和流量型六比四”对“以深度为主兼顾流量”这组正反例，开篇立尺子（第 7 行）、positioning 规格表（第 17 行）、第 2 节末尾的“不许出现判不了的词”清单示例（原第 111-115 行）三处原样重复。已改：第三处换成 style-guide 的时长例子（“口播 30 到 90 秒”对“节奏明快”），既满足任务卡要求的“正例/反例各一条”交付物，又不再是纯重述。
2. 三处小节收尾句（原第 61、116、140 行）分别和紧接的下一节标题内容基本同义反复。已改：三处分别重写——第 1 节末尾改成“把判断变成能照做的动作”这个新框架，不再逐字复述“怎么说话、素材从哪来”；第 2 节末尾精简去掉重复动词；第 3 节末尾改成“配音要用的参数放在哪”，不再复述标题里的“语速、音色、多音字规则”三个词。

### 3. 逻辑断裂

- benchmarks 一节前后矛盾（本节开头说读者“还没发过内容”，紧接着又用具体日期讲一段已经发生的往事）。处理方式同上“读不懂”第 1 条，两处问题共用同一处修改：把参考账号的历史和读者的账号分开点名。

### 4. AI 味儿

- 五处“审 N 点 + 多半是 + 纠正动作”的固定骨架读起来像同一个模具灌出来的。部分改，部分保留理由如下：
  - 已改：变换五处的开头动词和句子顺序，不再统一用“拿到结果审 N 点”起句——positioning 保留“选定之后审三件事”，persona 改成先说排障再说检查项，benchmarks 改成“回头看三件事”，tts 改成“落盘之后核三处”，四处开头各不相同。
  - 未改的部分：每一步“为什么要这一步 / 让 AI 做什么 / 审两三点 / 出错多半是什么”这个四段结构本身没有拆掉。这是 `00-写作背景包.md` 第 5 节明文规定的全书统一步骤形状（“每步四段：为什么要这一步；让 AI 做什么；拿到结果审哪两三点；出错多半是什么”），不是本课自己发明的模板，拆掉会和全书其余课的骨架对不上，所以只做了表面措辞的变化，没有拆结构。

### 5. 装

- 未命中禁令清单里的具体违规写法。诊断额外提到 benchmarks 段落回避“我”字但功能上接近作者夹带个人经历，这一条和“逻辑断裂”共用同一处修改：明确点名“参考账号”之后，这段文字的身份是案例引用，不再是没挑明的个人经历。

### 6. Prompt 输入是否读者手上真有（本课新增维度）

1. `harness/logs/2026-07-17-retro.md` 引用了读者清单之外的东西，且未交代来源。已改：明确这份报告是“参考账号”留下的，不是读者自己此刻就有的文件；文中不要求读者去打开这份文件，只是把它当证据出处标注，路径本身在仓库里可以 grep 到。
2. `douyin-ideate` 未标注读者现在没有这个技能。已改（与第 1 项“读不懂”第 3 条为同一处修改）。
3. 六个 Prompt 块本身：诊断确认全部合格，均只依赖读者已有的材料或本课内先造出的文件（例如第 1 节生成的 `brain/positioning.md` 供第 2 节的 sources Prompt 引用），未改动。
4. 诊断之外自查发现一处同类问题：第 4 节原文说 `voice_id` "只能从配音服务商控制台复制真实值"，核对 `.claude/skills/tts-dub/SKILL.md` 后发现实际取值方式是跑 `list-voices.mjs` 脚本查账户音色，而 `tts-dub` 这个 skill 要到第 05 课才交付给读者，本课如果点名这条命令，读者手上还没有它。已改成"这个编号要连上配音服务商的账户去查，编不出来的就先留一个占位字符串，等下一课装上配音工具再回来填"，不点名读者此刻用不了的命令，只交代下一课会补上。
