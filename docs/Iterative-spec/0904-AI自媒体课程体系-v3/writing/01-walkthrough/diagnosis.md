# 诊断清单

## 1. 哪里读不懂

- **位置**：第43行"站点之间靠文件接力"、第120行"其余的动作靠文件接力，站点之间靠文件接力"，对照全文的"动作"（第1、3、7、9等多处）、第4节 Prompt 里的"阶段"（"第一部分一张表：阶段、契约文件、输入、输出""节点是阶段"）
 **问题类型**：指代不明 / 术语不统一
 **为什么是问题**：同一个概念（选题、取题、创作、出审、发布这五步）先后被叫作"动作""站点""阶段"，第120行甚至在同一句里先说"动作"又说"站点"，没有任何一处显式说明这几个词是同一件事，读者容易以为"站点"是另外一个新概念。

- **位置**：第21行"candidate 起名字这件事也发生在这一步"
 **问题类型**：概念没解释就用了
 **为什么是问题**：前文一直用中文"候选"指代同一事物，这里突然切成英文 candidate，没有说明是不是同一个词的另一种叫法，也没有解释为什么换。

- **位置**：第51行"过审说的是这条内容内容上合格"
 **问题类型**：表述卡壳（疑似笔误）
 **为什么是问题**："内容内容"连续重复，读到这里会卡一下，分不清是笔误还是刻意的断句写法。

- **位置**：全文反复使用"契约文件"这个词（标题起、第9、11、13、70行等）
 **问题类型**：概念没有正面解释
 **为什么是问题**：全文从未有一句话正面说"契约是什么"，只能靠表格里"契约在哪定"这一列的文件路径反推，对手上什么背景都没有的读者不够友好。

- **位置**：第70行"人审是另一张单子，六项：事实、时效、定位、语气、合规、观感"
 **问题类型**：概念没解释就用了
 **为什么是问题**：这六个词（尤其"时效""定位""语气""观感"）具体审核时看什么，全文没有再展开，和后面七项脚本判据每项都配了"查什么"的说明形成反差，读完等于没读。

## 2. 哪里太啰唆

- **位置**：第43行"站点之间靠文件接力，人只在没写清楚的地方点头"，与第120行"其余的动作靠文件接力，站点之间靠文件接力，人只在没写清楚的地方点头"
 **问题类型**：同一句话说了两遍
 **为什么是问题**：这句话在第43行和第120行一字不差地重复出现；第120行内部还先说"动作靠文件接力"又说"站点之间靠文件接力"，同一句话里又把同一个意思讲了一遍。

- **位置**：第66行"三类位置里，只有第二类需要真的停住等答案……真正意义上的闸门只有出审和确认发布两处"
 **问题类型**：对表格内容的复述
 **为什么是问题**：紧跟在第55到60行的表格之后，把表格已经列清楚的三类逐条又用文字念了一遍，只有最后一句是新信息，前面部分可以更紧。

## 3. 哪里逻辑断裂

- **位置**：第55到60行表格把"异常呼叫"列为四个"位置"之一，第118至120行（第5节）却说"人固定出现的位置只有三个：出审、确认发布，加一个提前留条件的选题池指针"
 **问题类型**：前后矛盾
 **为什么是问题**：表格明确把异常呼叫当成"位置"给了完整一行（触发/决定/不管会怎样），第5节的结论却把它整个排除在"位置"计数之外，且没有一句话解释为什么它不算数，读者会疑惑到底是三个还是四个。

- **位置**：第70行"人审是另一张单子，六项：事实、时效、定位、语气、合规、观感"
 **问题类型**：结论没有依据
 **为什么是问题**：七项脚本判据每一项都注明"第几课定、第几课造"，说明有出处；六项人审清单直接列出来就完了，没说这六项定义在哪份契约、谁定的，跟全文反复强调的"写死在契约文件里"这条原则不对称。

- **位置**：第84行"机器没有听觉，几个词的实际读法有没有错，没经过耳朵核实，这一条留给出审时的人重点听"
 **问题类型**：承接不上
 **为什么是问题**："读法对不对"这个检查点既不在声画一致（逐字比对文本）里，也不在七项判据表的任何一行里，说明七项之外其实还有没被覆盖的东西，但第86行紧接着说"如果七项一项没查完就把成片推给人"，把七项当成一个完整闭环来论证分工，两处没有互相呼应。

## 4. 哪里有 AI 味儿

- **位置**：第1、2、3节
 **问题类型**：结构模板感
 **为什么是问题**：三节都是同一个模子——先给分类或判据，接一张表，再举一个具体例子，最后收一句总结或过渡句，三节严格重复这个套路，读起来像按同一个生成模板填空。

- **位置**：第2节"第一类……第二类……第三类"、第4节"第一点……第二点……第三点"
 **问题类型**：句式套路
 **为什么是问题**：两处用几乎一样的枚举腔调铺陈，读起来是同一种分点习惯的复用，略显程式化。

## 5. 哪里在装

**导游腔（交代写作安排、预告交付）**
- 第5行"这一课不装工具，不写一行代码，先把这条线从头到尾摆清楚"——直接交代本课写作范围和安排。
- 第91至92行"这一课要落的，是两样东西：一张端到端流程图，一份人出现点清单"——和禁令清单里"读完你会拿到两样东西"几乎是同一个句式。
- 第43行"接下来两节，先看这个点头的地方一共有几处"——预告下文章节安排。
- 第124行结尾"流程图和人出现点清单有了，可你手上一个工具都没有。这些环节要跑起来，机器上得先装齐哪些东西？"——用悬念留白给下一课打钩子，类似"还差最后一块拼图"式的预告。

**金句和倒装收束 / 对仗顺口溜**
- 第51行段尾"发布这个动作做完了收不回来"——短句定论式收尾，带一定金句感。
- 第62行"日志是给事后查的，当天没产出这件事，得当天有人知道"——"当天……当天……"的对仗式收尾。

**猜心句**：无
**俯视腔**：无
**作者加戏**：无
**表演式标题**：无（各节标题均为内容描述，未见悬念钓鱼、反常识甩脸、数字党等）
**黑话堆砌**：无（"slug""dry-run"等术语均在正文当场解释）

## 6. Prompt 及全文其它建议的输入检查

- **位置**：第4节 Prompt 中"第二部分照这张表画一张 mermaid flowchart，节点是阶段，箭头标交接的文件"
 **问题**：这一条要求给流程图的箭头标出"交接的文件"名字，但第92行已经明说"你手上还没有契约文件可以参考"，读者此刻根本没有任何真实文件名可用。第一部分的表格明确写了"我没说到的格子写待定，不要替我猜"这个兜底，但这条兜底只挂在"第一部分"，第二部分的"箭头标交接的文件"没有同样的豁免，容易让 AI 为了把图画完整而编出几个看着像真的、实际是编的文件名。

- **位置**：第4节 Prompt 中"另外，凡是要花钱、调用外部服务、有重试上限的步骤，它出问题时提醒我谁会知道"
 **问题**（次要，置信度较低）：这一条要求读者说清自己流水线里哪些步骤花钱、调外部服务、有重试上限，而这门课第一课的读者还没选定任何具体服务商或技术方案，只能靠猜测哪些环节"大概率"会花钱，这一点和"我打算这样切""人会在这几个位置出现"这两条纯靠自己口述设计意图不同，前者问的是设计意图，这一条问的是还没做出来的技术选型细节。

全文其余处提到"第 07/08/03/04/05/17/18/19/21 课"，性质是对课程后续章节的前瞻指路，不是要求读者当下去读、去装、去跑什么东西，不计入本项问题。
