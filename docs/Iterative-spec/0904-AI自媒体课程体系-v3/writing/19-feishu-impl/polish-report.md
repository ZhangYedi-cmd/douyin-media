# 润色报告：第 19 课 飞书实现与按钮回流

## 一、诊断问题的逐条处理

诊断见 `diagnosis.md`，subagent 以本课系列铁律（读者手上没有参考仓库，Prompt 输入必须是读者已经真实拥有的东西）为额外维度，逐条核对了 draft.md。

### 维度 3：逻辑断裂

1. **审核卡两个按钮 vs 三个按钮的矛盾（已改）**。draft.md 第 2 节把"通过 / 打回并自动重做 / 打回并挂待办"当三个平级按钮塞进同一张审核卡的映射表，和开篇"每张卡最多两个按钮"的决策、第 1 节 Prompt 里"只放通过和打回两个按钮"直接冲突。final.md 重写第 2 节：明确审核卡只有通过、打回两个按钮；打回按钮点下去先不改状态，弹出第二张打回原因卡，卡上再放两个按钮（打回并自动重做、打回并挂待办），这两个按钮才真正各自接一条出边。映射表拆成两张卡四行，标清"卡片"这一列。
2. **挂待办原因是否强制的矛盾（已改）**。原稿一处说"原因写完才真的触发状态翻转"（暗示按钮被禁用直到填完），另一处 Prompt 说"原因为空就用占位说明代替"，自相矛盾。final.md 统一成一种说法：按钮从头到尾都能点，"要求填原因"落到实现上是指改状态命令拿到的参数不能是空字符串，人没写就用占位说明顶替，不是按钮本身被禁用。

### 维度 6：Prompt 合法性（本课特有铁律）

1. **"照 02-执行方案.md 里按钮映射那一条"（已改）**。第 18 课材料清单里 02-执行方案.md 只覆盖四个决策点，不含按钮映射，这条映射表是第 19 课才第一次给出的内容。final.md 改写 Prompt 的构造方式：先让 AI 把按钮映射和熔断上限这两条决策，依据 state.ts 的三条出边和"每张卡最多两个按钮"这条已有决策，补进读者自己的 01-ADR.md，再照这条新补的决策去实现，不再让 AI"照"一份实际上不存在的条款。同时把开篇输入清单里"02-执行方案.md（……按钮映射……）"这处误写也删掉了，避免正文自相矛盾。
2. **"达到 01-ADR.md 定的熔断上限"（已改）**。同上，随按钮映射一并纳入"先补决策再实现"的 Prompt 结构里，正文明说这是这一课第一次定下来的东西，参考流水线的 `REWORK_LIMIT = 2` 只作为起步值参考。
3. **`3-review.md` 指代不清（已改）**。加了一句澄清：这是每条内容自己目录下的留痕文件，来自 `content/_template/` 六份模板之一，跟全局阶段契约 `pipeline/3-review.md` 是两个文件，名字撞了不是同一样东西。
4. **验证要求"确认发布卡"但没有任何 Prompt 要求实现它（已改）**。这是任务卡大纲第 4 节本身写定的验证动作，不能删。改成在第 2 节补一段：通过按钮触发之后，除了改状态还要另发一张确认发布卡，具体物料留给下一课，这一课的实现只要求这个动作真的发生，内容先给占位提示。这样第 4 节的验证点就有了对应的实现依据。
