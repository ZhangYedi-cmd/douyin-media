# 读稿诊断报告

（说明：诊断者按第 18 课结束时的"学员手头清单"作为唯一可验证基线，逐条核对。以下按严重程度排序，六维度全覆盖。）

## 维度 3：逻辑断裂（最严重，放在最前面因为它会直接阻断实操）

1. **审核卡到底是两个按钮还是三个按钮，全文自相矛盾。**
   - 开篇定的四条决策里明确写："三张卡分步、每张卡最多两个按钮"（第 3 段）。
   - 第 1 节的 Prompt 也照此执行："最后发审核卡，卡片上只放"通过"和"打回"两个按钮"（第 1 节 Prompt 第 3 条）。
   - 但第 2 节的表格和 Prompt 立刻把"通过 / 打回并自动重做 / 打回并挂待办"当成三个平级按钮来分配出边和 value（表格 + 第 2 节 Prompt："把三个按钮接到 review 状态的三条出边上"）。
   - 直到第 2 节正文才提到参考实现其实是"打回按钮点下去先弹出一张带表单的卡……两个提交按钮分别对应重做和挂待办"——也就是说"打回并自动重做""打回并挂待办"实际是第二张表单卡上的按钮，不是审核卡本身的按钮。但这个两级卡片结构从未在 Prompt 里交代给要下指令实现的读者，读者拿着第 2 节的 Prompt 去写代码，完全不知道自己是该在审核卡上直接放 3 个按钮（违反"最多两个按钮"的决策），还是要多做一张表单卡（这一步没人告诉他要做）。这是全文最大的实操断点。

2. **"挂待办必须填原因"和"原因为空也要落状态"自相矛盾。**
   - 第 2 节正文："打回挂待办这个按钮不能是点一下就直接生效，得先弹一张带输入框的卡让人写清楚打回的原因，原因写完才真的触发状态翻转"，明确说原因是硬性前置条件。
   - 第 2 节 Prompt 却写："打回并挂待办 → review 到 rejected，必须先收到人填的原因，原因为空就用一个占位说明代替，不能因为没填就不落状态。"又说空着也能过，用占位符顶替。
   - 表格里这一行"是否要求填原因"标的是"是"，跟 Prompt 里"空着也行"的实际行为不一致。三处对"是否强制"的表述互相打架。

## 维度 6：Prompt / 验证动作合法性核查（本课特有铁律，逐条给引用）

**(a) 类问题：要求读者用一个他实际上还没有的东西**

1. 第 2 节 Prompt："照我 docs/spec/feishu-gate/02-执行方案.md 里按钮映射那一条……"——第 18 课结束时清单里，02-执行方案.md 只对应四个决策点，"按钮映射"不在其中。这张按钮到出边的映射表恰恰是本课第 2 节才第一次给出，却让读者去自己文件里"照"一条实际上不存在的条款。
2. 第 2 节 Prompt："达到我 01-ADR.md 定的熔断上限就不再重做"——熔断上限不在第 18 课四个决策点之列，读者的 01-ADR.md 里大概率没有这一条。
3. 第 2、4 节反复要求核对 `3-review.md` 的留痕，这份文件的性质（是每条内容自己的留痕文件，还是全局阶段契约）全文没有交代清楚，容易和 `pipeline/3-review.md` 混淆。
4. 第 4 节验证路径一第 4 步要求核对"确认发布卡"有没有收到，但全文任何一段 Prompt 都没有指示读者实现"审核通过后自动推送确认发布卡"这个动作。

**(b) 类问题：把参考仓库的细节当成读者自己文件里已经写好的内容**

未发现明显问题，`tools/feishu-bot/` 下的代码引用都清楚标了"参考流水线的做法是……"。

## 维度 1：读不懂

1. 两个按钮 vs 三个按钮的矛盾同时是一处严重跳步。
2. `3-review.md` 前后指代不清，容易和 `pipeline/3-review.md` 撞名混淆。
3. 表格里的 toast 一词没有解释，第一次出现没有铺垫。

## 维度 2：太啰嗦

1. "第 10 课三轮熔断和本课熔断数字无关"这一点在同一节内说了四遍，密度偏高。
2. 开篇记忆锚点句和第 4 节开头基本是同一句话的复述，可以只留一处把话说透。

## 维度 4：AI 味儿

1. 三处节尾过渡句句式完全一致（"X了，Y要……"模具感）。
2. 开篇记忆锚点段"是不是真……了"四个分句逗号硬拉成一句，是排比变体。
3. 收尾段五个分句逗号硬拉成一句，是收尾清单式排比。

## 维度 5：哪里在装

1. "这不是这一步的服务本身的问题，是下一节要讲的常驻通道压根没在跑"是"不是……是……"转折拿腔句式的变体。
2. "失败了要说失败，不能糊过去"是为造收束感刻意压出的对仗短句。
3. "这是下一课要接着做的事"带交付预告腔。

## 总结

维度 3（逻辑断裂）和维度 6（Prompt 合法性）是硬伤，尤其是两个按钮变三个按钮的矛盾、以及确认发布卡从未被要求实现却被拿来验证，会让照做的读者在第 2 节和第 4 节直接卡住。维度 4/5 集中在三处重复过渡句和两处排比长句。维度 1、2 相对次要。
