## 3. 哪里逻辑断裂

**3.1（最严重，经核对第 27、28 课原文确认）开篇把第 27 课的交付物错误归到第 28 课名下，与本文档自己第 1.3 节的表格自相矛盾。**
- 核对结论：读 API 全通（六个快照接口+file/asset/health+SSE 推送 revision）和写 API 全通（四条快写+三条慢作业）明确是第 27 课交付；第 28 课只做 AppShell、两个数据 hook、六页拼装、单端口整合与验收。草稿开篇第一段把第 27 课的成果错记成第 28 课交付，而自己 1.3 节表格给出的归属是对的（第 27 行讲读写 API，第 28 行讲整站落地）。这会误导读者按"回第几课"的方法论去定位错误的课号。

**3.2（中等）第 3 节在要求 AI 逐环节判定之前，先给出了一个未经论证的具体结论（"当前建出来的版本落在中段偏工作流的位置"），与全文反复强调的"结论要有依据、不能替读者拍板"相矛盾。**

**3.3（轻微，未能核实，已排查明确为笔误）"第 01 课七项判据里事实、语气、定位这三项现在只归人判"这句话把两份不同的清单搞混了。核对结果：第 01 课七项终检闸里归人判的三项其实是钩子冷启动、事实与合规、封面，不是"事实、语气、定位"；"事实、时效、定位、语气、合规、观感"六项是第 06 课提到的参考仓库出审清单例子，不是学员自己第 01 课的七项终检闸。此处属于事实错误，已在 final.md 修正。**
