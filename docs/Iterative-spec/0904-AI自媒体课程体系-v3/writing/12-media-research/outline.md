## 1. 开篇：这一课不产一行代码
核心判断：调研、讨论选型、决策三步只产文档，AI 这一课不写任何实现代码；这一课判断的是选哪条路，不是路怎么修。
支撑材料：analyzed.md「承接源缺失，按台账处理」条目（第 11 课结尾原文与第 12 课接续点）；第 10 课成稿结尾「手改了一堆 meta.yaml」原句，作为学员真实痛感的引子；`docs/00-toolchain.md` 与前 11 课已交付的六步模板四件套（学员手上已有的东西，不重述参考仓库细节）。
交付物：一张四组互斥路线清单（入口形态、YAML 写法、并发保护、派生视图），每组一句话点出互斥在哪。
二级标题：不分。
收尾交接：四组路线摆出来了，逐组进入调研。

## 2. 调研：四组路线逐组摊开
核心判断：四组互斥路线各自独立，但用同一张固定四列对比表（方案 / 适用前提 / 代价 / 已知失败模式），调研阶段不下结论，只把每个候选的适用前提、代价、已知失败模式摆齐。
支撑材料：`2026-08-18-流水线CLI技术方案.md`（6 个写状态入口的历史事故、§4 YAML 注释保留硬约束、§7 dashboard 机器区改造、§11 v0.2 文件锁与审计）；`01-CLI执行方案.md`（写命令事务序、E_LOCKED 不排队、`media dashboard rebuild` 手动兜底、server 包边界不 import writer.ts）；`tools/console/packages/core/src/yaml-edit.ts` 头注释（25/25 往返测试全部不一致的真实数字）、`lock.ts`（咨询锁与 30 秒陈旧阈值）、`atomic.ts`（temp-then-rename 防半写文件）；`v1-10-架构抉择-CLI对比MCP.md`（懒加载发现、退出码确定性，仅取判据不取结论）。
交付物：一条「先出候选清单」的 Prompt（复用第 11 课调研模板的形状）+ 四张对比表（方案 / 适用前提 / 代价 / 已知失败模式）；入口形态这组额外一句「为什么长成命令行」的判据（懒加载、退出码比协议层报错更适合 AI 调）。
二级标题：2.1 入口形态：CLI / MCP / 内部 HTTP / 散脚本；2.2 YAML 写法：点位编辑 vs 整篇 dump；2.3 并发保护：文件锁 / 不做 / 队列；2.4 派生视图：同事务重生成 vs 另起进程。
收尾交接：四张表都摆齐了，进入讨论选型，逼每个候选自己交代弱点。

## 3. 讨论选型：四组各自的辩护人
核心判断：同一条辩护式 Prompt 换掉候选清单，对四组路线各跑一遍；AI 说不出某个方案的失败模式，就是在顺着倾向写，要换个问法重问。
支撑材料：`spec-lesson-standard.md`「讨论选型节」固定形状（成立前提 / 代价 / 主动交代失败模式 / 不许下结论）；第 2 节四张对比表里已经摆出的失败模式，作为「AI 说不出来就是在回避」的对照基准。
交付物：第 11 课讨论选型 Prompt 的复用说明（只需替换候选清单和适用场景两处占位）+ 四组各自的一段辩护结论摘录（每组挑一到两句最关键的失败模式自白，不重复贴四遍完整表格）。
二级标题：不分。
收尾交接：四组的弱点都被自己交代清楚了，可以拍板了，进入决策。
