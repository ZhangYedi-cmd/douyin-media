## 1. 四代演进，一刀切法：验证结果回给谁
核心判断: AI 工具从对话框到自愈循环一路演进，唯一决定它能不能自己纠错的，是验证结果最后回给谁，不是换了哪种框架或者模型能力强不强。
支撑材料: analyzed.md 条目 5（v1-02 旧稿四代对照表骨架，仅取其分代与信号流向框架，第三代改名护栏代并加撞名括注）、条目 3（承接台账 05/06 行，成片"还行"这句判断此刻回给的是学员自己）
交付物: 四代对照表（世代 / 信号回给谁 / 人要不要盯盘，四行）
二级标题: none
收尾交接: 四代演进说的是信号回给谁这一件事，落到具体流水线上，信号其实有四个可能落点，下一节把它们摆开。

## 2. 四个位置：信号能落在哪
核心判断: 验证信号只有四个可能的终点：人、机器、文档、没人管，其中文档如果没人主动去读，实际上就等于没人管，这是最容易被忽略的一档。
支撑材料: analyzed.md 条目 6（mini-v3-06 的流向判据：说得出文件名是流向文档，说不出来是流向没人管）、条目 7/8（`pipeline/2-create.md` 终检闸七组、`pipeline/3-review.md` 六项人审清单，作为"流向人""流向文档"这两格在真实仓库里的实物例子，仅供我核判据用，不作为学员输入）
交付物: 四位置模型表（位置 / 信号长什么样 / 谁负责推进 / 风险，四行）
二级标题: none
收尾交接: 四个位置摆清楚了，下一节把学员自己流水线上的检查点一条条填进这张表。

## 3. 把自己的契约摊开填表
核心判断: 每个检查点该落在哪个位置不是抄来的，是从学员自己第 03 课写的 `pipeline/` 契约里一条条找出来的，抄参考仓库的表格填不出自己的判断。
支撑材料: analyzed.md 条目 4（inventory 第 05 课节，学员手上确实有 `pipeline/1-ideate.md`、`2-create.md`、`3-review.md`、`4-publish.md`、`daily-run.md` 五份契约）、条目 11（第 03 课成稿，学员的契约骨架只有输入/输出/状态翻转/闸口四件事，体量比真实仓库短得多，这决定 Prompt 不能预设学员契约里已经细到脚本级）
交付物: Prompt 块（读学员自己的 `pipeline/` 五份契约，逐条列出检查点，建议目标位置，人确认第 4 列），外加拿到结果后人要核的两三点、出错多半是什么
二级标题: none
收尾交接: 表填完了，看一眼哪些格子标了该交给机器。

## 4. 该交给机器的格子，先标出来
核心判断: 这一课不解决怎么造检测脚本，只解决哪些格子该交给机器这个判断；机器要接手，判据得先能写成一条不看语境就能算出来的是非题，写不成的现在没有机器方案。
支撑材料: analyzed.md 条目 9（真实仓库 `dubbing-check` 六个脚本三比三的真实分法，作为"同一批检查天然分两半"的旁证，明确标注这是仓库例子不是学员此刻能查到的东西）、条目 1（背景包"一课一产物"口径，第 4 节不新增产物，收束填表结果）
交付物: 无新增产物；收束判据：给出一条可判的标准（这一格的不通过能不能写成退出码，写不成的留在流向人/流向文档），列出"该交给机器"的格子清单当例子
二级标题: none
收尾交接: 验证该由机器接的那些格子已经标出来了，机器要接得先有信号，这些信号从哪来（承台账第 07 行开头）。
