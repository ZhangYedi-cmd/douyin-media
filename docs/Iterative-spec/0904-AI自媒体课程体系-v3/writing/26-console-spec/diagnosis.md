# 读者诊断：26-console-spec/draft.md

派发对象：general-purpose subagent（model: sonnet），只读 draft.md 全文诊断，不给大纲和写作过程，附禁令清单原样作为第 5 项判定标准，另加本课专属第 6 项检查。

## 诊断结论（原样保留）

按严重程度从高到低排列，问题类型标注对应检查维度（1 读不懂 / 2 啰嗦 / 3 逻辑断裂 / 4 AI 味 / 5 装 / 6 本课额外项）。

1. 位置：第 1 节，"这两页对应的是审核台和治理任务详情两个能力，都是下一期页面，参考仓库到现在也没有实现它们背后的后端"。问题类型：第 6 项（严重）。前几行用的是"本仓库现在没有对应后端"，三行之后换成"参考仓库"，两个词读者分不清是不是一回事，命中任务卡背景包第 2 节点名过的错误类型。

2. 位置：第 4 节，"接口内部一律调用 core 包已有的 snapshot.ts、dashboard.ts 去拼数据，不自己重新解析 YAML"。问题类型：第 6 项 + 第 1 项（严重）。这两个文件名只存在于参考仓库 tools/console/packages/core/src/ 目录，课程 14-16 课从未提过这两个文件名，学员自己的 core 包按课文只有 parsers/state/writer 三块，这里把参考仓库的实现文件当成了学员已有的同名文件。

3. 位置：第 4.2 节，"仓库里 routes/jobs.ts 实际还注册了 harness-run（治理线巡检）和 create（新条目创建）两个作业类型"。问题类型：第 3 项 + 第 6 项（严重）。第 3 节刚说"server 和 ui 两个包现在还没有一行代码"，这里又说"仓库里 routes/jobs.ts 实际还注册了"，前后矛盾：一个不存在的文件怎么会"实际还注册了"什么。根源同第 2 条，把参考仓库的实现细节当成了课程讨论范围内已经存在的事实。

4. 位置：全篇多处，"不是……是……"转折句式（至少 4 处）。问题类型：第 5 项（中等）。命中处："随课发放的九页原型不是拿来抄代码的，是拿来抄规格的""不是漏看，是它们本来就不在这一轮范围里""这个问题不是控制台本身要解决的，是为了凑齐分离部署的前提专门加上去的""这不是它存心偏袒，是因为这两条路线的代价更容易描述"。同一句式在不到六千字的稿子里出现四次，读起来有翻案腔调。

5. 位置：对比表及后续多处，"SSE" 首次出现从未展开全称或解释机制。问题类型：第 1 项（中等）。读者只能靠表格里"代价""失败模式"两栏反推 SSE 大概是什么。

6. 位置：第 1 节"四条路线"与第 2 节"四组八条方案"计数说法不一致。问题类型：第 1 项（轻微，指代不明）。容易让读者以为总共只有四个候选而不是四个维度八条候选。

7. 位置：全篇，review.html / harness-task-detail.html 不在本轮范围的说明重复六处。问题类型：第 2 项（轻微）。其中三处（材料交代段、API 清单排除段、收尾自检段）文字上已经不再增加新信息，可以合并。

第 4 项（AI 味儿模板感）：无独立发现，固定的规格写作模板不算行文套路问题。

第 6 项额外检查逐条核对结论：三条 Prompt 的输入均在读者已有清单内（附录设计稿、调研节自产对比表、本课自产 01-ADR.md），没有发现 Prompt 层面的材料越界。但正文叙述层面发现了三处把参考仓库内容当成读者已有事实的问题，即上面第 1、2、3 条，这三处不是 Prompt 输入越界，是背景叙述把参考仓库的具体文件名、注册内容、"参考仓库"这个词本身，直接写进了读者要读的正文。
