# 润色报告：26-读设计稿，定契约

## 一、诊断问题逐条处理

诊断来源：general-purpose subagent（model: sonnet），只读 draft.md，附禁令清单与本课专属第 6 项检查（哪条 Prompt 的输入读者手上没有、哪句话把参考仓库文件当成读者自己的文件）。原始诊断存 `diagnosis.md`。

1. 【严重】"参考仓库到现在也没有实现它们背后的后端"与三行前"本仓库现在没有对应后端"用词不一致，读者分不清是不是一回事，命中背景包第 2 节点名的错误类型。
   处理：改。统一把参考实现的转述改成课程系列既有的固定说法「参考流水线」，删掉"本仓库"这个含糊说法；材料列表段落改成不重复展开理由，直接指向第 1 节细说。

2. 【严重】"接口内部一律调用 core 包已有的 `snapshot.ts`、`dashboard.ts` 去拼数据"——这两个文件名只在参考仓库 `tools/console/packages/core/src/` 里真实存在，课程 14-16 课从没提过，读者自己的 core 包按课文只有 `parsers`/`state`/`writer` 三块，这是把参考仓库的实现文件当成了读者已有的同名文件。
   处理：改。删掉具体文件名，改写成"复用 core 包已有的解析逻辑去读文件，不自己重新解析 YAML；新写的拼装逻辑收进 core 包一起维护，不要散落进 server 包"，只讲职责边界，不断言读者没有的具体文件。同时把 API 清单表里"投影自 core 的快照"两处，改成指向读者确实已有的真实文件（`meta.yaml`、`backlog.yaml`）。

3. 【严重】"仓库里 `routes/jobs.ts` 实际还注册了 `harness-run`……两个作业类型"与前一段"server 和 ui 两个包现在还没有一行代码"直接矛盾，且把参考仓库的实现文件路径当成了课程讨论范围内的既成事实。
   处理：改。删掉具体文件路径引用，改成"参考流水线里还实现了治理线巡检和新条目创建两类作业"，转述为参考事实而非读者仓库现状，同时消除前后矛盾。

4. 【中等】"不是……是……"转折句式全篇出现 4 处，读起来有翻案腔调。
   处理：改。四处逐一重写：开篇"抄的是规格，不是代码"（去掉"不是……是……"的先后顺序，改成先给结论再补否定）；第 1 节"本来就不在这一轮范围里"（删掉"不是漏看，是……"的铺垫，直接给结论）；调研表里分离部署那行"跟控制台本身要解决的事没关系，是为了凑齐分离部署这个前提才专门背上的负担"；第 2 节"原因很简单：这两条路线的代价更容易描述……"替换掉"这不是它存心偏袒，是因为……"。

5. 【中等】"SSE"首次出现从未展开全称或解释机制，读者只能靠表格反推。
   处理：改。在第 1 节 SSE 第一次出现处加括注："SSE，服务器往浏览器单向推消息的一条长连接，不用浏览器反复发请求去问有没有更新"，后文直接用简称。

6. 【轻微】"四条路线"（第 1 节）与"四组八条方案"（第 2 节）计数说法不一致，容易让读者以为只有四个候选。
   处理：改。统一成"四道选择题，一共八条候选方案"，第 1 节两处、第 2 节维持"四组八条方案"，前后对齐。

7. 【轻微】review.html / harness-task-detail.html 不在本轮范围的说明重复六处，其中材料列表段、API 清单排除段、收尾自检段三处文字上不再增加新信息。
   处理：部分改。材料列表段改成简短带指向（"理由第 1 节细说"），不复述完整理由；API 清单排除段和风险待定项段、收尾段各自承担不同的具体职能（穷举依据/开放问题/收尾自检），予以保留——这是本课任务卡明确要求反复点名的红线（避免学员误做两个没有后端的页面），不做进一步合并。

第 4 项（AI 味儿模板感）：诊断结论为无独立发现，未改动；固定的规格写作模板本身是任务卡与背景包的要求。

## 二、终检阶段的主要修改

三道门执行记录：

- **符号遍**（`check_style.py`）：硬禁令清零，警告项从 12 处降到 11 处（拆分长句降低了部分单句超 80 字的警告，其余为规格文档天然的长复合句，逐句读过确认不是逗号硬拉），无「」『』〈〉、星号、emoji、破折号、连续波浪线命中。
- **句子遍**：拆分了 5 处过长的复合句为多句（开篇材料清单段、第 1 节页面范围段、第 3 节包边界收尾段、第 4 节实施步骤第 1 步、第 5 节收尾首句），降低单句信息密度。
- **温度遍**：全篇 3 处"多半是……"卡点拦截（第 1、2、4 节各一处），达标（要求 ≥2）；收尾段加了一句略带画面感的松话（"点开哪个都是一张白板"）避免收尾过于工整；未使用"我""咱们"，符合规格类课程的克制口吻。
- **装腔词表 / 过度自信词表**：`check-lesson.sh` 独立扫描通过，零命中。
- **状态值核对**：正文出现的 `published`、`review`、`scheduled` 三个状态值，均在 `tools/console/packages/core/src/state.ts` 里能查到，无编造状态名。
- **命令与脚本名核对**：`media flip`、`media backlog apply`（含 `backlog`）、`media promote`、`media next-up set`（含 `next-up`）四条命令均在 `tools/console/packages/cli/src/commands/` 下有对应实现文件，且与第 27 课任务卡「2.1 大纲」第 4 节的映射表口径完全一致，`media next-up` 补全成 `media next-up set` 与仓库真实子命令对齐。
- **材料可溯**：随课发放的九个 HTML 文件、`css/theme.css`、`README.md`、`26-界面用语对照表.md` 四份材料路径均在仓库里实际存在（已用 Bash 逐一 `ls`/`grep` 核实）；`harness/logs/metrics.jsonl`、`harness/tasks.md`、`backlog.yaml`、`meta.yaml` 均为课程既有真实约定路径；`routes/jobs.ts` 中 `publish`/`rework`/`apply-proposal`/`harness-run`/`create` 五个作业类型已用 Bash 核实存在，但引用方式已改为不点名具体文件路径的"参考流水线"转述，避免读者误认已拥有该文件。
