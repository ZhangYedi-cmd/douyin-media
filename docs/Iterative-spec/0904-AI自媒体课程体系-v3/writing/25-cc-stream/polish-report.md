# 润色报告：第 25 课《无头作业：进程流归一与终局裁决》

## 一、诊断问题逐条处理

诊断来源：sonnet 子代理读者诊断（`diagnosis.md` 内容见下方存档），额外核查项是"哪条 Prompt 的输入是读者手上没有的、哪句话把参考仓库的文件当成了读者自己的文件"。

### 1. types.ts、normalize.ts 缺 Prompt（严重，已改）

诊断指出第 9 行承诺六个文件，全文实际只有 5 个 Prompt 块，`types.ts`/`normalize.ts` 从未被要求生成过，读者按课操作会在这里卡住。

处理：在第 2 节新增一条 Prompt（原文第 45-55 行），同时生成 `types.ts`（七种事件的类型定义，逐个说明各自携带什么字段）和 `normalize.ts`（有状态的归一函数，说明 `assistant` 消息里 `tool_use` 按 id 去重的规则）。六个文件现在都有对应的 Prompt：`types.ts`+`normalize.ts`（第 2 节）、`milestones.ts`（第 3 节）、`transport.ts`+`spawn.ts`+`index.ts`（第 4.1 节）。

### 2. 第 6.2 节：断言"两种场景做的事是同一件"和紧跟的表格自相矛盾（严重，已改）

诊断指出原文表格里"人工取消"和"进程重启"两行处理方式明显不同（前者直接复跑裁决函数，后者是一套三分支判断），但正文断言"是同一件"，自我推翻。

处理：重写整个第 6.2 节。不再引入"终局记录""留痕文件""中途事件"这几个未定义的概念（这些术语实际对应的是模块 7 才会造的控制台后端的 `result.json` 三级兜底，读者此刻没有这一层）。改为把这一课能给读者的真相源钉死成一个：`meta.yaml`，两种场景第一步做的事真的是同一件——复跑第 5.1 节的裁决函数；区别只在于进程重启后要多核一步锁有没有正常释放，这一步直接回指第 5.2 节已经讲过的陈旧判据（两个条件都满足才抢占），不是新概念。参考流水线更完整的三级快照兜底，改成清楚标注"这层属于模块 7 的控制台，这一课不用去搭"的一段延伸说明，不再和读者自己的构建路径混在一起。

### 3. "终局记录"等术语未定义（严重，随第 2 条一并解决）

处理同上：删除这些术语，改用读者已经在第 5.1、5.2 节接触过的具体概念（`meta.yaml`、裁决函数、咨询锁陈旧判据）来讲第 6.2 节的恢复规则，不再引入新词。

### 4. 第 6.1 节 Prompt 暗示读者已有一版终止实现（严重，已改）

诊断指出原 Prompt 用"改成""原来只有超时路径……现在……"这类措辞，暗示读者手上已经有一份只对超时生效的终止实现可供修改，但第 4.1 节明确把这部分留白（"怎么终止下一步会补"），读者实际上从未拥有过这个"原来的版本"。

处理：重写第 6.1 节的 Prompt，改成"给子进程实现一个先礼后兵的终止方法……这个方法要同时接住两条触发路径"，一次性要求覆盖超时和人工喊停两条路径，不再预设一个可供修改的旧版本。正文里"这套逻辑最早只接在超时这一条路径上，参考流水线后来……"这段历史陈述保留，因为它清楚标注的是参考流水线自己的历史，不是读者的构建历史，两者不会混淆。

### 5. 第 1 节同一个意思连续说了三遍（中，已改）

删掉第 15 行末尾"三层代码本身，没有一行认识发布、配音、复盘这些词"这句与前文重复的复述，只保留头注引用和第 17 段的反例，反例本身带来了新信息（说清楚做错了会付出什么代价），不算重复，予以保留。

### 6. 五处排障句高度雷同的句式模板（轻，部分改）

诊断指出"现象 X，多半是原因 Y；这种时候该做的是/该改的是 Z"这个句式在第 5.1、5.2 两节几乎逐字重复。改了其中一处（第 5.2 节"抢锁总是失败"那句），拆开成两句、去掉"这种时候该做的是……不是……"的固定尾巴，改成直接给后果。第 5.1 节那句保留了类似结构，因为它和第 5.2 节的用词已经不再重复（"该改的期望集合"对应的是一个具体的、和锁完全不同的操作对象），判断不算硬伤，不改。

### 7. 全文六次"说明+表格+Prompt"三段式节奏（轻，未改，理由见下）

诊断认为连续六个小节用同一个节奏会让人觉得是套模具写出来的。核实后发现全文九个小节里，第 1 节（只有表格没有 Prompt）和第 4.2 节（只有核对清单，没有表格也没有 Prompt）本来就打破了这个节奏，加上这次改稿又给第 5.2 节补了一张之前没有的锁规格表（这张表是纵向的规格罗列，跟其余几张横向对比表在形状上也不一样）。三段式本身是任务卡"2.1 大纲"明确要求的交付物形状（每节要有对照表/规格表 + Prompt），硬拆掉会导致某些小节缺交付物，判断保留现状更符合任务卡约束，在这里不改。

### 8. Prompt 输入是否越界（本课额外核查项，核实无问题）

诊断逐条核对了全部 Prompt 块的输入，确认：
- 第 5.2 节"看一下 media CLI core 包里已有的锁实现"这条 Prompt，措辞准确框定为"复用已有的"；核实过 `media` CLI core 包的 `writer.ts` 确实在内部导入并复用 `lock.ts`/`atomic.ts`（`acquireLock`、`writeFileAtomic`），这是读者第 12-16 课已经拥有的真实代码，不是把参考仓库的东西说成读者已有。
- 其余 Prompt（裁决函数、里程碑引擎、`transport.ts`/`spawn.ts`/`index.ts`、终止方法）都正确框定为"这一课要新造的东西"，没有暗示读者已经写过。
- 诊断唯一指出的越界风险是第 1、4 条已修的两处（缺 Prompt、暗示已有旧版本），均已处理，未发现"把参考仓库文件说成读者自己文件"的新增问题。
