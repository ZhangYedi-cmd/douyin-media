# 第 24 课草稿读者诊断

诊断人设定：会用 Claude Code / Cursor、没做过自动化流水线、认知停在单轮对话的学员，跟到第 23 课，手上只有课文和自己前几课做出来的东西（`harness/` 骨架三份文件 + 资产读写表、`douyin-retro` skill + 一份复盘报告、`douyin-ideate` skill + 一批入池候选、CLAUDE.md 治理线铁律段落），没有参考仓库。只诊断，不给修改建议。

---

## 一、哪里读不懂

1. **第 5 行**："这一课的记忆锚点是：自审是反哺作用在治理线自己身上，大环合上之后，连怎么治理这件事本身也进了回路。"
   问题类型：句子结构不通。
   为什么是问题：读不出主谓宾结构，"自审是反哺作用在治理线自己身上"这半句到底是在说"自审是一种反哺"还是"自审这件事本身受反哺作用"，需要反复读才能猜，作为全课开篇第一次定义"记忆锚点"，反而是最难懂的一句。

2. **第 76 行**（1.2 节 Prompt 结尾）："其余字段留空等第2节的三个新技能补。"
   问题类型：指代不明。
   为什么是问题：不清楚"其余字段"指的是 retro、ideate 任务卡里还没填的字段，还是指 backlog-gardener 等三个任务在注册表里应该留的整条空条目。紧接着第 79 行的核对提示又特别强调"如果 AI 一口气把 backlog-gardener、benchmark-refresher、account-audit 也全部写进了 yaml……多半是它照着训练数据编了一份完整配置"，两处对照容易让读者搞不清这一步产出的注册表到底该有几条任务、有没有那三个任务的占位条目。

3. 全文两处出现"四个治理 skill/任务"这个说法（开头第 6 行、第 239 行），具体指代的对象集合不是在同一处交代清楚的，读者要读到第 239 行才能倒推出这四个具体是谁，读到第 6 行时是无法确定的。详见类别三。

---

## 二、哪里太啰嗦

无明显问题。account-audit 的读写边界在第 2、3、4 节被重复陈述三次（第 142-144 行 / 第 158 行 / 第 222-229 行），但每一次都配合一个新动作（生成 skill / 建限幅表 / 二次核对 Prompt），属于功能性强化，不是同一句话原地重复，不算啰嗦。

## 三、哪里逻辑断裂

1. （最严重）**第 152 行核验指令与 account-audit 自身设计正面矛盾**。
   第 2 节 account-audit 的 Prompt（第 146-147 行）明确要求流程包含"自动档直接改yaml留git diff、提议档只写进报告等人审"，也就是把 account-audit 设计成在限幅内可以**自动**改写 `harness/tasks.md`。可紧接着第 152 行的核验段落却说：三个 skill（backlog-gardener、benchmark-refresher、account-audit）生成之后都要检查有没有把"只提议不落笔"这条铁律写进红线，红线里出现"经确认后可直接应用"这类措辞就该判定 AI 理解错了，"第 21 课定的例外只有入池和规则化清扫两类，其余一律要收回来"——account-audit 的自动调参显然不属于入池或规则化清扫这两类例外。按第 152 行这条核验标准去检查自己的 account-audit skill，读者很可能会把刚刚建立起来的自动挡当成 AI 的错误改掉，这和第 3 节整节的立论（调参限幅表存在的意义正是让 account-audit 有一部分参数可以自动调）正面冲突。

2. **第 81 行与第 83 行标题数字对不上**。第 81 行"调度器会喊人干活了，但真正干活的还差两个任务。"紧接着第 83 行二级标题是"## 2. 三个治理 skill 起步：backlog-gardener、benchmark-refresher、account-audit"——一个说差两个任务，标题列了三个技能，读者一眼就能看出数字不一致。

3. **开头"产出"清单遗漏了本课标题点名的主角**。第 3、6 行给出的产出是"一份任务注册表、四个治理 skill、一轮巡检记账"，完全没提到 account-audit；而 account-audit 正是本课标题"连治理线自己也要被复核"点名的对象，第 3、4 两整节都在讲它。读者读完开头会以为这一课只交付 4 个技能 + 注册表 + 账本，读到第 2 节才发现还有一个分量很重的第五个技能，开头预告和实际交付对不齐。

4. **"四个治理 skill"具体指代要读到第 239 行才能坐实**。第 239 行（第 5 节）写"四个治理 skill（retro、ideate、backlog-gardener、benchmark-refresher）"，明确限定不含 account-audit、也不含 dispatcher。但第 1、2 节反复出现的"四个治理任务"这个说法，此前没有一处把这四个具体名字和"四个治理skill"这个措辞对应写在一起，读者只能在读完全文回头才能确认自己前面理解的"四个"和最后总结的"四个"是不是同一组。

5. **第 241 行"还看不到什么"漏了风险最大的那个**。这段只提到 backlog-gardener 和 benchmark-refresher"这一课才第一次跑通，判断准不准还没经过时间检验"，却完全没提同样是本课第一次跑通、而且是唯一一个拿到了直接改配置文件权限的 account-audit。account-audit 的风险明显不比另外两个小，这里的遗漏让本该是全课收尾自我审视的这一段显得不完整。

6. **第 216 行"这张表跟第 21 课第 5 节的那张一字不差"这个断言不好验证**，而且如果第 21 课那张表是在第 24 课写出来之前排的，两张表要做到逐字相同本身就不太可能成立（除非第 21 课当时就已经把第 24 课的具体交付原文一字不差地写好了）。

## 四、哪里有 AI 味儿

1. 每一节结尾都用同一个句式模板收束——"已经做完 A，但/还差 B"：第 81 行"调度器会喊人干活了，但真正干活的还差两个任务"、第 154 行"三个技能都能跑了，但谁能碰治理线自己的配置，得先划边界"、第 202 行"边界画完了，得点破这一层到底是什么"、第 235 行"一轮真的巡检该跑起来了"、第 243 行结尾。五次几乎同一套"总结+留缺口"过渡装置连续出现，读起来像固定模板往里套内容，不像自然行文里长出来的过渡。

2. 第 5 行"这一课的记忆锚点是……"这个开篇装置句式固定，单独读这一句会有比较重的模板感（是否是全系列统一约定不在本次诊断范围内，只指出这句在本篇内的生硬感）。

## 五、哪里在装

1. **（系统性问题）全篇多次使用"不是A，是B"/"是……而不是……"翻案句式**，是禁令清单明确点名的"不是……而是……"及其变形，不是孤例：
   - 第 11 行"这些任务不是做不出来，是没人在正确的时间点上把它们叫起来。"
   - 第 129 行"它读的不是内容，也不是账号大脑，是治理线自己跑出来的执行记录。"
   - 第 172 行"不是调度节奏快慢的问题"、"出问题的地方不在治理线，是生产线和账号大脑"
   - 第 206 行"大环不是只喂给生产内容用的"、"不是一个孤立在外面的功能"
   - 第 220 行"这一层为什么必须是自审，而不是靠人时不时想起来盯一眼。"

2. **每节收尾"留一个缺口吊住下文"的处理方式**，精神上接近禁令清单点名的"按下不表""还差最后一块拼图"式导游腔预告：第 81 行"还差两个任务"，尤其是全文最后一句（第 243 行）"可这些都要你敲一次命令才动。怎么让它在你睡觉的时候自己跑？"——直接把下一课要解决的问题当悬念抛出来收尾，属于交付前预告/悬念钓鱼式收束。

3. 第 3 行"这一课回答这句话"、第 5 行"这一课的记忆锚点是"，都在向读者交代这一课的写作安排/记忆定位，带一点导游腔的味道。

## 六、本课专项：Prompt 输入与参考仓库数据核查（重点）

1. **（高）第 218 行"3 条报警线"这个数字全文没有定义来源**。"复盘逾期积压达到 17 条，超过了 3 条这条报警线"——这个"3条"报警线阈值在全文任何位置都没有被建立过：第 2 节 account-audit 的 Prompt 里统计的四项指标包含"逾期积压"，但没有给它配报警线数值；第 3 节的调参限幅表只覆盖 benchmark-refresher 间隔、backlog-gardener 间隔、ideate 间隔、retro 窗口、weighted-pool weight 五行，同样没有"逾期积压报警线"这一项。读者按第 2、3 节的 Prompt 生成自己的 account-audit 和限幅表，不会得到任何关于这个阈值的字段，读到第 218 行时无法对照自己仓库里该在哪里配这个"3条"，也不知道这个数字是不是需要自己另外设定。

2. **（中高）24h/72h/7d 这组数字前后的确定性程度不一致**。第 11 行用不加限定的语气陈述"发布满 24 小时该拉一次数据，满 72 小时再拉一次，满 7 天做终局归因"，读起来像是读者自己第 22 课 douyin-retro 已经钉死的既定事实；但到了第 1.2 节的 Prompt（第 68-69 行），同一组数字被表述为"参考流水线用的是 24h/72h/7d，你可以照抄这个思路，具体要不要跟参考流水线一样问我"——变成了参考流水线的建议值，需要读者自己决定要不要采用。同一组数字，前面当既定事实讲，后面当参考流水线起步值讲，读者搞不清自己第 22 课做的 douyin-retro 窗口到底是不是已经确定为 24h/72h/7d，还是要在这一课里重新确认。

3. **（低，正向对照，非缺陷）第 3 节调参限幅表（第 162-174 行）和第 4 节"参考流水线自己的账本"示例（第 218 行段首）在标注参考流水线属性这件事上做得比较到位**：两处都明确用"参考流水线的"这个措辞把具体数值圈出来，第 174 行还专门提醒"这张表上的数值是参考流水线的起步值，不是普适规律，你自己仓库的这张表数值要你自己定"。这部分没有把参考仓库内容误标成读者自己仓库已有的数据，与上面第 1、2 条形成对照。
