### 类别三·逻辑断裂

1. **（已改，最严重）第 152 行核验指令与 account-audit 自身设计矛盾**：原文让读者用"只提议不落笔"这条铁律去核对三个 skill（backlog-gardener/benchmark-refresher/account-audit），但 account-audit 自己的 Prompt 明确要求它"自动档直接改yaml留git diff"，两处正面冲突，按原核验标准会让读者把刚建好的自动档当错误删掉。**改法**：把核验拆成两段，backlog-gardener 和 benchmark-refresher 套原有的"只提议不落笔"检查；account-audit 单独一段说明它的红线不是这条，是"只能碰 harness/tasks.md 一份文件的 yaml 数值字段"，具体能不能自动改由第 3 节的限幅表定，检查它时看范围对不对，不是看它有没有自动改的权限。
2. **（已改）第 81/83 行"两个任务"和"三个 skill"数字对不上**：原文说"还差两个任务"，紧接的标题却列了三个技能。**改法**：把"两个任务"明确拆成 backlog-gardener/benchmark-refresher 两个"干活"的技能，account-audit 作为"不管内容、只管治理线自己"的第三样单独点出来，解释清楚这是"两个 + 一个"而不是简单的"两个"。
3. **（已改）开头"产出"清单遗漏了 account-audit**：开篇契约原来只写"一份任务注册表、四个治理 skill、一轮巡检记账"，account-audit 完全没露面，但第 3、4 两节整节都在讲它。**改法**：开篇产出清单加一句"外加自审元层 account-audit"，把它和四个治理 skill 并列点出来。
4. **（已改）"还看不到什么"漏了 account-audit 的风险**：收尾段只提到 backlog-gardener 和 benchmark-refresher 没经过时间检验，没提同样是第一次跑、而且唯一能直接改配置文件的 account-audit。**改法**：补一句"account-audit 是五个任务里唯一拿到直接改配置权限的，这一课它只交了一份心跳报告……动得对不对，现在没法验"。
5. **第 216 行"这张表跟第 21 课第 5 节的那张一字不差"不好验证**：诊断认为这个断言读者无法核实。**不改，说明理由**：这不是虚构断言，是真实事实——写作时逐字核对过 `courses/21-双线闭环与资产读写表.md` 第 5 节的三课地图表，任务卡也明确要求"三课地图与第 21 课第 5 节那张表逐字一致"，这句话本身就是在向读者交代这条一致性约束，不是编造出来吓唬读者的断言。

### 类别六·本课专项（Prompt 输入核查，最重要一类）

1. **（已改，高优先级）"3 条报警线"数字全文无来源**：第 4 节说"复盘逾期积压达到 17 条，超过了 3 条这条报警线"，但第 2、3 节的 Prompt 都没有让 AI 生成这个字段，读者自己的 tasks.md 不会有这个数字。**改法**：在第 3 节调参限幅表的 Prompt 里补一条独立的报警规则（逾期积压超过一个阈值就报警，阈值读者自己定），第 4 节改成"参考流水线自己那条报警规则定的阈值是 3 条……你自己第 3 节那条报警规则的阈值是多少，对着自己表里的数字来"，把参考值和读者自己要定的值分开说清楚。
2. **（已改）24h/72h/7d 窗口前后确定性不一致**：正文当既定事实讲，1.2 节的 Prompt 却把它处理成"参考流水线用的是……你可以照抄，具体要不要跟参考流水线一样问我"，让读者搞不清自己第 22 课做的 douyin-retro 窗口是不是已经定了。**核实后改法**：读者的 douyin-retro 是第 22 课做的，第 22 课成稿原文（`courses/22-复盘归因反哺大脑.md`）明确写了"24 小时、72 小时、7 天各跑一次"，这不是参考流水线独有的数字，是读者自己仓库里已经定过的东西。把 Prompt 改成"windows 按我第22课 douyin-retro skill 里已经定的窗口填，不要重新问我要不要改"，去掉"问我"这个多余的确认动作。
3. **（未改，标注为正向对照）第 3 节限幅表和第 4 节账本示例的"参考流水线的"标注**：诊断认为这两处做得到位，不是缺陷，不需要改动。
