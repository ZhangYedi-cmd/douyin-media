# 读者诊断（Step 5）

读者画像：会用 Claude Code、没做过自动化流水线、手上没有参考仓库，只有前几课自己做出来的东西（第 01、02 课产物，见《学员产物累计清单》第 02 课结束时那一节）。

派发对象：sonnet subagent（general-purpose），只给 draft.md 路径、读者画像、《学员产物累计清单》第 02 课结束时原文、SKILL.md 硬禁令清单、六项诊断任务（含本课特有的第六项：逐条核对每条 Prompt 假设读者手上已有的输入材料）。

# 《立骨架：仓库、目录、契约》诊断清单

## 一、哪里读不懂

1. 【高】第198行："00-ADR.md 里给这一段定的出口条件正是这一句。" 引用了一份读者从未见过、全文任何地方都没有交代过的文件（`00-ADR.md`）。读者此刻只拥有第01、02课的产物清单，没有这份 ADR，也不知道它是不是该出现在自己的仓库里。这句话让读者无法核实，只能选择相信一个来路不明的断言。
2. 【中】第160、166行："治理线复盘时填""治理线负责的产物"。"治理线"这个词第一次正式使用是在第4节，但全文从未正式命名过这个概念，唯一的铺垫是第22行目录树注释里的"另一条线"，从未被正式命名为"治理线"。读者在第4节冷不丁撞上这个词，只能靠猜。
3. 【中】"本仓"指代贯穿全文的模糊性（多处）。全文反复用"本仓"讲一个具体的例子（如第99行行数、第108-109行"真实事故"），但从未说明"本仓"是不是读者此刻正在搭的这个仓库，读者显然无法核实这些具体数字和事故细节。
4. 【中】`media` 命令在 3.1 节（第103行）就直接拿来用，但对它的说明（第 12 到 16 课要造，现在只是一个名字）要等到第125行、整个第3节收尾时才出现，中间读者会以为这是个已经存在的命令。
5. 【低】`dashboard.md`（第32、103行）：这份文件是什么、谁创建、本课要不要生成它的骨架，全文从未交代，也不在开篇承诺的"四件东西"清单里。
6. 【低】`build/` 目录（第224行 gitignore 片段）第一次、也是唯一一次出现具体名字，第164行只模糊提过"临时工程目录"，从未正式命名，两处对不上。
7. 【低】第45行反例句没有用引号框出举例的坏句子，和第58行同类反例处理方式不一致。
8. 【低】`content/_research/`（第31行）只被点名一次，此后既没有像 `_template`、`_backlog` 那样给出结构说明，也没有像 `harness/`、`tools/` 那样明说"留到后面课"。

## 二、哪里太啰唆

1. 【高】`4-publish.md` 编号排第4容易被误认成阶段4产物这条提醒，第108-109行（3.2节）和第162行（第4节）用几乎同一套论证和措辞讲了两遍。
2. 【中】状态值只能定义在一处、契约里不列全部状态值这条规则，在约40行篇幅内（103～143行）重复了四次。
3. 【低】重复的规则只留一处、其余改引用这个原则，在第2节表格、第3节收尾、Prompt 内、Prompt 后复核指引里反复出现，措辞高度相似。

## 三、哪里逻辑断裂

1. 【高】`dashboard.md` 作为选题契约输出（第103行）从未被建立：开篇承诺的"四件东西"不包含它，全文也没有任何 Prompt 让 AI 生成它的骨架。
2. 【高】`pipeline/lessons.md`（踩坑登记簿）被目录树和职责表列为该有的文件，第125行还说"标一个编号回指过去"，但全文没有一步真正创建或初始化它，第5节验收 Prompt 也不包含它。
3. 【中】第5节验收 Prompt 漏掉了 `backlog.yaml`：Prompt 只要求读 CLAUDE.md、daily-run.md、五份契约、`content/_template/`，没有把第4节同样产出的 `backlog.yaml` 纳入验收范围。
4. 【低】"治理线负责 `5-retro.md`"这个判断，依赖一个从未被正式命名的分工概念，前文只以"另一条线"含糊带过。

## 四、哪里有 AI 味儿

1. 【中高】每节结尾用几乎同一种句式收束（"……还没写""……还没定""……还没有验证过"），"已完成+还没完成"这个过渡公式在五个大节里反复套用。
2. 【中】"先摆一个看着合理其实有问题的方案，再给出真正判据"这个论证结构在全文反复套用（目录切法、CLAUDE.md、内容红线、流程纪律四处反例），手法趋同。
3. 【低】"真实事故"叙述配合精确到个位数的行数，带有用具体数字制造真实感的痕迹，读者既无法验证也用不上。

## 五、哪里在装

1. 【高】第2节标题"CLAUDE.md：规格表而不是成品"命中"不是……而是……"变形句式，出现在最显眼的小标题位置。
2. 【高】第5行"这条判据贯穿全课，最后一节会用它做验收"是导游腔/预告交付，直接向读者交代全课结构安排。
3. 【中】第41行"这件事要有一份文件说了算，下一节把它填出来"同样是预告下文安排的写法。
4. 【中】末句"这些判断依据写在哪？"功能上等同于预告下一课的交付悬念。

其余类别（金句化/对仗顺口溜、俯视腔、作者加戏、表演式标题、猜心句、黑话堆砌）扫描结果基本干净，未发现命中。

## 六、给 AI 的 Prompt 逐条核对输入材料

四条正式 Prompt：

1. Prompt 1（第2节，生成 CLAUDE.md）：全部内容由读者当场口述，不要求读仓库既有文件。通过。
2. Prompt 2（第3节，生成五份阶段契约）："生成之前告诉我：契约里出现了哪几处规则，在其它文件里已经写过一遍"没有点名要核对的"其它文件"是谁，Prompt 自身对引用对象交代不清，存在被曲解或漏查的风险。
3. Prompt 3（第4节，生成 content 模板与 backlog 头部）：明确写"先看第 3 节生成的五份契约"，属于课上刚产出、允许引用的范围。通过。
4. Prompt 4（第5节，验收复述）：明确列出要读 CLAUDE.md、`daily-run.md`、五份契约、`content/_template/`，均是课上产出，带防幻觉指令。通过；但未把第4节同样产出的 `backlog.yaml` 纳入验收范围（已归入维度三）。

小结：四条 Prompt 本身没有出现要求 AI 读一份读者不知道是否存在、内容也从未交代过的仓库文件这类硬伤。真正的问题出在正文叙事对读者已有材料的错误假设（`00-ADR.md`、"治理线"、`dashboard.md`、`build/`），已分别归入维度一和维度三。
