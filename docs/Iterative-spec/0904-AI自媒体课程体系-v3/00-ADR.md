## 1. 背景：为什么要重新规划

2026-09-02 按《AI架构师》范式把 18 课重写成 15 课（courses-v2），09-03 鹰眼做全书通读，结论是退回。风格、篇幅、事实核对三关全过，但读者照着 15 篇做不出流水线。根因不是哪一课写漏了，是全书的视角错了：15 课在「带读者参观一个已经建好的仓库」，每课的 Prompt 都以「读仓库里某个文件」开头，而读者手上没有仓库。审出来的 13 个盲区里，11 个是同一个病。

同一天你定了新口径：读者零仓库、从零 1:1 实现、全程 AI 产代码、重功能走 SPEC。这份 ADR 记录的就是这一轮定下来的东西。

## 2. 课程目标

一句话：让学员通过搭一条抖音自动化流水线，学会怎么跟 AI 干活。抖音是载体，不是教学目标。

分开写成三层，验收时按这三层对：

| 层 | 内容 | 学完的判据 |
|---|---|---|
| 能力目标 | 掌握和 AI 协作的流程；懂得怎么引导 AI；掌握 Loop 思维；掌握架构设计 | 第 32 课回收全书锚点时，学员能说出自己在流程上退出到了哪个位置、凭什么敢退 |
| 重点掌握项 | SPEC CODING、Loop 搭建、CLI 与状态收敛、反哺大环 | 这四块的课往厚里写；其余按「工具怎么用」压，按「这类问题怎么设计」留 |
| 产物目标 | 学完能 1:1 实现本仓库：media CLI、飞书闸口、console、10 个自封装 skill、1 个子代理、5 份阶段契约、brain 五份 | 第 33 课验收清单，允许不过但要写出差在哪 |

受众沿用 00-ADR：会用 Claude Code 或 Cursor、没做过自动化流水线的开发者，认知停在单轮对话。

## 3. 决策记录

每条按第 11 课钉死的四项写：决策、理由、被否方案、反悔成本。

### D1 读者前提：零参考仓库，从零建

- 决策：全书预设读者手上只有课文，没有 douyin-media 仓库，也不发 starter repo。
- 理由：一课一课攒出来的东西才是学员自己的；给了仓库，前面十课的动手环节会退化成「打开看一眼」。
- 被否：给仓库地址让读者 clone 对照（鹰眼第一轮的建议之一）。
- 反悔成本：高。33 课的材料清单和承接链全按「学员自己造」写的，改成有仓库要重排一半课。

### D2 零代码手写铁律

- 决策：学员不写一行实现代码。学员只写三类东西：中文的需求与判据、SPEC 文档、验收结论。代码、配置、脚本一律由 AI 产出。
- 理由：这是课程目标（教引导 AI）的直接推论。课文里出现大段代码就说明写偏了。
- 被否：关键脚本给源码让学员抄。
- 反悔成本：低到中。单课可以局部放宽，但会破坏全书的一致口径。

### D3 教法分级：按选型空间分档，不按行数

- 决策：三档。L1 轻，实现路线唯一、单文件、错了重跑，一条 prompt 钉死判据加三点验收。L2 中，多文件或带 references、有约定要定但没有互斥路线，一张规格表加两三条 prompt。L3 重，有互斥路线、跨组件契约、返工贵，走完整 SPEC 六步。
- 理由：dubbing-check 六个脚本 278 行但没有选型空间，判 L1；cc-stream 537 行但有「引擎进包、知识留外」要定，判 L2。行数不是判据。
- 被否：按代码量分档。
- 反悔成本：中。改档意味着那一课的结构整体重写。
- 现状分配：L1 是六个检测脚本、depause、子代理定义、三个治理 skill、tts-dub；L2 是 douyin-publish/retro/ideate、harness-dispatcher、cc-stream、brain 五份、pipeline 契约；L3 是 media CLI、飞书闸口、console。

### D4 SPEC 六步单独成课，七门 L3 只引用不重定义

- 决策：六步是调研、讨论选型、决策、写 SPEC、执行、验证。第 11 课讲方法本身，钉死六件事：六步各占第几节；调研节方案对比表的固定列（方案、适用前提、代价、已知失败模式）；「讨论选型」的 prompt 写法；ADR 固定四项；执行方案四节模板；里程碑出口条件必须是一句能跑的验证动作。第 12 到 16、18 到 19、27 课引用第 11 课，不许各自发明写法。
- 理由：你把 SPEC CODING 列为重点掌握项，原大纲里它只是被做三遍从没被单独讲过，学员换个题目未必迁移得动。「讨论选型」单独成一步，是因为 AI 列方案时会把自己想选的写得更饱满，得逼它给每个方案当辩护人。
- 被否：不单立课，靠一份内部写作规范 `spec-lesson-format.md` 统一七门 L3 的格式。
- 反悔成本：低。方法课本身不依赖别的课。
- 模板来源：`0818-看板工作台` 的 00 总览、01 执行方案、04 一致性 Review、06 施工记录。

### D5 详略配比：视频制作从简，四块重点厚写，模块 2 不算可精简

- 决策：怎么剪、怎么配音、多音字语速、封面怎么画一律走一遍流程即可。判断标准是这一段讲的是「这个工具怎么用」还是「这类问题该怎么设计」，前者压后者留。模块 2（07 到 10）表面讲配音质检，实际讲的是 Loop 架构，不在可精简范围。
- 理由：课程目标。旧 02 课原计划拆两课，按这条合回一课；tts-dub 从 L2 降到 L1。
- 被否：按 1:1 的逻辑把每个工具都讲透。
- 反悔成本：低。

### D6 console 1:1，五课，附设计稿

- 决策：模块 7 五课（27 定契约、28 后端读、29 后端写、30 前端骨架与前两页、31 余下四页与联调）1:1 实现 server + ui，`docs/design/` 九页原型加 theme.css 放进课程材料附录。`review.html` 和 `harness-task-detail.html` 是下一期内容，附录里标明不在 1:1 范围。
- 理由：你的拍板（Q1）。
- 被否：只教最小可用看板（鹰眼建议）；砍掉改成 `media --json` 自己接。
- 反悔成本：低。模块 7 在最后，砍它不影响前面 26 课。
- 本记录的保留意见见 §7 P1。

### D7 人审闸口只做飞书

- 决策：第 17 到 19 课只做飞书，1:1 实现 feishu-notify 的功能。需要学员有企业或团队账号能建自建应用，课里写明。
- 理由：你的拍板（Q2）。
- 被否：飞书为主加本地兜底；本地兜底为主线。
- 反悔成本：中。闸口是全书最关键的一道，换通道要重写三课。
- 本记录的保留意见见 §7 P4。

### D8 media 1:1，含 check

- 决策：media CLI 全量 1:1，`check` 进必做。分五课：12 调研与选型讨论（不产一行代码）、13 写 SPEC、14 执行 M1（core 与首批命令）、15 执行 M2（全量命令与存量迁移）、16 验证与收敛。
- 理由：你的拍板（Q3）。media 是全书记账唯一入口，九个子命令散在七课的动手步骤里，不 1:1 后面的课接不上。
- 被否：M1 必做、M2 选做、锁和 audit 进阶。
- 反悔成本：高。

### D9 抖音号问题由学员自己解决

- 决策：不为没有抖音号的学员另开路线。
- 理由：你的拍板（Q4）。
- 被否：第 20 课止步 dry-run、第 22 课给脱敏样例数据练归因。
- 反悔成本：低。脱敏样例数据仍放进课程材料附录，供第 22 课在学员没有真实播放数据时用。

### D10 顺序冲突：保持叙事顺序，先手改再收敛

- 决策：模块 0 到 2 期间学员手改 `meta.yaml`，课里明标「这是临时的，模块 3 会收敛掉」。第 15 课专设「存量写点迁移」一节，把前面所有手改的地方改成喊 `media`。
- 理由：只有学员真的散着写过，「扫一遍找出所有会写真相源的地方」才有东西可扫。这一步 1:1 复刻了你 0818 M2 里程碑做的事。
- 被否：media 两课提到第 07 课之前；第 07 课整课后移。
- 反悔成本：中。

### D11 编号整体重排，九模块 33 课

- 决策：旧编号作废，连续课号 01 到 33，映射表备查。
- 理由：33 门用 01A、07B 这种插入号，模块 3 和 7 各五门会全是后缀。
- 被否：插入号；按阶段重分模块编号。
- 反悔成本：旧 15 篇里的「第 N 课」互引要连带全改，已排成 W0 单独做。

### D12 brain 五份单开第 04 课，四填一空

- 决策：positioning、persona、style-guide、sources 在第 04 课当场填满，benchmarks 留空并说清为什么。四份过同一道审：不许出现判不了的词。写「技术深度和流量型六比四」可以，写「以深度为主兼顾流量」不行。
- 理由：你说可以告诉学员怎么写填什么，那就没理由拖到第 21 课。前移之后模块 1 到 5 对 brain 的引用全部落到实处。
- 被否：骨架课只建空文件，内容留到第 21 课。
- 反悔成本：低。

### D13 模板交付：做一份课程材料附录，装三类

- 决策：附录装数据契约模板全文（meta.yaml、4-publish.md、5-retro.md、backlog.yaml 头部、报告模板）、console 设计稿、脱敏样例数据。不进附录的三类：CLAUDE.md、pipeline 五份契约、brain 五份。
- 理由：数据契约形状固定，学员自己发挥反而和后面课里的命令对不上；那三类必须因人而异，照抄等于抄了你的账号，也破第 03、04 课「从你自己的流程倒推」的要求。
- 被否：全部模板贴进课里（字数不设限后可行，但没必要）；全部靠 prompt 生成。
- 反悔成本：低。

### D14 字数不设限，心法类多讲，代码行上限保留

- 决策：每课字数不做限制，`check-lesson.sh` 的汉字上限改成只报数不 FAIL。心法类内容（SPEC CODING、Loop、状态收敛、反哺）按讲透为准，可以多讲，不为篇幅收着写。代码行上限（实操 200 行、方法论 30 行）保留为 FAIL。（09-04 你补充：字数不设限，心法类内容可以多讲讲。）补两条自查进验收清单：一课一个产物，一句话说得出学员多了什么；每一节都要有判据或产物，只讲道理的节合并或删掉。
- 理由：字数闸不拆，1:1 之后每课六千到一万字全部假红，写作 agent 会掉进砍字循环。代码行那条防的是课程变成贴代码，和零代码手写铁律同向。
- 被否：直接删掉字数检查。
- 反悔成本：低。

### D15 写作范式与语气（沿用 02、03 两份文档，这里只列结论）

- 叙事单元是动作步骤，每步四段：为什么要这一步、让 AI 做什么（内联短 prompt）、拿到结果审哪两三点、出错多半是什么。
- 开篇一段承接上一课产出加本课输入加本课产出；每课一个记忆锚点；收尾两段说做到了什么、还看不到什么、下一课补什么。不写「总结与作业」。
- 绝对优先级压过所有规则：禁装逼、禁过度自信、做暖心工程师。命中即改。
- 零编造：状态值、命令、路径、数字写之前先 grep；grep 不到的不写。

### D16 写作流程：严格串行，承接以成稿为准

- 决策：每课一个 issue，跑 `/ai-arch-tutorial-style` 六步，Step 3 改为 AI 自选大纲。33 篇严格串行 01 到 33，触发条件是上一篇交稿，不是到点。每个 issue 材料清单第一条是上一课的 `final.md` 全文。失败重试一次，仍失败翻 blocked 上报，不接力不跳过。承接台账 `handoff-ledger.md` 降级为校验用，写完对不上就当场改台账。
- 理由：并行时后一篇拿到的是对前一篇的猜测，「三行承接契约」写不出现有成稿那种密度的承接。
- 被否：11 批乘 3 篇并行（已作废）。
- 反悔成本：进度飘，单点阻塞。09-04 03:28 第 08 课撞 session limit 就是这个代价，链条停了六个小时以上。

## 6. 关键约束汇总

内容层：
1. 读者零仓库，每课的 Prompt 不许以「读仓库里某个文件」开头，输入必须是学员前几课自己造出来的东西。
2. 学员不写一行实现代码。
3. 视频制作从简；SPEC、Loop、CLI 与状态收敛、反哺大环厚写；模块 2 不算可精简。
4. 每课一个产物，一句话说得出学员多了什么；每节有判据或产物。
5. 某一课 prompt 超过 5 条就该拆。全书约 102 条 prompt。
6. 三处已核出的实际错误必须修：旧 02 的 cp 路径少一级；overrides 落在哪个文件两课说法冲突；旧 14「cc-stream 五个文件」实为六个。

写作层：
7. 禁装逼、禁过度自信、做暖心工程师，压过一切。
8. 动作步骤四段式，prompt 分散在步骤里。
9. 零编造，写之前先 grep。
10. 汉字数只报不判；代码行实操 200 行硬上限；实操篇围栏块至少 3、排障句至少 2；状态值必须在 state.ts 里。

流程层：
11. 严格串行 01 到 33，靠上一篇交稿推进。
12. 承接第一真相源是上一课成稿，台账只做校验并记录漂移。
13. 失败重试一次，仍失败 blocked 上报，不接力不跳过。
14. 跑完三件人办：全链承接核对 32 组接口；删两个自动机（cron 是每年 9 月 4 日）；第 02 课安装命令人工过一遍。

## 7. 本记录的保留意见与待定项

这些是我按第一性原理看下来觉得该摆出来的，不是替你改决策。

P1 模块 7 五课与课程目标的张力。console 是派生视图，16500 行是 media 的两倍多，占 33 课的 15%，学员在这五课学到的主要是「引导 AI 写一个前端项目」，和 SPEC 方法在第 12 到 16 课已经练过一遍。1:1 是你的拍板，我不动它，但建议二选一：把模块 7 标成选修，第 33 课验收不把它算进必过项；或者压成三课（27 定契约、28 后端、29 前端）。要不要压，你定。

P2 「1:1」的边界要在第 33 课写死。学员的 brain、CLAUDE.md、五份契约按 D13 必须因人而异，所以 1:1 只能是结构和工具 1:1，内容不可能 1:1。验收清单应该分两栏：结构项逐条对，内容项只看「有没有、判不判得了」。现在的表述容易让学员拿自己的账号定位去对你的。

P3 六步里少了「一致性 Review」。你 0818 那套流程是拍板方案、执行方案、一致性 Review、施工记录，17 处冲突是靠 review 销账的。第 11 课的六步是调研、讨论选型、决策、SPEC、执行、验证，交叉评审没有位置。media 只有一份执行方案还好，console 五课、飞书两课的 SPEC 之间会有冲突，建议第 11 课把「验证」拆成「SPEC 一致性评审」和「机器验收」两步，或者在第 27 课单独加一节。

P4 飞书 1:1 的对象已经变了。PLUT-1（08-29，已 done）记录了你的拍板：接入 Multica 后，Multica 是唯一消息通知通道，不再维护飞书通道。契约文档的改写落在 `spec/multica-integration` 分支，main 上的 CLAUDE.md 和 pipeline 仍写飞书，feishu-bot 代码也没删。所以第 18、19 课 1:1 的是一条你自己已经决定不维护的通道。要确认一下：课程 1:1 的基准是 feishu-bot 那份代码（课里要说明这是历史实现），还是 Multica 通道（第 17 到 19 课要重定，而且学员得有 Multica 工作区）。09-03 你拍 Q2 时说「只做飞书」，可能没把 08-29 这条算进去。

P5 计划的真相源不在 git 里。04、05 两份计划、handoff-ledger、courses-v3 前 7 篇成稿、writing/v3-* 中间产物，全部只在 mac mini 的工作目录里，origin/main 停在 12c23a6，只有 courses-v2 的第 02 课。本地仓库更糟，整个 0901 目录处于 staged 删除状态，49 个文件。建议在续跑之前先让贾维斯提交一次，否则这一轮的所有决策只活在评论区。

P6 执行链路当前状态。第 08 课 09-04 03:28 撞 Claude session limit，issue 挂在 in_progress 但没有进程在写，巡检从 06:00 起连续四次报同一条，到 09:00 还没人踢。半成品在 `writing/v3-08-08/`，draft.md 19KB 已写完，缺 diagnosis 和 final。修法是把 PLUT-83 翻回 todo。另外，鹰眼那个 agent 的上下文已经爆了，09-03 13:47 起没有成功回复过，「提前到 22:30 执行」那条指令没被确认，后面要它干活得重开会话。建议顺手改巡检自动机的规矩：session limit 这类可自愈的中断，巡检可以自己踢一次再上报，不然一夜停六小时。

## 8. 风险（沿用鹰眼两轮列出的，加我的）

1. 飞书企业自建应用需要企业或团队账号，个人开发者卡在这里的概率高。config.example.yaml 里六步申请说明是全的，不算盲写，但门槛要在第 02 课就写明。
2. 第 02 课的装机命令要从各项目官方 README 取，仓库里没有，是全批最容易写错的一门。
3. 模块 7 五课能不能装下 16500 行，建议先只写第 27 课看 SPEC 出来有多厚。
4. 无人值守串行，一篇卡住全线停，巡检窗口 15:00 收口，后半程要人看。
5. 全链承接核对不在自动流程里，33 篇跑完要人做一次 32 组接口的核对。
