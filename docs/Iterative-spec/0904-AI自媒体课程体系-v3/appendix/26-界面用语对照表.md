# 07 · 界面用语对照表

> 起因：2026-08-19 真机走查（见 06-施工记录 §十）判定「文案与语义」3/10。根因是**界面文案的作者是契约文档，不是使用者**——
> 执行方案里的术语（P1 / 口径 / 留痕 / 降级 / DeadlineBadge / periodic:2d）被原样搬到了屏幕上。
> 本文是界面用语的**唯一出处**，前端改文案一律以此为准；与 03-前端执行方案.md 的措辞冲突时，以本文为准（那份文档描述的是实现契约，不是用户可见文案）。

## 0. 三条总原则

1. **界面说工作流的语言，不说系统的语言。** 用户脑子里的词是「选题 / 写稿 / 审核 / 发布 / 复盘」，不是 `meta.yaml` / `flip` / `periodic:2d`。
2. **技术标识只允许出现在三个地方**：① 可复制的命令条（CommandChip）；② 证据文件路径（点开可看原文的那种）；③ 悬停提示 / 展开后的详情区。**正文、标题、列头、按钮、空态一律不准出现。**
3. **实现细节不是文案。** 「解析失败降级为空表不崩页」「不吞、不崩页」「看板不代拉」这类句子是写给实现者的自我说明，用户不关心系统怎么保证自己不崩——**直接删掉**，不要翻译。

## 1. 状态词（最高优先级：全站唯一出处）

`components/StatusTag/StatusTag.tsx` 的 `statusLabel()` 已经是「唯一取值处」，但 `pages/kanban/StatusSection.tsx` 与 `pages/overview/WipStats.tsx` 各自又抄了一份带英文前缀的标签，且**同一状态出现了两个中文词**（ideated 在一处叫「已选题」、另一处叫「已立项」）。

**做法：两处自维护的 map 删除，改为调用 `statusLabel()`；英文枚举名不再上屏。**

| 枚举值 | 界面文案（唯一） | 现状里要改掉的写法 |
|---|---|---|
| `ideated` | 已选题 | ~~`ideated 已立项`~~（看板/在制统计） |
| `drafting` | 在写 | ~~`drafting 在写`~~ |
| `review` | 待审 | ~~`review 待我审核`~~ |
| `approved` | 待发 | ~~`approved 待发`~~ |
| `scheduled` | 已排期 | ~~`scheduled 已排期`~~ |
| `published` | 已发布 | ~~`published 已发布`~~ |
| `retro_done` | 复盘完成 | — |
| `rejected` | 已否 | 时间轴里不应排在「复盘完成」之后当第 8 步（它是分支不是终点） |

其它枚举同理，就近改为中文：

| 原文 | 界面文案 |
|---|---|
| `kouban` / `tuwen` | 口播 / 图文 |
| `depth` / `traffic` | 深度 / 流量 |
| `enabled` / `disabled` | 已启用 / 已停用 |
| `applied=false` | 待应用 |

> 详情页副标题里的 `content/2026-07-14/hy3-moe-teardown · kouban · depth` 是拼音枚举直出，必须改成「口播 · 深度」。

## 5. 空态与错误态

空态三段式：**说清为什么空 → 给下一步动作 → 技术细节退到折叠区**。

| 位置 | 现状 | 改为 |
|---|---|---|
| 数据复盘 | `尚无数据快照（harness/logs/metrics.jsonl 不存在或为空）· 补数据 = 跑 media metrics record，看板不代拉` | 标题「还没有复盘数据」+ 正文「已发布内容的播放数据由复盘任务抓取后才会出现在这里」+ 可复制命令 `media metrics record`（放 CommandChip） |
| 治理线注册表 | `harness/tasks.md 未注册任务（或解析失败，降级为空表不崩页）` | `还没有注册任何养护任务` |
| 运行账本 | `窗口内无运行记录` | `所选时间范围内没有运行记录` |
| 审核记录 | `暂无审核记录（3-review.md 未产出留痕）` | `还没有审核记录` |

## 7. 直接删除的句子（实现细节泄漏）

- 生产看板底部整段「状态机规则：…… 停留 >48h 的行 **DeadlineBadge** 转警示色，与总览警报联动同源。解析失败条目降级显示原文，不吞、不崩页。」——组件名上屏，且是给实现者的说明。要保留的只有「停留超过 48 小时会标黄」这一条对用户有用的规则，其余删。
- `harness/tasks.md（yaml 解析失败时降级为空表，不崩页）`→ 只留文件路径。
- `清扫归 douyin-ideate Step 2.0，看板只标记不删除` → 「清扫由养护任务执行，本页只做标记」。
- `harness/logs/index.jsonl · 逆序` → 「最近的排在前面」，路径退到悬停。
- 选题池每行的 `过期口径 >30 天` → 「超 30 天未动」。

## 8. 保留英文/技术原文的白名单

以下场景**必须**保留原文，不要「翻译」：

- CommandChip 里的命令全文（`media flip … --dry-run`）——它就是给人复制去终端跑的。
- 证据文件路径（`content/2026-06-15/open-weight-5/meta.yaml`）——点开要能对上文件系统。
- slug（`hy3-moe-teardown`）——它是内容的身份证，跨系统对账要用。
- 任务名 / skill 名（`benchmark-refresher`、`douyin-retro`）——与 `harness/tasks.md` 注册表一一对应，改了就对不上账。

> 判定口诀：**这串字符要不要被人原样复制或用来对账？要 → 保留原文；不要 → 说人话。**
