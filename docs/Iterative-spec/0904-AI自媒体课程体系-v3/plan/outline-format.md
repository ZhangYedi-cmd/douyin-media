# 任务卡「大纲」块的格式约定

每张任务卡在「## 2. 本课要讲什么」之后、「## 3. 学员交付」之前，插入一块「## 2.1 大纲」。写作代理照这块展开成 outline.md，frontmatter 写 `plan: fixed-from-card`，不再自己出方案。局部调整允许，但要在 outline.md 开头一段说明改了什么、为什么。

## 块的内容

```markdown
## 2.1 大纲

记忆锚点：<一句完整判断句，全课内容都归到它下面>

开篇契约：上一课交付了 <产物名、数量>；本课输入是 <什么>；本课产出 <几件东西，逐件点名>。

### 1. <一级标题>
- 核心判断：<一句完整判断句，有主语有谓语>
- 二级标题：<1.1 xxx / 1.2 xxx，本节要讲三块以上或预计超 1200 字才分；否则写「不分」>
- 交付物：<Prompt 块 / 对比表 / 清单 / 命令，至少一个可复制的操作块；方法论篇可以是一张表或一句判据>
- 学员此时手上有：<本节 Prompt 的输入来自哪里，对照 inventory.md 上一行或本课前面节的产物>
- 交接：<这一节解决了什么，把什么问题递给下一节>

### 2. <一级标题>
（同上）

……

### N. <收尾节的一级标题>
- 本课做到了什么、还看不到什么、下一课补什么
- 结尾抛出的问题：<与 handoff-ledger.md 本课行逐字一致>
```

## 规则

1. 一级标题 3 到 6 节，编号「N. 标题」。标题按 `~/.claude/skills/ai-arch-tutorial-style/references/structure.md` 的标题法则：名词短语，或「名词短语：白话补充」；不带「第一步 / WHAT / WHY / 原理深挖 / 跟做」前缀；不用悬念句、对仗句、数字党。
2. 每节对应一个动作步骤（为什么、让 AI 做什么、审什么、出错多半是），或者方法论篇的一个判据。只讲道理没有判据也没有产物的节，不许出现。
3. 二级标题最多两级，不出现 N.M.K。一组二级标题连读要能看出本节推进顺序。
4. 「学员此时手上有」这一行是防线：本节 Prompt 的每一个输入都要能在 inventory.md 上一课那一行找到，或者是本课前面节刚造出来的。找不到的，要么改输入，要么本节先造它。
5. L3 课（12 到 16、18、19、27 到 31）的一级标题要能对上第 11 课定的六步位置：本课做六步的第几步，节标题就按那几步的名字起，对比表固定列（方案 / 适用前提 / 代价 / 已知失败模式），ADR 固定四项（决策 / 理由 / 被否方案 / 反悔成本）。
6. 心法类课（06、11、17、21、32）不限节数上限的字数，但每节仍要有判据或产物。
7. 一课的 Prompt 总数超过 5 条，拆节或合并步骤，不许硬塞。
8. 大纲里每一个仓库路径、命令、状态值先 grep 确认存在。
