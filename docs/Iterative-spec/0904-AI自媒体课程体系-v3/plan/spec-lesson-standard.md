# SPEC 课统一标准（第 11 课钉死，18、19、26-28 课引用不重定义）

来源：`cards/11.md` 的「## 2.1 大纲」块。本页只摘录后续 L3 课直接要用的固定件，不重复第 11 课的论证过程。

## 六步节名（正文节号见第 11 课大纲第 2-7 节）

调研 → 讨论选型 → 决策 → 写 SPEC → 执行 → 验证

后续 L3 课的一级标题按自己覆盖到哪几步来命名，直接用这六个词，不许另造同义词（如把「决策」写成「拍板」当标题）。

## 调研节：方案对比表固定列

`方案 / 适用前提 / 代价 / 已知失败模式`

三到六行，一行一个候选方案；解释性文字放正文，不塞进表格。

## 讨论选型节：辩护式 Prompt 的固定形状

对每个候选依次要求：① 成立的前提（什么场景下这是对的选择）；② 代价（多花的时间、多背的心智负担、谁买单）；③ 主动交代已知失败模式（什么情况下它会输、输给哪个候选）；④ 不许下「综合来看方案 X 更好」这类结论——结论留给人来下。AI 说不出某个方案的失败模式，就是在顺着人的倾向写，换个问法重问。

## 决策节：ADR 固定四项

`决策 / 理由 / 被否方案 / 反悔成本`

四项之外不加别的字段；参照 `00-ADR.md` 里 D1-D16 各条的写法。

## 写 SPEC 节：执行方案固定四节模板

```
# 0X-<部分>执行方案
## 1. 实施步骤    第一步…第 N 步；每步 = 做什么 / 产出物 / 验收标准 / 依赖
## 2. <命令|接口|页面> × 功能 × 详细设计    逐条穷举
## 3. 对外契约    本部分提供给 / 依赖其他部分的接口
## 4. 风险与待定项    拍板未覆盖的点全部落这里，标注需要用户裁决的项
```

节名与节序不许改写；「2.」的具体单位（命令 / 接口 / 页面）按各课主题替换。模板原样来自 `docs/Iterative-spec/0818-看板工作台/00-执行版总览.md`「执行方案写作模板」一节。

## 执行节 + 验证节：里程碑出口条件写法

出口条件必须是一句能跑的验证动作，不写「基本完成」「差不多了」这类判不了真假的话。

- 反例：M1 基本完成。
- 正例：真实仓 `media check` 通过；YAML 注释零丢失。
- 正例：全仓状态写路径唯一——连续 7 天内 meta/backlog/dashboard 机器区的每次变更均能在 `audit.jsonl` 找到对应行。

验证节额外产出施工记录模板（里程碑 / 出口条件 / 实际结果 / 卡在哪 / 怎么绕过去），每个里程碑一行结论，绕不过去的留给以后的人接着看。

## 使用方式

18、19、26-28 课在自己的大纲里只引用本页的节名、表列名、ADR 四项、执行方案四节模板、出口条件写法，不重新定义、不改写词。若某课只覆盖六步里的一部分（如第 18 课只做前四步），一级标题按自己实际覆盖到的那几步命名，其余步骤不出现空标题。
