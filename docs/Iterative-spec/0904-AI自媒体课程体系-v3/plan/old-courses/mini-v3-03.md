## final.md 全文

# 立骨架：目录树、一份总纲与五份阶段契约

上一课的产出是 `docs/00-toolchain.md`，四节：十件工具各自顶在流程图的哪一站、每条装机命令取自哪个官方页面、每件工具一条自检命令配一个具体的期望输出、四项会过期的东西各配一条探测命令。文件末尾贴着当天跑完的那份自检输出。

十件工具现在互不认识。选题那件把调研结果写进自己的输出，创作那件不知道去哪读；发布那件不知道审核结论存在什么地方。这一课建一个仓库把它们接起来，写出来的东西全是中文规格：目录树、一份总纲、五份契约、一套文件模板，不含实现代码。

## 1. 目录按流程里的角色切

先说一种看着整齐的切法：按文件类型分目录，md 放一处，yaml 放一处，脚本放一处。这种分法建起来顺手，会在第一次跨段交接的时候卡住。创作那一段要读的语气规范，和它要写出来的口播稿，分在两个目录里；契约里写一条交接路径，得跨三个目录去指。想改一件事，你说不上来要动几个地方。

换成按角色切：一份东西由流程里的哪一段产出、被哪一段读，决定它住哪个目录。这样改动的影响范围能顺着流程数出来。

```
your-pipeline/
├── CLAUDE.md              # 总纲，AI 每次开工先读
├── brain/                 # 账号的判断依据，第 04 课填
├── pipeline/              # 五份阶段契约加一份踩坑登记簿
│   ├── daily-run.md       # 编排：串起取题到出审
│   ├── 1-ideate.md
│   ├── 2-create.md
│   ├── 3-review.md
│   ├── 4-publish.md
│   └── lessons.md         # 踩坑故事只登记在这一处
├── content/               # 一条内容一个目录
│   ├── _template/         # 新建一条内容就复制它
│   ├── _backlog/          # 选题池 backlog.yaml
│   └── _research/         # 每次调研留一份给人看的快照
├── docs/                  # 只读历史存档，前两课的两份 md 挪进来
├── tools/                 # 自己造的东西，第 12 课起才有
├── harness/               # 另一条线，只产报告不产内容，第 21 课才立
└── dashboard.md           # 派生视图，机器刷新
```

目录叫什么名字随你，分法照抄就行。

| 目录 | 谁产它 | 谁读它 | 这一课建不建 |
|---|---|---|---|
| `CLAUDE.md` | 你 | AI 每次开工 | 建 |
| `brain/` | 你。复盘只出提议，改它得你点头 | 选题和创作两段 | 建空目录，第 04 课填内容 |
| `pipeline/` | 你 | AI 跑到哪一段读哪一份 | 建，六份文件 |
| `content/` | 取题那一步建目录，创作往里写 | 下一段拿它当输入 | 建三个下划线开头的子目录 |
| `docs/` | 你和 AI 落盘时写 | 事后查 | 前两课那两份挪进来 |
| `tools/` 与 `harness/` | 后面的课 | 后面的课 | 不建 |

`docs/` 和 `dashboard.md` 是这张表里的两个例外，它们不在流程线上。`docs/` 存的是当时怎么想的快照，落盘之后不更新，现行规则不住这里。这一条要在建目录的当天就写进 `docs/README.md`，不然几个月后回头看，一份三月的设计稿和一份现在还生效的规则混在一起，你分不清哪句还算数。`dashboard.md` 由机器从各处状态汇总生成，人不手写它，它也不是真相源，哪一格对不上，以被它汇总的那些文件为准。

`tools/` 和 `harness/` 现在不建，空目录留在那里，你每次打开仓库都要想一下它是干什么的。

剩下几个空目录会撞上一个坑：git 只追踪文件不追踪目录，`brain/`、`content/_backlog/`、`content/_research/` 现在都是空的，`git init` 之后它们不会进版本库。要留住目录结构，各放一个空的 `.gitkeep`。

目录建出来还都是空的。AI 进到这个仓库第一眼该读哪一份，得有一份文件说了算。

## 2. CLAUDE.md：每次开工都会被读的那一份

`CLAUDE.md` 放在仓库根目录，Claude Code 每次开会话会把它读进上下文。[官方文档](https://code.claude.com/docs/en/memory)把这类文件叫项目记忆，意思是不用你每次手动粘一遍。每次都被读，这件事有代价：读了不改变任何做法的句子，你每次开工都在为它付钱。

所以别写成项目介绍。“这是一个抖音内容自动化项目，采用模块化设计”，这种话删掉不影响任何一次执行。写进去的每一条，都要能在某次执行里改变 AI 的做法。

本仓的 `CLAUDE.md` 分五块。

| 这一块 | 回答什么 | 写成什么样算填对 | 不写会怎样 |
|---|---|---|---|
| 系统一句话 | 这套东西由哪几条线组成，各自停在哪 | 每条线说得出终点 | AI 把第 21 课那条只产报告的线，当成生产线顺手做成了内容 |
| 干活前必读 | 每次动手前必须读哪几份文件 | 给出文件路径，并写明这些是硬约束 | AI 按训练里的通用套路写内容 |
| 内容红线 | 什么情况直接重做 | 每一条都能判真假 | 编造出来的数字要到人审那一步才被发现 |
| 流程纪律 | 哪些动作机器不能自己拍板 | 写死停在哪一步 | 不可逆的动作被自动跑掉 |
| 文档架构约定 | 一条规则该写在哪、写几处 | 一条规则只写一处，其余位置引用 | 同一条规则两处不一致 |

内容红线那块的填对判据是能判真假。内容要优质判不了；不编造数据、技术结论可溯源、时效性内容标注来源与日期，这三条判得了。

流程纪律那块，本仓写的是：工作日全自动只跑到出审为止，发布必须人审通过。这句话和第 01 课那两处闸门讲的是同一件事，分工不同。契约里写具体停在第几步，总纲这一句给的是所有阶段共同的边界。往流程里加一段新的时候，总纲那句已经把它罩住了，不用等新契约写完才有约束。

五块的内容是你的，组织成文件交给 AI。

```
我在建一条内容生产流水线的仓库，要写一份 CLAUDE.md，它是你每次开工前
必读的总纲。下面是我口述的五块：
<第一块 系统一句话：这套东西由哪几条线组成，每条从哪开始、停在哪>
<第二块 干活前必读：每次动手前必须读的文件路径，逐条列>
<第三块 内容红线：什么情况直接重做，逐条列>
<第四块 流程纪律：哪些动作你不能自己拍板，各自停在哪一步>
<第五块 文档架构约定：一条规则写在哪、写几处>
整理成 CLAUDE.md，五节，一块一节，顺序照上面。
每一条都要能判真假。判不了真假的条目单独挑出来列在末尾让我改，
不要替我改成一句听着更完整的话。
第三块和第四块里，凡是我说了要停、但没说停在哪一步的，标出来问我。
最后单独列一节：这份文件里哪些句子你读了也不会改变做法。
```

拿到结果做两件事。判不了真假的条目逐条改，改不动就删。最后那节列出来的句子直接删掉，别留着凑完整。

AI 干活时反复来问你一些 `CLAUDE.md` 里已经写过的事，多半是那几条写得判不了真假，它读完不知道该怎么办。

总纲给的是全局边界。每一段具体吃什么、吐什么，写在契约里。

## 3. 一份阶段契约只写四件事

契约和操作细节要分开住，因为它们的变化频率差着一个量级。配音换个模型、录屏改个参数，一个月能改三次；选题这一段吃什么、吐什么，半年不动。写在同一份文件里，改一次参数就动一次契约，你每次都得回头确认另外四份和总纲还对不对得上。参数改动不该付这个成本。

一份阶段契约只写这四件：

- 输入：这一段开工要读哪些文件，逐条给路径。
- 输出：跑完在磁盘上留下什么，哪些必产、哪些按需。
- 状态翻转：这一段结束时这条内容的状态从什么变成什么，由哪条命令改。
- 闸口：这一段有没有必须停下来等人的地方，停在第几步。

`pipeline/` 下还有一份 `daily-run.md`，它是编排文件，不算阶段契约。它写的是当天的顺序：先取哪条题、按什么优先级取、跑到哪一步为止。四件事那把尺子不往它身上套。

操作怎么做住别处。本仓放在 skill 里，就是第 02 课装的那种写给 Claude Code 读的说明书。你也可以先放一份普通的 md，位置不重要，别和契约混在一起就行。

体量上有个参考：本仓最长的创作契约 85 行，最短的选题契约 22 行。契约短是常态，写长了大概率是把操作细节写了进去。

选题契约的开头就写死了这条纪律：“执行细节全在 skill，本文件只钉阶段契约，不复述步骤，两处各写一份必漂移。”

漂移是这么发生的：同一条规则写在两个文件里，某天你改了其中一处，另一处没动。过一个月你自己也不记得哪份是新的，AI 读到哪份算哪份。

不复述的做法是引用。本仓有三处现成的样子。

第一处，合法状态值只定义在一个地方，五份契约一律写一句见 `media flip --help`。`media` 是第 12 到 16 课要造的命令行工具，管取题和状态记账，眼下它还只是个名字。契约里先按名字指路，不影响你现在把契约写完，但要在旁边注明这条命令还不存在，在那之前状态靠手改 `meta.yaml`，是临时做法。不注明的话，AI 跑到这一步会去试这条命令，试不到就自己编一套状态值出来。

第二处，发布物料那几个字段长什么样、什么时候产，定义在创作契约 `pipeline/2-create.md` 的终检闸里。发布契约 `pipeline/4-publish.md` 只写一句以那里为准，本阶段只消费不产。

第三处，踩坑的故事只登记在 `pipeline/lessons.md`，一坑一行；契约里相关的那条规则后面标一个编号回指过去，写成 `(L5)` 这样。故事和规则分开放，规则那一句才不会被越写越长的来龙去脉埋掉。

生成之前先记住三条删除判据，拿到结果照着删：复述了另一份文件里已经写死的规则，改成一句引用；写成了操作步骤的，挪去操作那一份；列出了状态值完整清单的，删掉，只留这一段从什么变到什么。

```
我要写五份阶段契约，放在 pipeline/ 下。每份只写四件事：
输入（这一段开工要读哪些文件，给路径）、
输出（跑完在磁盘上留下什么，标必产还是按需）、
状态翻转（这一段结束时这条内容的状态从什么变成什么，由哪条命令改）、
闸口（有没有必须停下来等人的地方，停在第几步）。
下面是我口述的五段：
<逐段口述：段名、输入、输出、状态怎么变、停不停>
每份契约照上面四件事分四节，一节一件。
操作细节不要写进契约。你觉得非写不可的那些，单独列在末尾，
我来决定它该住哪个文件。
路径写我给过的原文，我没给的写：待定。不要补一个看着合理的路径。
最后单独列一节：这五份里哪几句话在两份文件里各写了一遍。
```

最后那节列出的重复项，每一处挑一个位置留下，其余改成引用。留哪一处的标准只有一条：这条规则要改的时候，你只需要改一个地方。

五份契约里每份都带着一段完整的状态值列表，多半是你口述时把状态说成了一串名词。改成只说这一段从什么变到什么。

契约讲的是文件之间怎么交接。这些文件本身长什么样，还没定。

## 4. 内容目录的六份文件与选题池头部

一条内容一个目录，路径是 `content/<日期>/<slug>/`。日期是建目录时定下的计划发布日，真发布延后了也不改目录名；`slug` 是第 01 课起的那个代号，同时当目录名。新建一条内容就是把 `content/_template/` 整个复制过去。

模板真正定下来的东西，是每份文件旁边那三个标注：谁产、什么时候产、是不是必产。

| 文件 | 谁产 | 什么时候产 | 必产吗 |
|---|---|---|---|
| `meta.yaml` | 取题那一步 | 目录被建出来的同时 | 必产 |
| `1-brief.md` | 取题那一步，从选题池条目回填 | 同上 | 必产 |
| `2-script.md` | 创作 | 阶段 2 | 必产，口播稿的唯一真相源 |
| `3-review.md` | 人审 | 阶段 3 有意见要留时 | 按需，一次过审可以不建 |
| `4-publish.md` | 创作 | 出审之前 | 必产 |
| `5-retro.md` | 复盘 | 发布之后 | 第 21 课那条线填 |

内容目录里这份 `4-publish.md` 的时机是从一次事故来的。有一条内容出审时没产它，人在飞书点了通过，紧接着的确认发布卡当场报缺标题，发不出去。它编号排第 4、名字又叫发布，很容易被当成阶段 4 才产的东西。它归创作那一段产，出审之前必须在。这条教训在本仓登记为 L5，创作契约的终检闸里标着这个编号。

`meta.yaml` 是这条内容的状态真相源。交给 AI 生成之前，你得先把字段定下来：`slug`、标题、类型（口播还是图文）、`status`、这条题的来源、计划发布时间、发布之后回填的链接，再加一组时点，每个状态各记一个日期。

状态只写在 `status` 这一个字段里，不靠目录位置表示阶段。这条约束的理由在打回：一条内容被人审打回时，状态从 `review` 回到 `drafting`，目录一动不动。要是拿目录表示阶段，打回就得挪目录，所有指向它的路径全断。

进不进版本库也在这一层定。上面这六份都进。干活时的临时目录 `build/`（创作时装网页工程的地方）不进，`assets/` 里的成片 mp4 也不进，一条视频几十兆，版本库撑不住几个月。`assets/` 目录本身进，封面这类小文件留在库里没问题。

选题池那一头，`content/_backlog/backlog.yaml` 是候选题的唯一真相来源。头部四件事写在文件最上方的注释里，让每个改它的人先看见。

1. 这个文件管什么：所有候选题、它们的状态、发布后回填的数据都在这一个文件里，不散到别处。
2. 两层状态各管什么：池子管粗粒度的 `idea`、`picked`、`published` 三态，加上 `rejected`、`expired`、`archived` 三个异常态；内容目录的 `meta.yaml` 管细粒度状态，池子不镜像它。
3. 取题指针：一个 `next_up` 字段，人钦点下一条做哪个就填它的 id，取题之后置回空。这就是第 01 课说的人出现的第一种位置，事前给条件，人不在流水线照跑。
4. 字段说明：一行一个字段，写清它是什么、什么时候被填。至少要有 id、标题、这条走深度还是流量、形式是口播还是图文、状态、取题后回填的内容目录路径、打分、去重比对用的标签、入池日期。

第 2 条不写清楚，当天就会撞上：同一条内容在池子里写着 `idea`、内容目录的 `meta.yaml` 里已经是 `drafting`。这种情况多半是取题那一步只建了目录，没回头改池子。分工写在池子头部，改它的人第一眼就看得见该改哪一层。

骨架到这里齐了。

## 5. 让 AI 只读契约复述一遍

验收动作是让 AI 只读你的契约，把这条流程复述出来。你自己读不出缺口，缺掉的那部分在你脑子里，读到那儿会自动补上。AI 手上只有文件。

```
读 pipeline/daily-run.md 和 pipeline/1-ideate.md 到 4-publish.md 这五个文件。
只读这五个，不要推测文件里没写的事。
输出两样东西。
第一样是一张表，一行一个阶段，四列：阶段名、契约文件、输入文件、输出文件。
文件路径必须在这五个文件里原样出现过，找不到的格子写：契约里没写。
第二样是一份清单，列出所有会停下来等人的位置，一条一行，每条写清三件事：
在哪一步、由什么触发、人要做什么决定。
只列这五个文件里明确写了要停下来、或者要通知人的位置。
```

拿到结果核三点，问法和第 01 课核流程图时是同一套，换了输入。

第一点，表里的文件路径挑三条去仓库里查在不在。契约里提到一个目录名，它很容易补成一个看着合理的完整路径。

第二点，会停下来的位置有没有漏掉异常那一类。常见结果是它只列出出审和确认发布两道闸，撞了墙要喊人的那几种没列进去。真出现这种情况，回头看你的编排文件是怎么写异常的：写成出错处理，它就会当成实现细节收走。

第三点，凡是它写得比契约还完整的地方，都去对一遍原文。它补出来的通常是你的契约没写清的部分，这些地方比那张表本身更值得改。

这三点各自落到一条能判真假的判据上：表里的路径要能在那五个文件里原样查到；会停下来的位置条数，要和你第 01 课那份人出现点清单对得上；表里不出现任何契约没写过的文件名。三条都过了，这轮骨架才算写对。

对上了就 `git init`，把临时目录和媒体本体挡在版本库外面。

```
# .gitignore
content/*/*/build/
content/*/*/assets/*.mp4
```

现在这个仓库能被 AI 读懂了：流程分几段、每段吃什么吐什么、在哪儿停下来等人。它不知道的是内容本身。这条题该不该做、这段话该用什么口气说，眼下还只在你自己脑子里。这些判断依据写在哪？
