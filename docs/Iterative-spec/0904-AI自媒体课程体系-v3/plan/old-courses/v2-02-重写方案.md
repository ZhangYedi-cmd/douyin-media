## 一、现状诊断（对照数据）

| 维度 | 我们的 18 课（现状） | 《AI架构师》实操篇 | 差距 |
|---|---|---|---|
| 单篇说明文字 | 均值 6.9k 汉字，最长 8.4k | 均值 3.6k（第 6 章）~ 6k（第 7 章） | 约 2 倍 |
| 单篇代码行 | 均值 280 行 | 均值 170 行 | 1.6 倍 |
| Prompt 位置 | 集中在倒数第二节（"提示词引导第一步/第二步/第三步"、"三套核心提示词模板"） | 内联在每个动作步骤里，一步一段 | 结构性差异 |
| 每步的人工核对点 | 基本没有 | 每个 Prompt 后跟"拿到结果后审查哪两点" | 缺失 |
| 排障句（"如果你…多半是…"） | 18 课合计 18 处，13 课为 0 | 每篇 2–5 处坑点先行 | 缺失 |
| 先清单后代码 | 无 | 6.2/6.3/6.4/6.7 原句级复现 | 缺失 |
| 开篇契约（输入/产出） | 痛点铺陈 2–3 段 | "本节输入是 X，产出四部分…" | 缺失 |
| 收尾 | "总结与课后作业" | 一句本节盲区 + 下节补什么 | 形式差异 |
| 数据来源 | 07 课出现"75%/18%/4%"轮次成功率表、"60%–70% 首轮直通"等无来源数字 | 引用外部实验并标注口径（METR、HTTP Archive、"自报数据"） | 违反项目「不臆造数据」红线 |

结论：现有课程是"解释型"（讲机制 → 讲规范 → 末尾给模板），《AI架构师》是"施工型"（每一步都是让 AI 干一件事、人审一件事）。两者不是篇幅差异，是叙事单元不同。

## 二、单篇写作范式（从《AI架构师》抽出，作为每篇的硬约束）

**叙事单元 = 一个动作步骤**，每篇由 3–6 个动作步骤串成。每个步骤固定四段：

1. **为什么要这一步**（1–2 段）。只讲到能让学员判断"AI 交回来的东西对不对"的程度，不展开原理。
2. **让 AI 做什么**。内联一段短 Prompt（10–20 行），只针对当前这一步。凡是产出物有多种可能的，先让 AI 出清单/方案，人确认后再让它生成。
3. **拿到结果后审查什么**。明确 2–3 个人工核对点（"重点看可选字段的默认行为是否覆盖"、"复合状态谁优先"）。
4. **AI 几乎必然漏的点**（可选）。以"如果你发现 X，多半是 Y"的排障句给出。

篇级结构：

- **开篇契约**（1 段）：承接上一课产出 + 本课输入是什么 + 本课产出几件东西。不写痛点故事。
- **一个记忆锚点**：每课立一个判据/公式/三分法，全篇内容都归到它下面（如"验证信号流向人还是流向 AI"、"结束条件能否强校验"）。
- **动作步骤 × 3–6**（上面四段式）。
- **沉淀动作**（1 节）：本课验证过的规则补进 Skill / CLAUDE.md，给沉淀 Prompt。
- **收尾**（1–2 段）：本课做到了什么、还看不到什么、下一课补它。不写"总结与课后作业"节；作业如保留只给 1 条，且是"用本课方法处理你自己的项目"。

篇幅上限：实操篇 4.5k 汉字 + 200 代码行；方法论篇 4k 汉字、代码不超过 30 行。

其他硬约束：
- 代码块只用来展示"AI 交回来应该长什么样"，供对照，不是让学员读源码。
- 零编造数字。没有真实来源的统计一律删；项目真实数据可用但要注明"本仓库 N 条内容的观察"。
- 标题按内容自然命名，不带"第一步/WHAT/WHY"这类模板前缀。

## 六、每课动作步骤草案（供审，写作时按此展开）

格式：承接/输入 → 产出 → 动作步骤（AI 做什么 / 人审什么）→ 仓库材料 → 沉淀。

**L1 一条内容的端到端走查**（方法论，≤4k 汉字）
- 承接：无。输入：一篇技术文章。产出：一张链路图 + 人出现点清单。
- 步骤：① 把 daily-run 的执行步骤翻成"一次内容从取题到发布"的走查（仿 8.1 §4），标出 AI 自行的步骤与停下等人的步骤 ② 让 AI 读 `pipeline/*.md` 列出每阶段的输入/输出文件，人核对"哪几步是停下等人的"，状态值一律不展开（留到 L9） ③ 引出全课主线：人从哪里退出、凭什么敢退，下一课先动手把这条链跑一遍。
- 材料：`pipeline/daily-run.md`、`pipeline/1-ideate.md`～`4-publish.md`。

**L2 用开源 Skill 跑通第一条内容**（实操，原 03+04 合并，≤4.5k 汉字）
- 承接 L1。输入：`2-script.md`。产出：`build/` 网页、`audio-segments.json`、分段 mp3、`final.mp4`、`cover.png`。
- 步骤：① 写口播稿，人审"冷开第一句是否自成立" ② 让 `web-video-presentation` 做网页，它会停下对齐 5 件事，人只在这 5 点确认 ③ `npm run extract-narrations` 抽分段，人审"段数与动画步数一致" ④ `tts-dub` 合成，只讲三条纪律：先单段探余额、改文案必重抽再删旧 mp3、config 从 `brain/tts.config.json` 复制 ⑤ `npm run record` 录屏 ⑥ `baoyu-image-gen --ref` 出封面。配音参数、注音语法、封面风格细节各一段，指向 skill 文档。
- 收尾：这条链路跑通了，但每一步对不对都是你在听、你在看，AI 做完一步就停下等你。下一课给这个状态起名字，再说怎么走出去。
- 材料：`pipeline/2-create.md` 分支 A、`.claude/skills/web-video-presentation`、`tts-dub`。

**L3 验证信号流向谁**（方法论，短篇 ≤3k 汉字，原 02 瘦身）
- 承接 L2。输入：学员刚跑完的那条链路。产出：一句判据 + 一张"本链路每步验证信号现在流向谁"的表。
- 步骤：① 回放 L2：五个对齐点、每段 mp3 试听、录屏后看成片，全是人在收验证信号，这就是 Agent 形态 ② 四代演进（chatbot / agent / harness / loop）只用一刀切开：验证结果回给人还是回给 AI ③ 让 AI 把 L2 链路每一步列成表，人填"这步的验证信号现在是谁在收、能不能改成机器收"，填不出机器方案的留到 L4 ④ 收尾：模块 3 的三课就是把这张表里"人在收"的格子一个个改成"机器在收"。
- 不讲：状态迁移表、meta.yaml 状态值，这些移到 L9 状态真相源里讲，那时学员手里已经有需要记账的东西。
- 材料：L2 的 `build/` 产物、`pipeline/2-create.md` 分支 A 步骤 1–5。

**L4 反馈信号从哪来**（实操，原 05 改写）
- 承接 L3（那张"谁在收信号"的表）。产出：一张"配音批次的检查点表"（哪些可机器判、哪些留给人）+ 一个最小检测脚本。
- 步骤：① 让 AI 列出配音批次所有可能出错的点，人把它们分成"可写成断言"与"只能主观听" ② 对可断言项让 AI 写检测（以 `silencedetect` 找 >0.45s 段内死气为例），人审输出是否机器可读、阈值有没有来源 ③ 讲"真假离群"：含英文词的段语速字面偏慢是统计假象，判据要能区分 ④ 坑：ffmpeg 原地写入静默失败 exit 0（L16），所以"跑完必复扫验数"是规则不是建议。
- 收尾：信号有了，但现在是生成者自己跑检测自己判。下一课把判的人分出去。
- 材料：`.claude/skills/dubbing-check/SKILL.md` 检查点 2.1/2.2/2.3/2.4/1.2/3.1、`pipeline/lessons.md` L16。

**L5 裁判与选手分离**（实操，原 06）
- 承接 L4。产出：`.claude/agents/dubbing-reviewer.md`。
- 步骤：① 为什么生成者自评会自洽（机制推理，不引数字） ② 让 AI 起草 agent 定义，人审三处：tools 里有没有 Edit/Write（必须没有）、输出格式是否固定（VERDICT / ROUND / BLOCKING 每条带改法）、有没有"保守裁决"规则（每次 FAIL 消耗一轮重合成） ③ 派一次真实审批，人对照 reviewer 的 BLOCKING 是否可直接执行。
- 材料：`.claude/agents/dubbing-reviewer.md` 原文。

**L6 自愈回路与三轮熔断**（实操，样板课）
- 承接 L5。产出：跑通一次 FAIL→修→重合成→复审的回路，以及满 3 轮的停机动作。
- 步骤：① 回路时序：主回话合成 → 派 reviewer → FAIL 带改法 → 主回话按改法修（overrides / normalize / segment-overrides / 组件整句）→ 重合成 → 复审带轮次号 ② 三类真实缺陷各给一个修复动作与坑（死气→depause 不能原地写；多音字→按段注音，增删段必重排 overrides 键 L18；同段两读→改文案并三处同步 L17） ③ 熔断：为什么要有上限用机制说（不收敛的原因是结构性的，继续跑只会破坏已修好的段），上限取 3 是项目约定不是统计结论 ④ 满 3 轮的真实动作：停、reviewer 报告写进 `3-review.md`、`meta.yaml` 停在 drafting、飞书上报（daily-run 阻塞铁律：只写日志不算上报）。
- 必删：现有 07 课的轮次成功率表、"60%–70% 首轮直通"、`drafting_blocked` 状态、`npm run resume` 命令，仓库里都不存在。
- 材料：`pipeline/2-create.md` 步骤 3–4、`pipeline/daily-run.md` 阻塞即上报、`lessons.md` L9/L10/L16/L17/L18。

**L7 人审闸口**（原 08）
- 承接 L6。产出：飞书审核卡 + 按钮闭环。
- 步骤：① 判据"可逆 AI 自行，不可逆等人"，列出本链路哪些动作不可逆（发布、放量） ② 让 AI 按 `3-review.md` 人审清单起草卡片字段，人审"卡片给的信息够不够 30 秒内拍板" ③ 按钮回流：通过→approved，打回→drafting 带原因。
- 材料：`pipeline/3-review.md`、`.claude/skills/feishu-notify`。

**L8 发布 Skill 与 dry-run**（原 09 压缩到 3k）
- 步骤：① dry-run 铁律：先打印要执行的命令与物料清单 ② 确认发布卡是第二次人确认 ③ 发布收尾是唯一记账点（`media publish-done`）。
- 材料：`pipeline/4-publish.md`、`.claude/skills/douyin-publish`。

**L9 状态真相源与 media CLI**（原 11 + 原 10 + 原 02 的状态迁移表）
- 步骤：① 真相源 = 各 `meta.yaml` + `backlog.yaml`，`dashboard.md` 是派生 ② 让 AI 读 `state.ts` 说出迁移表的三个字段各管什么（requiresReason / line / viaCommand），人审"非法迁移是否被拒" ③ 一节讲为什么是 CLI 不是 MCP：按需 `--help` 不占上下文、人/脚本/AI 共用同一入口。
- 材料：`state.ts`、`media --help` 输出。

**L10 双线闭环与账号大脑**（原 12）
- 步骤：① 生产线消费、治理线保养 ② `brain/` 五个文件各管什么，让 AI 起草 positioning/persona，人审 ③ 治理线铁律：只产报告与提议，人审后回写。
- 材料：`brain/*.md`、`harness/tasks.md` 开头。

**L11 复盘归因**（原 13）／**L12 选题池**（原 14）／**L13 治理总调度**（原 15）／**L14 无头作业**（原 17）
