# 装备：十件开源件的来源、装机命令与三层自检基线

上一课的产出是 `docs/00-walkthrough.md` 里的两样东西。一张流程图，把一条内容切成选题、取题、创作、出审、发布五段，跨段交接的全是文件。一份人出现点清单，三种位置：事前在选题池顶上写一行指针指定先做哪一条、闸门上拍板（出审和确认发布两处）、异常时被叫醒。清单后面还挂了一张交审前的终检表，编号 A 到 G 七项，逐项标明归脚本还是归人，其中 E 是封面必须竖版 9:16。

那张图上现在一件工具都没有。这一课装十件，并且给每一件配一条能判真假的自检命令。

上一课划人和脚本的边界时用过一条准则：这一项的结论能不能被一条命令判成真假。装好了这三个字，按同一条准则处理。

## 1. 十件工具挂在流程图的哪一站

这十件工具各自钉在流程图的某一站上。装它的理由是那一站没它就断。

| 工具 | 来源 | 顶在哪一站 | 少了它哪一步跑不动 |
|---|---|---|---|
| Claude Code | [官方安装文档](https://code.claude.com/docs/en/setup) | 全线 | 所有 skill 都跑在它里面，它不在就没有流水线 |
| Node 20+ 与 npm | [nodejs.org](https://nodejs.org/en/download) | 取题、创作 | 录屏用的网页工程和后面第 12 到 16 课你要造的那个命令行工具都是 Node 的 |
| uv | [Astral 官方文档](https://docs.astral.sh/uv/getting-started/installation/) | 出审、发布 | 发布引擎和飞书服务是 Python 的，环境和依赖靠它管 |
| ffmpeg 与 ffprobe | [ffmpeg.org](https://ffmpeg.org/download.html) | 创作 | 配音质检读不出时长和静音，音画核对抽不了帧 |
| web-video-presentation | [ConardLi/garden-skills](https://github.com/ConardLi/garden-skills) | 创作 | 口播稿变不成能录屏的网页 |
| baoyu-image-gen | [JimLiu/baoyu-skills](https://github.com/JimLiu/baoyu-skills) | 创作 | 出不了竖版 9:16 封面，终检表 E 那一项过不去 |
| agent-reach | [Panniantong/agent-reach](https://github.com/Panniantong/agent-reach) | 选题 | 选题没有素材来源，池子会空 |
| social-auto-upload | [dreammis/social-auto-upload](https://github.com/dreammis/social-auto-upload) | 发布 | 发布那一步唯一真正动抖音的东西 |
| 飞书自建应用 | [开放平台](https://open.feishu.cn/app) | 出审、确认发布 | 两处闸门的卡推不出去，按钮也回不来 |
| TTS 引擎 | MiniMax 或 OpenAI | 创作 | 每段口播没有声音 |

表里的 skill 指一份写给 Claude Code 读的说明书，放进 `.claude/skills/` 下的一个目录，它按名字调用。第 05 课起你自己要造的那几个，形式也是这个。

前四件是底座，一次装齐，后面每一站都在用它们。Claude Code 是唯一一件所有站点都直接调用的，另外三件按表里标的那几站出现。这张表的用处是排查：某一站单独坏了，先查表里标着这一站的那几件；几站一起坏，查底座。

ffprobe 和 ffmpeg 是同一个包里的两个命令，配音质检靠 ffprobe 读音频时长和静音段，抽帧核对音画才用 ffmpeg。有些精简发行版只打包了 ffmpeg。如果质检脚本报的是找不到 ffprobe，多半是装了这种精简包，换完整版重装一次就好。

飞书那一件在开放平台申请，产物是三个字符串加一个群 id，不是一个二进制。

## 2. 装机命令的出处

最糟的做法是凭印象把命令写进自己的文档。包名记成两年前那个，参数从一篇转载博客抄来。这类命令在你自己机器上一跑就过，因为那台机器早就装好了，命令跑没跑其实无所谓。换到一台干净的机器上，得到的是一串 command not found。

装机命令是过期最快的一类内容。Claude Code 的 npm 包从 2.1.198 起要 Node.js 22 或更高。用官方那条安装脚本装的是原生二进制，运行时不吃你的 Node 版本。这个区别只写在官方文档里。凭印象写的人会把两种装法说成同一句话，读者在 Node 20 上装 npm 包，看到一条 EBADENGINE 警告，不知道该不该管。

下面两组命令照上面那张表的链接取，取的日期是 2026 年 9 月。你自己动手时重新点一遍链接。

### 2.1 系统底座那四项

```bash
# Claude Code：macOS 13.0+ / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash
claude --version    # 打印出一个版本号就算装上了
claude doctor       # 只读诊断，不开会话
claude              # 首次跑它，走浏览器登录

# Node 20+ 与 npm：官网下 LTS 安装包，或者 brew install node
node -v && npm -v

# uv：Python 环境与依赖管理
curl -LsSf https://astral.sh/uv/install.sh | sh
uv --version

# ffmpeg 与 ffprobe：同一个包，两个命令都得在
brew install ffmpeg
ffmpeg -version | head -1 && ffprobe -version | head -1
```

Claude Code 要账号。官方文档写明免费版不含它，得是 Pro、Max、Team、Enterprise 或者 Console 账号。这一项花钱，课程不给替代路径。

uv 的安装脚本会改你的 shell 配置文件，把 uv 加进 PATH。如果 `uv --version` 报 command not found，多半是当前这个终端还没重新加载配置，开一个新窗口再跑一次。

### 2.2 项目件那六项

```bash
# 两个 skill 仓库（skills 这个命令由 npx 临时下载，不用先装）
npx skills add ConardLi/garden-skills -s web-video-presentation
npx skills add JimLiu/baoyu-skills
mkdir -p ~/.baoyu-skills          # 图片模型的 key 放这个目录下的 .env

# 选题情报
pip install https://github.com/Panniantong/agent-reach/archive/main.zip
agent-reach install --env=auto    # 顺带装 Node.js、mcporter、bird CLI、gh CLI、instaloader
agent-reach doctor                # 逐条列出通道，看哪几条是活的

# 发布引擎
git clone https://github.com/dreammis/social-auto-upload.git
cd social-auto-upload
uv venv && source .venv/bin/activate
uv pip install -e .               # 装完会注册 sau 命令
# patchright 是 playwright 的一个改版驱动，随上一步装进来；下面这条下它要用的 chromium，
# 前面那个环境变量指向国内镜像，不设的话下载常年卡住
PLAYWRIGHT_DOWNLOAD_HOST="https://npmmirror.com/mirrors/playwright" patchright install chromium
cp conf.example.py conf.py
sau douyin login --account main   # 扫码登录，cookie 落到 cookies/ 下，account 名字后面一直用

# 配音引擎，二选一
export MINIMAX_API_KEY=<你的 key>   # MiniMax：支持多音字注音和音高
export OPENAI_API_KEY=<你的 key>    # OpenAI：不支持多音字注音和音高，只能靠改文本
```

飞书那一件没有命令，是六步点击：

1. 在开放平台建一个企业自建应用。
2. 在凭证与基础信息页拿 App ID 和 App Secret。
3. 在应用能力里开机器人，发布应用，把机器人拉进你要收卡的那个群。
4. 在事件与回调里把订阅方式选成长连接，订阅 card.action.trigger 这个事件。
5. 加密策略选不加密，记下 Verification Token。
6. 把这三个字符串加上群的 `chat_id` 填进服务的配置文件。

第 4 步是这六步里唯一有设计含义的。选长连接，飞书主动连到你这台机器上，你不用给它配公网入口和回调地址。通道本身第 19 课才实现，眼下把这四个值拿到手存好就行。配置里还有一个命名空间字段，怎么用也在第 19 课。如果你的飞书应用同时给两个项目使用，还共用同一个群，这个字段要分开填，否则一次点击会被两边的服务同时吃掉。

## 3. 自检分三层：命令在、凭据通、真跑一次

`--version` 打印出来只证明这个二进制在 PATH 上。密钥配没配对、登录态还在不在、这件工具在你给的参数下出不出得了东西，它一样都不管。

按代价把自检分三层。第一层判命令在不在 PATH 上，就是上面两个命令块里的 `node -v`、`uv --version`、`ffprobe -version` 这类，几十毫秒，随便跑。第二层判凭据通不通：配置读到了没有、密钥被对面认了没有、登录态还在不在。这一层要读磁盘，有的还要发一次网络请求。第三层真跑一次出产物，判的是这件工具在你的参数下能出东西，花钱，慢的要几分钟。

十件里底座那四件到第一层就够了，它们不带凭据，`node -v` 打印出版本号这件事本身就是结论。剩下六件要走到第二层或者第三层。

| 工具 | 自检命令 | 期望输出 | 层 |
|---|---|---|---|
| Claude Code | `claude doctor` | 安装健康、设置文件没有解析错误，没有列出待修项 | 二 |
| agent-reach | `agent-reach doctor` | 你要用的那几条通道标成可用 | 二 |
| social-auto-upload | `sau douyin check --account main` | 打印 valid | 二 |
| 飞书自建应用 | 起服务，看它连上没有 | 日志里出现连接建立那一行，且没有鉴权失败 | 二 |
| baoyu-image-gen | 让它按一句提示词生一张 9:16 图，落到 `/tmp/selftest.png` | `/tmp/selftest.png` 存在，且不是 0 字节 | 三 |
| TTS 引擎 | 合成一段十几个字的测试文案，落到 `/tmp/selftest.mp3` | `/tmp/selftest.mp3` 存在，ffprobe 读出的时长大于 0 | 三 |

web-video-presentation 没进这张表。它是一套写给 Claude Code 的方法和模板，装进去就在，没有自己的凭据和二进制，第一次真用它的时候（第 05 课）自然就验了。

第三层那两条不是一条现成命令，是一次带产物的跑批。判据仍然要能被机器读：文件在不在、字节数是不是 0、时长是不是大于 0，这三样都写得成一条 test 或者一次 ffprobe 调用。期望输出写成运行成功、无报错，机器读不了。

如果 `sau --help` 或者 `sau douyin check` 报 command not found，多半是虚拟环境没激活，或者 `uv pip install -e .` 那一步没跑成。官方安装文档把这两条列成排查的第一顺位。

装机当天三层全跑一遍。之后第三层不再全量跑，太贵。第一层随时可跑。第二层那几条要天天跑，因为它们判的东西会过期。

## 4. 会过期的那四项

十件里有四件的自检结论有保质期。其余那些装上就在，除非你自己删掉。agent-reach 是个中间情况：它本体不过期，但它下面挂的几条通道各有各的登录态，`doctor` 报的就是这个。

| 会过期的项 | 会怎么坏 | 坏在哪一步 | 探它的那条命令 | 层 |
|---|---|---|---|---|
| 抖音登录态 | cookie 到期，或者被平台踢下线 | 发布 | `sau douyin check --account main` | 二 |
| Claude Code 登录态 | 登录过期，或者当期额度用尽 | 任何一步 | `claude doctor` | 二 |
| 飞书长连接 | 进程掉了，或者凭证被改 | 出审、确认发布 | 起服务后看它有没有连上 | 二 |
| TTS 余额 | 用完了 | 创作里的配音 | 批量合成前先拿单段试合成 | 三 |

TTS 余额那一行有一笔真实的账。EP13 那条内容做到配音时，MiniMax 接口返回错误码 1008，账户余额耗尽，从配音到出审整段停在那里。改法写进了创作阶段的契约：批量合成前先拿单段试合成探一次余额，返 1008 就停在只差配音的 `drafting` 状态，推飞书报充值，不推审也不硬往下跑。探余额这一下属于第三层，要花钱，但只花一段的钱。

抖音登录态那一行的规矩更硬：cookie 失效不自动重登，`check` 返回 invalid 就停下来等人扫码。扫码这件事要人在场，无人值守的时候这台机器做不了，写成自动重登只会在半夜静静失败一次又一次。

这四项的共同点是它们坏的时候你不在场。上一课那三种人出现位置里的第三种，异常时被叫醒，接的就是这一类，同类里还有选题池空了。2026-06-30 到 07-05 那六天流水线连续空跑，日志里每天记了一行，六天没有人打开过日志。编排文件后来把上报写成铁律，只写本地日志不算上报。

所以这四条探测命令不能只躺在装机文档里当一次性动作。它们要挂到每天跑的那条编排上，探到不对就推消息给人。

推消息这一层自己也会坏。飞书那一条掉了的时候，它没办法通知你它掉了。所以某天流水线跑完什么都没产出、日志里又没有报错，先把这四条探测命令挨个手动跑一遍。

## 5. 让 AI 把清单和自检落成 docs/00-toolchain.md

前面四节的东西现在散在四张表里。这一课的产出是把它们并成一份文件 `docs/00-toolchain.md`，再附一份跑完的自检输出。做法和上一课一样：你口述，AI 整理，你核对。

```
我在建一条内容生产流水线，机器上要装齐这些工具。下面是我手上的四份材料：

<材料一：工具清单，逐行给出 工具 / 来源链接 / 顶在哪一站 / 少了它哪一步跑不动>
<材料二：我实际跑过的安装命令，原样贴>
<材料三：自检命令，逐行给出 工具 / 命令 / 期望输出 / 属于第几层>
<材料四：会过期的项，逐行给出 会怎么坏 / 坏在哪一步 / 用哪条命令探>

整理成 docs/00-toolchain.md，四节，一份材料一节，顺序照上面。
第二节的每条命令后面注明它取自哪个官方页面，给链接。
链接你不确定的，那一格写成：待核对，附我该去看的页面。不要凭记忆补。
第三节的期望输出那一列，凡是我写得含糊的，替我改成一个具体的文件路径
或者一段具体的字符串；改不动的标出来问我。
第四节每一项后面加一列：这一项坏了谁会知道。我没说的写：待定。

最后单独列一节：上面哪些格子是你补的，不是我给的。
```

拿到结果核三件事。

带链接的那些命令，随手挑两条点开对一遍。安装命令是模型见过版本最多的一类内容，写得越顺越要对。

期望输出那一列，凡是留着运行成功、无报错这种话的，换成一个具体的文件路径或者一段具体的字符串。判据要写成机器读得了的样子，人读得懂不算数。

最后那一节列出来的补填格子，逐个问一句这是哪来的。上一课核流程图时用的是同一个问法，答案往往指向你自己还没想清楚的地方。

改完之后从头到尾把第三节那张表跑一遍，输出贴到 `docs/00-toolchain.md` 末尾。全绿的意思是逐条跑过，每条的实际输出和期望那一列对得上。有一条对不上就把它单独记下来，写清是哪一条、实际打印的是什么。

这份输出当天没什么用，刚装完当然是好的。它的用处在几个月后：某一项坏掉的时候，同一条命令，手上有一份当时打印过什么的对照。

十件工具现在都在这台机器上了，各跑各的。选题那件不知道创作那件要什么，发布那件也不知道审核结果写在哪。把它们串起来的那个仓库还不存在。这套流水线的骨架长什么样？
