# 账号大脑：五份 md 与一份配音配置各写什么

上一课的产出是一个能 `git init` 的骨架仓。目录按流程里的角色切，`CLAUDE.md` 分五块。`pipeline/` 下五份阶段契约每份只写四件事：输入、输出、状态翻转、闸口。`content/_template/` 里六份文件各自标了谁产、什么时候产、必不必产，选题池 `backlog.yaml` 的头部写了四件事。最后的验收是让 AI 只读那五份契约，把阶段表和会停下来等人的位置复述出来。

契约管的是文件之间怎么交接。今天该做哪条题、稿子该用什么口气说，这些事契约一个字没提，`brain/` 那个目录还是空的。这一课把它写出来：五份给人和 AI 读的 md，加一份给脚本读的配音配置，一共六个文件。

## 1. 六个文件各归谁读

```text
brain/
├── positioning.md    # 定位：目标人群、内容支柱、深度与流量的配比
├── persona.md        # 人设与语气：第一人称、开口给钩子、术语必须解释
├── style-guide.md    # 规范：时长、结构、字幕封面、违禁词
├── sources.md        # 信息源：抓哪些平台、检索用哪些关键词
├── benchmarks.md     # 对标账号与自己验证过的打法
└── tts.config.json   # 配音配置：音色、语速、缩写念法
```

哪一份由哪一段读，上一课的契约里已经写死了。`pipeline/1-ideate.md` 的输入节列的是 positioning、sources、benchmarks 三份。`pipeline/2-create.md` 的输入节列的是 persona 和 style-guide 两份。`tts.config.json` 不给人读，创作契约 `pipeline/2-create.md` 的第 3 步把它复制进当条内容的工作目录，配音脚本读那个副本。

| 文件 | 谁读它 | 读完做什么决定 | 本课填不填 |
|---|---|---|---|
| `positioning.md` | 选题 | 今天该取深度题还是流量题，这条题该不该做 | 填满 |
| `sources.md` | 选题 | 去哪些平台抓、用哪些词检索 | 填满 |
| `benchmarks.md` | 选题 | 这条题按哪条验证过的打法能加分 | 只写头部 |
| `persona.md` | 创作 | 这段话该用什么口气说 | 填满 |
| `style-guide.md` | 创作 | 视频多长、结构怎么排、封面怎么做 | 填满 |
| `tts.config.json` | 配音脚本 | 用哪个音色、语速多少、缩写怎么念 | 填满 |

`CLAUDE.md` 的干活前必读那一块指的就是这个目录，写明这些是硬约束不是参考。所以这里写的每一句话，都会被读进当天那条内容的上下文。

五份 md 要过同一把尺：每一条都得能变成一个动作。写技术深度和流量型六比四，选题那一步能照着这个数排出今天做哪条题；写以深度为主兼顾流量，同样一句话，它排不出来，只能靠猜。同一把尺在两段上的量法不同：选题读的三份，量的是能不能排出今天做哪条题；创作读的两份，量的是能不能拿它对着写完的稿子逐句核对。

这把尺和 `CLAUDE.md` 里的内容红线管的是两码事。红线管什么情况下这条内容直接重做，比如有没有编造数据；大脑管做什么内容、用什么口气说。红线是否决项，大脑是选择依据。

AI 每天交上来的内容风格飘忽，今天像教程明天像新闻稿，多半是 `positioning.md` 里的支柱写成了几个形容词，它每天读到的约束都一样宽。

## 2. positioning.md：配比要写成能照着取题的数字

这一份决定取题规则，写歪了后面几份跟着歪，所以先写它。本仓这份文件分七节，每节回答一个具体问题。

| 这一节 | 回答什么 | 填对了长什么样 |
|---|---|---|
| 一句话定位 | 这个账号做什么方向 | 一句话说得完，含方向和立身点 |
| 目标人群 | 内容讲给谁听 | 分类列出，每类写清他们想拿走什么 |
| 内容支柱 | 分几类内容，各自什么特点 | 每个支柱写清它长尾还是短时效 |
| 内容比例 | 支柱之间怎么排 | 一个数字比例，选题那一步能照着混排 |
| 形式 | 口播还是图文 | 哪类内容配哪种形式，说得出理由 |
| 发布节奏 | 哪几天出内容，谁来出 | 工作日和休息日分开写 |
| 不做什么 | 什么题一眼否掉 | 每一条能一眼判定 |

内容比例那一节的数字会被下游直接消费。上一课写的选题契约，输入节里 positioning 那一条后面括着一句支柱与 6:4 配比。契约点名要的就是这个数（照这个数把深度题和流量题混排成当天清单的选题技能，第 23 课才造）。写成形容词，这一步就没有输入。

交给 AI 起草的时候别让它直接写文件。产出物有多种可能的时候，它会挑一个自己觉得合理的直接落盘，你只看到结果，看不到它排除了什么。

```
我要做一个抖音技术账号，方向是 AI 工程提效和源码解读。
先不要写文件。给我三个内容支柱的划分方案，每个方案说清楚：
1. 分几个支柱，各自面向哪类观众；
2. 支柱之间按什么比例排产，这个比例怎么落到每天取一条题的规则上；
3. 这个方案的不做清单，写成能一眼判定的形式，比如不做纯搬运。
三个方案要有实质差异，不要同一个方案换措辞。
我选定之后你再写 brain/positioning.md。
```

选定之后审三件事。比例有没有落成一个数字，六比四能照着取题，以深度为主取不了。不做清单里每一条能不能一眼判定，不做无技术增量的纯搬运可以判，不做低质量内容判不了，改到能判为止，改不动就删。有没有编造受众数据。

第三件事几乎每次都会中招。起草出来的目标人群那一节带着规模和增长率，多半是它按训练里见过的市场分析文档在补，这些数字你手上没有，让它删干净。本仓最后留下的不做清单只有三条：不做无技术增量的纯搬运、不做标题党但内容空洞、不碰未经核实的爆料。三条都能对着一条选题当场判真假。

内容做什么定了，怎么说还没定。

## 3. persona.md 与 style-guide.md：写成能对着稿子核对的条目

这两份归创作读。语气住 `persona.md`，形式规范住 `style-guide.md`，分开住的原因是它们的改动频率不一样：语气定下来很少动，时长和封面规范会跟着数据反复调。

`persona.md` 四节：人设一句话、口播语气、图文语气、禁忌。

```
按 brain/positioning.md 的定位写 brain/persona.md，包含四节：
人设一句话、口播语气规则、图文语气规则、禁忌。
约束：
1. 语气规则要写成创作那一步能照着核对的条目，例如第一人称、
   开口三秒给钩子、术语必须解释，不要写生动有趣这类没法核对的词；
2. 禁忌只写能判定的，例如不堆术语装高深、不空喊太强了；
3. 还没定的东西留成待补充清单，不要替我编，例如固定开场白、
   固定结尾引导语、账号自称。
```

第 3 条约束是这份文件最容易出事的地方。编一个固定开场白，它会被写进每一条稿子，等你发现不合适，前面几十条已经这么念完了。本仓这份文件到今天还留着三条待补充，固定开场白、固定结尾引导语、自称与账号名，一条都没编。

拿到结果按下面这张表分拣，判得了的留在正文，判不了的改到能判，还没定的挪进待补充。

| 条目 | 判得了吗 | 怎么处理 |
|---|---|---|
| 第一人称，像跟同行面对面聊 | 判得了，看稿子里的人称 | 留 |
| 开口三秒给钩子，不铺垫 | 判得了，看第一句是不是钩子 | 留 |
| 术语必须解释 | 判得了，扫一遍术语看有没有解释 | 留 |
| 不空喊太强了，要说清强在哪 | 判得了，找到那句看后面有没有依据 | 留 |
| 语气要生动有趣 | 判不了 | 删 |
| 固定开场白 | 现在还没有 | 挪进待补充 |

`style-guide.md` 管六件事，同一把尺换成秒数和张数来量。

```
写 brain/style-guide.md，六节：
标题钩子的套路库、口播时长与结构、字幕与封面、
图文的张数与配图风格、违禁词与合规、视觉资产。
约束：
1. 时长、张数、结构这三节全部给数字或者可数的东西，
   例如时长区间、钩子占几秒、单条几张以内，不要写节奏明快这类词；
2. 标题钩子写成套路名加一个示例句，不要写成固定文案，
   它是拿来套的模子，不是拿来抄的稿子；
3. 违禁词清单和视觉资产这两节，我没给你具体内容的就留成待补，
   不要照着平台公开规范抄一份长清单充数。
```

本仓这份文件里，口播时长写的是 30 到 90 秒，深度内容可以到 2 到 3 分钟；结构写的是钩子占 3 秒、主体分点、结尾给一个可执行的东西或者引导互动；图文写的是单条 6 到 12 张以内、一图一观点。创作完能拿秒表和张数核。

违禁词和视觉资产两节至今写着待补，这是有意留的。平台的公开规范抄得到，抄来的那份和你实际会被判违规的点对不上；哪些词真的会踩线，要发过内容、被判过一次才知道。留白等着一次加一条，比先摆一份长清单每天进创作上下文有用。封面模板同理，得有几条内容验证过风格才定得下来。

下一课开始写稿之后，如果口播稿第一句念出了赛道配比这种内部规则，多半是整份 `positioning.md` 被当素材塞进了创作 Prompt。这几份文件是用来给 AI 定行为的，整篇喂进去它就会漏出来。创作那一步引用 `persona.md` 的语气条目就够，定位文档不用贴。

说什么和怎么说都定了，素材从哪来还没定。

## 4. sources.md：素材源与三层关键词矩阵

选题读这一份，读完要能直接开抓。所以它得写成检索时能当参数用的词表，光写平台名单不够。

它分三块：素材源、关键词矩阵、对标账号。第三块转指 `benchmarks.md`，下一节讲。

素材源按用途分两类写。流量时效那一类是各家实验室的官方账号、社区热议帖、模型发布页，抓的是今天有什么新东西；深度可沉淀那一类是代码托管平台的趋势榜和论文站，抓的是值得讲透的东西。如果两类混在一起列成一个平台清单，选题那一步就分不清今天该往哪边抓。

关键词矩阵分三层。

```
按 brain/positioning.md 的两个支柱写 brain/sources.md 的关键词矩阵，分三层：
Layer A 平台体裁词：看同类内容在这个平台上以什么形式在火，5 个左右；
Layer B 深度域词：对应技术深度支柱的具体技术名词，10 个左右；
Layer C 流量信号词：追新闻和新模型热度的词，7 个左右。
每层给词就行，不要写解释性长句。
词表下面加一句：这是起步值，复盘时标注哪个词出的选题更火，动态增删。
如果某一层你凑不满，就少给几个，不要用近义词凑数。
```

三层各自的判据不一样。Layer A 判的是这些词描不描述得了内容形式，实测、效率、工具这类词落到检索上，捞回来的是别人用什么形式做这个题。Layer B 判的是这一层里有没有具体到能检索的词，宽词也留着，它们同时是给选题归类用的标签，但一层里全是宽词就检索不出东西。Layer C 判的是时效，这一层的词半年之后大概率要换一批。

本仓这份文件里还有一句注记：抖音主站反爬重，无法无人爬，所以本账号不再爬平台，关键词改作两用，一是给检索当种子，二是给选题归类当标签。这句话记的是一条走不通的路。写进文件之后 AI 每轮就不会再去试一次，不写，它每轮都要重新发现一遍。

前四份填满了，第五份只写头部。

## 5. benchmarks.md：现在只写头部，正文留空

对标账号是谁、哪条打法有效，这两件事要有数据才写得出来。你现在一条内容都没发，手上没有任何一条属于自己账号的数据。这时候填进去的东西全是从别处看来的经验，而它会被当成打法用在之后每一轮的选题打分上。

头部四行写清楚这个文件管什么、谁能改、什么时候长出第一行、每条打法要带什么。

1. 管什么：对标账号、爆款拆解、自己验证过的有效打法。
2. 谁能改：复盘那一段只产变更提议，人审通过之后才落到这个文件里。
3. 什么时候长出第一行：第一批内容发出去、复盘拉到数据之后。
4. 每条打法必须带什么：证据是哪几条内容、几个数据点同向、报告文件路径。

第 4 条决定这份文件三个月后还能不能用。本仓现在的打法条目都长这样：结尾给具体行动号召能撬评论和涨粉，证据写的是七个数据点同向，正面举了哪一条内容，反面举了另外三条，其中一条的评论数在 24 小时、72 小时、7 天三个时间窗都是 1，末尾给出报告路径 `harness/logs/2026-07-17-retro.md`。带着这些东西，过几个月你还判断得出这条打法该不该删。

文件末尾还要留一节放证据不够的观察项，标注勿当打法用。有些现象只有一两个数据点，删掉可惜，写进正文又会被当成定论，给它们一个单独的位置最省事。

留空是有代价的。本仓这份文件的有效打法那一栏，第一次填上内容是 2026-07-17，此前空置了二十多天。这二十多天里选题每轮都在读它打分，读到的是一张空表，打出来的分靠的全是没验证过的经验。这句话写在文件的引言里。代价认下来就行，它比一张编出来的表小，但你要知道这段时间的选题分数是什么成色。

五份 md 齐了。还有一份不给人读的配置。

## 6. tts.config.json：音色、语速、多音字住配置

配音有一批参数会经常动：音色换了、语速快了半档、某个缩写念错了、某个多音字读成了另一个音。这些参数全住配置文件，脚本只负责读它。调参数就不用改代码，也不用每次回头确认脚本里还有没有别的地方硬写了同一个值。

| 键 | 管什么 | 什么时候改 |
|---|---|---|
| `provider` | 用哪家的合成服务 | 换服务商时 |
| `voice_id` | 账户里的克隆音色编号 | 换音色时 |
| `speed` 与 `pitch` | 全局语速和音高 | 整体听着快了或慢了 |
| `normalize` | 缩写的念法规整 | 听到某个缩写念错时 |
| `pronunciation` | 全局多音字注音 | 不改，多音字一律走 overrides |
| `overrides` | 按段覆盖语速、音高、注音 | 合成完发现某一段离群时 |

`normalize` 和 `pronunciation` 分工不同。`normalize` 只改送去合成的那份文本，字幕源文件一个字不动，所以把 `RAG` 写成 `R A G` 之后，念的是三个字母，屏幕上还是三个字母连着的原样。这条分工要写在配置的说明里，不写，改的人会直接去改稿子，字幕跟着变成 `R A G`。

`pronunciation` 这一栏本仓留空，多音字一律走 `overrides` 逐段处理。全局注音会误伤：同一个字在不同段落读音不同，全局写死一个，另一段就错了。`overrides` 的键是段落编号，改哪段注哪段（哪些段算离群、怎么量出来，第 07 到 08 课造检查脚本时再讲）。

这份配置住在 `brain/` 下当账号级模板。创作开工时把它复制进当条内容的工作目录，那条内容特有的多音字和单段语速加在副本里；确认是通用规则的，再回写到 `brain/` 这份模板。

`voice_id` 眼下只能从服务商控制台复制过来，别手敲。下一课装上配音技能之后，这条命令能列出账户里所有可用音色，拿它核一遍：

```bash
node <tts-dub 技能路径>/scripts/list-voices.mjs
```

编号抄错一个字符，要到合成那一步才报错，那时候你已经写完稿子做完网页了。

六个文件都在磁盘上了，得验一遍。

## 7. 让 AI 只读 brain/ 复述判据

验收动作和上一课是同一套，换了输入：让 AI 只读这六个文件，把它读完能据以做决定的东西列出来。交给它做，是因为它只能看到文件里写下来的字，你还带着一堆没写下来的默认解释。

```
读 brain/ 下的六个文件，只读这六个，不要看仓库里其他任何文件。
输出两栏。
第一栏：你读完能据以做出判断的条目，一条一行，每条写清
它出自哪个文件、你会用它做哪个决定（取题 / 写稿 / 配音）。
第二栏：你读到了但判不了真假的条目，一条一行，
每条写清它出自哪个文件、为什么判不了。
两栏都只许写这六个文件里原样出现过的内容，不要补充、不要给修改建议。
最后回答两个问题：
按这六个文件，今天该取一条深度题还是流量题，依据是哪一句？
一条口播稿写完，你能按哪几条逐句核对它？
```

拿到结果核三条，每条都能判真假。

第一条，第二栏里不出现你以为已经填满的条目。留白项掉进第二栏是对的，固定开场白、违禁词清单本来就还没定；正文里填满的条目掉进去，说明那一条写成了判不了的词，回去改。

第二条，最后那两个问题的答案各自指得回至少一行原文。取题那个问题应该指到内容比例那一行的数字，核对稿子那个问题应该列出语气条目和时长结构。指不回具体句子、只回一段概述的，说明这几份文件还停在介绍账号的层面。

第三条，两栏加起来不出现这六个文件里没写过的内容。它自己补出来的那些，通常正是你没写清的地方，逐条回去补进文件，然后重跑一次这个验收。

第二栏本身还有个用处：里面列出的留白项就是你的待补清单，攒够材料回来填。

大脑写完了，AI 知道你要什么内容了。现在真去做一条出来，从稿子到成片要走几步？
