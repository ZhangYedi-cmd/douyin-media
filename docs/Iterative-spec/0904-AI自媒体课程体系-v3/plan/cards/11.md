## 2. 本课要讲什么

1. **全新课，也是全书最重要的一课之一。**六步：调研 → 讨论选型 → 决策 → 写 SPEC → 执行 → 验证。每步解决什么、prompt 怎么写、产物长什么样、卡住的判据是什么。
2. **第 2 步「讨论选型」是这套方法的关键**：AI 列方案时会不自觉把自己想选的写得更饱满，得单独一轮逼它给每个方案找活路——让它扮演每个方案的辩护人，说清这个方案在什么情况下会输。AI 顺着你说，就是没在辩护，换个问法重来。
3. 用一个小例子走完整轮：拿第 08 课那六个脚本回看，如果当初走 SPEC 会多出什么、少踩什么。
4. **本课是后面七门 L3 课（12-16、18-19、27）的唯一参照，它们只引用不重定义。**因此这六件事必须钉死：①六步各占正文第几节、节标题怎么起；②调研节里方案对比表的固定列（方案 / 适用前提 / 代价 / 已知失败模式）；③「讨论选型」那步的 prompt 长什么样；④ADR 的固定四项（决策 / 理由 / 被否方案 / 反悔成本）；⑤执行方案的四节模板，不许各课改写；⑥里程碑出口条件的写法（一句能跑的验证动作，不写「基本完成」）。

## 2.1 大纲

记忆锚点：六步方法的分量都压在「讨论选型」这一步——不逼 AI 给每个方案当一次辩护人，前面摆再多候选也是陪衬。

开篇契约：上一课交付了一次真实的 FAIL → 修 → 重合成 → PASS 全过程记录，Loop 合上了，同时留下一堆手改的 `meta.yaml`；本课输入是十课攒下来的全部经验，尤其第 10 课那次真实的自愈过程；本课产出两件东西：一份 `docs/spec/` 目录约定，和六步方法的四件套模板（调研 / ADR / 执行方案 / 施工记录）。

### 1. 从条 prompt 到大件：什么时候要换挡
- 核心判断：能不能把一件事直接交给一条 prompt，看的是有没有互斥路线、错了返工贵不贵，不看代码行数或字数。
- 二级标题：不分
- 交付物：一张三条判据的清单——有没有一条路线一旦选错就要推倒重来；这件事跨不跨多个文件或多个组件；决策要不要留痕给以后的人看
- 学员此时手上有：第 10 课交付的 FAIL → 修 → 重合成 → PASS 全过程记录；前面十课手改 `meta.yaml` 的真实体感
- 交接：判据摆出来了，进入六步的第一步：调研。

### 2. 调研：把选型空间摊开
- 核心判断：调研不是自由讨论，是让 AI 先列出互斥候选清单，人确认后逐个填进同一张表——表列必须固定，否则后面没法比。
- 二级标题：2.1 让 AI 先出候选清单，人确认再往下走 / 2.2 对比表怎么填：方案、适用前提、代价、已知失败模式
- 交付物：一条「先出候选清单」的 Prompt + 调研模板——固定四列的对比表（方案 / 适用前提 / 代价 / 已知失败模式）
- 学员此时手上有：判据清单（本课第 1 节产物）；第 08 课那六个检测脚本，作为回看素材
- 交接：候选摆齐了，但表里每个方案的优点都是 AI 自己写的，偏向性还没被逼出来，进入讨论选型。

### 3. 讨论选型：逼每个方案当自己的辩护人
- 核心判断：AI 列方案时会不自觉把自己想选的写得更饱满，讨论选型这一步单独存在，就是为了逼它给每个方案找活路——说清这个方案在什么情况下会输。AI 顺着你说，就是没在辩护，换个问法重来。
- 二级标题：不分
- 交付物：辩护式 Prompt 模板（对每个候选依次要求：成立的前提、代价、主动交代已知失败模式，不许下「综合来看」的结论）
- 学员此时手上有：调研节产出的对比表（本课第 2 节产物）
- 交接：每个方案的弱点都被自己说出来了，可以拍板了，进入决策。

### 4. 决策：把选择钉成 ADR
- 核心判断：ADR 只记四件事——决策、理由、被否方案、反悔成本——多写别的就是在替执行方案抢戏。
- 二级标题：不分
- 交付物：ADR 模板（决策 / 理由 / 被否方案 / 反悔成本四项固定），用第 08 课六个检测脚本回看举一条例子——如果当初走了六步，会多出一条「为什么不把六个脚本合成一个大脚本」的 ADR
- 学员此时手上有：讨论选型节的辩护结论（本课第 3 节产物）
- 交接：决策落了纸，但落纸的决策还变不成代码，中间差一份能让 AI 照着施工的规格，进入写 SPEC。

### 5. 写 SPEC：把决策展开成可施工的规格
- 核心判断：执行方案只有四节，节名不许各课改写：实施步骤、命令（或接口/页面）× 功能 × 详细设计、对外契约、风险与待定项。
- 二级标题：不分
- 交付物：执行方案四节模板原文（照抄，不改写）
- 学员此时手上有：ADR（本课第 4 节产物）
- 交接：规格能施工了，但纸面上的规格和真跑起来的东西之间还差一步，进入执行。

### 6. 执行：照 SPEC 交付里程碑
- 核心判断：执行不是一次性把 SPEC 全部实现完，是切里程碑，每个里程碑一个能跑的出口条件。
- 二级标题：不分
- 交付物：里程碑出口条件写法——反例是「基本完成」这类判不了真假的话，正例是「某个动作在真实数据上跑一次，返回什么结果才算过」
- 学员此时手上有：执行方案四节模板（本课第 5 节产物）
- 交接：里程碑出口条件写清楚了，但过了出口条件不等于东西是对的，进入验证。

### 7. 验证：一句能跑的验证动作收口
- 核心判断：验证要验的是「写路径真的只有一条」这类容易自己以为对了的东西，光靠肉眼看代码不够，要留下可以回查的证据。
- 二级标题：不分
- 交付物：施工记录模板——里程碑出口条件对照表（里程碑 / 出口条件 / 实际结果 / 卡在哪 / 怎么绕过去）
- 学员此时手上有：里程碑出口条件（本课第 6 节产物）
- 交接：六步走完一轮了，回头拿这一课自己举的例子对一遍——如果第 08 课那六个脚本当初走过这六步。

### 8. 回看六步：如果第 08 课走过这条路
- 本课做到了什么、还看不到什么、下一课补什么：六步方法定完了，用第 08 课六个检测脚本回看一遍——如果当初先调研、先讨论选型，会多出哪条 ADR、少踩哪个坑；六步只是纸上过了一遍，还没真正拿一件大事练手。
- 结尾抛出的问题：六步方法有了。拿第一件重活来练：状态写入口这件事，先走前三步，调研、讨论选型、拍板，一行代码都不写。
