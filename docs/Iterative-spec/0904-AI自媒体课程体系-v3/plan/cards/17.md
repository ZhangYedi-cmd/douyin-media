## 2.1 大纲

记忆锚点：可逆的 AI 自行，不可逆的等人。

开篇契约：上一课交付了 `docs/spec/media/03-施工记录.md` 和一份验收输出，`media check` 在自己仓库跑通，写路径唯一得到自证；本课输入是 `tools/console/packages/core/src/state.ts` 里 `review` 状态的三条出边、`pipeline/3-review.md` 与 `pipeline/4-publish.md` 全文、`CLAUDE.md` 的「流程纪律」节；本课产出两件东西：一张不可逆动作表、一份卡片字段草案。

### 1. 判据：错了能不能收回，不是会不会犯错
- 核心判断：要不要设人审闸口，问的不是"AI 会不会判断错"，是"判断错了这个动作能不能撤回"。四类动作收不回：发出去收不回、花钱、对外可见、覆盖真相源；剩下的，改错了大不了再改一次，不需要设闸。
- 二级标题：不分。
- 交付物：不可逆动作表（四类判据逐类举本流水线里对应的真实动作：状态翻转 `media flip` 可逆，vs 真发 `sau douyin upload-video` 和记账 `media publish-done` 不可逆）。
- 学员此时手上有：第 16 课交付的 `media check` 通过结论和 `03-施工记录.md`。
- 交接：四类判据定完，接下来要在真实流程里找到这些动作各自落在哪条状态出边上。

### 2. 闸口位置：定在哪条边上
- 核心判断：闸口不是设在"AI 最容易出错"的地方，是设在"出了错收不回"的那条边前面。`review` 状态往 `drafting`（打回重做）、往 `rejected`（打回挂待办）都还能再改回来，连过审后的 `approved` 也能退回 `drafting`；真正不可逆的是 `approved` 之后那一步——`media publish-done` 记账和它背后那一次抖音真发。`pipeline/3-review.md` 写的"工作日全自动只跑到出审"，就是把自动化停在这条边前面。
- 二级标题：不分。
- 交付物：一张状态出边表，标出 `review` 三条出边里哪条可逆（自动可做）、哪条不可逆（必须人）。
- 学员此时手上有：上一节的不可逆动作表；`pipeline/3-review.md`、`pipeline/4-publish.md` 全文；`CLAUDE.md`「流程纪律」节。
- 交接：闸口位置定了，接下来定这道闸具体长什么样——人在飞书上看到什么、点什么。

### 3. 卡片放什么：三十秒判完的信息配额
- 核心判断：卡片要让人三十秒内判完，前提是信息够但不多——哪些字段必须直接上卡、哪些字段点进去看，是这一节要划的线；这份草案不是最终实现，是留给第 18、19 课的约束。这条闸口这一版只做飞书：这是参考仓库的历史实现，需要学员有企业或团队账号才能建自建应用，后面 18、19 课动手前都要确认这一条。
- 二级标题：不分。
- 交付物：卡片字段草案（表：卡片作用 / 上卡字段 / 按钮 / 触发后去哪）。
- 学员此时手上有：第 1 节的不可逆动作表、第 2 节的闸口位置；`pipeline/3-review.md` 的人审清单（事实/时效/定位/语气/合规/观感）。
- 交接：字段草案定了，接下来是把它变成一条能跑的技术通道，这够得上走完整 SPEC 六步。

### 4. 收尾：第二件重活
- 本课做到了什么、还看不到什么、下一课补什么：不可逆动作表划清了什么改错能再来一次、什么不能；卡片字段草案定了人要看什么、点什么。但草案只是字段清单，背后走长连接还是 webhook、卡片具体怎么拆、按钮点下去多久必须有响应、一个应用服务多条业务线怎么防串——一件都还没定。
- 结尾抛出的问题：不可逆动作表和卡片字段草案有了。这是第二件重活，六步再走一遍：飞书通道要定哪几件事？
