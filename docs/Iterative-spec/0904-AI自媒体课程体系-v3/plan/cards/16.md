## 2.1 大纲

记忆锚点：造完不等于造对，唯一入口的证据不是嘴上说的，是 `audit.jsonl` 里能查到的那一行。

开篇契约：上一课交付了全量 `media` 命令和存量迁移记录；本课输入是这套刚收敛完的写入口，加上它跑起来之后新生成的 `audit.jsonl`；本课产出两件东西：`docs/spec/media/03-施工记录.md`，和一份验收输出。

### 1. 开篇：造完了，还没证明造对了
- 核心判断：验证这一步验的不是「代码能跑」，是「写路径真的只有一条」这类容易自己以为对了的东西——光靠肉眼看代码不够，要留下可以回查的证据。
- 二级标题：不分
- 交付物：一句判据——凡是改了状态的动作，都要能在 `audit.jsonl` 里查到对应的一行，查不到就不算数；再举两三种真实会撞的墙作反例（两层状态不同步、发布记录无链接这类）说明为什么不能只靠肉眼看代码
- 学员此时手上有：第 15 课的全量 `media` 命令和存量迁移记录
- 交接：先看怎么留证据——`--dry-run` 和 `audit.jsonl`。

### 2. 留证据：--dry-run 先出计划再执行，audit.jsonl 当账本
- 核心判断：写命令先 `--dry-run` 打印会发生什么变更，人确认了再真跑；每次真跑都会在 `audit.jsonl` 追加一行，这行记录是唯一性自证的原始材料。
- 二级标题：不分
- 交付物：一次 `--dry-run` 的读法（看懂它打印的变更清单）+ 一段 `audit.jsonl` 怎么读（哪个字段对应哪次改动）
- 学员此时手上有：第 15 课全量命令；跑起来之后产生的 `audit.jsonl`
- 交接：知道怎么留证据、怎么读证据了，接下来用它自证写路径唯一。

### 3. 自证写路径唯一：media check 在自己仓库跑通
- 核心判断：模块 3 的出口条件是一句能跑的验证动作——`media check` 在自己仓库上跑一遍，返回退出码，error 级警报为零才算过；这就是全书状态中枢立住的标志。
- 二级标题：不分
- 交付物：一条自证清单（`media check` 退出码怎么读 / 手动改一次 `meta.yaml` 会不会被 `check` 抓出来 / `audit.jsonl` 里能不能找齐最近几次状态变更）
- 学员此时手上有：`--dry-run` 与 `audit.jsonl` 的读法（本课第 2 节产物）
- 交接：唯一性有证据了，最后一件事是把这轮施工的过程记下来。

### 4. 施工记录怎么写：出口条件、卡在哪、怎么绕过去
- 核心判断：施工记录不是流水账，是给每个里程碑一行结论——出口条件是什么、实际结果是什么、卡在哪、怎么绕过去，绕不过去的留给以后的人接着看。
- 二级标题：不分
- 交付物：施工记录模板（里程碑 / 出口条件 / 实际结果 / 卡在哪 / 怎么绕过去），填入 M1、M2 两个里程碑的真实情况
- 学员此时手上有：`media check` 的验收输出（本课第 3 节产物）；第 13 课执行方案里的 M1/M2 出口条件
- 交接：`03-施工记录.md` 落盘，模块 3 收口。

### 5. 收尾：状态中枢立住了，但不是所有动作都能自己拍板
- 本课做到了什么、还看不到什么、下一课补什么：`03-施工记录.md` 和验收输出都落盘了，`media check` 跑通，写路径唯一得到自证；但状态中枢能自己改状态，不代表所有改动都该让它自己拍板。
- 结尾抛出的问题：状态中枢立住了，机器能自己改状态。可有些动作改错了收不回来。哪些动作不能让机器自己拍板？
