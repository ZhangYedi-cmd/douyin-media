### 1. 调研：企业自建应用怎么配，四个决策点是什么
- 核心判断：飞书自建应用的六步配置（建应用 → 拿 App ID/Secret → 开机器人拉群 → 回调订阅选长连接 → 记 Verification Token → 填 config）本身没有选型空间，照做就行；真正要拍板的是四件事——通道形态、卡片怎么拆、按钮回调的超时怎么接、一个应用服务多条业务线怎么防串。这条闸口是参考仓库的历史实现，配自建应用需要企业或团队账号，动手前先确认这一条。
- 二级标题：1.1 六步配置照做；1.2 四个待决策点长什么样。
- 交付物：企业自建应用配置六步清单 + 四个待决策点的识别列表。
- 学员此时手上有：第 17 课交付的卡片字段草案。
- 交接：六步配置是没有选型的照做，四个决策点才是这一课要走六步方法的地方，从通道形态开始。

### 2. 长连接 vs webhook：机器没有公网地址
- 核心判断：选长连接（飞书官方 SDK 的 WebSocket 模式），因为学员机器大概率没有公网地址，走 webhook 要额外接 ngrok/cloudflared 做内网穿透，多一层依赖就多一层失败点。
- 二级标题：不分。
- 交付物：方案对比表（方案 / 适用前提 / 代价 / 已知失败模式），长连接与 webhook 各一行。
- 学员此时手上有：第 1 节识别出的四个决策点。
- 交接：通道形态定了，下一步定卡片本身怎么拆。

### 3. 卡片结构：一张卡还是按流程拆几张
- 核心判断：卡片不是一张卡装完所有字段和按钮，是按状态拆：审核卡（通过 / 打回两个按钮）→ 打回后弹出的原因卡（打回并自动重做 / 打回挂待办两个按钮）→ 过审后的确认发布卡（确认发布 / 取消两个按钮，带最终命令与物料）。四个动作分布在两张卡上，不是塞进一张卡的四个按钮。
- 二级标题：不分。
- 交付物：方案对比表（方案 / 适用前提 / 代价 / 已知失败模式：一张卡装全部字段按钮 vs 按状态拆多张卡）+ 三张卡片的字段与按钮草表。
- 学员此时手上有：第 17 课卡片字段草案、本课第 1 节的决策点清单。
- 交接：卡片结构定了，下一步定按钮点下去之后，这个动作要在多长时间内有响应。

### 4. 3 秒回调窗口：同步只做内存操作
- 核心判断：飞书要求按钮回调 3 秒内返回，超时报错；所以同步路径只能做内存操作和状态标记，真正的重活（起 `claude -p` 重做、真发到抖音）必须甩到异步线程去做。
- 二级标题：不分。
- 交付物：方案对比表（方案 / 适用前提 / 代价 / 已知失败模式：同步路径只做内存操作 vs 同步路径直接跑完重活再返回）+ 一张同步/异步动作分类表。
- 学员此时手上有：第 16 课「状态记账唯一入口收敛为 media」的结论。
- 交接：回调窗口定了，最后一个决策点是一个应用怎么服务多条业务线不串。

### 5. 命名空间隔离：一个应用服务两条线
- 核心判断：同一个飞书应用/群可能被多个项目复用，回调事件是负载均衡投递、不是广播；卡片 `value` 必须带命名空间字段，服务收到不属于自己命名空间的事件直接丢弃、不处理也不报错。
- 二级标题：不分。
- 交付物：方案对比表（方案 / 适用前提 / 代价 / 已知失败模式：各建独立应用 vs 复用同一应用靠命名空间过滤）+ 一条排障句（点了旧卡没反应，先查是不是命名空间不匹配被静默丢弃）。
- 学员此时手上有：前四节定完的三个决策点。
- 交接：四个决策点都拍完板了，收进正式的 ADR 和执行方案。

### 6. 决策与写 SPEC：ADR 四项与执行方案四节

- 二级标题：不分。
- 交付物：`docs/spec/feishu-gate/00-调研.md` + `01-ADR.md` + `02-执行方案.md` 三份文档骨架，执行方案按第 11 课四节模板（实施步骤 / 决策点 × 功能 × 详细设计 / 对外契约 / 风险与待定项）写。

## 本课必须定死的四个决策点
