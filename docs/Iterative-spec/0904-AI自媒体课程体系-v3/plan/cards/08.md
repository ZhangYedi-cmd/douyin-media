## 2.1 大纲

记忆锚点：六个脚本要不要自动下 PASS/FAIL，不是写代码那一刻才知道的——它能不能被写成一句断言，第 07 课分类的时候就已经定了。

开篇契约：上一课（第 07 课·反馈信号从哪来）交付了配音批次检查点表，六项要量什么、阈值多少都定了；本课输入是这张检查点表，加上学员自己第 05/06 课做出的那条内容的 `build/` 工程（`audio-segments.json`、`public/audio/<chapter>/<step>.mp3`）；本课产出一件东西：一个全量的 `dubbing-check` skill（六个检测脚本 + `depause.mjs` + `SKILL.md`）。

### 1. 六个脚本的共同契约：先定形状，再动手写
- 核心判断：能不能自动下 PASS/FAIL 不是写脚本时才发现的，第 07 课那三条判据已经把六项检查点分成了两类——能断言的三项该是硬门槛（有明确对错，退出码非 0 即 1），只能候选的三项该是建议（只列风险点、不下结论，退出码恒为 0）；脚本的契约要把这条边界写死，不留给每个脚本自己决定。
- 二级标题：
  - 1.1 输入统一：都读 `build/` 里的 `audio-segments.json`，用同一个"工程目录"当命令行参数
  - 1.2 输出统一：每段一行 ✗/✓，末尾一句汇总结论
  - 1.3 退出码分两类：完整性 / 死气 / 真相源同步这三项能写成断言，判 FAIL 直接 exit 1；语速离群 / 多音字 / 音画一致这三项只能列候选给人看，脚本不下判断，恒 exit 0
- 交付物：
  ```
  Prompt：给这六项检查点定一份共同契约：都接受同一个"工程目录"参数，都读 audio-segments.json，
  输出格式都是「每段一行结果 + 末尾一句汇总」；六项里，完整性、死气、真相源同步这三项属于能
  写成断言的硬门槛，退出码按有问题 exit 1、无问题 exit 0；语速离群、多音字、音画一致这三项
  只能列候选给人判断，脚本只打印风险点，不设 exit 1，退出码恒为 0。按这份契约写出一张六行表，
  每行：脚本名 / 检查点 / 属于哪一类 / 退出码策略。
  ```
- 学员此时手上有：第 07 课交付的检查点表（六项：量什么/怎么量/阈值/谁来判）；第 07 课分类结果（能断言 / 只能人看两类）
- 交接：契约定完，六个同构的脚本谁先写、剩下的怎么批量出，需要一个样板。

### 2. 造一个样板，照样板批量复制剩下五个
- 核心判断：六个脚本结构同构，不该写六条 Prompt 一个个造，该写一条钉死样板、一条照样板批量复制——Prompt 数量跟着脚本数量线性增长，就是没用上"契约已经定死"这件事。
- 二级标题：
  - 2.1 挑一个硬门槛类先造样板（完整性检查最简单：文件存在、非 0 字节、时长大于 0）
  - 2.2 照样板批量复制剩下五个，含 `depause.mjs`
- 交付物：
  ```
  Prompt A（造样板）：按上一步的契约表，写 check-completeness.mjs：读 audio-segments.json，
  逐段检查 public/audio/<chapter>/<step>.mp3 是否存在、非 0 字节、时长 > 0，段数与
  audio-segments.json 一致；不一致的每段打印一行，末尾汇总，属于硬门槛，有问题 exit 1。

  Prompt B（批量复制）：照 check-completeness.mjs 的结构，按契约表剩下五行，依次写出
  check-silence.mjs（死气检查，硬门槛）、check-source-sync.mjs（真相源同步，硬门槛）、
  check-pace.mjs（语速离群，候选类）、check-pronunciation.mjs（多音字，候选类）、
  check-av-consistency.mjs（音画一致，候选类），以及 rec/depause.mjs（去停顿工具，按
  "去停顿不切词、不能原地写、跑完必须复扫"三条约束实现）。
  ```
- 学员此时手上有：契约表（本课第 1 节产出）；自己 `build/` 工程里真实的 `audio-segments.json` 和 `public/audio/` 目录结构（第 05/06 课产出）
- 交接：六个脚本 + `depause.mjs` 都能跑了，但它们各自为政，还没打包成一个可复用的整体。

### 3. 打包成 skill：一份 SKILL.md 把脚本变成检查清单
- 核心判断：脚本单独能跑不等于能被下一课的裁判直接复用——裁判要知道"该按什么顺序跑、每项检查点对应哪个脚本、跑出的结果怎么读"，这层说明书是 `SKILL.md` 的活，不是脚本自己的活。
- 二级标题：不分
- 交付物：
  ```
  Prompt：把六个脚本和 depause.mjs 整理成 dubbing-check 的 SKILL.md：按检查点编号列出每个
  脚本对应哪个检查点、怎么调用、退出码怎么读；末尾给一条"一页流程"，按合成前/合成后/录屏前
  的顺序把六项检查点串成一条能贴在工位上的清单。
  ```
- 学员此时手上有：六个脚本 + `depause.mjs`（本课第 2 节产出）
- 交接：全量 `dubbing-check` skill 交付完成。

### 4. 数字有了，判断还没交出去
- 本课做到了什么：六项检查点从表变成了能跑的脚本，退出码按"能断言/只能候选"分成了两类，打包进了一份 `dubbing-check` skill。
- 还看不到什么：脚本只负责吐数字和候选清单，PASS 还是 FAIL 现在还是学员自己拍板。
- 下一课补什么：把判断这件事从学员手上交给一个独立的裁判角色。
- 结尾抛出的问题：六个脚本能出数字了，可下判断的还是你。让写稿的那个 AI 自己判自己的活，行不行？
