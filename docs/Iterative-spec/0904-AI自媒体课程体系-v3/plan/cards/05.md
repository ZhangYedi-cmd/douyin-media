## 2.1 大纲

记忆锚点：这条内容从网页到成片一次走完，讲的是流程在哪一步、人在哪一步确认，不是这个工具具体怎么调参。

开篇契约：上一课交付了 `brain/` 五份和 tts 配置，AI 知道你的账号要什么内容、什么口气；本课输入是账号大脑里的定位、人设、语气规范和一份口播稿选题；本课产出四件：一个 `build/` 工程、一条 `final.mp4`、一张竖版 `cover.png`、一个 `tts-dub` skill。

### 1. 口播稿到网页 demo：装 web-video-presentation
- 核心判断：网页 demo 是成片的骨架，先按口播稿的段落节奏搭出页面，人在这一步确认的是段落划分和大纲对不对，不是画面细不细。
- 二级标题：不分
- 交付物：Prompt 块（读 `brain/` 四份 + 口播稿，用 web-video-presentation 生成网页工程）
- 学员此时手上有：`brain/` 四份文件、`tts.config.json`（上一课产出）
- 交接：demo 搭出来了，下一步把它录成一条真正的视频。

### 2. 网页录制成片：`npm run record` 与字幕层
- 核心判断：录制是无人值守的一次性动作，人在这一步确认的是录出来的成片时长和翻页节奏对不对，字幕层要用 `?subs=1` 单独核对，不是等成片出来才发现漏配。
- 二级标题：不分
- 交付物：命令块（`npm run record` + `?subs=1` 参数说明，修正旧稿 `cp ../../brain/` 少一级的路径错误）
- 学员此时手上有：第 1 节产出的 web-video-presentation 工程
- 交接：无声成片录完了，下一步把配音接上去。

### 3. 配音与合成：tts-dub skill（L1，两条 Prompt）
- 核心判断：这一课的 tts-dub 只给配置契约和合成脚本两条 Prompt 钉死判据，多音字、语速、去停顿留到模块 2 的 Loop 里再展开，这里人只确认音色像不像、整体能不能听。
- 二级标题：不分
- 交付物：两条 Prompt 块（配置契约 1 条 + 合成脚本 1 条）
- 学员此时手上有：第 2 节的无声成片工程、`brain/tts.config.json`
- 交接：配音合上了，最后补一张封面，把产物归位。

### 4. 封面与产物归位：baoyu-image-gen 与 build/ 目录
- 核心判断：封面要竖版比例，不能拿横屏视频帧充数，人在这一步确认的是封面比例和这条内容的第一眼观感。
- 二级标题：不分
- 交付物：Prompt 块（baoyu-image-gen 出竖版 `cover.png`）+ `build/` 目录归位清单
- 学员此时手上有：第 3 节的 `final.mp4`
- 本课做到了什么、还看不到什么、下一课补什么：第一条成片出来了，学员自己看着点头觉得还行；但下次不在场时没人替他做这个判断，下一课把这个「点头」拆开看能不能交给别人或机器。
- 结尾抛出的问题：第一条成片出来了，你眼睛看着觉得还行。可下次你不在场的时候，谁来看这个「还行」？

## 共同约束（33 门课一致，不许改写）

> 本课程的目标不是教人做自媒体，是让学员通过这条流水线学会怎么跟 AI 干活：掌握和 AI 协作的流程、懂得如何引导 AI、掌握 Loop 思维与架构设计。抖音只是载体。
>
> 因此：**视频制作本身（怎么剪、怎么配音、怎么调多音字和语速、封面怎么画）一律从简，走一遍流程即可，不做深入讲解。** SPEC CODING、Loop 搭建、CLI 与状态收敛、反哺大环这四块是学员要重点掌握的，往厚里写。
>
> 判断标准：这一段讲的是「这个工具怎么用」还是「这类问题该怎么设计」。前者压，后者留。
>
> 注意别误伤 —— 模块 2 那四课（07-10）表面在讲配音质检，实际讲的是 Loop 架构，配音只是素材，不属于可精简范围。

还有一条铁律贯穿全书：**学员不写一行实现代码。**学员写的只有三类东西——中文的需求与判据、SPEC 文档、验收结论。代码、配置、脚本一律由 AI 产出。课文里出现大段代码就说明写偏了。
