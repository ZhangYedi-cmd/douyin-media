## 2.1 大纲

记忆锚点：生产线消费资产，治理线保养资产，治理只提议不改。

开篇契约：上一课交付了 `douyin-publish` skill 和一次 dry-run 到底，生产线整条通了；本课输入是学员自己的 `CLAUDE.md`、`pipeline/` 五份阶段契约、`tools/console/packages/core/src/state.ts`（含全量 `media` 命令）；本课产出 `harness/` 骨架（README + tasks.md + report-template.md）+ 一张资产读写表。

### 1. 双线边界：谁消费、谁保养
- 核心判断：生产线只会把选题池和账号大脑当存量吃，从不往里补；没有一条独立的、按自己节奏跑的线专门负责保养这些存量资产，它们会越用越薄。
- 二级标题：不分
- 交付物：生产线 / 治理线对比表（列：驱动方式、消费还是保养、动作是否可逆）
- 学员此时手上有：`CLAUDE.md`、`pipeline/` 五份契约、`content/_backlog/backlog.yaml` 头部（第 20 课结束时的骨架状态）
- 交接：边界画完，第一条要立起来的铁律是治理线凭什么只能提议，不能自己动手改

### 2. 只提议不落笔：治理线的第一条铁律
- 核心判断：治理线要碰的是账号大脑这类判断依据，自动改错了没人发现，等于让系统自己改自己判断对错的标准，所以这条边界必须写进契约，不能靠自觉。
- 二级标题：不分
- 交付物：prompt 让 AI 在 `CLAUDE.md` 补一节「治理线铁律」，附一个反例（没有这条闸，一次误判会怎样传导到下一轮选题打分）
- 学员此时手上有：`brain/benchmarks.md`（第 04 课填的四份大脑文件里，这一份留空，待第 22 课复盘后写）
- 交接：铁律立完，得有一个目录和一个字段把「这笔账归哪条线」钉死

### 3. harness 骨架与 line 字段记账
- 核心判断：治理线要有自己的目录和状态迁移，`line` 字段是唯一能让机器判定「这笔账归生产线还是治理线」的地方，不能靠人记。
- 二级标题：不分
- 交付物：prompt 让 AI 起草 `harness/README.md`（治理线定位与铁律）+ `harness/tasks.md`（任务注册表空壳，第 24 课填满）+ `harness/report-template.md`（治理执行记录报告模板）
- 学员此时手上有：第 2 节的铁律文案、`tools/console/packages/core/src/state.ts` 里已有的状态迁移规则
- 交接：骨架立完，读写边界还只是一句话，得落成一张表才防得住漂移

### 4. 资产读写表
- 核心判断：把「谁能读、谁能写、谁只能提议」钉死成一张表，比铁律的文字描述更防漂移——文字会被绕过，表格里没写的权限，谁都不能碰。
- 二级标题：不分
- 交付物：资产读写表（列：资产 / 生产线权限 / 治理线权限 / 改动是否需要人审），至少覆盖 `backlog.yaml`、`brain/*`、各条目 `meta.yaml`、`harness/logs/`
- 学员此时手上有：第 1 到 3 节的全部产出、`content/_backlog/backlog.yaml`、`brain/` 五份文件
- 交接：读写边界钉死了，得先看一眼这套闭环最终要走多远

### 5. 反哺大环：三课才能讲完的一件事
- 核心判断：反哺大环不是这一课能讲完的东西，它横跨三课——这一课回答「治理线为什么只提议」，第 22 课回答「一条内容怎么单次归因」，第 24 课回答「连治理线自己怎么调参也要进这个循环」，提前点破全貌，免得学完这一课就以为反哺已经闭环了。
- 二级标题：不分
- 交付物：一张反哺大环三段地图（课号 / 回答什么问题 / 交付什么）
- 学员此时手上有：本课前四节全部产出
- 交接：治理线的骨架立住了，第一个真正要跑的治理任务是复盘
