> 一句话：把散在 6 个入口、靠 Claude 手编 YAML 的状态记账，收敛成一个事务性 CLI——**skill 保留判断，交出笔**。

## 1. 背景与问题

当前流水线的状态记账（meta.yaml / backlog.yaml / dashboard.md 三处联动）全靠手编：

- **全仓共 6 个写状态入口**：daily-run 取题 promote、daily-run 出审翻状态、douyin-publish Step 5、feishu-bot server（自带正则实现）、douyin-ideate 入池与清扫、douyin-retro 收口。其中 5 个是 Claude 手编文件。
- **记账事故全部出自手编**：EP04 / open-weight-5 状态漏翻（多文件一致性靠自觉）、backlog 与 meta 双层不同步、dashboard 与真相源漂移。
- feishu-bot 的 `meta.set_status()` 是**第二套状态翻转实现**（正则改行），与 SOP 文档里的规则各自独立演化。

## 2. 目标与决策记录

本方案由 2026-08-18 讨论定案，关键分叉及拍板：

| # | 分叉 | 决策 |
|---|---|---|
| D1 | CLI 首要目标 | **记账正确性优先**。只包「翻状态 / 记账」类操作，把多文件一致性做成事务；创作、复盘归因等判断类环节不碰。CLI 小而硬 |
| D2 | 「查询作品信息」语义 | **本地状态查询**（读仓内真相源）。抖音创作者中心拉数仍归 douyin-retro，不进 CLI |
| D3 | dashboard.md 命运 | **CLI 自动重生成机器区**，叙事保留人写区（见 §7） |
| D4 | 技术栈 | **Node/TypeScript**。与看板后端 ADR 同语言，「解析 + 状态机 + 警报」核心写一次，CLI 与未来的 HTTP 壳共用 |
| D5 | CLI 名称 | **`media`** |

**边界一句话**：翻状态、动指针、多文件一致性 = CLI；一切需要「想」的（选题评分、归因叙事、撞题判断、内容创作）= skill。

## 3. 总体形态：一仓多包，共享核心

代码住 `tools/console/`，**独立 git 仓**（沿 ADR：主仓含敏感物料不推 GitHub，主仓 .gitignore 掉该目录），npm workspaces：

```
tools/console/
├── packages/core/        # 领域核心：规则唯一真相源
│   ├── parsers/          # contents / backlog / harness / logs，一源一 parser，解析失败降级返回原文+parseError，不抛穿
│   ├── state.ts          # 双层状态机：合法迁移表 + 每个迁移动哪些文件（见 §5.1）
│   ├── alerts.ts         # 警报规则（`media check` 与未来看板 P1 共用同一份代码）
│   └── writer.ts         # 事务写入（见 §4）
├── packages/cli/         # 本方案交付物：bin = `media`
└── packages/server/      # 留空占位，看板后端二期按 ADR 实现，import core
```

依赖极简：`yaml`（注释保留写入，见 §4）、`commander`（或等价 CLI 框架）。core 无任何服务端依赖。

## 4. 硬约束：YAML 注释必须原样保留

`backlog.yaml` / `meta.yaml` 的灵魂在注释里（终检记录、取题说明、清扫留痕、状态机文档）。常规「js-yaml 解析 → 改 → dump」会抹掉全部注释，**是本 CLI 最大的翻车点**。

- 写路径一律用 `yaml` 包 Document API 做**定点节点修改**：只动目标字段，其余字节原样保留。
- 每条写命令配 round-trip 测试：改一个字段，git diff 里只允许出现该字段（及事务约定的关联字段）。
- 禁止任何「整文件重新序列化」的写法进入 writer.ts。

## 5. CLI 详细设计

### 5.1 状态机（core/state.ts，规则从此只活在这一处）

**meta.yaml 细粒度**：

```
ideated → drafting → review → approved → scheduled → published → retro_done
                        │  ↘ rejected ──→ drafting（人决定重做）
                        └──→ drafting（打回重做）
```

- `approved → published` 允许直达（立即发布，不经 scheduled）。
- `approved → drafting` 允许（2026-08-18 增补：看板审批通过后反悔改稿场景）。
- `published → retro_done` 是唯一治理线迁移（douyin-retro 收口时翻）。
- 其余任何跳转（如 review 直达 published）非法，`media flip` 直接拒绝。

**backlog.yaml 粗粒度**：`idea → picked → published`；异常出口 `idea → expired / rejected / archived`。只在 promote 与 publish-done 两个时点翻动（沿现行单一真相源规则）。

### 5.2 通用约定（对 AI 友好的核心）

- 读命令全部支持 `--json`（agent 消费的结构化输出；缺省给人看的表格）。
- 写命令全部支持 `--dry-run`（打印将发生的全部文件变更，不落盘）。
- **写命令 = 事务**：全部校验（迁移合法、id 存在、指针一致、目录状态）在内存中通过后才落盘；任一步失败 = 零写入 + 非零退出码 + 报错写明「哪条规则拦的你」。
- **每次写后自动**：重生成 dashboard 机器区 + 跑一遍 `check`，警报附在命令输出尾部——agent 每记一次账，顺带得到一次全仓体检。

### 5.3 读命令（4 条）

| 命令 | 输出 | 替代的现状 |
|---|---|---|
| `media st [slug]` | 在制总览 / 单条 meta 全量（状态、时间轴、交付物、blocker） | Claude 逐个 Read meta.yaml |
| `media next` | 模拟取题：会取谁、为什么（next_up 指针优先 → score 最高，同分先 depth，expired 排除） | daily-run 步骤 2 的人肉规则执行 |
| `media backlog ls [--status idea] [--sort score] [--expiring]` | 选题池查询；`--expiring` 列临近机械过期条目 | Claude 通读 backlog.yaml 全文（1000+ 行） |
| `media check` | 一致性体检：双层不同步、picked 无 content_path、scheduled 超时无人回填（EP04 类）、meta 翻了 backlog 没翻、review 停留超时、published 无作品链接 | 无替代——现靠人翻 dashboard 偶然发现 |

### 5.4 写命令（7 条 + 1 维护）

| 命令 | 事务内容 | 内置闸口 |
|---|---|---|
| `media promote <id>` / `--auto` | backlog `idea→picked` + 回填 `content_path` + 从 `_template` 建目录写 meta（`source` 反向指针）+ `next_up` 置 null，五处一次改齐 | id 必须 `idea`；目录不得已存在；`--auto` 走 `media next` 同一套取题逻辑 |
| `media flip <slug> <status> [--reason]` | meta status 翻转 + timestamps 补时间戳 | §5.1 迁移合法性表；`rejected` 必须带 `--reason` |
| `media publish-done <slug> [--scheduled <time>] [--url <url>]` | Step 5 三翻齐：meta→`published/scheduled` + backlog `picked→published` + dashboard 移出在制 | 当前必须 `approved`（承接「只发 approved」铁律）；url 缺省则 check 挂「作品链接待补」 |
| `media backlog add <file.yaml>` | 批量入池：schema 校验、自动编号（YYYY-MM-DD-NNN）、tags 30 天去重比对 | 撞车条目列出并**默认拒收**，skill 判断后删掉重提或 `--force` 单条放行——去重比对是机械活归 CLI，收不收是判断归 skill |
| `media backlog sweep [--dry-run/--apply]` | 机械规则清扫（today 超 2 天、timeliness≥4 超 7 天）置 `expired` + 注释留痕 | 只执行规则化清扫（CLAUDE.md 记账例外）；判断性剔除不归它 |
| `media backlog apply <id> --action merge/archive --proposal <报告路径>` | 落 backlog-gardener 人审通过的提议，提议报告路径写进条目注释（可溯源） | 仅 `idea` 条目；proposal 路径必须存在 |
| `media next-up set <id>` / `clear` | 人钦点取题指针 | id 必须存在且为 `idea` |
| `media dashboard rebuild` | 手动全量重生成 dashboard 机器区（日常不用，写命令自带） | — |

**刻意不做**：retro 的 metrics 归因、dashboard 数据汇总表的复盘结论、gardener 的撞题判断、harness 运行日志、创作者中心拉数——判断产物不是记账，留在 skill。

## 6. 与现有 skill 的融合（6 个写入口逐个改）

原则：skill 保留判断，交出笔。每个 SKILL.md 里「改哪些文件」的段落，整段替换为一条 `media` 命令引用。

| 现状写入口 | 现在怎么写 | 改成 |
|---|---|---|
| daily-run 步骤 2（取题） | 编排 agent 手编 backlog 四处 + 建目录 | `media next --json` → `media promote <id>`（或 `--auto`）。`1-brief.md` 仍由 agent 写（判断活） |
| daily-run 步骤 4（出审） | 手编 meta→review + dashboard | `media flip <slug> review`，照旧调 feishu-notify 推卡 |
| douyin-publish Step 5 | Claude 手编三文件（历史两次漏翻在此） | `media publish-done <slug>`，SKILL.md Step 5 整段缩成这一行 |
| feishu-bot server.py | 自带 `meta.set_status()` 正则（第二套实现） | 回调 handler 改 subprocess 调 `media flip`。**最关键一条**：不切则仓里两套翻状态实现必然漂移。meta.py 读函数可保留或改走 `media st --json` |
| douyin-ideate（入池+清扫） | 手工追加 backlog + 手改 dashboard 选题池小节 | 调研/评分/写 reason 照旧；候选产出后 `media backlog add`；Step 2.0 清扫改 `media backlog sweep --apply`；dashboard 不再手碰 |
| douyin-retro（收口） | 手编 meta→retro_done + dashboard 数据汇总 | `media flip <slug> retro_done`；数据汇总归因叙事照旧 Claude 写（人写区） |

backlog-gardener 本就只提议不写，不变；其提议经人审后的落地从「受权会话手编」变为 `media backlog apply`（补上现流程最模糊的一环）。

### 6.1 融合机制

1. **skill 怎么找到 `media`**：全局 `npm link` 使 PATH 可见；各 SKILL.md 同时写死绝对路径兜底（`node tools/console/packages/cli/…`），防定时 agent 的 PATH 差异。
2. **文档降级（防漂移铁律的代价，必须做）**：`pipeline/*.md` 阶段契约的状态翻转描述、`backlog.yaml` 头注释的状态机文档、CLAUDE.md「状态记账唯一位置」，统一降级为「见 `media` 对应命令」。状态机规则只活在 `core/state.ts`，`media flip --help` 打印迁移表即活文档。
3. **feishu 3 秒回调窗口**：subprocess 调 CLI，Node 冷启动 ~100ms 量级，不影响「物料确定性拼装 + 真发异步」的现有设计。

## 7. dashboard.md 改造

拆两区：

- **机器区**：`<!-- auto:begin -->…<!-- auto:end -->` 标记，含在制列表、选题池计数、check 警报、待人确认中可机器判定的部分；由 CLI 每次写后从真相源重算重写。
- **人写区**：标记外全部内容（「最后同步」叙事线、复盘结论等），CLI 永不碰。

手编漂移就此归零；git 历史存档价值保留。

## 8. 测试

- core 状态机 / parsers：用**真实仓库文件**做 fixture。
- YAML round-trip：改一字段，diff 只允许该字段（§4）。
- `check` 规则回归样例取自历史事故：EP04 scheduled 超时漏翻、双层不同步、published 无链接，各造一个 fixture。

## 9. 迁移顺序（防双写路径）

CLI 与手编**不长期并存**（并存期两条写路径即新事故源）。按事故率从高到低逐入口切，每切一个同步改其 SKILL.md：

1. core + CLI 落地，fixtures 测试全过；
2. 先切 **publish-done + promote**（历史事故集中地）；
3. 切 feishu server（消灭第二套实现）；
4. 切 ideate / retro / sweep；
5. 文档降级收尾；`media check` 注册进治理线日巡（`harness/tasks.md` 加一行）——状态漏翻从「人偶然发现」变「治理线每日必报」。

## 11. v0.2 增补（2026-08-18，看板后端方案反哺，已拍板）

看板升级为「裁决台」后写者从一个变为多个（看板动作层、飞书 server、定时 agent、无头 CC 任务），以下四项收进 CLI——**无论写入发起自哪个壳，落盘前的最后一米都是同一段代码**：

1. **文件锁**（writer.ts）：advisory lock，多写者互斥；拿不到锁即报错退出（事务毫秒级，不排队）。
2. **审计账本**：每次写命令 append 一行 `tools/console/logs/audit.jsonl`（谁 / 何时 / 哪条命令 / 改了什么）。放 CLI 而非 server 的理由：全部写者天然统一过闸。
3. **原子落盘**：temp-then-rename，防常驻监听方（chokidar）读到半写 YAML。
4. **新命令两条**：
   - `media metrics record <slug> --window <24h|72h|7d> --json '…'`——douyin-retro 每窗拉数后调用，append 进 `harness/logs/metrics.jsonl`（append-only，天然装多窗快照）；7d 终值回填 `backlog.metrics`。补上「backlog.metrics 55 处全 `{}`、复盘数据只活在叙事里」的结构化缺口，看板 P6 唯一数据源。属记账非判断，在 D1 边界内。
   - `media publish-done <slug> --url <url>` 增加**补填语义**：条目已 `published` 时仅回填作品链接（清「链接待补」类系统性欠账），非法重复翻状态仍拒绝。

另：看板 server **禁止 import writer.ts** 的包边界约束、四包结构（core / cli / cc-stream / server）见看板后端方案 §4，此处不复述。
