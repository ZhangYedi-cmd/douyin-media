### S8 切换细步与回滚（M3 出口条件的收口项）

1. **改造点只有两处函数体**：`_async_publish` 与 `_async_rework` 内的 `subprocess.run(["claude","-p",...])` 段替换为：`POST http://127.0.0.1:5170/api/actions/{publish|rework}`（token 从 `tools/console/.runtime/token` 读）→ 每 10s 轮询 `GET /api/jobs/:id` 至终态（上限 = job 超时 + 5min）→ 用 `job.verdict` + `job.milestones` 更新飞书卡。判成败逻辑（读 meta.status）从 python 移进 job runner，python 只消费 `verdict.ok`。
2. **不动的部分**：`_async_approve`/`_async_todo`/`_async_rework_limit` 的快写（M2 已改为 subprocess 调 `media flip`，无需再绕 server 一跳）；notify.py 出卡；3 秒回调窗口纪律（POST + 轮询都在异步线程里）。
3. **锁迁移**：`_publishing`/`_publishing_lock` 在新路径（console_api:true）下线，`publish_confirm` 分支的重复点击防护改为「POST 得到 409 JOB_DUPLICATE → toast 勿重复点击」，全系统发布幂等锁唯一实现 = job runner。**2026-08-18 验收更正：两变量暂不物理删除——第 4 条要求旧路径原样可用，而旧路径 finally 块硬依赖它们，字面删除会使回滚路径 NameError；随旧路径在 M4 后一并删。**
4. **回滚方式**：`config.yaml` 加 `console_api: true/false`，false 时走保留的旧 spawn 代码路径（一个 if 分支，不删旧函数）；回滚 = 翻配置 + `bash start.sh restart`，不 revert commit。旧路径保留一个里程碑周期（M4 结束），之后删。
5. **禁止自动 fallback**：console 连接拒绝时按发布失败上报卡片（写明「console 未启动，请 `start.sh start` 或翻回 console_api:false」），不静默退回旧路径——双写路径并存正是 CLI 拍板 §9 要消灭的事故源。

## 2. 接口 × 功能 × 详细设计

### 2.0 横切约定（全部接口共用）

| 项 | 约定 |
|---|---|
| 监听 | `127.0.0.1:5170`（后端拍板 §5 安全/§11；端口经 `CONSOLE_PORT` 覆盖） |
| 鉴权 | 全部 `/api/*` 必须带 token：`Authorization: Bearer <token>`；EventSource 与 `<img>/<video>` 无法带 header 的场景接受 `?token=`。token 启动时生成（`crypto.randomBytes(24).toString("base64url")`），持久化 `tools/console/.runtime/token`（0600，已存在则复用，token 跨重启稳定）；静态 UI 文件不校验 |
| 读响应信封 | `{ "revision": <int>, "now": "<ISO>", "data": {...} }`；revision 语义见 §2.5 |
| 动作响应信封 | `{ "ok": true, "dryRun": <bool>, "result": <media --json 输出透传>, "check": <media 写后自带体检输出> }`（CLI 拍板 §5.2：每次写后附全仓体检） |
| 错误信封 | `{ "error": { "code": "<机器码>", "message": "<人话>", "detail": <可选，CLI stderr 透传> } }` |
| 错误码表 | 401 `AUTH_BAD_TOKEN`｜400 `BAD_PARAM`（body schema/slug 正则不过）｜403 `PATH_FORBIDDEN`（safeResolve 拒）｜404 `NOT_FOUND`｜409 `MEDIA_REJECTED`（CLI 状态机/锁拦下，detail 带规则名）｜409 `JOB_DUPLICATE`｜409 `PRECONDITION_FAILED`｜409 `REWORK_LIMIT`｜413 `FILE_TOO_LARGE`｜502 `MEDIA_UNAVAILABLE`（execFile ENOENT/超时）｜500 `INTERNAL` |
| 参数卫生 | `slug`/`id` 过 `^[a-z0-9][a-z0-9-]{1,64}$` 与 `^\d{4}-\d{2}-\d{2}-\d{3}$`；一切 media 调用走 `execFile` args 数组，不经 shell（后端拍板 §5，注入面为零） |
| 数据来源 | 读接口全部从 store 持有的 Snapshot 投影，**零现场 IO**（`/api/file` `/api/asset` 除外）；写接口全部 subprocess，server 进程内不 import writer（后端拍板 B1） |

### 2.5 store / watcher / SSE 详细设计

**store.ts（revision 唯一产地）**：

```ts
class Store {
  snapshot!: Snapshot; alerts: Alert[] = []; revision = 0;
  private prevAlertKeys = new Set<string>();

  rebuild(reason: "fs" | "tick" | "boot") {
    const t0 = performance.now();
    const snap = buildSnapshot(this.root);            // core 纯函数（B3）
    const raw  = computeAlerts(snap, new Date());
    this.alerts = this.debounceAlerts(raw);           // 连续两次快照都在才算 active（§8 坑 2 兜底）
    this.snapshot = snap; this.revision++;
    this.buildMs = performance.now() - t0;
    this.sse.broadcast("refresh", { revision: this.revision, reason });
  }
  private debounceAlerts(raw: Alert[]): Alert[] {
    const stable = raw.filter(a => this.prevAlertKeys.has(a.key));
    this.prevAlertKeys = new Set(raw.map(a => a.key));
    return stable;   // 新警报最迟下一次重建（文件事件或 ≤10min tick）转正，可接受的迟到
  }
}
```

- **10min tick**（后端拍板 B3）：`setInterval(() => store.rebuild("tick"), 600_000)`——时间型警报（待审积压、治理逾期）在文件不动时也要过期；全量重建 <100ms，10 分钟一次直接复用同一条 rebuild 路径，不做「只重算 alerts」的特殊分支。
- revision 只在 rebuild 里递增；读接口/SSE/health 共用同一数值，前端重连比对（后端拍板 B2）。

**watcher.ts（chokidar 四坑落法，后端拍板 §8）**：

```ts
const WATCH = ["content", "harness/logs", "harness/tasks.md", "pipeline/logs", "dashboard.md"];
const EXT_OK = /\.(ya?ml|md|jsonl|mp4|png)$/;        // 扩展名白名单；mp4/png 为乙类轨迹与封面观测
const watcher = chokidar.watch(WATCH.map(p => join(root, p)), {
  ignored: [/(^|[\/\\])\../, /node_modules/],         // 坑 4：.git、点文件
  ignoreInitial: true,
  awaitWriteFinish: { stabilityThreshold: 300, pollInterval: 50 },  // 大文件(mp4)写完再报
});
let t: NodeJS.Timeout | null = null;
watcher.on("all", (ev, p) => {
  if (ev !== "addDir" && !EXT_OK.test(p)) return;     // addDir 放行：audio-segments/ 出现是轨迹观测点
  if (t) clearTimeout(t);
  t = setTimeout(() => store.rebuild("fs"), 500);     // 坑 1：trailing debounce 聚合一事务多文件
});
```

- 坑 2（跨文件中间态）：debounce 为主 + store 的警报去抖兜底；坑 3（dashboard 自触发环）：CLI 写 dashboard 落在同一 debounce 批次，server 零写、环闭不上——`tools/console/logs/`（audit/jobs 日志）**刻意不在 watch 白名单**，job 落盘不会反向触发重建；原子写（temp-then-rename）由 CLI writer 保证（CLI 拍板 §11.3），parser 降级容错是最后防线。

### 2.6 job runner 详细设计（状态机、落盘、prompt、里程碑表）

**Job 状态机**：

```
queued ──→ running ──→ verifying ──→ succeeded
              │             └──────→ failed
              └─(timeout/kill)→ verifying   ← 超时不直接判死：先跑 verdict，
                                              文件状态说成功就是成功（信任分级：文件状态唯一裁决）
```

**类型（api-types.ts）**：

```ts
type JobType  = "publish" | "rework" | "apply-proposal";
type JobState = "queued" | "running" | "verifying" | "succeeded" | "failed";
interface Job {
  id: string;                 // `${type}-${yyyyMMddHHmmss}-${4hex}`
  type: JobType; slug?: string; report?: string; reason?: string;
  state: JobState;
  milestones: { id: string; label: string; at: string }[];
  narration: { messageId: string; text: string }[];   // say 事件，只展示永不驱动状态（§7.4）
  stalling: boolean;                                  // 连续 2 次 api_retry/rate_limit → true，任一其他事件清零
  costUsd?: number; turns?: number; durationMs?: number;
  startedAt?: string; endedAt?: string;
  verdict?: { ok: boolean; metaStatus?: string; expect?: string[]; diff?: string; note?: string };
  error?: string; logPath: string;
}
```

**JobRunner（jobs/runner.ts）**：

```ts
class JobRunner {
  private jobs = new Map<string, Job>();
  private locks = new Set<string>();          // 继承 feishu `_publishing` 教训（B5）
  private queue: string[] = []; private active: string | null = null;

  submit(def: JobDef, params): { ok: true; job: Job } | { ok: false; code; message };
  //  precheck → 锁占用查重 → 建 Job(queued) → 入队 → runNext()
  private async run(job: Job) {
    // 1) def.before?.(params)            — rework 的 execFile media flip drafting 在此
    // 2) runHeadlessCC({ prompt, allowedTools, cwd: repoRoot, timeoutMs, logPath })
    // 3) for await (ev of run.events):   norm 事件 → engine.feed(ev) 收里程碑 →
    //    job 增量更新 → sse.jobUpdate(job)（tool 驱动步骤条、say 只进 narration——§7.4）
    // 4) state=verifying → def.verdict(freshRead, result) → succeeded/failed
    // 5) 写 logs/jobs/<id>.result.json（终态快照；缺失 = 进程曾崩）→ 释放锁 → runNext()
  }
}
```

- **单并发**：`active` 非空时新 job 停在 queued（流水线本来串行，B5）；不同 lockKey 可排队，同 lockKey 直接 409。
- **落盘两件**：`logs/jobs/<id>.jsonl` = 子进程 stdout **原始流原样落盘**（cc-stream 的 logPath 钩子，纯 tee 不加工）；`<id>.result.json` = 终态 Job JSON（崩溃降级回答的数据源，§2.3）。
- **verdict.ts**：`readMetaStatus(slug)` 不走 Snapshot（可能落后 debounce 半秒），现场 `fs.readFile` meta.yaml 解析 status 单字段——读操作不破零写铁律；apply-proposal 的 diff 抓取用 `execFile("git", ["diff","--","brain/"])`。

### 2.7 cc-stream 包详细设计（后端拍板 §7）

**文件布局与导出面**（零依赖叶子包，只用 node 内建；包内没有一行代码认识发布/meta.yaml/media——§7.3）：

```
packages/cc-stream/
├── src/
│   ├── types.ts        # RawEvent / NormEvent / MilestoneRule / MilestoneHit / SpawnOptions / HeadlessRun
│   ├── transport.ts    # 传输层
│   ├── normalize.ts    # 事件归一层
│   ├── milestones.ts   # 里程碑引擎（通用）
│   ├── spawn.ts        # spawn 助手
│   └── index.ts        # export { runHeadlessCC, parseStream, createNormalizer, createMilestoneEngine } + 全部类型
├── fixtures/           # <date>-claude-<version>.jsonl（真实探测输出，含 README 重采集约定）
├── scripts/capture-fixture.sh
└── test/
```

**6 种归一事件 TS 类型（§7.2 的落地形态）**：

```ts
type NormEvent =
  | { kind: "started";  sessionId: string }
  | { kind: "tool";     id: string; name: string; input: unknown }
  | { kind: "toolDone"; id: string; ok: boolean }
  | { kind: "say";      messageId: string; text: string }      // 同 messageId 覆盖式更新（增量重复消息去重后的语义）
  | { kind: "stalling"; reason: "api_retry" | "rate_limit" }
  | { kind: "done";     ok: boolean; costUsd?: number; turns?: number; durationMs?: number };
```

**传输层（transport.ts）**：

```ts
async function* parseStream(
  stdout: NodeJS.ReadableStream,
  opts?: { onRaw?: (line: string) => void }        // 原始 JSONL 落盘钩子（server 接 logs/jobs/<id>.jsonl）
): AsyncGenerator<RawEvent>
```

按 `\n` 切分、尾部残段缓冲到下一 chunk（半行缓冲）；每完整行先过 `onRaw`（**解析失败也落盘**）再 `JSON.parse`，parse 失败计数后跳过；`system/hook_*` 噪音在此丢弃；未知 `type` 原样透传给归一层（由它静默跳过——前向兼容，§7.2）。

**事件归一层（normalize.ts，有状态：去重）**：

```ts
function createNormalizer(): (raw: RawEvent) => NormEvent[]
```

映射规则：`system/init`→`started`；`assistant` 消息内 `tool_use` 块按 `tool_use.id` 集合去重（同一消息随内容块增长重复出现——§7.2 实测），首见才发 `tool`；`text` 块聚合为 `say`（带 messageId，覆盖语义）；`tool_result`→`toolDone(id, ok=!is_error)`；`api_retry`/`rate_limit_event`→`stalling`；`result`→`done(ok=!is_error, costUsd=total_cost_usd, turns=num_turns, durationMs=duration_api_ms)`；其余静默跳过。

**里程碑引擎（milestones.ts，声明式匹配表由调用方注入）**：

```ts
interface MilestoneRule {
  id: string; label: string;
  match: { tool: string | RegExp; input?: Record<string, RegExp> };  // input 各字段 String() 后正则测试，全部命中才算
  once?: boolean;                                                     // 默认 true
}
type MilestoneTable = MilestoneRule[];
interface MilestoneHit { id: string; label: string; at: string }
function createMilestoneEngine(table: MilestoneTable): { feed(ev: NormEvent): MilestoneHit[] }
// 只对 kind==="tool" 求值；命中即吐；once 规则命中后失效
```

**spawn 助手（spawn.ts）**：

```ts
interface SpawnOptions {
  prompt: string; allowedTools: string[]; cwd: string;

  logPath?: string;                       // 接 transport.onRaw，原样 append

  events: AsyncIterable<NormEvent>;       // spawn+transport+normalize 已组合；里程碑引擎由调用方自接
  pid: number; kill(): void;
  exit: Promise<{ code: number | null; signal: string | null; stderrTail: string }>;  // stderr 环形缓冲末 50 行
}
function runHeadlessCC(opts: SpawnOptions): HeadlessRun
// 参数拼装：["-p", prompt, "--output-format", "stream-json", "--verbose",
//           "--allowedTools", allowedTools.join(",")]；stdio = ["ignore","pipe","pipe"]
```

**fixture 测试策略与重采集约定（§7.5）**：

1. 现有 2026-08-18 真实探测输出为首个 fixture，命名 `<采集日期>-claude-<claude --version>.jsonl`。
2. 测试双档：对**全部** fixture 跑宽断言（归一层零抛异常、必需事件 `started`+`done` 出现、tool/toolDone 成对）；对**最新** fixture 跑精确快照断言（归一事件全序列比对）。协议漂移让宽断言先红——这是本包唯一真实风险的探测器。
3. `scripts/capture-fixture.sh`：固定探测 prompt（读一个文件 + 跑一条 `echo` + 正常收尾）跑 `claude -p ... --output-format stream-json --verbose`，stdout 存 fixtures/，并打印 claude 版本供命名。**每次 Claude Code 升版跑一次**，约定写进 fixtures/README.md，并在 `harness/tasks.md` 的 sop-doc-sync 类巡检接入时列为检查项（仅登记约定，本方案不改 tasks.md）。

### 2.8 运行时（后端拍板 §11）

- **config**：`PIPELINE_REPO_ROOT`（默认 = console 仓根上二级，即 `tools/console` → 主仓根；ADR 沿用）；`CONSOLE_PORT`（默认 5170）；`MEDIA_BIN`（默认 `media`，兜底绝对路径 `node <console>/packages/cli/dist/index.js`——CLI 拍板 §6.1 的 PATH 差异对策同样适用于 launchd 环境）。
