## 2. 页面 × 功能 × 详细设计

### 2.1 页面清单、路由与文件布局

一句话：**共实现 6 个路由页 + 1 个全局壳**（拍板 §4 六页清单；v2 原型多出的 review / harness-task-detail 两页已拍板**下一期再做**，见 §4-Q1），路由用 HashRouter（静态托管零 fallback 配置，clone 即跑；详见 §2.12）。

| 页 | 路由 | 目录 | 对照原型 | 建造序 |
|---|---|---|---|---|
| 全局壳 | — | `src/app/` | 各页共有的 .app/.sidebar/.topbar | S1/S2 |
| P1 总览 | `#/` | `src/pages/overview/` | `overview.html` | 1 |
| P3 详情 | `#/content/:slug` | `src/pages/detail/` | `detail.html`（砍内嵌播放器与批注，见 §4-Q2） | 2 |
| P4 选题池 | `#/backlog` | `src/pages/backlog/` | `backlog.html` | 3 |
| P5 治理线 | `#/harness` | `src/pages/harness/` | `harness.html`（砍已读标记；task-detail 见 §4-Q1） | 4 |
| P2 看板 | `#/kanban` | `src/pages/kanban/` | `kanban.html`（拍板已瘦身为列表） | 5 |
| P6 数据 | `#/metrics` | `src/pages/metrics/` | `metrics.html` | 6 |

砍掉清单（拍板 §4，不实现也不留桩）：⌘K 全局搜索、标记已读 localStorage、内嵌视频播放器、拖拽。

```
packages/ui/
├── index.html                  # <div id="root">，无其它内容
├── vite.config.ts              # §2.12
├── tsconfig.json               # verbatimModuleSyntax: true（焊死 type-only import core）

    ├── main.tsx                # ConfigProvider(themeConfig) > ConsoleProvider > RouterProvider
    ├── theme.css               # 原型 token 原样搬入（自绘组件用 var()）

    │   ├── overview/  detail/  backlog/  harness/  kanban/  metrics/
```

说明：StatusTag、FileDrawer 是对拍板 5 件跨页组件清单的**新增**（满足「跨页复用满 2 处才升 components/」：StatusTag 用于 P2/P3/P4，FileDrawer 用于 P1/P3/P5），属详细设计层新内容，登记于此。

一句话：晨检页，10 秒回答「今天正常吗 / 有几条在制 / 有什么要我处理」；警报区渲染 computeAlerts 输出、待办按损失分级置顶（拍板 §4 P1 行）。

**布局区块图**（对照 `overview.html` 2fr:1fr 双列）

```
页头：h1 总览 ＋ 日期/一句话口径（mono 小字）
┌─ 左列 2fr ────────────────────┬─ 右列 1fr ──────────────┐
│ ① 今日运行卡（daily-run 状态）  │ ④ 待我处理（分级待办清单） │
│ ② 警报区（AlertCard 列表）      │ ⑤ 治理线心跳（进度条组）   │
```

|---|---|---|---|---|
| ① | 今日运行卡：daily-run 当日状态（乙类文件轨迹进度，后端方案 §9 场景 1）+ 日志尾部折叠 | Card + Collapse + 自绘 logblock | `dailyRun: { date, phase, phaseLabel, summary, logPath, logTail }` | 「看日志全文」→ FileDrawer(logPath) |

一句话：单条内容的深审与裁决页；状态操作区展示当前状态的合法迁移及对应动作（拍板 §4 P3 行，迁移表由 server 从 core state.ts 算好下发，ui 不内嵌规则）；成片不做页内播放器（砍掉清单，冲突记录见 §4-Q2）。

**布局区块图**（对照 `detail.html`，1fr:360px）

```

① 头卡：标题 + StatusTag + 复制目录/复制 dry-run 命令(CommandChip copy)
        mono 信息行（目录·类型·pillar·系列·来源 T-xxx→P4·账号）
        ② 阶段时间轴（Steps 横向：7 节点，done/now/wait）

│ ③ 产物 Tabs：                       │ ⑥ 审核决策卡：               │
│    口播稿(文本) / 封面(图) /         │    终检清单（check-list）     │
```

**数据源**：`usePageData<ContentDetail>(`/api/content/${slug}`)`，需要字段：
`{ meta（全量）, timeline: {status, at?}[], files: {path, role, exists, size?}[], checks: {label, level:'ok'|'warn'|'bad', note}[], allowedTransitions: {to, action}[], source: {backlogId}, auditTrail: {at, text, kind}[], publishInfo?: {title, desc, tags, visibility} }`。
job 进度：`useJob(activeJobId)`——activeJobId 从 `useJobs()` 里按 slug 匹配。

**动作矩阵（本页是全站写动作最密的页；全部走 §2.10 useAction / useJobAction 流）**

| meta.status | 按钮 | 背后调用 | 流程 |
|---|---|---|---|

### 2.12 vite.config、路由方式与构建产物进 git

**vite.config.ts（dev proxy 与 SSE 注意点，拍板 §2 注释要求落地）**

```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  define: { __BUILD_TIME__: JSON.stringify(new Date().toISOString().slice(0, 16)) },
  server: {
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:5170',
        changeOrigin: true,
        // ── SSE 经 proxy 的三条注意（拍板 §2「关 buffering，留注释」）──
        // 1) 超时置 0：/api/events 是无限长连接，默认 timeout 会掐断后无限重连
        timeout: 0,
        proxyTimeout: 0,
        // 2) dev server 不得加 compression 类中间件（压缩会缓冲 SSE 分块）
        // 3) 响应端 no-buffering 头（Cache-Control: no-cache 等）由 server 侧负责
      },
    },
  },
  build: { outDir: 'dist', sourcemap: false },
})
```

**路由方式**：`createHashRouter`。理由一句话：单端口 serveStatic 下 BrowserRouter 需要 server 做 SPA fallback（所有非 /api 路径回落 index.html），HashRouter 零 server 配合、clone 即跑；本地单人工具无 URL 美观诉求。（此为详细设计层选择，不动任何拍板项。）

**构建产物进 git 操作步骤（拍板 §6「产物进 git、约定改 ui 必重 build」的落地）**

1. `tools/console/.gitignore` 确认：忽略 `node_modules/`、`logs/`，**不含** `dist/` 规则（若有历史规则加 `!packages/ui/dist/`）。
2. `packages/ui/package.json` scripts：`"dev": "vite"`、`"build": "tsc -b && vite build"`（tsc 先跑，type-only import 违规在此编译期红）。
3. 每次改 ui 源码后：`npm run build -w @console/ui` → `git add packages/ui/src packages/ui/dist` → 同一 commit 提交（**约定：含 src 变更的 commit 必须同时含重建后的 dist**，写进 `packages/ui/CLAUDE.md` 第 5 条）。
4. 同步校验凭证：侧栏 side-foot 显示 `__BUILD_TIME__`，与 commit 日期肉眼可对；漂移不可忍时再按拍板 §6 预案改 .gitignore + 本地 build 约定。
5. server serveStatic 指向 `packages/ui/dist`（02 的配置，路径在 §3 契约里对齐）。
