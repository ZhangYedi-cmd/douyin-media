## 1. 选型决策与理由（含一次推翻的记录）

| # | 决策 | 说明 |
|---|---|---|
| F1 | **React**（推翻早前「a+ 零构建 vanilla」分析结论） | 前提变了：该分析针对**只读看板**；产品其后升级为**裁决台**（审批 + dry-run 确认流、job 任务面板/SSE 进度流、待办分级倒计时），皆为有状态交互组件——vanilla 路线的「保存/恢复 UI 态」补丁本质是手搓乞丐版 React。前提变，结论跟着变 |
| F2 | **Vite，不用 Umi** | 六页本地单人工具只需要「组件+路由+构建」；Umi 的约定式路由/插件体系是中后台规模收益，本项目背不动其构建链与隐式约定（对 AI 增量维护不友好）。讨论中比较过，用户拍板 Vite |
| F3 | **antd**（用户拍板，推翻我方「不上组件库」建议；拍板时当期主版本 v5，实施期落位 **v6**——2026-08-18 编排裁决：决策实质是「上 antd + token 映射」非锁主版本，v6 已经 D 包浏览器实测端到端生效，不回退） | 真实用武之地正是原型手写最重处：P4 表格排序/筛选/行展开=Table、job 里程碑=Steps/Timeline、dry-run 确认=Modal/Popconfirm、P3 详情=Drawer、后续表单=Form |
| F4 | **视觉冲突解法：token 映射，不是双轨** | 原型 theme.css 的 Neutral Modern token（色板/圆角/字体/间距/语义色）映射进 antd `ConfigProvider` theme 配置——antd 组件长成原型的样子，而非原型迁就 antd 默认蓝。theme.css 保留服务自绘组件，两边引用同一组 CSS 变量值 |
| F5 | 不上图表库 | metrics 折线 = 参数化 SVG 组件（~60 行），数据点几十个、单序列，引图表库不成比例 |
| F6 | 不上状态管理库（redux/zustand/react-query 均不） | 后端「SSE 只推 refresh + revision」的模型天然消解前端缓存/失效问题，见 §3 |

依赖清单刻意穷尽：`react` `react-dom` `react-router-dom` `antd` + devDeps（`vite` `typescript` `@vitejs/plugin-react` `@types/react` `@types/react-dom`）。新增依赖须回到本表记录理由。
> 登记（2026-08-18，实施期增补）：`@types/react` `@types/react-dom`——react 19 包内零 `.d.ts`，无类型包则 TS+JSX 项目 `tsc` 必挂（实测 189 错同源），属基线遗漏非新能力。
> 登记（2026-08-19，实施期增补）：`react-markdown`——真机走查发现口播稿与治理报告以源码呈现，是每日最高频阅读路径；用户 2026-08-19 拍板接受破「依赖四件」上限。
> 登记（2026-08-19，实施期增补）：`remark-gfm`——同批引入，为 `react-markdown` 提供 GFM 表格/删除线/任务列表支持；理由同上（口播稿/治理报告最高频阅读路径，用户 2026-08-19 拍板破「依赖四件」上限）。

## 2. 包结构（五包全景）

```
tools/console/
├── packages/core/        （不变）
├── packages/cli/         （不变）
├── packages/cc-stream/   （不变）
├── packages/server/      serveStatic 指向 ui/dist
└── packages/ui/          Vite + React + antd + TS
    ├── src/
    │   ├── pages/        overview/ kanban/ detail/ backlog/ harness/ metrics/
    │   │                 一页一目录，页面私有组件就近放（AI 改一页只进一个目录）
    │   ├── components/   跨页共享：JobPanel(任务面板) / CommandChip(命令生成/执行)
    │   │                 AlertCard(分级警报) / DeadlineBadge(死线倒计时) / LineChart(SVG)
    │   ├── lib/          api.ts(fetch+token) / sse.ts(EventSource+revision) / theme.ts(antd token 映射)
    │   └── theme.css     原型 token 体系原样搬入（自绘组件用）
    └── vite.config.ts    dev proxy /api → 5170（SSE 经 proxy 注意关 buffering，留注释）
```

**依赖方向新增一条**：ui 对 core 仅 **type-only import**（`Snapshot`/`Alert`/`Job` 等类型），运行时零依赖——前后端共享一份类型定义，接口不匹配编译期即红。

## 3. 数据层：一个 hook，没有状态管理

全站数据流只有两种，各一个 hook：

```tsx
// 形态一：页面数据。挂载时 fetch；SSE context 的 revision 变化 → 自动重拉
const { data, stale } = usePageData<OverviewData>("/api/overview")

// 形态二：job 进度。消费 SSE 的 job:<id> 事件流，驱动 JobPanel
const job = useJob(id)   // { state, milestones, narration, costUsd, ... }
```

**UI 态在组件里，不进全局**：重新 fetch 换的是 data，组件自身 state（展开行、筛选值、滚动位）原地不动——这是换 React 最实惠的一笔收益，vanilla 路线需要手写保存/恢复的问题在此自动消失。附带收益：JSX 默认转义，vanilla 路线的 `esc()` 注入纪律问题消失。

## 4. 页面 × antd 组件对照（实施导航）

| 页 | 核心组件 | 备注 |
|---|---|---|
| P1 总览 | Alert/Card + DeadlineBadge + Statistic | 待办按损失分级置顶、死线倒计时、同类合并；警报区渲染 computeAlerts 输出 |
| P3 详情 | Drawer/Descriptions + Timeline + CommandChip | 状态操作区展示当前状态的合法迁移（来自 state.ts）及对应动作 |
| P4 选题池 | **Table**（排序/筛选/expandable） + CommandChip | promote/next-up/sweep 动作；「模拟取题」块渲染 `media next --json` |
| P5 治理 | List + Card + CommandChip/JobPanel | 结构化提议=按钮直落（backlog apply）；散文提议=派发任务（嵌 brain diff 审计） |
| P2 看板（瘦身） | 简化状态列表，非七列全宽 | 单人在制 0~2 条，形态从团队看板降为列表 |
| P6 数据 | Table + LineChart(自绘 SVG) | 数据源 `harness/logs/metrics.jsonl`（CLI v0.2），有数据后接入 |
| 全局 | ConfigProvider(theme.ts) + Layout 侧栏 + JobPanel 常驻挂角 | 健康灯读 /api/health（revision + 进程态） |

建造顺序沿产品决策：**P1 → P3 → P4 → P5 → P2/P6**，每建一页完整可用。砍掉清单不变：⌘K 全局搜索、标记已读 localStorage、内嵌视频播放器、拖拽。

## 5. 原型的新角色：设计稿

`docs/design/` 六页高保真原型**降级为设计稿**：像素规格、布局、语义色约定照它抄，代码不搬（HTML 骨架与手写 DOM 操作弃用）。唯一整体迁移的资产是 theme.css token 体系（→ §1 F4 双通道承接）。

## 6. 开发 / 构建 / 部署

- **dev**：`vite dev` + proxy `/api`（含 SSE）；后端另起（`start.sh`），前后端各自热更。
- **prod**：`vite build` → `packages/ui/dist/` → server serveStatic，单端口 5170，与后端方案 §3 一致。
- **构建产物进 git**（server 仓 clone 即跑，不强制前端工具链）；无 CI，约定「改 ui 必须重 build」——单人仓成本可接受，若产物 diff 噪音不可忍受再改 .gitignore + 本地 build 约定。

## 7. AI 维护约定（写进 ui 包根 CLAUDE.md）

1. 一页一目录，页面私有组件不出目录；跨页复用满 2 处才升 components/。
2. 数据获取只准走 usePageData/useJob 两个 hook，不得在组件里裸 fetch。
3. 视觉值只准引 token（antd theme 或 theme.css 变量），不得写死色值/字号。
4. 新增依赖须先在本方案 §1 依赖表记录理由。
