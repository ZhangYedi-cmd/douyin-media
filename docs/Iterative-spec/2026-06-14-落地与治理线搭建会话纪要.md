## 一、复盘 douyin-retro（从零建成，治理线第 1 个任务）
- **先证伪**：`sau` CLI 只有 login/check/upload，**零数据回采**——复盘不能靠它。
- **数据通道**：chrome-devtools 探明创作者中心指标地图 → 用 **Playwright + 复用 sau 的抖音 cookie**（`scripts/fetch.py`）**免扫码**拉后台，导出投稿列表 xlsx（16 列原始精度）+ 抓同类对标，标准库解析、零额外依赖。
- **归因模型**：`references/funnel-attribution.md`——传播漏斗（曝光→CTR→2s跳出→5s完播→完播→互动→涨粉）+ 症状→病因→动作表。
- **首份真报告**（14 条作品）关键结论：CTR 不差、但**完播率全线垫底、2s 跳出 ~50%** → 主漏点是**前 2 秒钩子 / 节奏**，不是封面；深度长视频完播低但收藏高，建议深度题以「收藏率+精准涨粉」为成功指标而非完播。

## 二、选题 douyin-ideate：砍掉「看抖音」死路
- **证伪**：headless 抓 `douyin.com` 主站搜索 = 空白（反爬重）；computer-use（本机 4K 指针 gate 坏）/ Claude-in-Chrome（需人值守）都进不了无人流水线。
- **决策**：整条「看抖音平台热点」删除，选题只靠 agent-reach（X/Reddit/HN/GitHub/arxiv）。
- **平台信号改从哪来**：由发布后的复盘反向补（自己受众的真信号，比爬通用热榜更贴账号）。

## 三、创作录屏彻底无人化 + 配音接专用引擎
- **录屏**：新建 `web-video-presentation/scripts/auto-record.mjs`——headless Playwright `record_video` 确定性渲染（按音频时长逐 step 推进）+ ffmpeg 配音 mux，**全程零点击**。技术路线 + 端到端（真 scaffold 演示，4.2s 精确命中）双实测通过。`--serve` 一条命令出片。
- **顺手修 bug**：`scaffold.sh` 把绝对路径喂 `npm create vite` 会被吃掉开头 `/`，改为 cd 父目录 + basename。
- **配音**：接入既有 `tts-dub`（直调 MiniMax HTTP，绕开坏掉的 mmx CLI，多音字/单段语速可控）。`list-voices.mjs` 找到账户**两个**克隆音色，选定最新 `moss_audio_4dd8142e…`，写入 repo 根 `tts.config.json`。两音色实测可合成。
- **创作四件套链路**：`web-video-presentation`（网页+分段文案）→ `tts-dub`（配音）→ `dubbing-check`（体检）→ `auto-record`（出 mp4）。约束：每 step 都要有口播（无静音步），否则录制时间线错位。
