## 四、需要人拍板的未决项

1. **CHK-05 的 status 判定范围要不要含 `retro_done`**（影响 #22/25/26 三行能否机器化）。
   现行 `alerts.ts` 的 CHK-05 严格照 01 方案原文只判 `status=published`；但 CHK-01 原文把 `published/retro_done` 并列判定。真实仓当前有 4 条 `retro_done` 且无作品链接的条目（spec-driven-development / context-engineering / karpathy-autoresearch / gemini-cli-teardown），若不管这个空隙就把对应行删掉转交机器区，这些追踪会**静默消失**。本提案默认保守处理：**这三行暂留人写区**，等 CHK-05 范围拍板后再决定是否能机器化。
2. **「已发布」小节要不要建第四个机器区**（#34-35）。三区定义没覆盖它，本提案不越权新增，维持人写区。
3. **#19/#20（EP04/open-weight-5 发布状态调查）与 #29（kimi 自主声明）这类「机器告警 + 人工调查」混合行，人审时具体怎么拆分排版**（是整行留人写区、机器区另生成一条精简重复告警；还是在人写区行内加一个「关联机器告警：CHK-03」的引用）。本提案默认「整行人写区 + 机器区独立生成一条」（轻度重复，信息不丢），最终排版细节留给人审时定。
4. **#39/#41 两行的拆分排版**：现状是「机器计数 + 人写叙事」挤在同一段文字里，人审改造时需要真的把这行拆成两行（一行进机器区标记内，一行留在标记外），不是简单加个 HTML 注释就能解决，需要人工重新排版这两行的措辞。
